# Как внести вклад в проект / Contributing to CodeRush

---

## 🇷🇺 Русская версия

Спасибо за интерес к проекту CodeRush! Мы рады любой помощи: от исправления опечаток в уроках до добавления новых тренажёров. Чтобы наша совместная работа была продуктивной, пожалуйста, следуйте этим простым правилам.

### Как сообщить об ошибке или предложить идею

Если вы нашли баг на сайте или у вас есть идея нового курса, не спешите сразу писать код. Сначала свяжитесь с нами:
1. Напишите в Telegram: [@GhostFromCastle](https://t.me/GhostFromCastle).
2. Или создайте Issue в этом репозитории, подробно описав проблему или предложение.

### Как отправить свой код (Pull Request)

Если вы хотите исправить баг или добавить новую фичу самостоятельно:
1. Сделайте форк (Fork) этого репозитория.
2. Создайте новую ветку для ваших изменений (например, `fix-typo-lesson-4` или `feature-new-dictionary`).
3. Внесите изменения и протестируйте их локально (не забудьте проверить работу на мобильных экранах).
4. Сделайте коммит с понятным сообщением (например, `Исправил ссылку в уроке 4`).
5. Отправьте изменения в свой форк и создайте Pull Request в ветку `main` нашего репозитория.

### Стиль кода и правила проекта

- **Стек:** проект написан на чистом HTML, CSS и JavaScript без использования сборщиков и тяжелых фреймворков.
- **Архитектура CSS:** мы придерживаемся методологии БЭМ и используем CSS-переменные. Старайтесь не плодить лишние классы.
- **Без комментариев:** в коде проекта нет комментариев (ни в HTML, ни в CSS, ни в JS). Код должен быть самодокументируемым.
- **Пути к файлам:** все ссылки внутри проекта должны быть относительными (без слэша в начале), чтобы сайт корректно работал на GitHub Pages.
- **Уроки:** если вы добавляете или редактируете урок, соблюдайте структуру (заголовки, блоки кода, раздел «Если что-то не работает», задачи в `<details>`).

Спасибо, что помогаете делать образование доступнее!

## 🇬🇧 English version

Thank you for your interest in CodeRush! We appreciate any help, from fixing typos in lessons to adding new trainers. To make our collaboration productive, please follow these simple rules.

### Reporting issues or suggesting ideas

If you find a bug or have an idea for a new course, please don't start writing code immediately. First, contact us:
1. Message us on Telegram: [@GhostFromCastle](https://t.me/GhostFromCastle).
2. Or create an Issue in this repository describing the problem or suggestion in detail.

### Submitting code (Pull Request)

If you want to fix a bug or add a new feature yourself:
1. Fork this repository.
2. Create a new branch for your changes (e.g., `fix-typo-lesson-4` or `feature-new-dictionary`).
3. Make your changes and test them locally (don't forget to check mobile responsiveness).
4. Make a commit with a clear message.
5. Push to your fork and create a Pull Request to the `main` branch of our repository.

### Code style and project rules

- **Stack:** the project is built with vanilla HTML, CSS, and JavaScript without build tools or heavy frameworks.
- **CSS Architecture:** we follow the BEM methodology and use CSS variables. Try not to create unnecessary classes.
- **No comments:** there are no comments in the project code (neither in HTML, CSS, nor JS). Code should be self-documenting.
- **File paths:** all links within the project must be relative (no leading slash) so the site works correctly on GitHub Pages.
- **Lessons:** if you add or edit a lesson, follow the structure (headings, code blocks, "If something doesn't work" section, tasks in `<details>`).

Thank you for helping make education more accessible!
