Работа с файлами и папками

~35 минут Windows Теория и Практика

В прошлых уроках мы научились перемещаться по файловой системе и смотреть, что в ней есть. Но смотреть - это только половина дела. Настоящая работа начинается, когда мы создаём файлы, копируем, переименовываем и удаляем. Именно этим и займёмся сегодня.

Осторожно: часть команд из этого урока необратимо меняют файловую систему. Удалённый через терминал файл не попадает в корзину - он исчезает навсегда. Поэтому сначала разберёмся с правилами безопасности, а потом уже будем действовать.

Правила безопасности

Три простых правила, которые спасут вас от потери данных.

Правило 1: сначала проверь, потом делай

Перед любой командой, которая меняет файлы, посмотрите cd (или pwd) и dir. Вы точно в той папке? Вы точно понимаете, что будете менять? Ошибка в один символ может стоить дня работы.

Правило 2: следи за пробелами и кавычками

del my file.txt попытается удалить два файла: my и file.txt. А del "my file.txt" - один файл с пробелом в имени. Разница критична. Если в имени есть пробел - всегда берите в кавычки.

Правило 3: проверяй wildcard перед удалением

Команда del * удаляет все файлы в текущей папке. А rd /s /q папка - папку со всем содержимым без подтверждения. Перед использованием wildcard (символов * и ?) сначала выполните dir * - посмотрите, что попадёт под действие.

Корзины нет

В отличие от проводника Windows, терминал не отправляет файлы в корзину. del и rd удаляют сразу. Восстановить потом можно специальными утилитами, но не всегда успешно. Относитесь к удалению как к безвозвратному действию.

Создание папок: mkdir и md

Команда mkdir (make directory) создаёт новую папку. В Windows работает и короткий алиас md - они эквивалентны.

mkdir NewProject

Создали папку NewProject в текущей директории. Если такая папка уже есть, команда не выдаст ошибку, но и новую не создаст - просто проигнорирует.

Можно создать несколько папок сразу:

mkdir html css js

Появятся три папки в текущем каталоге. Удобно при создании структуры проекта.

Вложенные папки

Обычная mkdir a\b\c сработает только если папка a уже существует. Чтобы создать всю цепочку с нуля, нужен ключ /p (в cmd) - его ещё называют «parents»:

mkdir /p Projects\MyApp\src

Теперь в текущей папке есть Projects, а в ней - MyApp, а в ней - src. Одна команда - три уровня вложенности. Очень удобно при развёртывании структуры нового проекта.

В PowerShell mkdir - это алиас на New-Item, и он умеет создавать вложенные папки без всяких ключей:

mkdir Projects\MyApp\src

Создание файлов

Для создания пустого файла в cmd есть несколько способов. Самый простой - перенаправление вывода в несуществующий файл:

type nul > empty.txt

type nul - это «ничего не вывести». Знак > перенаправляет этот пустой вывод в файл. Результат - пустой файл empty.txt. Если файл уже был - он перезапишется (станет пустым).

А если нужен файл с содержимым:

echo Привет, мир! > hello.txt

В файл hello.txt запишется «Привет, мир!» - и вы сразу увидите его через type hello.txt (о команде type чуть ниже).

Знак > перезаписывает файл. Знак >> (двойной) дописывает в конец, не стирая старое:

echo Вторая строка >> hello.txt

Теперь в файле две строки. Это удобный способ вести лог или накапливать данные без редактора.

В PowerShell файл создаётся ещё проще - командой New-Item (алиас ni):

New-Item -Path "empty.txt" -ItemType File

Чтение файлов: type и more

Прежде чем что-то менять, полезно уметь читать. В cmd для этого есть type - прямой аналог cat в Linux:

type hello.txtПривет, мир!Вторая строка

Выводит содержимое файла в терминал. Просто и понятно.

Минус: если файл длинный (например, лог на тысячи строк) - содержимое пронесётся перед глазами и останется только конец. Для больших файлов используют more - постраничный просмотр:

type bigfile.txt | more

Вертикальная черта | - это конвейер, о котором подробно в уроке 8. Пока просто запомните: она передаёт вывод type в more, и тот показывает по одному экрану за раз. Листать - Space, выйти - Q.

В PowerShell type работает как алиас на Get-Content, а для постраничного просмотра удобнее more или Out-Host -Paging.

Копирование: copy

Команда copy копирует файл из одного места в другое. Исходный файл остаётся на месте.

copy file.txt D:\Backup\file.txt

Скопировали файл file.txt в D:\Backup. Если папки назначения нет - будет ошибка.

Можно не указывать новое имя - тогда сохранится исходное:

copy file.txt D:\Backup\

А можно, наоборот, скопировать с новым именем в ту же папку:

copy file.txt file-backup.txt

Wildcards

Копировать можно по маске. Это называется wildcard - шаблон с символами * и ?:

  • * - любое количество любых символов.
  • ? - ровно один любой символ.
copy *.txt D:\Backup\

Скопирует все файлы с расширением .txt. А так:

copy report?.txt D:\Backup\

Скопирует файлы report1.txt, report2.txt, reportA.txt - любые с одним символом перед .txt. Файл report10.txt не попадёт - там два символа.

Перезапись: ключ /Y

По умолчанию, если файл назначения уже существует, copy спросит подтверждение: «Перезаписать? Y/N». Ключ /Y отключает этот вопрос - перезаписывает без подтверждения:

copy /Y file.txt D:\Backup\

Удобно в скриптах. Но в ручной работе лучше без /Y: случайно перезаписать важный файл очень легко.

Копирование папок: xcopy

У copy есть важное ограничение: он не копирует папки целиком. Только файлы. Для папок есть отдельная команда xcopy:

xcopy source_folder target_folder /E /I

Ключи:

  • /E - включить все подпапки, включая пустые.
  • /I - если target_folder не существует, считать его папкой, а не спрашивать.

Без этих ключей xcopy копирует только файлы из верхнего уровня исходной папки. С /E - всю структуру целиком.

В PowerShell копирование папок проще - Copy-Item с ключом -Recurse:

Copy-Item source_folder -Destination target_folder -Recurse

Перемещение и переименование: move и ren

Для перемещения файла в другое место используется move:

move file.txt D:\Archive\file.txt

Файл исчезнет из текущей папки и появится в D:\Archive. В отличие от copy, исходного файла больше нет.

Если новое имя не указано - сохранится старое:

move file.txt D:\Archive\

Переименование: ren

Отдельная команда для переименования - ren (или rename):

ren old_name.txt new_name.txt

Файл old_name.txt теперь называется new_name.txt. Содержимое не изменилось, только имя.

Команда ren работает и с папками:

ren OldFolder NewFolder

Важно: ren переименовывает в той же папке, где находится файл. Путь ко второму имени не нужен. Если хочется переименовать и переместить одновременно - используйте move.

В PowerShell move - алиас на Move-Item, ren - на Rename-Item. Работают так же, как в cmd.

Удаление файлов: del

Команда del (или erase) удаляет файлы. Без корзины, без подтверждения.

del file.txt

Файл исчез. Можно удалить несколько сразу:

del a.txt b.txt c.txt

По маске

del *.tmp

Удалит все файлы .tmp в текущей папке. Перед этим обязательно проверьте: dir *.tmp - что попадёт под действие.

Удаление во вложенных папках: /s

del /s *.bak

Ключ /s - удалить во всех подпапках рекурсивно. Осторожно: del /s * из корня диска снесёт практически всё.

Файлы только для чтения: /f

Если файл помечен атрибутом «только чтение», del откажется его удалять. Ключ /f (force) снимает это ограничение:

del /f readonly.txt

Без подтверждения: /q

При удалении по маске del может спрашивать подтверждение «Удалить? Y/N» для каждого файла. Ключ /q (quiet) отключает эти вопросы:

del /q *.tmp

Используйте только когда точно уверены, что удаляете то, что планировали.

Удаление папок: rmdir и rd

Для папок - rmdir (или короткий алиас rd):

rmdir EmptyFolder

Удалит папку, только если она пустая. Если внутри есть файлы - ошибка.

Чтобы удалить папку со всем содержимым, нужен ключ /s:

rmdir /s OldFolder

Терминал спросит подтверждение: «Удалить папку и всё её содержимое? Y/N». Ключ /q убирает этот вопрос:

rmdir /s /q OldFolder

Именно эта команда используется в скриптах и в инструкциях «как удалить папку одной командой». Она радикальна: удаляет всё без единого вопроса.

Опасная комбинация

rmdir /s /q удаляет папку со всем содержимым без подтверждения. Ошибка в пути = потеря данных. Всегда перед такой командой делайте dir по нужной папке - убедитесь, что удаляете именно её. И никогда не запускайте rmdir /s /q от корня диска (C:\, D:\) - это снесёт всё.

Атрибуты файлов: attrib

Иногда файл не удаляется или не перезаписывается, хотя должен. Причина часто в атрибутах - специальных флагах, которые управляют поведением файла.

Основные атрибуты:

  • R (Read-only) - только чтение. Нельзя изменить и не удаляется обычной del.
  • H (Hidden) - скрытый. Не виден в dir без ключа /a.
  • S (System) - системный. Обычно у файлов ОС.
  • A (Archive) - архивный. Используется программами резервного копирования.

Посмотреть атрибуты:

attrib file.txtA    R     C:\Users\Иван\file.txt

Здесь у файла два атрибута: A (архивный) и R (только чтение).

Снять атрибут «только чтение»:

attrib -R file.txt

Поставить обратно:

attrib +R file.txt

Скрыть файл от dir:

attrib +H secret.txt

Показать обратно:

attrib -H secret.txt

Знание attrib часто спасает: если del не работает, а вы уверены, что файл существует - скорее всего, дело в атрибуте R или S.

Шпаргалка

Самое важное в одном месте:

  • mkdir папка создать папку
  • mkdir /p a\b\c вложенные папки
  • echo текст > file создать файл с текстом
  • echo текст >> file дописать в файл
  • type file прочитать файл
  • type file | more постранично
  • copy src dst копировать файл
  • xcopy src dst /E копировать папку
  • move src dst переместить
  • ren old new переименовать
  • del file удалить файл
  • del /s *.tmp по маске во вложенных
  • rd папка удалить пустую папку
  • rd /s /q папка удалить со всем содержимым
  • attrib file атрибуты файла
  • *.txt, report?.txt маски файлов

Если что-то не работает

Типичные ошибки при работе с файлами и папками.

  • «Файл не найден». Опечатка в имени или вы не в той папке. Проверьте dir - что реально есть в текущей директории. Обратите внимание на расширения: notes.txt и notes - разные имена.
  • «Отказано в доступе». Одна из трёх причин: 1) файл системный (требуется запуск от администратора), 2) у файла атрибут «только чтение» (снять через attrib -R), 3) файл занят другой программой (закройте её).
  • «Папка не пуста». Используете rmdir без /s на папке, внутри которой есть файлы. Добавьте /s.
  • «Слишком длинное имя файла». Windows имеет ограничение на длину пути - около 260 символов. Если файл лежит в глубоко вложенной папке, полный путь может не влезть. Решение: переместите папку ближе к корню диска или сократите имя.
  • «Синтаксическая ошибка в имени файла». Скорее всего, в пути пробел без кавычек. Возьмите весь путь в двойные кавычки: copy "C:\Program Files\file.txt" D:\backup\.
  • del не удаляет файл. Проверьте атрибуты: attrib file.txt. Если стоит R - del /f. Если S (системный) - запустите терминал от администратора.
  • copy перезаписал файл без спроса. Ключ /Y был указан или установлен в переменной окружения COPYCMD. В ручной работе лучше проверять через dir, существует ли файл назначения.
  • «Команда rd не работает с непустой папкой». Именно так - rd удаляет только пустые. Для непустых - rd /s (с подтверждением) или rd /s /q (без).

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Все действия выполняйте в отдельной папке (создайте её через mkdir practice и перейдите в неё), чтобы не задеть ничего важного.

Задача 1. Создайте и прочитайте

В папке practice:

  1. Создайте файл notes.txt с текстом «Первая заметка».
  2. Допишите в него вторую строку: «Вторая заметка».
  3. Прочитайте файл через type.
  4. Проверьте через dir, что размер файла больше нуля.
Подсказка

Создание - echo с >. Дописывание - echo с >>. Чтение - type.

Разбор 
mkdir practicecd practiceecho Первая заметка > notes.txtecho Вторая заметка >> notes.txttype notes.txtПервая заметкаВторая заметкаdir notes.txt

В dir увидите, что размер файла - около 30 байт: две строки плюс символы перевода строки. Если бы вторую строку добавляли через > (одинарное) - первая бы стёрлась, файл остался бы только со второй строкой.

Задача 2. Копирование и переименование

Продолжая с предыдущей задачей:

  1. Скопируйте notes.txt в файл notes-backup.txt.
  2. Создайте папку archive.
  3. Переместите notes-backup.txt в archive.
  4. Переименуйте archive в old-notes.
  5. Проверьте через dir и dir old-notes, что всё на месте.
Подсказка

Копирование - copy, перемещение - move, переименование - ren. Обратите внимание: ren для папки не требует пути, только новое имя.

Разбор 
copy notes.txt notes-backup.txtmkdir archivemove notes-backup.txt archive\ren archive old-notesdir...  notes.txt  old-notesdir old-notes...  notes-backup.txt

Что получилось: в текущей папке остались notes.txt (исходный) и old-notes (папка). Внутри папки - notes-backup.txt. Обратите внимание: переименование папки через ren не требует обратного слэша, а перемещение файла в папку - требует (archive\).

Задача 3. Wildcards и атрибуты

Создайте три файла с разными расширениями и поработайте с ними:

  1. Создайте report1.txt, report2.txt, report10.txt (любое содержимое).
  2. Выполните dir report?.txt - какие файлы показаны?
  3. Выполните dir report*.txt - в чём разница?
  4. Установите report1.txt атрибут «только чтение» (attrib +R).
  5. Попробуйте удалить его через del report1.txt - что произойдёт?
  6. Снимите атрибут (attrib -R) и удалите нормально.
Подсказка

? означает ровно один символ, * - любое количество. Поэтому report?.txt найдёт только report1 и report2, а report*.txt - все три, включая report10.

Разбор 
echo A > report1.txtecho B > report2.txtecho C > report10.txtdir report?.txtreport1.txt  report2.txtdir report*.txtreport1.txt  report2.txt  report10.txtattrib +R report1.txtdel report1.txtОтказано в доступе.attrib -R report1.txtdel report1.txt

Что тут важного:

  • report?.txt нашёл только файлы с одним символом. report10 имеет два символа - не подходит.
  • report*.txt нашёл все три - * заменяет любое количество символов, включая ноль и десять.
  • Атрибут R защищает файл от удаления - Windows не даёт удалить то, что помечено «только чтение». Это полезно случайно, но мешает намеренно.
  • attrib -R снимает защиту, и del срабатывает.
Задача 4. Уборка

Аккуратно удалите всё созданное:

  1. Перейдите в папку practice (если вышли из неё).
  2. Посмотрите через dir /s, что внутри - убедитесь, что удаляете именно то, что создали.
  3. Удалите папку old-notes целиком (со всем содержимым).
  4. Удалите оставшиеся файлы в practice.
  5. Вернитесь на уровень выше (cd ..) и удалите саму папку practice.
  6. Проверьте через dir, что от неё ничего не осталось.
Подсказка

Для папки с содержимым - rd /s. Для файлов - del. Для самой practice после очистки - rd practice (уже пустая, ключ /s не нужен).

Разбор 
cd practicedir /srd /s old-notesУдалить папку и всё содержимое? Y/NYdel notes.txtdel report2.txtdel report10.txtcd ..rd practicedir

Проверка dir /s перед удалением - полезная привычка. Даже если вы уверены, что в папке, лучше ещё раз посмотреть. Пять секунд проверки - против часов восстановления.

Обратите внимание: rd /s без /q спрашивает подтверждение. Это защита от случайности. В скриптах используют /q, но в ручной работе лучше без него.

Что мы узнали и что дальше

Научились управлять файлами и папками в терминале. Узнали, что создание, копирование, перемещение и удаление - четыре базовые операции, без которых немыслима никакая работа. Познакомились с командами mkdir, copy, xcopy, move, ren, del и rd, разобрали их ключи и типичные ошибки.

Отдельно разобрались с wildcards - масками * и ?, которые экономят время при работе с группами файлов. И с атрибутами через attrib - почему файл не удаляется и как это исправить. Научились читать файлы через type и смотреть большие файлы через more.

И запомнили три правила безопасности: сначала проверь, потом делай; следи за пробелами и кавычками; проверяй wildcard перед удалением.

В следующем уроке займёмся системными командами - разберёмся с процессами (какие программы работают, как их завершить), узнаем, как получить полную информацию о системе, и научимся управлять службами.
