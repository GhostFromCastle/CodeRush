Основы скриптов в PowerShell

~35 минут Windows Только практика

Мы подошли к финалу курса по терминалу Windows. Мы научились перемещаться по файлам, управлять процессами и даже проверять сеть. Но настоящая магия начинается, когда вы объединяете эти команды в скрипты.

В PowerShell скрипты сохраняются в файлах с расширением .ps1. В этом уроке мы напишем наш первый скрипт и разберём главные фишки PowerShell: переменные и конвейеры.

Политика выполнения (Execution Policy)

Windows очень заботится о безопасности. По умолчанию она запрещает запускать любые скачанные или созданные вами скрипты .ps1, чтобы вирусы не могли навредить системе.

Если вы попытаетесь запустить скрипт, то увидите ошибку:

... выполнение сценариев отключено в этой системе.

Чтобы разрешить запуск своих скриптов, нужно открыть PowerShell от имени администратора и ввести команду:

Set-ExecutionPolicy RemoteSigned

Эта команда разрешает запуск локальных (ваших) скриптов, но требует цифровую подпись для скачанных из интернета. Это безопасный компромисс.

Переменные в PowerShell

Как и в любом языке программирования, в PowerShell можно хранить данные в переменных. Они всегда начинаются со знака доллара $.

$name = "Алексей"Write-Host "Привет, $name!"

Команда Write-Host выводит текст на экран (аналог echo). Обратите внимание, что переменная подставляется прямо в строку без дополнительных знаков.

Конвейеры и фильтрация

Главная сила PowerShell - это конвейеры (pipes, символ |). Они позволяют передавать результат одной команды в другую как объекты.

В связке с конвейером часто используют команду Where-Object для фильтрации. Внутри фигурных скобок {} пишется условие, где $_ означает «текущий объект».

Пример: найти все процессы, которые потребляют больше 100 мегабайт памяти (колонка WorkingSet).

Get-Process | Where-Object {$_.WorkingSet -gt 100MB}

Создаём первый скрипт

Давайте соберём всё вместе и напишем скрипт, который выводит приветствие и список самых прожорливых по памяти процессов.

Шаг 1. Откройте Блокнот (или VS Code).

Шаг 2. Напишите следующий код:

$user = $env:USERNAMEWrite-Host "Привет, $user! Запускаю диагностику..."$topProcesses = Get-Process | Sort-Object -Property WorkingSet -Descending | Select-Object -First 3Write-Host "`nТоп-3 программы по памяти:"$topProcesses | Format-Table Name, WorkingSet

Шаг 3. Сохраните файл с именем diag.ps1 (обязательно выберите «Тип файла: Все файлы», чтобы не добавилось .txt).

Шаг 4. Откройте PowerShell, перейдите в папку с файлом и запустите его:

.\diag.ps1

Скрипт выведет ваше имя (взятое из переменной окружения $env:USERNAME) и таблицу с тремя самыми тяжёлыми процессами.

Шпаргалка

Самое важное в одном месте:

  • .ps1 расширение скрипта
  • Set-ExecutionPolicy разрешить скрипты
  • $var = "text" создать переменную
  • Write-Host вывести текст
  • | конвейер (передача данных)
  • Where-Object фильтрация
  • $_ текущий объект

Если что-то не работает

Разберём типичные ошибки при создании скриптов.

  • «Запуск сценариев отключён». Вы не выполнили Set-ExecutionPolicy RemoteSigned или запустили PowerShell не от имени администратора.
  • «Файл не найден». Вы находитесь не в той папке. Используйте cd, чтобы перейти туда, где лежит diag.ps1.
  • Скрипт открывается в Блокноте, а не запускается. Вы запускаете его двойным кликом. В PowerShell запускайте файлы через консоль: .\имя_файла.ps1.
  • Кракозябры вместо русских букв. В старых версиях PowerShell консоль не понимает кодировку UTF-8 без настройки. Сохраняйте скрипты в кодировке Windows-1251 или добавьте [Console]::OutputEncoding = [System.Text.Encoding]::UTF8 в начало скрипта.

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Разрешаем скрипты

Откройте PowerShell от имени администратора и разрешите выполнение локальных скриптов.

Подсказка

Используйте команду Set-ExecutionPolicy с параметром RemoteSigned.

Решение учителя 
Set-ExecutionPolicy RemoteSigned
Задача 2. Переменные и математика

Создайте две переменные с числами, сложите их и выведите результат на экран с помощью Write-Host.

Подсказка

Создайте $a = 5 и $b = 10. Результат сохраните в $sum = $a + $b. Выведите через Write-Host "Сумма: $sum".

Решение учителя 
$a = 5$b = 10$sum = $a + $bWrite-Host "Сумма: $sum"
Задача 3. Фильтр служб

Выведите список всех служб Windows (команда Get-Service), но оставьте только те, которые сейчас запущены (статус Running).

Подсказка

Используйте конвейер: Get-Service | Where-Object {$_.Status -eq "Running"}.

Решение учителя 
Get-Service | Where-Object {$_.Status -eq "Running"}
Задача 4. Скрипт-отчёт

Напишите скрипт report.ps1, который выводит ваше имя пользователя, текущую дату и количество запущенных процессов. Сохраните и запустите его.

Подсказка

Используйте $env:USERNAME для имени, Get-Date для даты и (Get-Process).Count для количества процессов. Не забудьте про Write-Host.

Решение учителя 
$user = $env:USERNAME$date = Get-Date$procCount = (Get-Process).CountWrite-Host "Отчёт для: $user"Write-Host "Дата: $date"Write-Host "Запущено процессов: $procCount"
