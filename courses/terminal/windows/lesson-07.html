Основы скриптов в PowerShell

~50 минут Windows Теория и Практика

До этого момента мы вводили команды по одной. Ввели - выполнили - ввели следующую. Это удобно для разовых задач, но что если нужно выполнять одну и ту же последовательность каждый день? Создавать папки, копировать файлы, проверять процессы, отправлять отчёт? Каждый раз печатать десятки команд вручную - бессмысленная трата времени.

Именно для этого существуют скрипты - файлы с набором команд, которые выполняются как одна программа. В PowerShell такие файлы имеют расширение .ps1. Сегодня научимся их писать.

Мы разберём: как разрешить запуск скриптов (Windows по умолчанию их блокирует), как писать комментарии, работать с переменными, принимать решения через if, повторять действия через циклы, создавать свои функции и запускать всё это из терминала. Это уже полноценное программирование - просто на языке, встроенном в Windows.

Политика выполнения: почему Windows блокирует скрипты

Первое, с чем сталкивается каждый, кто пытается запустить .ps1-файл, - сообщение об ошибке:

.\hello.ps1 : Не удается загрузить файл ... так как выполнение сценариев отключено в этой системе.

Это не баг, а защита. Windows по умолчанию запрещает запуск любых скриптов - чтобы случайно скачанный из интернета файл не навредил системе. Это называется Execution Policy (политика выполнения).

Посмотреть текущую политику:

Get-ExecutionPolicyRestricted

Restricted - «запрещено всё». Именно это стоит по умолчанию на большинстве систем.

Разрешить запуск своих скриптов

Откройте PowerShell от имени администратора (правая кнопка на «Пуск» - «Терминал (Администратор)») и выполните:

Set-ExecutionPolicy RemoteSigned

Windows спросит подтверждение - отвечайте Y. Готово, теперь можно запускать свои скрипты.

Что значит RemoteSigned

Политик несколько, и RemoteSigned - разумный компромисс:

  • Restricted - запрещено всё. Значение по умолчанию.
  • AllSigned - разрешены только подписанные скрипты. Строго, но неудобно - свои скрипты тоже нужно подписывать.
  • RemoteSigned - локальные скрипты работают, а скачанные из интернета - только с цифровой подписью. Оптимальный выбор для большинства.
  • Unrestricted - разрешено всё. Небезопасно.
  • Bypass - вообще никаких проверок. Только для специальных случаев.

После смены политики её значение сохраняется навсегда. Обратно вернуть можно так же: Set-ExecutionPolicy Restricted.

Альтернатива: запуск без смены политики

Если менять политику не хочется (или нет прав администратора) - можно запустить скрипт в обход через ключ -ExecutionPolicy Bypass:

powershell -ExecutionPolicy Bypass -File .\hello.ps1

Работает, но каждый раз нужно писать длинную команду. Для регулярной работы удобнее один раз сменить политику.

Первый скрипт: Hello, World

Традиционно начинают с простого. Создайте файл hello.ps1 в любом удобном месте (например, в домашней папке). Проще всего через Блокнот:

  1. Откройте Блокнот (notepad в терминале или через «Пуск»).
  2. Напишите одну строку (см. код ниже).
  3. Сохраните как hello.ps1 - обязательно выберите «Тип файла: Все файлы», чтобы Блокнот не добавил .txt в конец.
Write-Host "Привет, это мой первый скрипт!"

Теперь в терминале перейдите в папку со скриптом и запустите:

.\hello.ps1

Точка и обратный слэш .\ - это важный момент. В PowerShell нельзя запустить скрипт по имени - только с указанием пути. Точка означает «текущая папка», то есть «запусти hello.ps1 из текущей директории». Это защита от случайного запуска одноимённого скрипта из PATH.

Если всё правильно - увидите приветствие. Первый скрипт работает.

Комментарии

Комментарии - это текст в скрипте, который не выполняется. Он нужен для заметок: объяснений, напоминаний, пометок. Через месяц вы забудете, зачем написали эту строку - комментарий спасёт.

Однострочный: #

# Это комментарий. Всё, что после решётки, не выполняется.Write-Host "Привет"  # А это - комментарий после кода

Многострочный: <# ... #>

<#Это многострочный комментарий.Он полезен для больших блоков:описания скрипта, списка изменений, заметок.#>Write-Host "Привет"

Многострочные комментарии часто используют в начале скрипта - как «шапку» с описанием:

<#.SYNOPSISСкрипт для резервного копирования документов..DESCRIPTIONКопирует папку Documents в указанную папку назначения.Логирует каждый шаг в файл..EXAMPLE.\backup.ps1 -Destination D:\Backups#>

Такой формат понимает Get-Help - если скрипт написан с такой шапкой, справка работает и для него.

Переменные

Переменная - это имя, за которым хранится значение. В PowerShell переменные начинаются со знака доллара $.

$name = "Алексей"$age = 25$isStudent = $true

Имя переменной - любое, из букв, цифр и подчёркиваний. Регистр не важен: $name и $Name - одна и та же переменная. Но принято писать в едином стиле по всему скрипту.

Типы данных

PowerShell определяет тип автоматически, но можно указать явно:

  • Строка - в кавычках. $name = "Алексей".
  • Число - без кавычек. $age = 25, $pi = 3.14.
  • Логическое - $true или $false.
  • Массив - через запятую в @(). $colors = @("red", "green", "blue").
  • Хеш-таблица - через @{}. $user = @{Name="Иван"; Age=30}.

Явное указание типа:

[int]$age = 25[string]$name = "Алексей"

Полезно, когда нужно, чтобы переменная не превратилась в другой тип случайно. Например, [int]$age = "25" автоматически преобразует строку в число.

Использование переменных в строках

Самый удобный способ - интерполяция: переменная подставляется прямо в строку с двойными кавычками.

$name = "Алексей"$age = 25Write-Host "Меня зовут $name, мне $age лет"Меня зовут Алексей, мне 25 лет

В одинарных кавычках интерполяции нет:

Write-Host 'Меня зовут $name'Меня зовут $name

Это важное отличие: "..." подставляет переменные, '...' - нет. Используйте двойные, когда хотите, чтобы переменные раскрылись.

Встроенные переменные

PowerShell сам заполняет некоторые переменные полезными значениями. Их можно читать (и иногда менять), но не нужно объявлять:

  • $env:USERNAME - имя текущего пользователя.
  • $env:COMPUTERNAME - имя компьютера.
  • $env:USERPROFILE - домашняя папка.
  • $PSScriptRoot - папка, в которой лежит текущий скрипт (только в скрипте, не в командной строке).
  • $HOME - домашняя папка пользователя.
  • $PWD - текущая рабочая папка.
  • $args - аргументы, переданные скрипту.

Пример:

Write-Host "Привет, $env:USERNAME!"Write-Host "Ты на компьютере $env:COMPUTERNAME"

Операторы

PowerShell использует непривычные для программистов операторы сравнения - словесные, а не символьные. Это сделано, чтобы избежать путаницы с перенаправлением ввода-вывода (> в PowerShell означает перенаправление, а не «больше»).

Сравнение

  • -eq - равно ($a -eq $b).
  • -ne - не равно.
  • -gt - больше.
  • -lt - меньше.
  • -ge - больше или равно.
  • -le - меньше или равно.

Пример:

$age = 25$age -gt 18True$age -eq 30False

Строки

  • -like - совпадает с шаблоном (с * и ?). "hello" -like "he*" вернёт $true.
  • -match - совпадает с регулярным выражением. "hello123" -match "\d+" вернёт $true.
  • -contains - проверка, есть ли элемент в массиве.

Логические

  • -and - И (оба условия верны).
  • -or - ИЛИ (хотя бы одно верно).
  • -not - НЕ (инверсия).

Пример:

$age = 25$hasLicense = $true$age -gt 18 -and $hasLicenseTrue

Арифметика

Тут всё привычно:

$a = 10$b = 3$a + $b    # 13$a - $b    # 7$a * $b    # 30$a / $b    # 3.333...$a % $b    # 1 (остаток от деления)

Условный оператор: if / else

Основной способ заставить скрипт «принимать решения». Синтаксис почти как в других языках:

if (условие) {    # выполняется, если условие истинно}

Полная форма:

if (условие) {    # если истина}elseif (другое условие) {    # если первое ложно, но это истинно}else {    # если все предыдущие ложны}

Пример - проверка возраста:

$age = 25if ($age -ge 18) {    Write-Host "Совершеннолетний"}else {    Write-Host "Несовершеннолетний"}

Более сложный - с elseif:

$score = 75if ($score -ge 90) {    Write-Host "Отлично"}elseif ($score -ge 70) {    Write-Host "Хорошо"}elseif ($score -ge 50) {    Write-Host "Удовлетворительно"}else {    Write-Host "Плохо"}

Проверки идут сверху вниз. Как только одна сработала - остальные пропускаются. Поэтому порядок важен: сначала самое строгое условие, потом мягче.

Проверка на существование файла

Очень частая задача - проверить, существует ли файл или папка, прежде чем что-то с ними делать. Для этого есть Test-Path:

$file = "C:\Users\Иван\notes.txt"if (Test-Path $file) {    Write-Host "Файл существует"}else {    Write-Host "Файла нет"}

Test-Path возвращает $true или $false - идеально для if. Работает и для файлов, и для папок, и для реестра.

Тернарный оператор

В PowerShell 7 (не в 5.1) появился сокращённый вариант для простых условий:

$status = $age -ge 18 ? "Adult" : "Minor"

«Если age >= 18 - вернуть «Adult», иначе - «Minor»». Короче, чем if/else. В Windows PowerShell 5.1 не работает - используйте обычный if.

Циклы

Циклы нужны, когда какое-то действие надо повторить много раз. Например, обработать все файлы в папке или выполнить операцию для каждого пользователя из списка.

foreach

Самый популярный цикл. «Для каждого элемента из коллекции - сделай что-то»:

$colors = @("red", "green", "blue")foreach ($color in $colors) {    Write-Host "Цвет: $color"}

Результат:

Цвет: redЦвет: greenЦвет: blue

Внутри фигурных скобок $color по очереди принимает каждое значение из массива.

Цикл по файлам в папке

Очень частая задача - сделать что-то со всеми файлами в папке:

$files = Get-ChildItem -Path "C:\Temp" -Fileforeach ($file in $files) {    Write-Host "Файл: $($file.Name), размер: $($file.Length) байт"}

Здесь $($file.Name) - подстановка свойства объекта. Просто $file.Name внутри строки не сработает так, как ожидается - PowerShell попытается найти переменную с именем file.Name. Скобки $(...) говорят: «сначала вычисли выражение, потом подставь результат».

for

Классический цикл «сделай N раз, с счётчиком»:

for ($i = 1; $i -le 5; $i++) {    Write-Host "Итерация $i"}

Разбор:

  • $i = 1 - начальное значение счётчика.
  • $i -le 5 - условие продолжения (пока i меньше или равно 5).
  • $i++ - что делать после каждой итерации (увеличить на 1).

while

Цикл «пока условие истинно»:

$count = 0while ($count -lt 3) {    Write-Host "Счётчик: $count"    $count++}

Выполняется, пока count < 3. Внутри цикла обязательно нужно менять условие (count++), иначе цикл будет бесконечным.

Управление циклом

Два ключевых слова для управления:

  • break - прервать цикл полностью.
  • continue - пропустить текущую итерацию и перейти к следующей.
foreach ($n in 1..10) {    if ($n -eq 5) {        break    }    if ($n % 2 -eq 0) {        continue    }    Write-Host $n}

Выведет 1 3 - на чётных срабатывает continue, а на 5 - break, и цикл завершается.

Конструкция 1..10

1..10 - это диапазон. PowerShell автоматически создаёт массив чисел от 1 до 10. Можно 1..100, 5..1 (обратный порядок), даже "a".."e" - для букв. Очень удобно в циклах.

Функции

Функция - это именованный блок кода, который можно вызывать многократно. Если вы делаете что-то повторяющееся - оберните это в функцию.

Простая функция

function Say-Hello {    Write-Host "Привет!"}Say-Hello

Объявили функцию Say-Hello, потом вызвали её по имени. Результат - «Привет!».

Обратите внимание на имя: Глагол-Существительное. Как у встроенных команд. Так принято - если функция Get-Something - она что-то возвращает, Set-Something - что-то меняет. Это делает код предсказуемым.

С параметрами

function Greet-User($name) {    Write-Host "Привет, $name!"}Greet-User "Алексей"Greet-User "Мария"

Параметр $name указывается в скобках после имени функции. При вызове функции значение передаётся в кавычках (если это строка).

С несколькими параметрами

function Add-Numbers($a, $b) {    $sum = $a + $b    Write-Host "Сумма: $sum"}Add-Numbers 5 3Сумма: 8

Возврат значения: return

Функция может не писать в консоль, а возвращать результат - чтобы вызывающий код мог с ним работать:

function Get-Sum($a, $b) {    return $a + $b}$result = Get-Sum 10 20Write-Host "Результат: $result"Результат: 30

Разница принципиальная:

  • Write-Host внутри функции - выводит на экран, но ничего не возвращает. Снаружи работать с результатом не получится.
  • return - возвращает значение. Снаружи можно сохранить в переменную, передать в конвейер, обработать.

Правило: если функция должна «сделать что-то и показать» - Write-Host. Если «вычислить и отдать» - return.

Аргументы скрипта

Скрипт может принимать аргументы командной строки - как обычные программы. Например, скрипт для копирования файлов, которому передают путь источника и назначения.

Через $args

Простейший способ - встроенная переменная $args:

# script.ps1Write-Host "Всего аргументов: $($args.Count)"foreach ($arg in $args) {    Write-Host "Аргумент: $arg"}

Запуск:

.\script.ps1 hello world 123Всего аргументов: 3Аргумент: helloАргумент: worldАргумент: 123

Через param (правильный способ)

Более правильный и удобный способ - объявить параметры в блоке param() в самом начале скрипта:

param(    [string]$Source,    [string]$Destination,    [int]$Count = 1)Write-Host "Копирую из $Source в $Destination"Write-Host "Количество: $Count"

Запуск:

.\script.ps1 -Source C:\Data -Destination D:\Backup -Count 5.\script.ps1 -Source C:\Data -Destination D:\Backup

Преимущества:

  • Типы проверяются автоматически ([int]$Count не примет строку).
  • Значения по умолчанию ($Count = 1).
  • Понятные имена параметров (-Source, -Destination).
  • Справка Get-Help работает корректно.

Вызывать можно и без имён - по позиции:

.\script.ps1 C:\Data D:\Backup

Но с именами надёжнее: если скрипт разрастётся, вы сами через месяц не вспомните, что первый аргумент - это Source, а второй - Destination.

Обработка ошибок: try / catch

Что делать, если что-то пошло не так? Файл не найден, нет прав, сеть недоступна. Вместо того чтобы скрипт падал с ошибкой, можно «поймать» её и обработать аккуратно:

try {    Get-Content "C:\nonexistent\file.txt"    Write-Host "Файл прочитан"}catch {    Write-Host "Ошибка: $($_.Exception.Message)"}finally {    Write-Host "Завершено"}

Как это работает:

  • try - что попробовать сделать.
  • catch - что делать, если была ошибка. $_ - сам объект ошибки, $_.Exception.Message - текст ошибки.
  • finally - что выполнить в любом случае (и при успехе, и при ошибке). Необязателен.

По умолчанию try/catch срабатывает только на «останавливающие» ошибки (terminating). Многие команды PowerShell при сбое выдают «не останавливающие» - и catch их пропустит. Чтобы поймать, нужно добавить -ErrorAction Stop:

try {    Get-Content "C:\nonexistent\file.txt" -ErrorAction Stop}catch {    Write-Host "Поймали ошибку: $($_.Exception.Message)"}

Это тонкость, на которой часто спотыкаются. Запомните: если catch не срабатывает, хотя ошибка есть - добавьте -ErrorAction Stop.

Полный пример: скрипт для резервного копирования

Соберём всё вместе в один осмысленный скрипт. Он принимает исходную и целевую папку, копирует файлы и логирует каждый шаг.

param(    [string]$Source = "C:\Data",    [string]$Destination = "D:\Backup")Write-Host "=== Запуск резервного копирования ==="Write-Host "Источник: $Source"Write-Host "Назначение: $Destination"if (-not (Test-Path $Source)) {    Write-Host "Ошибка: исходная папка не найдена"    exit 1}if (-not (Test-Path $Destination)) {    New-Item -Path $Destination -ItemType Directory | Out-Null    Write-Host "Создана папка назначения"}$files = Get-ChildItem -Path $Source -File$count = 0foreach ($file in $files) {    try {        Copy-Item $file.FullName -Destination $Destination -ErrorAction Stop        $count++        Write-Host "Скопирован: $($file.Name)"    }    catch {        Write-Host "Ошибка с $($file.Name): $($_.Exception.Message)"    }}Write-Host "=== Готово. Скопировано файлов: $count из $($files.Count) ==="

Что тут происходит по шагам:

  1. param() - объявляет два параметра с значениями по умолчанию. Можно запустить без аргументов - возьмутся дефолты.
  2. Выводим информационные сообщения.
  3. Test-Path проверяет, существует ли исходная папка. Если нет - выходим с кодом ошибки exit 1.
  4. Если папки назначения нет - создаём через New-Item. | Out-Null подавляет вывод команды (иначе она напишет «создано...» в консоль).
  5. Get-ChildItem -File получает список файлов (только файлы, без папок).
  6. Цикл foreach копирует каждый файл. Внутри try/catch - если один файл не скопируется, скрипт продолжит работу с остальными.
  7. В конце - итоговая статистика.

Это уже полноценный скрипт, который можно использовать в реальной работе. Запустить можно так:

.\backup.ps1 -Source "C:\Users\Иван\Documents" -Destination "D:\Backups\Documents"

  • # комментарий
  • <# ... #> многострочный
  • $var = "..." переменная
  • "$var" интерполяция
  • '...' без интерполяции
  • if / elseif / else условие
  • -eq, -ne, -gt, -lt сравнение
  • foreach ($x in $arr) по коллекции
  • for / while с счётчиком / пока
  • function Name {} функция
  • param() аргументы скрипта
  • try / catch обработка ошибок
  • -ErrorAction Stop чтобы поймать ошибку

Если что-то не работает

Типичные проблемы при написании и запуске скриптов.

  • «Выполнение сценариев отключено». Не сменили Execution Policy. Откройте PowerShell от администратора и выполните Set-ExecutionPolicy RemoteSigned. Это нужно один раз - настройка сохранится.
  • «Файл не найден» при запуске .\script.ps1. Вы не в той папке. Проверьте через pwd или Get-Location, что терминал открыт там, где лежит скрипт. Или используйте полный путь: C:\Scripts\script.ps1.
  • «Скрипт открывается в Блокноте, а не запускается». Вы кликнули по нему двойным в проводнике. Windows по умолчанию связывает .ps1 с Блокнотом. Запускайте через терминал: .\script.ps1.
  • «Кракозябры вместо русских букв». Проблема с кодировкой файла. По умолчанию PowerShell 5.1 ждёт Windows-1251, а Блокнот может сохранить в UTF-8. Решения: 1) сохранить файл в кодировке Windows-1251 в Блокноте; 2) в PowerShell 5.1 добавить в начало скрипта [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; 3) использовать PowerShell 7 (там UTF-8 по умолчанию).
  • «try/catch не ловит ошибку». Скорее всего, ошибка «не останавливающая». Добавьте -ErrorAction Stop к той команде, которая падает. Это самая частая тонкость в PowerShell.
  • «Переменная не подставилась в строку». Проверьте кавычки. В одинарных '...' подстановки нет - только текст. Нужны двойные "...". Если переменная - свойство объекта, используйте $($obj.Prop).
  • «Цикл завис и не завершается». Скорее всего, бесконечный while - не меняется условие. Или for без увеличения счётчика. Прерывается через Ctrl + C. Проверьте, что внутри цикла условие выхода когда-нибудь станет ложным.
  • «Скрипт работает неправильно, но ошибки нет». Добавьте Write-Host в ключевых местах, чтобы понять, где логика ломается. Или используйте Set-PSDebug -Trace 1 для пошагового выполнения. Или запустите в VS Code с точками останова - это самый удобный способ отладки.

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Все выполняются в отдельной папке (например, C:\Scripts) - чтобы не задеть ничего важного.

Задача 1. Первый скрипт

Пройдите базовый путь:

  1. Проверьте текущую политику выполнения через Get-ExecutionPolicy.
  2. Если она Restricted - смените на RemoteSigned (от администратора).
  3. Создайте файл hello.ps1 с одной строкой: Write-Host "Привет!"
  4. Запустите через .\hello.ps1.
  5. Добавьте в скрипт комментарий в начале - что делает этот скрипт.
Подсказка

Для создания файла можно использовать Блокнот (notepad hello.ps1 прямо из терминала) или New-Item hello.ps1. При сохранении в Блокноте выберите «Тип файла: Все файлы», чтобы не получилось hello.ps1.txt.

Разбор 
Get-ExecutionPolicyRestricted# от администратора:Set-ExecutionPolicy RemoteSigned# в файле hello.ps1:# Мой первый скрипт - выводит приветствиеWrite-Host "Привет!".\hello.ps1Привет!

Обратите внимание:

  • Get-ExecutionPolicy работает без администратора. А Set- - требует прав.
  • После смены политики она сохраняется навсегда - в следующих сессиях менять не нужно.
  • Комментарий с # не выполняется - скрипт выводит только «Привет!».
Задача 2. Переменные и условия

Создайте скрипт check-age.ps1, который:

  1. Задаёт переменную $age со значением 20.
  2. Выводит приветствие с вашим именем (можно взять из $env:USERNAME).
  3. Проверяет через if: если возраст 18 или больше - выводит «Взрослый», иначе - «Ребёнок».
  4. Запускает скрипт и проверяет результат.
  5. Меняет $age на 15 и запускает снова - результат должен измениться.
Подсказка

Синтаксис: $age = 20, потом if ($age -ge 18) { ... } else { ... }. Не забудьте двойные кавычки, если хотите подставить переменную в Write-Host.

Разбор 
# Проверка возраста$age = 20$name = $env:USERNAMEWrite-Host "Привет, $name!"Write-Host "Твой возраст: $age"if ($age -ge 18) {    Write-Host "Взрослый"}else {    Write-Host "Ребёнок"}

Запуск:

.\check-age.ps1Привет, Иван!Твой возраст: 20Взрослый

Если поменять $age = 15 - результат будет «Ребёнок».

Обратите внимание на -ge - «больше или равно». Если написать >= (как в других языках), PowerShell не поймёт - это не оператор сравнения, а часть перенаправления вывода.

Задача 3. Циклы

Создайте скрипт multiplication.ps1, который выводит таблицу умножения на 7:

  1. Используйте цикл for от 1 до 10.
  2. На каждой итерации выводите строку вида «7 x 3 = 21».
  3. Запустите и проверьте, что все 10 строк на месте.
Подсказка

Синтаксис: for ($i = 1; $i -le 10; $i++) { ... }. Внутри - $result = 7 * $i, потом Write-Host "7 x $i = $result".

Разбор 
# Таблица умножения на 7for ($i = 1; $i -le 10; $i++) {    $result = 7 * $i    Write-Host "7 x $i = $result"}

Вывод:

7 x 1 = 77 x 2 = 147 x 3 = 21...7 x 10 = 70

Можно попробовать другие циклы для сравнения:

foreach ($i in 1..10) {    Write-Host "7 x $i = $(7 * $i)"}

Второй вариант короче, но менее нагляден. Оба работают. Используйте тот, что понятнее вам.

Задача 4. Функции и параметры

Создайте скрипт report.ps1 с параметрами и функцией:

  1. В начале - param() с двумя параметрами: $UserName (по умолчанию $env:USERNAME) и $ShowDate (по умолчанию $true, тип [bool]).
  2. Функция Write-Divider, которая выводит линию из 40 символов «=».
  3. Использование: Write-Divider, потом «Отчёт для: $UserName», Write-Divider, если $ShowDate - вывод текущей даты через Get-Date, потом Write-Divider.
  4. Запустить с параметрами и без - посмотреть разницу.
Подсказка

Синтаксис: param([string]$UserName = $env:USERNAME, [bool]$ShowDate = $true). Для логического флага при вызове - .\report.ps1 -ShowDate $false.

Разбор 
param(    [string]$UserName = $env:USERNAME,    [bool]$ShowDate = $true)function Write-Divider {    Write-Host ("=" * 40)}Write-DividerWrite-Host "Отчёт для: $UserName"Write-Dividerif ($ShowDate) {    Write-Host "Дата: $(Get-Date)"    Write-Divider}

Запуск без параметров:

.\report.ps1========================================Отчёт для: Иван========================================Дата: 26.10.2026 14:30:15========================================

С параметрами:

.\report.ps1 -UserName "Мария" -ShowDate $false========================================Отчёт для: Мария========================================

Что тут интересного:

  • Значения по умолчанию позволяют запускать скрипт без аргументов - он работает с разумными настройками.
  • Функция Write-Divider убирает дублирование: вместо трёх строк с «====» - три вызова функции.
  • Конструкция "=" * 40 - повторяет строку 40 раз. Быстрый способ создать разделитель.
  • Флаг -ShowDate $false - отключает вывод даты. Удобно для разных сценариев использования.

Это уже похоже на настоящий инструмент. Такие скрипты пишут для реальной работы: отчёты, резервные копии, мониторинг.

Что мы узнали и что дальше

Научились писать скрипты в PowerShell - превращать наборы команд в файлы .ps1, которые можно запускать одной командой. Разобрались с Execution Policy: почему Windows блокирует скрипты и как это отключить безопасно (RemoteSigned).

Освоили основы программирования на PowerShell: комментарии (# и <# ... #>), переменные ($name = "...") с интерполяцией в двойных кавычках, операторы сравнения (-eq, -gt и другие) и логические (-and, -or).

Изучили обработку ошибок через try/catch/finally с важной тонкостью: большинство ошибок PowerShell «не останавливающие», и чтобы их поймать - нужен -ErrorAction Stop.
