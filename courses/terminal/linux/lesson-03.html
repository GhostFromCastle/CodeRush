Управление файлами и папками

~35 минут Linux Теория и Практика

В прошлом уроке мы научились перемещаться по файловой системе и смотреть, что в ней есть. Но смотреть - это только половина дела. Настоящая работа начинается, когда мы создаём файлы, копируем, перемещаем и удаляем. Именно этим и займёмся сегодня.

Осторожно: часть команд из этого урока необратимо меняют файловую систему. Удалённый файл в терминале не попадает в корзину - он исчезает навсегда. Поэтому сначала разберёмся с правилами безопасности, а потом уже будем действовать.

Правила безопасности при работе с файлами

Прежде чем что-то делать, запомните три правила. Они простые, но спасут вас от потери данных.

Правило 1: сначала проверь, потом делай

Перед любой командой, которая меняет файлы, посмотрите pwd и ls. Вы точно в той папке? Вы точно понимаете, что будете менять? Ошибка в один символ может стоить недели работы.

Правило 2: следи за пробелами и кавычками

rm my file.txt - удалит два файла: my и file.txt. А rm "my file.txt" - один файл с пробелом в имени. Разница критична. Если имя содержит пробелы - всегда берите в кавычки.

Правило 3: не используй rm с wildcard без проверки

Команда rm * удаляет всё в текущей папке. А rm -rf / - пытается удалить вообще всю систему. Wildcard (символы *, ?) - мощный инструмент, но требует предельной осторожности. Всегда сначала проверяйте через ls *, что именно попадёт под удаление.

Корзины нет

В отличие от Windows и macOS, терминал Linux не отправляет файлы в корзину. rm удаляет файл сразу - точнее, помечает место на диске как свободное. Восстановить потом можно, но это уже специальная процедура форензики, и не всегда успешно. Относитесь к rm как к безвозвратному действию.

Создание файлов: touch

Самая простая команда для создания файла - touch. Она создаёт пустой файл, если его не существует.

$ touch notes.txt

Всё, файл notes.txt создан в текущей папке. Пустой - ноль байт. Проверить можно через ls -l.

Можно создать несколько файлов сразу:

$ touch a.txt b.txt c.txt

Или файлы с более сложными именами (тут не забываем кавычки):

$ touch "my notes.txt" "проект 2026.md"

У touch есть ещё одна роль: если файл уже существует, touch обновляет его время последнего изменения, но не трогает содержимое. Это иногда используется в скриптах - «пометить файл как свежий». Содержимое через touch не задать.

Создать файл с содержимым: echo > file

Если нужно создать не пустой файл, а сразу с текстом - используют перенаправление вывода:

$ echo "Привет, мир!" > hello.txt

Что произошло: команда echo вывела строку, но не в терминал, а в файл hello.txt. Файл создан с этой строкой. Подробно про > и другие операторы перенаправления поговорим в уроке 8. Пока просто запомните, что так можно создавать файлы с содержимым.

Создание папок: mkdir

Команда mkdir (make directory) создаёт папку:

$ mkdir projects

Можно создать несколько папок сразу:

$ mkdir html css js

Вложенные папки: ключ -p

Обычно mkdir a/b/c не сработает, если нет папки a. Ключ -p (parents) создаёт всю цепочку папок, если их нет:

$ mkdir -p projects/myapp/src

Теперь в папке projects есть myapp, а в ней - src. Один командой. Очень удобно при создании структуры проекта.

Копирование: cp

Команда cp (copy) копирует файлы и папки. Синтаксис:

cp источник назначение

Копирование файла

$ cp notes.txt notes-backup.txt

Создали копию notes.txt под именем notes-backup.txt. Оригинал остался на месте.

Можно скопировать файл в другую папку - сохранив имя:

$ cp notes.txt projects/

Теперь notes.txt есть в текущей папке и в projects/. Две независимые копии.

Копирование папок: ключ -r

Просто cp projects projects-backup не сработает - надо указать ключ -r (recursive), чтобы скопировать папку со всем содержимым:

$ cp -r projects projects-backup

Ключ -i: не перезаписывать случайно

По умолчанию cp перезаписывает существующие файлы без предупреждения. Это опасно. Ключ -i (interactive) просит подтверждения:

$ cp -i notes.txt notes-backup.txtcp: overwrite 'notes-backup.txt'?

Отвечаете y - перезапишет, n - отменит. Полезная привычка при работе с важными файлами.

Перемещение и переименование: mv

Команда mv (move) делает две вещи: перемещает файл в другое место и переименовывает его. По сути, это одна и та же операция - меняется путь к файлу.

Переименование

$ mv notes.txt todo.txt

Файл notes.txt теперь называется todo.txt. Содержимое не изменилось, только имя.

Перемещение в другую папку

$ mv todo.txt projects/

Файл перемещён в projects/. Из текущей папки он исчез.

Перемещение с переименованием

$ mv todo.txt projects/tasks.txt

Переместили в projects/ и заодно переименовали в tasks.txt.

Перемещение папок работает так же - -r не нужен (в отличие от cp):

$ mv projects/archive projects-backup/

Папка archive переехала в projects-backup/.

Удаление: rm

Самая опасная команда в этом уроке. rm (remove) удаляет файлы и папки. Без корзины, без подтверждения, без возможности отменить.

Удаление файла

$ rm notes.txt

Файл удалён. Восстановить можно только специальными утилитами, и не всегда успешно.

Удаление нескольких файлов

$ rm a.txt b.txt c.txt

Удаление папки: -r

Просто rm projects не сработает - папка не пустая или вообще папка. Нужен -r:

$ rm -r projects

Удалит папку projects со всем содержимым. Без предупреждений.

Ключ -i: подтверждение

Как и с cp, ключ -i просит подтверждения для каждого удаляемого файла:

$ rm -ri projectsrm: descend into directory 'projects'? yrm: remove regular file 'projects/notes.txt'? y...

Медленно, но надёжно. Рекомендую использовать -i для папок, в которых есть что-то ценное.

Опасная команда

В интернете можно встретить совет «если хочешь почистить систему - запусти sudo rm -rf /*». Никогда так не делайте. Эта команда пытается удалить всё содержимое корня системы. Даже если система защитит себя (современные версии частично защищают), вы потеряете многое и, скорее всего, сломаете ОС. Это не «очистка», это разрушение.

Полезные сокращения: фигурные скобки

В bash есть удобный способ создавать много файлов и папок с похожими именами - через фигурные скобки:

$ mkdir -p project/{src,docs,tests}

Создаст три папки внутри project: src, docs, tests. Одной командой.

С файлами тоже работает:

$ touch file{1..5}.txt

Создаст file1.txt, file2.txt, file3.txt, file4.txt, file5.txt. Конструкция {1..5} разворачивается в диапазон от 1 до 5.

А можно даже так:

$ mkdir -p 2026/{Q1,Q2,Q3,Q4}/{reports,backups}

Создаст структуру из 8 папок: 2026/Q1/reports, 2026/Q1/backups, 2026/Q2/reports и так далее. Очень удобно для организации проектов.

Шпаргалка

Самое важное в одном месте:

  • touch file создать пустой файл
  • echo "text" > file создать с содержимым
  • mkdir dir создать папку
  • mkdir -p a/b/c вложенные папки
  • cp src dst копировать файл
  • cp -r src dst копировать папку
  • mv src dst переместить или переименовать
  • rm file удалить файл
  • rm -r dir удалить папку
  • {a,b,c} несколько значений

Если что-то не работает

Типичные ошибки при работе с файлами и способы их решить.

  • «rm: cannot remove 'file.txt': No such file or directory». Файла нет. Проверьте через ls, что он существует и вы в правильной папке.
  • «rm: cannot remove 'projects': Is a directory». Пытаетесь удалить папку без -r. Используйте rm -r projects.
  • «cp: omitting directory 'projects'». То же с копированием: папку надо через cp -r.
  • «Permission denied». У вас нет прав на эту операцию. Например, попытка удалить файл в /etc под обычным пользователем. Решение - sudo (см. урок 5) или другая папка.
  • «mv: cannot move 'X': Permission denied». Часто бывает при перемещении между разными файловыми системами (например, с домашней папки на флешку) или при недостатке прав.
  • «Я случайно удалил важный файл». К сожалению, rm необратим обычными средствами. Единственный вариант - прекратить запись на диск и обратиться к специалисту по восстановлению данных (или использовать extundelete, testdisk - но успех не гарантирован). Правило на будущее: перед rm - проверьте через ls, что удаляете.
  • «Файл с пробелом в имени не создаётся/удаляется». Возьмите имя в кавычки: touch "my file.txt", rm "my file.txt".
  • «Я перезаписал файл случайно». cp без -i перезаписывает молча. Привыкайте использовать cp -i для важных файлов или настройте алиас alias cp='cp -i' в ~/.bashrc.

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Первая - на создание, вторая - на копирование и перемещение, третья - на удаление, четвёртая - комплексная (создание структуры проекта). Все действия выполняются в отдельной папке, чтобы не задеть ничего важного.

Задача 1. Создайте и посмотрите

В домашней папке создайте:

  1. Пустой файл test.txt.
  2. Файл hello.txt с содержимым «Привет, Linux!».
  3. Папку practice.

Проверьте результат через ls -la. Убедитесь, что все три объекта созданы.

Подсказка

Для пустого файла - touch. Для файла с текстом - echo "..." > имя. Для папки - mkdir.

Разбор 
$ cd ~$ touch test.txt$ echo "Привет, Linux!" > hello.txt$ mkdir practice$ ls -latotal 20drwxr-xr-x  5 student student 4096 Oct 25 12:00 .drwxr-xr-x 10 root    root    4096 Oct 20 10:00 ..-rw-r--r--  1 student student    0 Oct 25 12:00 test.txt-rw-r--r--  1 student student   15 Oct 25 12:00 hello.txtdrwxr-xr-x  2 student student 4096 Oct 25 12:00 practice

Обратите внимание: у test.txt размер 0 (пустой), у hello.txt - 15 байт (длина строки «Привет, Linux!» в кодировке UTF-8). У папки practice первый символ d в правах - признак директории.

Задача 2. Копирование и перемещение

Продолжая с предыдущей задачей:

  1. Скопируйте hello.txt внутрь папки practice.
  2. Переименуйте test.txt в empty.txt.
  3. Переместите empty.txt в practice.
  4. Проверьте, что в домашней папке остались только practice и hello.txt.
Подсказка

Копирование - cp, переименование и перемещение - mv. В перемещении с одновременным переименованием можно обойтись одной командой mv.

Разбор 
$ cp hello.txt practice/$ mv test.txt empty.txt$ mv empty.txt practice/$ lshello.txt  practice$ ls practice/empty.txt  hello.txt

Всё на месте: два файла в practice, два объекта в домашней папке. Обратите внимание: hello.txt существует в двух местах - копия независимая, изменения в одной не влияют на другую.

Кстати, шаги 2 и 3 можно было объединить: mv test.txt practice/empty.txt - переместить и переименовать одной командой.

Задача 3. Удаление с проверкой

Аккуратно удалите созданное:

  1. Удалите файл hello.txt из домашней папки.
  2. Удалите папку practice целиком (со всем содержимым).
  3. Проверьте через ls -la, что ничего лишнего не осталось.

Важно: перед удалением папки выполните ls practice/ - убедитесь, что вы удаляете то, что планировали.

Подсказка

Файл - rm file. Папку - rm -r dir. Если хотите подтверждение для каждого файла - rm -ri dir.

Разбор 
$ ls practice/empty.txt  hello.txt$ rm hello.txt$ rm -r practice/$ ls -latotal 16drwxr-xr-x  3 student student 4096 Oct 25 12:05 .drwxr-xr-x 10 root    root    4096 Oct 20 10:00 ..drwxr-xr-x  2 student student 4096 Oct 25 12:05 Desktop...

Всё чисто. Обратите внимание: ls practice/ перед удалением - полезная привычка. Даже если вы уверены, что в папке, лучше ещё раз проверить. Пять секунд проверки - против часов восстановления.

Задача 4. Структура проекта

Создайте структуру для типичного веб-проекта в домашней папке. Должно получиться дерево:

myproject/├── src/│   ├── css/│   ├── js/│   └── images/├── docs/└── README.md

Плюс внутри каждой папки css, js, images создайте по одному пустому файлу: style.css, app.js, logo.png соответственно. README.md - с текстом «# Мой проект».

Подсказка

Используйте mkdir -p для вложенных папок и фигурные скобки для нескольких папок сразу. Файлы - через touch.

Разбор

Короткое решение - одной командой на папки:

$ mkdir -p myproject/{src/{css,js,images},docs}$ touch myproject/src/css/style.css$ touch myproject/src/js/app.js$ touch myproject/src/images/logo.png$ echo "# Мой проект" > myproject/README.md$ find myprojectmyprojectmyproject/srcmyproject/src/cssmyproject/src/css/style.cssmyproject/src/jsmyproject/src/js/app.jsmyproject/src/imagesmyproject/src/images/logo.pngmyproject/docsmyproject/README.md

Команда find myproject выводит всё дерево папки. Мы её разберём подробно в следующем уроке. А пока обратите внимание, что вся структура создана пятью командами. Мышкой вы бы кликали минут пять - а тут секунды.

Конструкция {src/{css,js,images},docs} - это вложенные фигурные скобки. Bash разворачивает их в src/css src/js src/images docs и передаёт mkdir -p. Один вызов - четыре папки.

Что мы узнали и что дальше

Научились управлять файлами и папками в терминале. Узнали, что создание, копирование, перемещение и удаление - это четыре базовые операции, без которых немыслима никакая работа в Linux. Познакомились с командами touch, mkdir, cp, mv и rm, разобрали их ключи и типичные ошибки.

Отдельно разобрались с правилами безопасности: rm необратим, имя с пробелом требует кавычек, wildcard может натворить бед. Изучили фигурные скобки {a,b,c} и диапазоны {1..5} - они сильно сокращают команды при создании структуры проекта.

В следующем уроке научимся читать содержимое файлов и искать - в файлах и по файловой системе. Разберём cat, less, find и grep. Это те инструменты, которыми вы будете пользоваться постоянно: логи, конфиги, поиск ошибок в проекте - всё это через них.
