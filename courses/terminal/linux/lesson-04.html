Чтение файлов и поиск

~40 минут Linux Теория и Практика

В прошлом уроке мы научились создавать, копировать и удалять файлы. Но зачем нужны файлы, если мы не можем заглянуть внутрь и понять, что там? В этом уроке разберёмся, как читать содержимое файлов и как искать - и по файловой системе, и внутри самих файлов.

Эти инструменты - хлеб системного администратора и разработчика. Логи сервера, конфиги, исходный код, текстовые данные - всё это читается и ищется через команды, которые мы сегодня освоим.

Прочитать файл целиком: cat

Самая простая команда для чтения - cat (от английского concatenate - «соединять»). Она выводит содержимое файла в терминал:

$ cat hello.txtПривет, Linux!

Просто и понятно. Но есть нюанс: если файл длинный, содержимое просто пронесётся перед глазами и останется только последняя часть в окне. Для больших файлов cat - плохой выбор.

Когда cat подходит:

  • Файл короткий (несколько строк).
  • Конфиг на 10-20 строк.
  • Нужно быстро заглянуть в один файл.

Когда cat не подходит:

  • Логи на тысячи строк.
  • Большие тексты.
  • Файлы, которые нужно читать постранично.

Полезный ключ: -n (нумерация строк)

$ cat -n hello.txt     1  Привет, Linux!

Добавляет номера строк. Удобно, когда нужно сказать коллеге «посмотри на строку 42» или сравнить два файла по номерам.

Постраничный просмотр: less

Для больших файлов есть less - команда, которая открывает файл в постраничном просмотрщике. Можно листать стрелками, искать по тексту, не выходя из просмотра.

$ less /var/log/syslog

Откроется первая страница файла. Внизу будет строка состояния - сколько просмотрено, из какого файла.

Управление внутри less

Это не обычный вывод в терминал - это интерактивный просмотрщик. Клавиши работают специальные:

  • ↑ / ↓ - листать по одной строке.
  • Space - страница вниз.
  • b - страница вверх.
  • g - в начало файла.
  • G (большая) - в конец файла.
  • /слово - поиск вперёд. Enter - применить.
  • n - следующее совпадение, N - предыдущее.
  • q - выйти обратно в терминал.

Ключевые g, G, /, q - запомните их, остальное придёт с опытом. Именно эти четыре используются постоянно.

Почему «less», а не «more»

Есть ещё команда more - старый предшественник less. Она тоже листает постранично, но не умеет двигаться назад, искать по тексту и работать с большинством файлов. less - современная и полноценная замена. Существует даже шутка: «less is more» - «less (меньше) - это больше (функций)».

Начало и конец файла: head и tail

Иногда нужно посмотреть не весь файл, а только его начало или конец. Например, в логах - свежие записи всегда в конце, в конфигах - шапка с параметрами в начале.

head - первые строки

$ head /var/log/syslog

По умолчанию показывает первые 10 строк. Можно указать другое количество через ключ -n:

$ head -n 20 /var/log/syslog$ head -n 1 hello.txt

Первая команда - 20 строк, вторая - одну строку. Ключ -n работает во многих командах (потом встретим его ещё не раз).

tail - последние строки

$ tail /var/log/syslog

Те же 10 строк, но с конца. Тоже можно изменить через -n.

tail -f - следить за файлом

Незаменимая вещь при работе с логами. Ключ -f (follow) «подписывается» на файл и показывает новые строки по мере их появления:

$ tail -f /var/log/syslog

Открывается последние 10 строк, и терминал остаётся в «живом» режиме - как только в файл дописывается что-то новое, оно тут же появляется на экране. Выход - Ctrl + C.

Это must-have при отладке: запускаете tail -f на логе приложения, воспроизводите проблему в браузере - и видите, что приложение пишет в реальном времени.

Поиск в файловой системе: find

Второй важный инструмент - find. Ищет файлы и папки по разным критериям: по имени, размеру, дате изменения, владельцу.

Поиск по имени

$ find . -name "*.txt"

Что тут что:

  • . - начальная точка поиска. Точка означает «текущая папка» (можно указать абсолютный путь, например /home/student).
  • -name - искать по имени.
  • "*.txt" - шаблон имени. Звёздочка означает «любые символы». Кавычки важны - без них bash попытается сам развернуть звёздочку, и результат будет непредсказуемый.

Команда выведет все файлы .txt в текущей папке и во всех вложенных - рекурсивно.

Только файлы или только папки

$ find . -type f -name "*.txt"$ find . -type d -name "src"

-type f - только файлы (file), -type d - только папки (directory). Полезно, когда у вас есть папки и файлы с похожими именами.

Поиск по размеру

$ find . -size +10M

Найдёт всё, что больше 10 мегабайт. Очень полезно для поиска «что же занимает всё место на диске». Ключ -size понимает байты (c), килобайты (k), мегабайты (M), гигабайты (G). Знак + - «больше чем», - - «меньше чем».

Поиск с действием

Одна из мощных фич find - можно не просто найти файлы, но и что-то с ними сделать. Ключ -exec позволяет запустить команду для каждого найденного файла:

$ find . -name "*.bak" -exec rm {} \;

Найдёт все файлы .bak и удалит их. Конструкция {} заменяется на путь к файлу, а \; - конец команды для -exec (обратный слэш нужен, чтобы bash не съел точку с запятой).

Осторожно: с -exec rm будьте предельно внимательны. Сначала выполните команду без -exec, посмотрите, что она находит. Убедитесь, что это именно то, что вы хотите удалить. И только потом добавляйте -exec.

Поиск внутри файлов: grep

Третья ключевая команда - grep. Ищет текст внутри файлов. Одна из самых используемых команд в Linux вообще.

Простой поиск

$ grep "error" /var/log/syslog

Найдёт все строки, где встречается слово «error», и выведет их. Регистр учитывается: «error» и «Error» - разные строки.

Игнорировать регистр: -i

$ grep -i "error" /var/log/syslog

Ключ -i (ignore case) - найдёт и «error», и «Error», и «ERROR».

Номера строк: -n

$ grep -n "error" /var/log/syslog142:Oct 25 14:30:00 ... error loading config287:Oct 25 14:35:12 ... fatal error: ...

Показывает номер строки перед каждой найденной. Удобно, когда потом нужно открыть файл и посмотреть контекст.

Рекурсивный поиск: -r

Один из самых мощных сценариев. Ищем не в одном файле, а во всех файлах внутри папки:

$ grep -r "TODO" ./src

Найдёт все строки с «TODO» во всех файлах папки ./src рекурсивно. Отличный способ найти все незавершённые задачи в проекте.

Комбинирование ключей

$ grep -rin "error" ./logs

Рекурсивно, игнорируя регистр, с номерами строк - в папке logs. Ключи можно писать вместе или раздельно (-r -i -n), результат одинаковый.

Вывести только имена файлов: -l

$ grep -rl "import config" ./src

Вместо содержимого строк - только список файлов, где есть совпадения. Полезно, когда ищешь «в каких файлах используется эта функция».

Исключить: -v

$ grep -v "DEBUG" /var/log/syslog

Инвертирует результат - показывает строки без указанного слова. Отлично подходит для фильтрации логов: «покажи всё, кроме отладочного шума».

Почему grep

Название происходит от команды g/re/p в редакторе ed: global regular expression print. Историческое наследие - но прижилось настолько, что стало отдельной командой. А ещё от него произошёл глагол «погрепать», которым программисты называют поиск по тексту - «погрепай логи».

Подсчёт строк, слов, символов: wc

Ещё одна полезная команда - wc (word count). Считает:

$ wc file.txt  42  312 2048 file.txt

Три числа подряд: строк, слов, байт. Порядок запомнить легко: стр → слов → байт.

Можно запросить только что-то одно:

$ wc -l file.txt42 file.txt

Только количество строк - -l. Аналогично -w (слова), -c (байты).

wc -l очень часто используют вместе с другими командами для подсчёта количества чего-либо. Например, «сколько файлов у нас есть»:

$ ls | wc -l

Но про этот синтаксис с вертикальной чертой - подробно в уроке 8. Пока просто знайте, что wc -l - популярная команда.

Шпаргалка

Самое важное в одном месте:

  • cat file весь файл в терминал
  • less file постраничный просмотр
  • head -n 5 file первые 5 строк
  • tail -f file следить за файлом
  • find . -name "*.txt" найти файлы по имени
  • find . -size +10M файлы больше 10 МБ
  • grep "text" file найти текст в файле
  • grep -rin "error" . найти везде, без регистра
  • wc -l file количество строк

Если что-то не работает

Типичные проблемы при чтении и поиске.

  • «cat вывел огромный файл, я ничего не успел прочитать». Для больших файлов используйте less. Если уже так получилось - просто прокрутите вверх или используйте Ctrl + Shift + PageUp (в большинстве терминалов).
  • «less не закрывается». Нажмите q. Именно маленькую английскую. Не Esc, не Ctrl+C (хотя обычно тоже работает), а именно q.
  • «find ничего не находит». Проверьте три вещи: 1) путь правильный? 2) шаблон в кавычках? 3) точно ли есть такой файл (проверьте ls)?
  • «find . -name *.txt находит не то». Кавычки забыли. Без кавычек bash сначала сам разворачивает *.txt в список файлов - и find получает не шаблон, а кучу аргументов. Всегда в кавычках: "*.txt".
  • «grep не находит текст, хотя он там точно есть». Проверьте регистр (попробуйте -i). Возможно, в файле не обычный текст, а бинарные данные - grep по умолчанию их не выводит, нужен ключ -a.
  • «grep -r выдаёт Permission denied на некоторые папки». Так бывает, когда grep пытается залезть в чужие папки без прав. Можно игнорировать ошибки через 2>/dev/null (об этом в уроке 8) или запускать с sudo.
  • «tail -f показывает не всё». По умолчанию tail показывает 10 последних строк на старте. Если нужно больше - используйте tail -n 100 -f file. А чтобы следить за файлом с самого начала - tail -f покажет только новое.
  • «Хочу остановить cat/tail -f/less, а терминал не реагирует». Ctrl + C прерывает любую команду. Если не работает - закройте окно.

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Первая - на чтение файлов, вторая - на head/tail, третья - на find, четвёртая - на grep. Все задачи можно выполнять на своих файлах, создать которые - часть упражнений.

Задача 1. Создать и прочитать

Создайте файл poem.txt с любым четверостишием (используйте echo с перенаправлением или откройте nano - если он есть). Затем:

  1. Прочитайте его через cat.
  2. Прочитайте через cat -n.
  3. Откройте через less, полистайте, закройте.
Подсказка

Многострочный текст через echo можно создать так:

$ echo -e "Строка 1\nСтрока 2\nСтрока 3\nСтрока 4" > poem.txt

Ключ -e включает интерпретацию \n как переноса строки.

Разбор 
$ echo -e "Буря мглою небо кроет,\nВихри снежные крутя;\nТо, как зверь, она завоет,\nТо заплачет, как дитя." > poem.txt$ cat poem.txtБуря мглою небо кроет,Вихри снежные крутя;То, как зверь, она завоет,То заплачет, как дитя.$ cat -n poem.txt     1  Буря мглою небо кроет,     2  Вихри снежные крутя;     3  То, как зверь, она завоет,     4  То заплачет, как дитя.$ less poem.txt

В less можно нажать q, чтобы выйти. Если файл короткий - он поместится на экране, но less всё равно откроется в режиме просмотра.

Задача 2. Голова и хвост

Создайте файл numbers.txt с числами от 1 до 20, каждое на новой строке. Затем:

  1. Покажите первые 5 строк через head.
  2. Покажите последние 3 строки через tail.
  3. Откройте tail -f на этом файле в одном терминале. В другом (или через echo >>) добавьте строку. Убедитесь, что она появилась.
Подсказка

Числа от 1 до 20 одной командой: seq 1 20 > numbers.txt. Ключи head/tail с количеством строк: -n 5 и -n 3. Для добавления строки используйте >> (двойное перенаправление) - оно дописывает в конец, а не перезаписывает.

Разбор 
$ seq 1 20 > numbers.txt$ head -n 5 numbers.txt12345$ tail -n 3 numbers.txt181920$ tail -f numbers.txt

Теперь в другом терминале:

$ echo 21 >> numbers.txt

И в первом терминале, где открыт tail -f, сразу же появится «21». Выход - Ctrl + C.

Конструкция >> - это дописывание. В отличие от > (одинарного), которое перезаписывает файл целиком, >> добавляет в конец, не трогая старое содержимое.

Задача 3. Найдите файлы

Найдите в своей домашней папке:

  1. Все файлы с расширением .txt.
  2. Все папки с именем Documents.
  3. Все файлы больше 1 МБ.

Плюс создайте несколько пустых файлов (touch test1.txt test2.txt) и найдите их через find.

Подсказка

Поиск начинаем из домашней папки: find ~ .... По имени - -name "*.txt", по типу - -type d для папок, по размеру - -size +1M.

Разбор 
$ find ~ -name "*.txt"/home/student/poem.txt/home/student/numbers.txt/home/student/test1.txt/home/student/test2.txt$ find ~ -type d -name "Documents"/home/student/Documents$ find ~ -size +1M -type f/home/student/Downloads/movie.mp4/home/student/.cache/browser/cache.db

Обратите внимание: find ищет рекурсивно - заходит во все вложенные папки. Это и хорошо (найдёт всё), и плохо (может занять время на большой папке).

Ещё момент: find по домашней папке покажет и скрытые папки вроде .cache. Это нормально, find не пропускает скрытое.

Задача 4. Поиск в тексте

Создайте несколько текстовых файлов с разным содержимым. Например:

  • log.txt: строки с «INFO», «WARNING», «ERROR».
  • config.txt: параметры типа «debug=true», «port=8080».

Затем найдите:

  1. Все строки со словом «ERROR» во всех файлах.
  2. Все строки со словом «error» (без учёта регистра).
  3. Все строки без слова «INFO».
  4. Все файлы, где есть слово «port».
Подсказка

Вспомните ключи grep: -r рекурсивно, -i без регистра, -v инверсия, -l только имена файлов.

Разбор

Создание файлов:

$ cat > log.txt << EOFINFO: server startedWARNING: low memoryERROR: connection failedINFO: retryEOF$ echo -e "debug=true\nport=8080\nhost=localhost" > config.txt

(Конструкция << EOF - это «heredoc», позволяет ввести многострочный текст. Подробнее - в уроке 8.)

Поиск:

$ grep -r "ERROR" ../log.txt:ERROR: connection failed$ grep -ri "error" ../log.txt:ERROR: connection failed$ grep -v "INFO" log.txtWARNING: low memoryERROR: connection failed$ grep -rl "port" ../config.txt

Что произошло:

  • grep -r прошёлся по всем файлам в текущей папке и нашёл строку с «ERROR».
  • -i добавил поиск без учёта регистра.
  • -v показал строки, где слова «INFO» нет.
  • -l вывел только имя файла, где есть «port» (полезно, когда файлов много).

Что мы узнали и что дальше

Освоили чтение файлов и поиск - те операции, без которых работа в терминале невозможна. Узнали, что cat подходит для маленьких файлов, а less - для больших, с возможностью листать и искать внутри. Разобрались с head и tail (включая волшебный tail -f для слежки за логами в реальном времени).

Изучили find - мощный поиск файлов по имени, типу, размеру и другим критериям. И grep - поиск текста внутри файлов с множеством полезных ключей (-r, -i, -n, -v, -l). Плюс wc для подсчёта строк, слов и байт.

В следующем уроке разберём права доступа и sudo. Это тема, которая поначалу пугает новичков: почему нельзя зайти в какую-то папку, почему «Permission denied», и что такое вообще этот суперпользователь root. Разберёмся с chmod, chown и когда нужен sudo.
