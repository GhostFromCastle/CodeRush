Права доступа и sudo

~40 минут Linux Теория и Практика

Наверняка вы уже сталкивались с загадочным сообщением Permission denied. Или замечали в выводе ls -l странные буквы rwxr-xr-x. Или слышали про «запустить с sudo», но не совсем понимали, что это значит.

В этом уроке разберёмся с одной из самых важных концепций Linux - правами доступа. Именно они делают Linux многопользовательской и безопасной системой: один пользователь не может случайно (или намеренно) сломать файлы другого. Плюс разберём, что такое sudo и когда без него не обойтись.

Зачем вообще права доступа

Вспомните, как устроен обычный компьютер под Windows: если вы - единственный пользователь, вы можете делать всё. Удалить любую программу, изменить любой файл, залезть в системные папки. Ограничений почти нет.

В Linux всё иначе. С самого начала система проектировалась как многопользовательская. На одном сервере могут одновременно работать десятки людей (через SSH), у каждого - своя домашняя папка, свои файлы, свои настройки. И ни один из них не должен видеть или менять данные другого.

Отсюда и появились права доступа. У каждого файла и папки есть владелец и набор разрешений: кто может читать, кто может изменять, кто может запускать. Без этих ограничений многопользовательская система превратилась бы в хаос.

Аналогия

Представьте офис с общими и личными шкафчиками. В общий шкафчик можно положить что угодно, его содержимое доступно всем. А личный шкафчик заперт на ключ, и открыть его может только владелец. Права доступа - это как раз про то, какой шкафчик общий, какой - личный, и у кого есть ключи.

Как читать права: ls -l разбор

Помните, в уроке 2 мы смотрели ls -l и я обещал разобрать права подробно? Время пришло. Смотрим на вывод:

$ ls -l notes.txt-rw-r--r-- 1 student student 1024 Oct 25 12:00 notes.txt

Нас интересуют первые 10 символов: -rw-r--r--. Разберём их по частям.

Первый символ - тип файла

Самый первый символ показывает, что это за объект:

  • - - обычный файл.
  • d - папка (directory).
  • l - символическая ссылка (как ярлык в Windows).
  • c - символьное устройство (например, терминал).
  • b - блочное устройство (жёсткий диск, флешка).
  • s - сокет (для межпроцессного взаимодействия).
  • p - именованный канал (pipe).

В 95% случаев вы будете видеть - (файл) или d (папка). Остальные типы - редкость, но встречаются в системных директориях.

Девять символов - три группы по три

Оставшиеся 9 символов - это и есть права. Они разбиты на три тройки:

- rwx r-x r-x   ^^^ ^^^ ^^^   |   |   |   |   |   └─ права для всех остальных (others)   |   └───── права для группы (group)   └───────── права для владельца (owner/user)

То есть у каждого файла есть три «категории» пользователей:

  • Владелец (user, u) - тот, кому принадлежит файл. Обычно это тот, кто его создал.
  • Группа (group, g) - группа пользователей, которой принадлежит файл. В Linux пользователи объединяются в группы (например, «студенты», «разработчики», «админы»).
  • Остальные (others, o) - все прочие пользователи системы.

Для каждой категории указывается три права:

  • r (read) - читать. Для файла - открывать и смотреть содержимое. Для папки - видеть её содержимое через ls.
  • w (write) - писать. Для файла - изменять содержимое. Для папки - создавать, удалять и переименовывать файлы внутри.
  • x (execute) - выполнять. Для файла - запускать его как программу. Для папки - заходить внутрь через cd.

Если какое-то право отсутствует - на его месте стоит - (дефис). Например, r-- значит «только читать», r-x - «читать и выполнять, но не изменять».

Пример: разбираем -rw-r--r--

- rw- r-- r--

Читаем по тройкам:

  • - - обычный файл.
  • rw- - владелец может читать и писать, но не выполнять.
  • r-- - группа может только читать.
  • r-- - остальные могут только читать.

Что это означает на практике? Владелец может открыть файл и что-то в нём изменить. Все остальные (группа и прочие) могут только смотреть, но не менять. Никто не может запустить файл как программу.

Это типичные права для текстового файла - например, README.md или заметки.

Ещё примеры

-rwxr-xr-x - обычный файл, владелец может всё, остальные - читать и выполнять. Так выглядят программы: ты (владелец) можешь её запускать и менять, а другие пользователи - только запускать.

drwxr-xr-x - папка, владелец может всё, остальные - читать и заходить внутрь. Так выглядят большинство обычных папок.

drwx------ - папка, доступная только владельцу. Так выглядят /root и домашние папки пользователей (по умолчанию).

-rw------- - файл, который видит только владелец. Типичные права для приватных ключей SSH, паролей, личных данных.

Права на папку - это не то же, что на файл

Для файла r, w, x означают «читать, писать, запускать». А для папки - «видеть содержимое, создавать/удалять внутри, заходить внутрь». Это разные вещи, хотя буквы одинаковые. Особенно важно: без права x на папку вы не сможете в неё зайти, даже если у вас есть право r.

Числовая запись прав

Буквенная запись rwxr-xr-x удобна для чтения, но длинная. На практике чаще используют числовую - три цифры вроде 755 или 644.

Как это работает. Каждое право имеет числовой вес:

  • r (read) = 4
  • w (write) = 2
  • x (execute) = 1
  • отсутствие права = 0

Чтобы получить число для одной категории - складываем веса. Например:

  • rwx = 4 + 2 + 1 = 7
  • rw- = 4 + 2 + 0 = 6
  • r-x = 4 + 0 + 1 = 5
  • r-- = 4 + 0 + 0 = 4
  • -wx = 0 + 2 + 1 = 3
  • --x = 0 + 0 + 1 = 1
  • --- = 0 + 0 + 0 = 0

Теперь всё просто: три цифры = права для владельца, группы и остальных.

755 = rwx r-x r-x - владелец может всё, остальные - читать и выполнять.

644 = rw- r-- r-- - владелец может читать и писать, остальные - только читать.

600 = rw- --- --- - только владелец, и только читать и писать.

700 = rwx --- --- - только владелец, полный доступ.

777 = rwx rwx rwx - вообще все могут всё. Так обычно делать не надо - это опасно.

Быстрый способ запомнить

Три популярные комбинации, которые вы будете видеть чаще всего:

  • 755 - для папок и программ (обычно).
  • 644 - для обычных файлов (текст, картинки, конфиги).
  • 600 - для приватных файлов (ключи, пароли).

Если сомневаетесь - используйте эти три. Для 95% случаев их достаточно.

Изменение прав: chmod

Команда chmod (change mode) меняет права доступа. Два способа записи - числовой и буквенный.

Числовой способ

$ chmod 755 script.sh

Устанавливает права rwxr-xr-x для файла script.sh. Всё, что было раньше, заменяется целиком.

$ chmod 600 secret.key

Устанавливает rw------- - только владелец может читать и писать.

Числовой способ удобен, когда вы точно знаете, какие права хотите установить. Быстро и однозначно.

Буквенный способ

Более гибкий - позволяет добавлять или убирать отдельные права, не трогая остальные.

Синтаксис: chmod [кто][операция][права] файл

  • Кто: u (владелец), g (группа), o (остальные), a (все три категории).
  • Операция: + (добавить), - (убрать), = (установить ровно).
  • Права: r, w, x.

Примеры:

$ chmod +x script.sh$ chmod u+w notes.txt$ chmod g-w document.txt$ chmod o=r-- data.txt$ chmod a+x bin/program

Разбираем по одной:

  • chmod +x script.sh - добавить право на выполнение всем категориям (потому что не указали «кому» - значит, для всех). Самый частый вариант использования.
  • chmod u+w notes.txt - добавить владельцу право на запись.
  • chmod g-w document.txt - убрать у группы право на запись.
  • chmod o=r-- data.txt - установить права остальным ровно r-- (только чтение), независимо от того, что было.
  • chmod a+x bin/program - добавить всем право на выполнение.

Буквенный способ удобен, когда нужно поменять что-то одно, не задумываясь о полной картине. Например, «сделать файл исполняемым» - это chmod +x, и не надо вспоминать, какие там остальные права.

Рекурсивное изменение: -R

Ключ -R (recursive) применяет права ко всей папке и всему, что внутри:

$ chmod -R 755 project/

Все файлы и папки внутри project/ получат права 755. Осторожно: это сделает все файлы исполняемыми, что обычно не нужно. Для проектов с кодом лучше отдельно ставить права на папки и файлы.

Смена владельца: chown

Иногда нужно не просто изменить права, а передать файл другому пользователю. Для этого есть chown (change owner).

$ chown maria notes.txt

Теперь notes.txt принадлежит пользователю maria. Вы (если вы - не root) больше не можете менять этот файл, даже если раньше были его владельцем.

Смена группы: через двоеточие

$ chown maria:developers notes.txt

Владелец - maria, группа - developers. Двоеточие разделяет пользователя и группу.

$ chown :developers notes.txt

Если указать только группу (с двоеточием в начале) - владелец не меняется, меняется только группа.

Рекурсивное изменение: -R

$ chown -R maria:developers project/

Меняет владельца и группу всей папки project и всего, что внутри.

chgrp - отдельная команда для группы

Есть отдельная команда chgrp, которая меняет только группу:

$ chgrp developers notes.txt

Результат тот же, что и chown :developers notes.txt. Но обычно используют именно chown - одна команда на все случаи.

Кто такой root и зачем sudo

В Linux есть особый пользователь - root (суперпользователь, «корневой пользователь»). Он существует не для повседневной работы, а для администрирования.

У root есть абсолютно все права

Права доступа его не ограничивают. Root может:

  • Читать и изменять любой файл в системе.
  • Менять владельца любого файла.
  • Устанавливать и удалять программы.
  • Управлять пользователями и группами.
  • Изменять настройки системы.
  • Останавливать системные службы.

Именно поэтому работать под root постоянно - плохая идея. Одна ошибка в команде может снести систему целиком. Например, rm -rf / под обычным пользователем по большей части не сработает («Permission denied»), а под root - снесёт всё, до чего дотянется.

sudo - выполнить команду от имени root

Вместо того чтобы заходить под root, современные системы используют sudo (superuser do). Это команда, которая позволяет обычному пользователю выполнить одну конкретную команду с правами root.

$ sudo apt update

Вы просите систему: «выполни apt update от имени root». Система спросит ваш пароль (не root-пароль, а ваш собственный), проверит, есть ли у вас право на sudo, и выполнит команду.

После выполнения - вы снова обычный пользователь. Никакой «сессии root» не остаётся.

Чем это лучше, чем «зайти под root»

Три причины:

  1. Безопасность. Root-доступ только на время одной команды. Случайно оставленный терминал под root - это дыра в безопасности. А обычный пользователь ничего страшного не натворит.
  2. Аудит. Все команды через sudo записываются в логи. Если что-то пошло не так - можно понять, кто и что делал.
  3. Осознанность. Каждый раз, когда пишете sudo, вы думаете: «а мне точно нужны root-права для этого?». Это защищает от случайных разрушительных команд.
sudo - это не «сделай красиво»

Новички иногда думают: «не работает команда - добавлю sudo». Это неправильный подход. sudo нужен только тогда, когда действие действительно требует прав администратора (установка пакетов, изменение системных файлов, управление службами). Если вы не понимаете, зачем нужен root для конкретной операции - разберитесь сначала, потом применяйте.

Когда нужен sudo

Типичные случаи:

  • Установка и удаление программ через пакетный менеджер (apt, dnf).
  • Изменение системных конфигов в /etc.
  • Управление службами (systemctl restart nginx).
  • Работа с привилегированными портами (<1024).
  • Изменение владельца чужих файлов через chown.
  • Создание пользователей.

Когда sudo НЕ нужен

Если вы работаете со своими файлами в домашней папке - sudo не нужен. Ни для создания, ни для удаления, ни для чтения. Ваша домашняя папка - ваша территория, там вы хозяин.

Если sudo «не помогает» - значит, проблема не в правах, а в чём-то другом. Добавление sudo к команде, которая падает по другой причине, не решит проблему, а только запутает.

Опасность: sudo с командой из интернета

Отдельное предупреждение. В интернете часто пишут «выполните sudo curl ... | bash». Это значит: «скачай скрипт и выполни его с правами root». Если скрипт вредоносный - он получит полный контроль над вашей системой. Никогда не запускайте такие команды, не прочитав скрипт.

$ curl https://example.com/install.sh

Сначала посмотрите, что в нём. Поняли, что безопасно - тогда уже запускайте:

$ bash install.sh

Или с sudo, если скрипту действительно нужны root-права (например, установка в системные директории).

Шпаргалка

Самое важное в одном месте:

  • rwx read, write, execute
  • u, g, o владелец, группа, остальные
  • 755 rwxr-xr-x (для папок, программ)
  • 644 rw-r--r-- (для файлов)
  • 600 rw------- (для приватных)
  • chmod 755 f установить права числом
  • chmod +x f добавить исполняемость
  • chown user f сменить владельца
  • chown user:group f сменить владельца и группу
  • sudo cmd выполнить от root

Если что-то не работает

Типичные проблемы с правами и их решения.

  • «Permission denied» при попытке зайти в папку. Нет права x на эту папку. Проверьте через ls -ld папка. Если папка ваша - chmod +x поможет. Если чужая - только sudo (если вы админ) или обращение к владельцу.
  • «Permission denied» при попытке изменить файл. Нет права w. Если файл ваш - chmod u+w файл. Если чужой - нужен sudo или просьба к владельцу.
  • «bash: ./script.sh: Permission denied». Пытаетесь запустить скрипт, но у него нет права на выполнение. Решение: chmod +x script.sh. Это самая частая проблема у новичков - скрипт есть, а не запускается.
  • «chmod: changing permissions: Operation not permitted». Пытаетесь изменить права на файл, который не ваш. Только владелец (или root через sudo) может менять права. Проверьте через ls -l, кто владелец.
  • «sudo: command not found». sudo не установлен (бывает в минимальных дистрибутивах). Зайдите под root (su -) и установите: apt install sudo.
  • «user is not in the sudoers file». У вас нет прав на sudo. Обычно это значит, что вас не добавили в группу sudo (или wheel в некоторых дистрибутивах). Решение - через root добавить: usermod -aG sudo username. После этого - перелогиниться.
  • «Не хочу вводить пароль каждый раз для sudo». Можно настроить NOPASSWD в /etc/sudoers.d/ для конкретных команд. Но это снижает безопасность - делайте только если понимаете риски. По умолчанию пароль требуется - и это правильно.
  • «Как запретить другим читать мой файл». chmod 600 файл - только вы сможете читать и писать. chmod 700 папка - только вы сможете заходить в папку.
  • «Случайно снял право читать у самого себя». Например, chmod 000 file. Как владелец - вы всё равно можете изменить права обратно: chmod 644 file. Владелец не может быть «заблокирован» от собственного файла - он всегда может вернуть права через chmod.

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Первые две - на чтение и изменение прав, третья - на sudo, четвёртая - на реальные сценарии. Все задачи безопасные.

Задача 1. Расшифруйте права

Для каждой записи прав определите, что может делать владелец, группа и остальные.

  1. -rw-r--r--
  2. -rwxr-xr-x
  3. -rw-------
  4. drwxr-xr-x
  5. drwx------
  6. -rwxrwxrwx
Подсказка

Первый символ - тип (- файл, d папка). Дальше три тройки: владелец, группа, остальные. В каждой тройке r - читать, w - писать, x - выполнять.

Разбор
  1. -rw-r--r-- - обычный файл. Владелец: читать, писать. Группа: читать. Остальные: читать.
  2. -rwxr-xr-x - обычный файл. Владелец: полный доступ. Остальные: читать и выполнять. Типично для программ.
  3. -rw------- - обычный файл. Только владелец: читать и писать. Никто больше не имеет доступа. Типично для приватных ключей.
  4. drwxr-xr-x - папка. Владелец: полный доступ. Остальные: читать содержимое и заходить внутрь. Обычная папка.
  5. drwx------ - папка. Только владелец. Используется для домашних директорий по умолчанию.
  6. -rwxrwxrwx - обычный файл. Все могут читать, писать, выполнять. Опасно - так обычно не надо.
Задача 2. Попрактикуйтесь с chmod

Создайте в домашней папке несколько файлов и меняйте им права:

  1. Создайте script.sh. Сделайте его исполняемым через chmod +x.
  2. Создайте secret.txt. Установите права 600.
  3. Создайте public.txt. Установите права 644.
  4. Создайте папку work. Установите права 700.
  5. Проверьте через ls -l, что права установились правильно.
Подсказка

Для создания - touch и mkdir. Для прав - chmod. Для проверки - ls -l или ls -ld для папки.

Разбор 
$ cd ~$ touch script.sh secret.txt public.txt$ mkdir work$ chmod +x script.sh$ chmod 600 secret.txt$ chmod 644 public.txt$ chmod 700 work$ ls -l-rwxr-xr-x 1 student student   0 Oct 25 12:00 script.sh-rw------- 1 student student   0 Oct 25 12:00 secret.txt-rw-r--r-- 1 student student   0 Oct 25 12:00 public.txtdrwx------ 2 student student 4096 Oct 25 12:00 work

Обратите внимание: после chmod +x script.sh права стали rwxr-xr-x. Почему всем трём категориям? Потому что +x без указания «кому» применяется ко всем сразу. Если хотели только владельцу - chmod u+x.

Права на папку work проверяются через ls -ld work - ключ -d показывает информацию о самой папке, а не о её содержимом.

Задача 3. sudo: когда нужен

Для каждой команды определите, нужен ли sudo или нет. Обоснуйте.

  1. apt update
  2. ls ~/Documents
  3. cat /etc/nginx/nginx.conf
  4. mkdir ~/projects
  5. systemctl restart nginx
  6. touch ~/notes.txt
  7. chown maria ~/shared.txt
  8. grep "error" ~/logs/app.log
Подсказка

Если команда работает с вашими файлами в вашей домашней папке - sudo не нужен. Если с системными (/etc, /var), с пакетами или службами - нужен.

Разбор
  1. apt update - нужен sudo. Управление пакетами - админская операция.
  2. ls ~/Documents - без sudo. Ваша папка, ваши файлы.
  3. cat /etc/nginx/nginx.conf - зависит от прав. Обычно читать конфиг может любой. Если выдаёт Permission denied - sudo cat.
  4. mkdir ~/projects - без sudo. Создаёте папку в своей домашней директории.
  5. systemctl restart nginx - нужен sudo. Управление службами - админская операция.
  6. touch ~/notes.txt - без sudo. Ваш файл.
  7. chown maria ~/shared.txt - нужен sudo. Передать файл другому пользователю может только root. Обычный пользователь не может «отдать» свой файл кому-то другому - это было бы странно.
  8. grep "error" ~/logs/app.log - без sudo. Читаете свой лог.

Общий принцип: работа с вашими файлами в вашей домашней папке - без sudo. Всё остальное, что касается системы - с sudo.

Задача 4. Реальные сценарии

В каждой ситуации определите, что нужно сделать и почему.

  1. Вы написали скрипт deploy.sh, но при запуске ./deploy.sh выдаёт «Permission denied».
  2. Вы хотите, чтобы файл ~/.ssh/id_rsa (приватный ключ) никто, кроме вас, не мог прочитать.
  3. Вы работаете с коллегой над проектом в папке ~/shared-project (в домашней папке коллеги). Вы хотите иметь доступ на запись.
  4. Вы хотите установить пакет htop.
Подсказка

Для каждой ситуации подумайте: это про chmod, про chown, про sudo или про комбинацию?

Разбор
  1. Скрипт не запускается. Нет права на выполнение. Решение: chmod +x deploy.sh. Дальше ./deploy.sh запустится. Именно так делают все после скачивания скриптов из интернета (git clone, curl и т.д.) - права на выполнение не сохраняются, их надо ставить вручную.
  2. Защитить приватный ключ. chmod 600 ~/.ssh/id_rsa. SSH сам проверяет, что права на приватный ключ не шире, чем 600, и отказывается работать, если права слабее. Это защита от того, чтобы ключ случайно не оказался доступен другим.
  3. Доступ к чужому проекту. Это задача для владельца (коллеги), а не для вас. Правильный подход: коллега сам делает chmod -R g+w ~/shared-project и добавляет вас в группу, либо chown на общую группу. Вы сами себе права на чужой файл поставить не можете - и это правильно. Если нужны срочные действия - через sudo, но лучше договориться с коллегой.
  4. Установка htop. Пакетный менеджер требует root: sudo apt install htop (Ubuntu/Debian) или sudo dnf install htop (Fedora). Без sudo не установится - программы ставятся в системные директории /usr, куда у обычного пользователя доступа нет.

Общее правило: права на файлы контролирует владелец файла (или root). Если файл не ваш - вы не можете самовольно изменить его права, и это правильно. В противном случае вся система безопасности рухнула бы.

Что мы узнали и что дальше

Разобрались с правами доступа - фундаментальной концепцией Linux. Узнали, что у каждого файла есть три категории пользователей (владелец, группа, остальные) и три типа прав (read, write, execute). Научились читать вывод ls -l и понимать запись rwxr-xr-x.

Освоили два способа изменения прав через chmod: числовой (755, 644, 600) и буквенный (+x, u+w, g-w). Поняли, что означают три самые частые комбинации - 755 для папок, 644 для файлов, 600 для приватных данных.

Познакомились с chown для смены владельца и sudo для выполнения отдельных команд с правами root. Разобрались, почему постоянно работать под root - плохая идея, и почему sudo - это правильный компромисс между удобством и безопасностью.

И главное: теперь сообщения вида Permission denied не будут вас пугать. Вы будете понимать, откуда они берутся и что с ними делать.

В следующем уроке займёмся процессами и системным мониторингом. Разберёмся, что такое процесс, как посмотреть, что сейчас работает на системе (ps, top), как завершить зависшую программу (kill) и как понять, что именно нагружает ваш компьютер.
