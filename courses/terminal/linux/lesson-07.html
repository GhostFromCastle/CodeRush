Управление пакетами

~40 минут Linux Теория и Практика

В Windows программы обычно скачивают с сайта: находишь установщик, скачиваешь .exe, запускаешь, жмёшь «Далее-Далее-Готово». В Linux всё иначе. Здесь программы устанавливаются через пакетные менеджеры - специальные системы, которые сами находят нужное, скачивают и устанавливают.

Звучит сложно? На самом деле, проще, чем в Windows. Одна команда в терминале - и у вас новая программа. Плюс все зависимости (библиотеки, которые нужны программе) тоже устанавливаются автоматически. Никаких «найдите на сайте нужную версию библиотеки» - система всё сделает сама.

В этом уроке разберёмся, как это работает, какие пакетные менеджеры существуют, и как пользоваться основными командами.

Что такое пакет и репозиторий

Прежде чем говорить про команды, разберёмся с двумя ключевыми понятиями.

Пакет

Пакет - это архив с программой, её файлами (исполняемые, конфиги, документация) и метаданными (название, версия, что нужно для работы). Пакет - это «коробка» с программой, готовая к установке.

У каждого пакета есть имя и версия. Например, htop 3.2.1 или nginx 1.24.0. Обновление программы - это просто установка более нового пакета с тем же именем.

Репозиторий

Репозиторий - это сервер, где хранится коллекция пакетов. У каждого дистрибутива Linux есть свои официальные репозитории: в них пакеты проверены разработчиками дистрибутива и протестированы на совместимость.

Когда вы даёте команду «установи программу X», пакетный менеджер:

  1. Ищет пакет с таким именем в списке доступных (кеш репозитория).
  2. Определяет, какие ещё пакеты нужны для работы X (зависимости).
  3. Скачивает все нужные пакеты из репозитория.
  4. Устанавливает их в правильном порядке.
  5. Настраивает программу (например, запускает её службу или создаёт конфиги).

Всё это - одна команда в терминале.

Аналогия

Пакетный менеджер - это как интернет-магазин, только для программ. Вы говорите «хочу htop», магазин сам находит нужный товар, проверяет, что есть все аксессуары (зависимости), и привозит всё одной посылкой. Никаких «а вот эту батарейку купите отдельно».

Семейства дистрибутивов и пакетные менеджеры

В мире Linux нет единого пакетного менеджера. Есть несколько семейств дистрибутивов, у каждого - свой инструмент.

Debian / Ubuntu и родственники: apt

Самое популярное семейство. Включает Ubuntu, Debian, Linux Mint, Kali Linux, Pop!_OS и многие другие. Пакеты имеют расширение .deb, а для управления используются:

  • apt - современный инструмент, основная команда.
  • dpkg - низкоуровневый (работает с отдельными .deb-файлами).

Мы будем учиться именно на apt, потому что это самая распространённая система (Ubuntu - самый популярный дистрибутив для серверов и начинающих).

Fedora / RHEL / CentOS: dnf

Второе по популярности семейство. Red Hat Enterprise Linux, Fedora, CentOS, Rocky Linux, AlmaLinux. Пакеты - .rpm, пакетный менеджер - dnf (раньше был yum, но он устарел).

Arch Linux: pacman

Дистрибутив для продвинутых. Пакетный менеджер pacman. Команды отличаются, но принцип тот же.

openSUSE: zypper

Ещё одно семейство. Менеджер - zypper.

Что это значит для нас

В этом уроке мы разберём apt (потому что вы с высокой вероятностью используете Ubuntu или Debian), и покажем соответствия для dnf (для Fedora). Если у вас другой дистрибутив - принцип тот же, команды спросите в документации своего дистрибутива.

Первое, что нужно сделать: apt update

Перед установкой чего-либо важно обновить список доступных пакетов:

$ sudo apt update

Что это делает: скачивает с серверов репозитория свежий список пакетов - какие версии есть, какие новые появились, какие обновились. Это не обновление самих программ (для этого другая команда). Это обновление «каталога», по которому менеджер ищет нужное.

Представьте, что у вас есть бумажный каталог товаров магазина. apt update - это когда вы заказываете свежий каталог, потому что появились новые товары и изменились цены. Сами товары у вас дома от этого не меняются.

Почему нужен sudo: список хранится в системной папке /var/lib/apt/lists/ - туда может писать только root.

Как часто делать apt update

Перед любой установкой или обновлением. Плюс раз в неделю, если хотите держать систему в актуальном состоянии. Это быстро - обычно 2-5 секунд при хорошем интернете.

Поиск пакета: apt search

Хотите узнать, есть ли нужная программа в репозитории? Ищите по ключевому слову:

$ apt search htop

Выведет список пакетов, в имени или описании которых есть «htop». У каждого пакета - имя, версия, краткое описание.

Поиск по описанию тоже работает. Например, найти все программы для работы с изображениями:

$ apt search "image editor"

Вывод длинный, обычно его прогоняют через less или ограничивают:

$ apt search htop | head

Информация о пакете: apt show

Прежде чем установить пакет, полезно посмотреть, что это вообще такое:

$ apt show htop

Выдаст подробную информацию: версию, размер, зависимости, автора, ссылку на сайт, полное описание. Можно оценить, действительно ли это та программа, которая нужна.

Установка: apt install

Основная команда для установки:

$ sudo apt install htop

Что произойдёт:

  1. apt найдёт пакет htop в своём каталоге.
  2. Проверит зависимости (какие ещё пакеты нужны).
  3. Покажет, что собирается установить, и спросит подтверждение (обычно Y/n).
  4. Скачает все пакеты.
  5. Установит их и настроит.

Через 10-30 секунд программа установлена. Можно запускать: htop.

Несколько пакетов одной командой

$ sudo apt install htop curl git vim

Установит все четыре пакета (и их зависимости) одной операцией. Удобно, когда настраиваешь новую систему или новый сервер: одной командой ставишь весь нужный набор инструментов.

Ключ -y: без подтверждения

$ sudo apt install -y htop

Ключ -y (yes) - автоматически отвечает «да» на все вопросы. Полезно в скриптах автоматической установки. В интерактивной работе - не обязательно, лишнее подтверждение не мешает.

Обновление установленных программ: apt upgrade

Отдельная команда - для обновления всех установленных программ до последних версий:

$ sudo apt upgrade

После apt update (который обновил каталог) эта команда установит свежие версии всех программ, для которых есть обновления. Покажет список и спросит подтверждение.

Комбинация update + upgrade

Классический сценарий обновления системы:

$ sudo apt update$ sudo apt upgrade

Первая - обновить каталог. Вторая - установить все обновления. Обычно это делают раз в неделю-две, чтобы система получала патчи безопасности и новые функции.

Ключ -y и здесь

$ sudo apt upgrade -y

Не спрашивать подтверждения. Для ручной работы лучше без -y - чтобы видеть, что именно обновляется и не согласиться, если что-то неожиданное.

Удаление: apt remove и apt purge

Две команды для удаления, с важной разницей.

apt remove - удалить программу

$ sudo apt remove htop

Удаляет программу и её файлы, но оставляет конфигурационные файлы. Если вы установите htop снова - все настройки вернутся.

Это удобно, когда хочется «убрать программу на время» или «переустановить без сброса настроек».

apt purge - удалить полностью

$ sudo apt purge htop

Удаляет программу вместе с конфигами. Если установите заново - получите «с нуля», как в первый раз.

Используйте purge, когда хотите полностью избавиться от программы. Например, если она больше не нужна, или если хотите сбросить настройки.

apt autoremove - убрать ненужное

$ sudo apt autoremove

Удаляет пакеты, которые были установлены как зависимости, но больше не нужны (потому что программа, которой они требовались, уже удалена). Освобождает место.

Полезно запускать после remove или purge. Например: удалили программу - её библиотеки остались. autoremove их подчистит.

Установка .deb вручную: dpkg

Иногда нужно установить программу, которой нет в репозитории - например, скачали .deb-файл с сайта разработчика. Для этого есть команда dpkg:

$ sudo dpkg -i program.deb

Ключ -i - install. Установит пакет из файла.

Проблема с зависимостями

dpkg не умеет сам скачивать зависимости. Если пакету нужны библиотеки, которых нет в системе, установка провалится с ошибкой «dependency problems».

Решение - «доустановить» недостающее через apt:

$ sudo apt install -f

Ключ -f (fix broken) - «починить сломанное». apt посмотрит, чего не хватает, и установит нужные пакеты из репозитория.

Порядок такой: сначала dpkg -i (установить, что есть), потом apt install -f (дотянуть зависимости).

Список установленных пакетов: apt list

Сколько программ установлено в системе? Какие? Есть команда:

$ apt list --installed

Выведет всё установленное - обычно сотни пакетов (базовая система - это уже 500-1000 пакетов). Вывод длинный, лучше сразу фильтровать:

$ apt list --installed | grep htop

Или проверить конкретный пакет:

$ dpkg -l htop

dpkg -l (list) - покажет статус, версию, архитектуру пакета. Если установлен - в первой колонке будет ii («installed»).

Очистка кэша: apt clean

Когда apt скачивает пакеты, он сохраняет их в кэш - на случай, если понадобятся ещё раз. Кэш живёт в /var/cache/apt/archives/. Со временем там накапливается много.

$ sudo apt clean

Полностью очищает кэш. Безопасно - если пакет понадобится снова, apt просто скачает его ещё раз.

$ sudo apt autoclean

Удаляет только устаревшие версии пакетов (те, что уже не актуальны). Более мягкий вариант - не трогает свежее, но освобождает место от старого.

Соответствия для других дистрибутивов

Если вы на Fedora / RHEL (менеджер dnf) - вот соответствия команд:

Задача apt (Ubuntu/Debian) dnf (Fedora/RHEL)
Обновить каталог sudo apt update sudo dnf check-update
Обновить систему sudo apt upgrade sudo dnf upgrade
Установить sudo apt install htop sudo dnf install htop
Удалить sudo apt remove htop sudo dnf remove htop
Поиск apt search htop dnf search htop
Информация apt show htop dnf info htop
Список установленных apt list --installed dnf list installed

Если у вас Arch (pacman) - команды ещё короче (pacman -S для установки, pacman -Rns для удаления), но принцип тот же.

Как узнать свой дистрибутив

Если не знаете, какой у вас дистрибутив - выполните:

$ cat /etc/os-release

Увидите имя, версию и кодовое название. По полю ID поймёте, к какому семейству относитесь: ubuntu или debian - используйте apt; fedora или rhel - dnf; arch - pacman.

Что не надо делать

Несколько типичных ошибок, которые стоит избегать.

Не используйте sudo с apt search и apt show

apt search и apt show только читают каталог. Им не нужен root. sudo здесь лишний - только замедлит (потому что спросит пароль) и ничем не поможет.

sudo нужен только для операций, меняющих систему: install, remove, upgrade, update.

Не смешивайте apt и dpkg

Есть apt (высокоуровневый) и dpkg (низкоуровневый). Они работают с одной базой, но лучше пользоваться apt - он умеет работать с зависимостями. dpkg - только для случаев, когда пакета нет в репозитории (или для очень специфических операций вроде dpkg -l).

Не скачивайте .deb с сайтов сомнительного качества

Установка пакетов из официального репозитория через apt install - безопасна: пакеты подписаны, проверены, вы получаете только проверенные версии. А .deb-файл откуда-то из интернета может содержать что угодно. Если очень нужно - хотя бы проверьте источник (официальный сайт разработчика, а не файлопомойка).

Не запускайте apt upgrade с -y вслепую

Иногда обновления могут сломать совместимость. upgrade -y согласится на всё, включая потенциально рискованные обновления. В ручной работе лучше видеть, что обновляется.

Не добавляйте сторонние репозитории вслепую

В интернете много инструкций вида «sudo add-apt-repository ppa:...». Это добавляет новый репозиторий, которому apt будет доверять. Если репозиторий скомпрометирован - вы можете получить вредоносные пакеты. Добавляйте только проверенные (официальные PPA крупных проектов, репозитории от известных компаний).

Шпаргалка

Самое важное в одном месте:

  • apt update обновить каталог
  • apt upgrade обновить систему
  • apt search htop найти пакет
  • apt show htop инфо о пакете
  • apt install htop установить
  • apt remove htop удалить (конфиги остаются)
  • apt purge htop удалить полностью
  • apt autoremove убрать ненужные зависимости
  • dpkg -i pkg.deb установить из файла
  • apt install -f починить зависимости

Если что-то не работает

Типичные проблемы с пакетными менеджерами.

  • «E: Could not get lock /var/lib/dpkg/lock-frontend». Какая-то другая программа (обычно другой apt или автообновление) сейчас работает с пакетами. Подождите 1-2 минуты или проверьте: sudo lsof /var/lib/dpkg/lock-frontend. Если процесс реально завис - можно убить его, но лучше просто подождать.
  • «E: Unable to locate package htop». Пакет не найден. Причины: 1) не сделан apt update (или давно); 2) в имени опечатка; 3) пакета нет в вашем репозитории (бывает для очень новых или экзотических программ).
  • «dpkg was interrupted, you must manually run sudo dpkg --configure -a». Предыдущая установка прервалась (закрыли терминал, отключили питание). Выполните: sudo dpkg --configure -a - он доведёт до конца незавершённые операции. Потом можно продолжать.
  • «You don't have enough free space in /var/cache/apt/archives». Место кончилось. Очистите кэш: sudo apt clean. Если всё равно мало - освободите место другими способами (см. урок 6, du).
  • «Hash Sum mismatch» при установке. Пакет скачался повреждённым или подменён прокси. Решение: очистить кэш (sudo apt clean), обновить (sudo apt update) и попробовать снова. Обычно проблема на стороне сети.
  • «Зависимости сломались после dpkg -i». Классика: sudo apt install -f. Эта команда найдёт и поставит недостающее.
  • «Как установить программу, которой нет в apt»? Варианты: 1) поискать PPA / сторонний репозиторий (осторожно!); 2) скачать .deb и установить через dpkg -i + apt install -f; 3) если программа совсем экзотическая - использовать snap или flatpak (другие системы установки), но это отдельная тема.
  • «Не хочу обновлять всё, только один пакет». sudo apt install --only-upgrade имя. Или просто sudo apt install имя - если версия новее, apt обновит, если та же - скажет «already newest version».

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Первая - на поиск, вторая - на установку, третья - на обновление, четвёртая - на удаление. Все задачи безопасные - устанавливайте и удаляйте небольшие пакеты, ничего не сломается.

Задача 1. Найдите пакет

Выполните три шага:

  1. Обновите каталог пакетов через sudo apt update.
  2. Найдите пакет htop через apt search htop.
  3. Посмотрите подробную информацию о нём через apt show htop - версия, размер, зависимости.
Подсказка

Порядок важен: сначала update (без sudo не сработает), потом уже search и show (без sudo - они только читают).

Разбор

Что мы узнали:

  • Версия - 3.0.5-7build2.
  • Размер - 372 KB (сам пакет, с зависимостями будет больше).
  • Зависимости - libc6, libncursesw6 и другие библиотеки. Если их нет - apt поставит автоматически.
  • Сайт - htop.dev (можно зайти и почитать подробности).
Задача 2. Установите программу

Установите пакет htop через sudo apt install htop. Затем запустите его и проверьте, что работает.

Внутри htop:

  1. Нажмите M - отсортируйте процессы по памяти.
  2. Нажмите P - верните сортировку по процессору.
  3. Нажмите F10 (или q) - выйдите.
Подсказка

Если apt install просит подтверждение - отвечайте Y (или просто Enter, если Y выбран по умолчанию).

Что произошло по шагам:

  1. apt нашёл пакет в каталоге.
  2. Скачал 154 KB из репозитория.
  3. Распаковал и установил в /usr/bin/htop.
  4. Зарегистрировал man-страницу (теперь man htop работает).

Запуск htop без sudo - правильно. Программа не требует административных прав, чтобы показывать процессы.

Задача 3. Обновите систему

Проведите «сеанс обновления»:

  1. Выполните sudo apt update - обновите каталог.
  2. Выполните sudo apt upgrade - обновите установленные пакеты.
  3. Посмотрите, сколько пакетов было обновлено.
  4. Очистите кэш через sudo apt clean.
Подсказка

На свежеустановленной системе обновлений может быть много (десятки пакетов). На системе, которую регулярно обновляют - ноль или пара.

Разбор 
$ sudo apt updateHit:1 http://archive.ubuntu.com/ubuntu jammy InReleaseHit:2 http://security.ubuntu.com/ubuntu jammy-security InReleaseAll packages are up to date.$ sudo apt upgradeReading package lists... DoneBuilding dependency tree... DoneCalculating upgrade... Done0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.$ sudo apt clean

В этом примере система уже свежая - обновлений нет. Если вы недавно поставили Linux и не обновляли - увидите список обновлений (десятки пакетов) и apt их установит.

Ключевые цифры в выводе: X upgraded, Y newly installed. Если X = 0 - всё актуально. Если X > 0 - были обновления, и они установлены.

Задача 4. Удалите и очистите

Попрактикуйтесь с удалением:

  1. Удалите htop через sudo apt remove htop.
  2. Проверьте, что его больше нет: htop выдаст «command not found».
  3. Удалите конфиги через sudo apt purge htop (даже если уже remove - purge дочистит остатки).
  4. Запустите sudo apt autoremove - удалить ненужные зависимости.
  5. Снова установите htop - чтобы убедиться, что всё работает.
Подсказка

remove и purge взаимозаменяемы - после remove можно сразу purge (он удалит остатки конфигов).

Разбор 
$ sudo apt remove htopReading package lists... DoneThe following packages will be REMOVED:  htop0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.Do you want to continue? [Y/n] YRemoving htop (3.0.5-7build2) ...$ htopbash: htop: command not found$ sudo apt purge htop# ничего не удалит - уже удалён remove, но если были конфиги - удалит их$ sudo apt autoremoveReading package lists... Done0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.$ sudo apt install htop# ... установка заново$ htop# работает

На что обратить внимание:

  • remove действительно удаляет исполняемый файл - команда перестаёт работать.
  • purge после remove обычно уже нечего удалять (нет конфигов), но если программа их создавала - purge их дочистит.
  • autoremove в примере ничего не удалил - у htop зависимости уже были установлены системой (libc6, libncurses и т.п.). Если бы мы ставили что-то с экзотическими зависимостями - autoremove их бы убрал.
  • Установка заново работает мгновенно - пакет уже в кэше (или его не удалил apt clean).

Именно так выглядит цикл «установил - поигрался - удалил - поставил обратно», который вы будете делать постоянно при изучении Linux.

Что мы узнали и что дальше

Разобрались с управлением пакетами - тем, как в Linux устанавливаются, обновляются и удаляются программы. Узнали, что такое пакет и репозиторий, почему это удобнее, чем скачивать установщики с сайтов вручную.

Познакомились с семействами дистрибутивов и их пакетными менеджерами: apt для Ubuntu/Debian, dnf для Fedora/RHEL, pacman для Arch, zypper для openSUSE. Разобрали команды для apt - как основного инструмента - и составили таблицу соответствий для dnf.

Освоили базовый цикл работы: apt update (обновить каталог), apt search (найти пакет), apt show (посмотреть информацию), apt install (установить), apt upgrade (обновить систему), apt remove или apt purge (удалить), apt autoremove (убрать ненужное).

Затронули dpkg -i для установки .deb вручную и apt install -f для починки сломанных зависимостей. И разобрали типичные ошибки: забыли apt update, заблокирован dpkg-lock, кончилось место в кэше.

В следующем, финальном уроке курса займёмся перенаправлением ввода-вывода и конвейерами. Это тема, которая превращает отдельные команды в мощные цепочки: вывод одной команды передаётся на вход другой, результат сохраняется в файл, ошибки отделяются от обычного вывода.
