Перенаправление ввода-вывода и конвейеры

~50 минут Linux Теория и Практика

Это финальный урок курса по терминалу Linux. Мы прошли долгий путь: научились перемещаться по файловой системе, управлять файлами, читать и искать, работать с правами, процессами и пакетами. Осталась последняя, но очень важная тема - перенаправление ввода-вывода и конвейеры.

Именно она превращает отдельные команды в мощные инструменты. Вы уже видели в предыдущих уроках загадочные >, >>, | и 2>/dev/null, но, возможно, не до конца понимали, как это работает. Сегодня разберёмся досконально.

После этого урока вы сможете делать то, что раньше казалось магией: находить самые большие файлы, фильтровать логи от лишнего, объединять результат нескольких команд в одну строку.

Три потока каждой команды

Прежде чем работать с перенаправлением, нужно понять одну вещь: у каждой программы в Linux есть три канала связи с миром. Они называются файловые дескрипторы.

  • stdin (standard input) - стандартный ввод. Откуда команда берёт данные. По умолчанию - клавиатура.
  • stdout (standard output) - стандартный вывод. Куда команда пишет результат. По умолчанию - терминал.
  • stderr (standard error) - стандартный поток ошибок. Куда команда пишет сообщения об ошибках. По умолчанию тоже терминал, но это отдельный канал.

У каждого канала есть номер:

  • 0 - stdin.
  • 1 - stdout.
  • 2 - stderr.

Эти номера называются файловыми дескрипторами. Запомните их - они будут встречаться в записях вида 2>.

Зачем разделять вывод и ошибки

Казалось бы, зачем два отдельных канала для «результата» и «ошибки»? Разве нельзя писать всё в одно место? Можно, но неудобно. Разделение позволяет: например, сохранять только полезный вывод в файл, а ошибки - отдельно или вообще выбрасывать. Или фильтровать одно, не трогая другое. Об этом - ниже.

Куда идёт вывод команды

Возьмём простую команду ls в домашней папке:

$ lsDesktop  Documents  Downloads  Music

Что произошло технически:

  1. ls прочитала содержимое папки.
  2. Записала результат в stdout (файловый дескриптор 1).
  3. По умолчанию stdout направлен в терминал - и мы видим список.

Теперь возьмём команду с ошибкой:

$ ls /nonexistentls: cannot access '/nonexistent': No such file or directory

Здесь ls записала сообщение об ошибке в stderr (файловый дескриптор 2). В терминале оно выглядит так же, как обычный вывод, но канал другой.

Именно поэтому можно отдельно перенаправить полезный вывод и отдельно - ошибки. Раз stdout и stderr - разные каналы, можно управлять каждым независимо.

Перенаправление stdout: > и >>

Самый частый вид перенаправления - записать вывод команды в файл вместо терминала. Синтаксис:

$ команда > файл

Пример:

$ ls > filelist.txt

Что произошло: ls выполнилась, но её вывод (stdout) не попал в терминал, а был записан в файл filelist.txt. В терминале ничего не появилось - всё ушло в файл.

Проверим:

$ cat filelist.txtDesktopDocumentsDownloadsMusicfilelist.txt

Всё на месте. Обратите внимание - filelist.txt тоже попал в список, потому что файл был создан до того, как ls прочитала папку.

Опасность: > перезаписывает файл

Важный момент: > (одинарное) полностью перезаписывает файл. Если файл существовал - его старое содержимое исчезает.

$ echo "старое" > test.txt$ cat test.txtстарое$ echo "новое" > test.txt$ cat test.txtновое

Второй echo с > затёр старое содержимое. Это не всегда то, что нужно.

Дописывание: >>

Если нужно добавить в конец файла, не стирая старое - используйте >> (двойное):

$ echo "первая строка" > log.txt$ echo "вторая строка" >> log.txt$ echo "третья строка" >> log.txt$ cat log.txtпервая строкавторая строкатретья строка

Отличный способ вести лог-файл: каждое новое событие дописывается в конец, ничего не теряется.

Перенаправление stdin: <

По умолчанию команды читают ввод с клавиатуры. Ключ < позволяет читать из файла:

$ команда < файл

Пример: команда wc -l (считает строки) может работать двумя способами:

$ wc -l filelist.txt5 filelist.txt$ wc -l < filelist.txt5

В первом случае wc открыла файл сама (передав имя как аргумент). Во втором - оболочка открыла файл и передала его содержимое в stdin команды. Разница небольшая, но иногда важная: во втором случае wc не знает, откуда данные, поэтому не может вывести имя файла.

Ключ < используется реже, чем > - обычно командам просто передают имя файла. Но иногда он нужен: например, при работе с командами, которые читают только из stdin.

Перенаправление stderr: 2>

Помните, у нас есть отдельный канал ошибок (stderr, дескриптор 2). Его тоже можно перенаправить:

$ команда 2> файл_ошибок

Пример - попробуем прочитать несуществующий файл:

$ cat /nonexistent 2> errors.log$ cat errors.logcat: /nonexistent: No such file or directory

В терминале ничего не появилось - ошибка ушла в файл errors.log. Очень полезно при работе со скриптами: если что-то пошло не так, ошибка не мешает основному выводу.

Порядок перенаправлений важен

Ключевая тонкость. Разница между команда > file 2>&1 и команда 2>&1 > file огромна.

> file 2>&1:

  1. Сначала > file - stdout перенаправляется в файл.
  2. Затем 2>&1 - stderr перенаправляется «туда же, куда сейчас указывает stdout» - то есть тоже в файл.

Итог: и обычный вывод, и ошибки попадают в файл. Правильно.

2>&1 > file:

  1. Сначала 2>&1 - stderr перенаправляется «туда же, куда сейчас указывает stdout». А stdout пока указывает в терминал - значит, stderr идёт в терминал.
  2. Затем > file - stdout перенаправляется в файл.

Итог: обычный вывод - в файл, а ошибки - в терминал. Не то, что хотели.

Правило

Всегда пишите > file 2>&1, а не наоборот. Первое работает как ожидается, второе - сбивает с толку. Порядок перенаправлений читается слева направо.

/dev/null - «чёрная дыра»

В Linux есть специальный файл /dev/null - «устройство ноль». Всё, что в него записано, исчезает навсегда. Ничего не сохраняется, ничего не возвращается.

Используется для подавления ненужного вывода:

$ ls /nonexistent 2> /dev/null

Ошибка есть, но она уходит в «чёрную дыру» - в терминал ничего не выводится. Полезно, когда знаешь, что команда может выдать ошибку, но она тебе неинтересна.

Полностью «заглушить» команду - и вывод, и ошибки:

$ команда > /dev/null 2>&1

Ничего не увидишь, но команда выполнится. Иногда полезно, когда нужно просто запустить что-то в тишине.

Конвейеры: |

Самое мощное изобретение Unix. Вертикальная черта | - конвейер (pipe) - соединяет две команды: вывод первой идёт на вход второй.

$ команда1 | команда2

Поток данных:

  1. команда1 пишет в stdout.
  2. Вместо того чтобы попасть в терминал, этот вывод идёт в stdin команды команда2.
  3. команда2 обрабатывает и выдаёт свой результат.

Простой пример

$ ls | wc -l5

Что произошло:

  • ls выдала список файлов - строки.
  • Эти строки пошли в wc -l, которая считает количество строк.
  • Результат - одно число: сколько файлов в папке.

Одной командой мы ответили на вопрос «сколько файлов в папке». Без конвейера пришлось бы считать вручную.

Более сложный пример

$ ls /usr/bin | grep python | head -n 5

Цепочка из трёх команд:

  1. ls /usr/bin - все файлы в /usr/bin.
  2. grep python - оставить только строки со словом «python».
  3. head -n 5 - показать первые 5.

Результат - первая пятёрка программ в системе, связанных с Python. Это уже осмысленный анализ.

Цепочка любой длины

Можно соединять сколько угодно команд:

$ ps aux | grep firefox | grep -v grep | wc -l

Что тут происходит:

  1. ps aux - все процессы.
  2. grep firefox - только с firefox.
  3. grep -v grep - убрать строку, где сам grep.
  4. wc -l - посчитать оставшиеся.

Результат - сколько именно процессов firefox запущено. Одной строкой.

Классические конвейеры

Несколько рецептов, которые используются постоянно.

Сортировка по размеру

$ du -sh ~/* | sort -rh | head -n 10

Самые большие папки в домашней директории. Разбирали в уроке 6, но теперь понятно, как это работает:

  • du -sh выдаёт строки вида «размер путь».
  • sort -rh сортирует по убыванию (по числам).
  • head -n 10 - первые 10 строк - топ-10.

Поиск в логах

$ tail -f /var/log/syslog | grep -i error

Следить за логом в реальном времени и показывать только строки с «error». Идеально для отладки.

Подсчёт уникальных значений

$ cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head

Топ IP-адресов, с которых чаще всего заходили на сервер. Классика анализа логов:

  • awk '{print $1}' - вывести первое поле (обычно IP в логе веб-сервера).
  • sort - отсортировать, чтобы одинаковые IP шли подряд.
  • uniq -c - подсчитать повторы.
  • sort -rn - отсортировать по количеству.
  • head - показать топ.

Сохранить и показать: tee

Обычно вывод идёт либо в файл, либо в терминал. Команда tee делает и то, и другое: пишет в файл и одновременно показывает на экране.

$ ls | tee filelist.txtDesktopDocumentsDownloadsMusic

Вывод показан на экране и сохранён в filelist.txt. Удобно, когда хочешь сразу видеть результат и при этом иметь его копию.

Дописывание в конец - ключ -a:

$ ls | tee -a filelist.txt

Heredoc: многострочный ввод

Отдельная полезная конструкция - heredoc. Позволяет передать многострочный текст в команду прямо в терминале, без создания промежуточного файла.

$ cat << EOF > note.txtПервая строкаВторая строкаТретья строкаEOF

Что произошло:

  • cat << EOF - «читай ввод до строки «EOF»».
  • Всё, что вы ввели между этой строкой и «EOF», считается содержимым.
  • > note.txt - записать это содержимое в файл.

Три строки попали в note.txt. Слово «EOF» может быть любым - это просто маркер конца, не команда. Часто используют EOF, но можно и END, и КОНЕЦ - что удобнее.

Heredoc пригодится в скриптах: когда нужно передать большой блок текста команде, а создавать отдельный файл лень.

Полная картина: все операторы вместе

Соберём в одном месте, что мы изучили:

Оператор Что делает Пример
> file Вывод в файл (перезапись) ls > list.txt
>> file Вывод в файл (дописать) echo "x" >> log.txt
< file Ввод из файла wc -l < list.txt
2> file Ошибки в файл cmd 2> err.log

Шпаргалка

Самое важное в одном месте:

  • stdin (0) ввод, по умолчанию клавиатура
  • stdout (1) вывод, по умолчанию терминал
  • stderr (2) ошибки, по умолчанию терминал
  • > в файл (перезапись)
  • >> в файл (дописать)
  • 2> ошибки в файл
  • 2>&1 ошибки вместе с выводом
  • | конвейер
  • /dev/null чёрная дыра
  • tee и в файл, и на экран

Если что-то не работает

Типичные ошибки при работе с перенаправлением.

  • «> перезаписал файл, я потерял данные». Да, > стирает старое содержимое. Для дописывания - >>. Если данные критичные - сначала проверьте, существует ли файл, или используйте cp для бэкапа перед перезаписью.
  • «Вывод в файл, но при cat там пусто». Возможно, команда писала в stderr, а вы перенаправили только stdout. Или команда упала до того, как успела что-то вывести. Проверьте через cmd > file 2>&1 - чтобы поймать всё.
  • «Ошибки в файл ушли, но и в терминал тоже». Скорее всего, вы написали 2>&1 > file вместо > file 2>&1. Порядок важен.
  • «Конвейер не работает - команда1 зависает». Возможно, команда2 не читает stdin (например, ждёт имя файла аргументом). Проверьте справку команды2 через --help. Если она не поддерживает stdin - конвейер бесполезен.
  • «cat > file - как выйти?» Если вы запустили cat > file без аргументов - он читает с клавиатуры, пока не нажмёте Ctrl + D. Это «конец файла», сигнал «больше ввода не будет». После Ctrl + D - вернётесь в приглашение, а введённый текст будет в файле.
  • «ls | wc -l показывает не то число». Проверьте глазами: ls сначала без конвейера. Возможно, файлов меньше, чем кажется, или есть скрытые (тогда ls -a | wc -l).
  • «tee не показывает вывод». Проверьте, что команда перед tee вообще что-то выдаёт. Иногда ошибочно путают: cmd | tee file - tee в конце конвейера, а не в начале.
  • «Heredoc не срабатывает». Убедитесь, что закрывающий маркер (EOF) стоит на отдельной строке, без пробелов в начале, и точно совпадает с открывающим. Даже лишний пробел перед EOF сломает конструкцию.

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Первые две - на базовое перенаправление, третья - на конвейеры, четвёртая - комплексная, объединяющая всё, что изучили за курс.

Задача 1. Сохраните вывод

В домашней папке:

  1. Запишите список файлов в list.txt через ls > list.txt.
  2. Проверьте, что файл создан - cat list.txt.
  3. Допишите в конец этого файла строку «конец списка» через echo "конец списка" >> list.txt.
  4. Снова проверьте через cat - строка должна быть в конце, а старое содержимое - сохраниться.
Подсказка

Помните разницу: > перезаписывает, >> дописывает. На шаге 1 используйте > (создаём с нуля), на шаге 3 - >> (дописываем).

Разбор 
$ ls > list.txt$ cat list.txtDesktopDocumentsDownloads...$ echo "конец списка" >> list.txt$ cat list.txtDesktopDocumentsDownloads...конец списка

Обратите внимание: list.txt появится и в самом списке при втором ls (если сделаете), но это нормально - файл создаётся первым, потом ls его видит.

Задача 2. Ошибки отдельно

Попробуйте прочитать несуществующий файл, но так, чтобы:

  1. Ошибка ушла в файл errors.log.
  2. В терминале ничего не было.
  3. Потом проверьте через cat errors.log - ошибка должна быть там.
  4. Повторите с /dev/null - ошибка должна полностью исчезнуть.
Подсказка

Для ошибок в файл - 2> errors.log. Для полного подавления - 2> /dev/null.

Разбор 
$ cat /nonexistent 2> errors.log# в терминале пусто$ cat errors.logcat: /nonexistent: No such file or directory$ cat /nonexistent 2> /dev/null# в терминале пусто, и в файлах ничего

В чём разница:

  • Во втором случае ошибка сохранена - можно потом прочитать и разобраться, что было.
  • В третьем случае ошибка исчезла навсегда - даже если очень захотите прочитать, не сможете. Используйте /dev/null только когда точно знаете, что ошибка неинтересна.
Задача 3. Конвейеры

Используйте конвейер для каждой задачи:

  1. Посчитайте количество файлов в /usr/bin.
  2. Найдите все файлы в /usr/bin, начинающиеся с «py» - первые 5 имён.
  3. Из всех запущенных процессов (ps aux) оставьте только ваши (где вы - пользователь), посчитайте их количество.
  4. Найдите в домашней папке все .txt-файлы, отсортируйте их по имени.
Подсказка

Для подсчёта - wc -l. Для фильтра - grep. Для первых строк - head. Для сортировки - sort. Для поиска файлов - find.

Разбор

Решения:

# 1. Количество файлов в /usr/bin$ ls /usr/bin | wc -l1854# 2. Файлы на "py", первые 5$ ls /usr/bin | grep ^py | head -n 5py3cleanpy3compilepy3versionspython3python3.10# 3. Мои процессы$ ps aux | grep ^student | wc -l42# 4. Все .txt, отсортированные$ find ~ -name "*.txt" | sort/home/student/list.txt/home/student/note.txt/home/student/poem.txt

Что тут интересного:

  • ^py - регулярное выражение «начинается с py». Просто py нашёл бы «py» в любом месте имени.
  • ^student - строки, начинающиеся с имени пользователя. В ps aux первая колонка - имя пользователя, поэтому работает.
  • find | sort - конвейер между разными командами: find выдаёт пути, sort их сортирует.
Задача 4. Комплексная

Составьте одну команду (можно с конвейером) для каждой задачи:

  1. Топ-3 самых больших файлов в домашней папке с их размерами.
  2. Список всех процессов, отсортированный по использованию памяти (по убыванию), только 5 самых прожорливых.
  3. Количество уникальных пользователей в системе (по ps aux).
  4. Содержимое вашего list.txt сохранить в copy.txt и одновременно показать на экране.
Подсказка

Вспомните: find + du - размеры файлов. ps aux | sort -k4 -rn - сортировка по памяти. awk + sort -u - уникальные значения. tee - и в файл, и на экран.

Разбор

Возможные решения:

# 1. Топ-3 файлов по размеру$ find ~ -type f -exec du -h {} + | sort -rh | head -n 3# 2. Топ-5 процессов по памяти$ ps aux | sort -k4 -rn | head -n 5# 3. Уникальные пользователи в ps$ ps aux | awk '{print $1}' | tail -n +2 | sort -u# 4. Показать и сохранить$ cat list.txt | tee copy.txt

Разбор:

  • find -exec du - для каждого файла вызвать du -h, чтобы получить размер. Потом sort по убыванию и top-3.
  • sort -k4 -rn - сортировка по 4-й колонке (%MEM в ps aux), числами, по убыванию.
  • awk '{print $1}' - вывести первую колонку (имя пользователя). tail -n +2 - убрать заголовок. sort -u - уникальные.
  • cat | tee - и показать, и сохранить. Альтернатива: tee copy.txt < list.txt.

Каждая задача - одна строка в терминале. Мышкой на это ушли бы минуты. В этом и есть сила конвейеров.

Что мы узнали и что дальше

Разобрались с перенаправлением ввода-вывода и конвейерами - темой, которая превращает отдельные команды в мощные инструменты. Узнали, что у каждой программы есть три файловых дескриптора: stdin (0), stdout (1) и stderr (2). Поняли, почему вывод и ошибки - это отдельные каналы.

Освоили все основные операторы: > (в файл), >> (дописать), < (из файла), 2> (ошибки в файл), 2>&1 (объединить с основным выводом), | (конвейер), /dev/null (чёрная дыра), tee (и в файл, и на экран), << (heredoc).

Изучили классические рецепты: топ-большие файлы, топ-IP из логов, поиск в реальном времени. Теперь вы понимаете, что стоит за командами из предыдущих уроков - ls | wc -l, du -sh | sort -rh, grep -r | head - и можете строить свои цепочки под конкретную задачу.

Что делать дальше

Восемь уроков - это база. Дальше - практика и углубление. Направления, в которых стоит развиваться:

  • Bash-скрипты. Переменные, условия, циклы, функции. Автоматизация рутинных задач - отдельный большой мир. У нас в курсе «Скрипты» есть целый раздел по Bash.
  • Продвинутые инструменты. awk, sed, xargs, rsync, ssh с ключами и туннелями.
  • Сеть. curl, wget, ss, tcpdump, netstat.
  • Управление сервером. systemctl, journalctl, конфиги в /etc, бэкапы, cron-задачи.
  • Контейнеры и облако. Docker, Kubernetes, работа с облачными платформами через CLI.

Терминал - это навык, который улучшается с практикой. Чем больше вы его используете в повседневной работе, тем быстрее и естественнее он становится. Через месяц регулярной практики вы будете удивляться, как раньше обходились без него.

Не бойтесь экспериментировать. Терминал прощает ошибки гораздо чаще, чем кажется: большинство команд безопасны, а разрушительные требуют явного подтверждения (или прав root). А если что-то сломается - всегда есть Ctrl + Z, Ctrl + C и возможность разобраться.

Спасибо, что были с нами все восемь уроков. Удачи в освоении командной строки!
