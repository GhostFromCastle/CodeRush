Методы

~30 минут Средний уровень Теория и Практика

Добро пожаловать на средний уровень! Начальный мы закрыли - теперь у вас есть весь базовый набор инструментов. Пора учиться писать код не только правильно, но и красиво. И первый шаг на этом пути - методы.

До этого момента почти весь код жил внутри одного большого метода Main. Мы писали строчку за строчкой, и это работало, пока программа была маленькой. Но представьте, что у вас десять мест, где нужно посчитать среднее арифметическое. Или пять мест, где нужно вывести приветствие. Что, копировать один и тот же код десять раз?

Методы решают эту проблему. Они позволяют один раз написать действие и вызывать его по имени сколько угодно раз.

Проблема дублирования

Посмотрите на этот код - он выводит приветствие трижды, и каждый раз мы пишем одно и то же:

Console.WriteLine("Привет, Алексей!");Console.WriteLine("Добро пожаловать в CodeRush!");Console.WriteLine("Привет, Мария!");Console.WriteLine("Добро пожаловать в CodeRush!");Console.WriteLine("Привет, Иван!");Console.WriteLine("Добро пожаловать в CodeRush!");

Шесть строк, из которых три - одно и то же. Если завтра мы захотим поменять текст «Добро пожаловать в CodeRush!» на что-то другое, придётся править в трёх местах. А если таких мест сто? Это уже не работа, а наказание.

С методом тот же код выглядит так:

Greet("Алексей");Greet("Мария");Greet("Иван");

Три строки вместо шести. Текст приветствия написан в одном месте, и если его надо поменять - правим только там.

Что такое метод

Аналогия простая. Представьте пульт от телевизора. На нём есть кнопка «Включить». Вы нажимаете её - телевизор включается. Вам не нужно знать, какие там внутри микросхемы, какие сигналы посылаются. Достаточно знать: «кнопка Включить делает так, чтобы телевизор заработал».

Метод - это такая же кнопка. Мы один раз описываем, что должно произойти, даём этому действию имя, и потом вызываем по имени. Внутреннее устройство метода нас больше не интересует.

Главная мысль

Метод - это именованный блок кода, который можно вызывать из любого места программы. Один раз написали - много раз используем.

Первый метод - без параметров

Начнём с самого простого. Напишем метод, который просто выводит приветствие:

static void SayHello(){    Console.WriteLine("Привет!");    Console.WriteLine("Добро пожаловать!");}

Разберём эту запись по частям:

  • static - «статический». Пока просто запомните: метод нужно писать со словом static, если мы хотим вызывать его из Main. Подробнее разберём в уроке про классы.
  • void - «пустота». Означает, что метод ничего не возвращает. Просто выполняет действие и всё.
  • SayHello - имя метода. Придумываем сами. Обычно оно описывает, что метод делает.
  • () - пустые скобки. Значит, метод не принимает никаких данных.
  • { ... } - тело метода. Что именно происходит, когда его вызывают.

Теперь где-то в Main можно написать:

SayHello();SayHello();SayHello();

И приветствие выведется три раза. Согласитесь, это удобнее, чем писать одни и те же строки трижды.

Где писать методы

Метод пишется внутри класса Program, но не внутри Main. Проще всего - сразу после закрывающей скобки Main, перед закрывающей скобкой класса. Тогда структура программы остаётся чистой.

Метод с параметрами

Метод выше выводит всегда одно и то же. Но что, если мы хотим передать ему имя? Сделаем так:

static void Greet(string name){    Console.WriteLine($"Привет, {name}!");}

Внутри скобок появилось string name - это параметр. Он работает как обычная переменная, только внутри метода. Когда мы вызываем метод, мы передаём туда конкретное значение:

Greet("Алексей");Greet("Мария");Greet("Иван");

На экране появится:

Привет, Алексей!
Привет, Мария!
Привет, Иван!

Один метод - три разных приветствия. Именно так и должна работать правильная программа: описание действия в одном месте, конкретные данные приходят в момент вызова.

Несколько параметров

Метод может принимать не один, а много параметров - они перечисляются через запятую. Например:

static void PrintSum(int a, int b){    Console.WriteLine($"{a} + {b} = {a + b}");}

Вызов: PrintSum(3, 5); - программа выведет 3 + 5 = 8.

Порядок параметров важен. Если у метода (int a, int b), а вы вызовете PrintSum(5, 3) - то внутри a будет равно 5, а b - 3. Поменяются местами только числа в выводе, но сумма останется той же. А вот если метод работает со строками, порядок уже важен по смыслу.

Методы, возвращающие значение

До сих пор все наши методы просто что-то делали: выводили, здоровались, печатали. Но часто нужно, чтобы метод возвращал нам результат, с которым мы потом будем работать. Например, метод, который считает сумму двух чисел и возвращает её нам.

Для этого вместо void пишем тип возвращаемого значения, а в конце добавляем команду return:

static int Sum(int a, int b){    return a + b;}

Что изменилось:

  • Вместо void - int. Значит, метод возвращает целое число.
  • Вместо вывода на экран - return a + b;. Команда return «выдаёт» результат тому, кто вызвал метод.

А теперь самое интересное - как этим пользоваться:

int result = Sum(3, 4);Console.WriteLine(result);Console.WriteLine(Sum(10, 20));

Метод вернул число - и мы можем сразу положить его в переменную или вывести. Как обычное значение. Представьте, что Sum(3, 4) после выполнения как будто превращается в 7, и дальше код работает с этим 7.

void или тип?

Запомните простое правило: если метод что-то делает (выводит, рисует, печатает) и не отдаёт результат - пишем void. Если метод считает и отдаёт результат - пишем тип этого результата (int, double, string и т.д.) и внутри используем return.

return прерывает метод

Важная деталь: команда return не только возвращает значение, но и сразу завершает метод. Код после неё не выполнится. Вот пример:

static int Check(int x){    if (x < 0)    {        return 0;    }    return x * 2;}

Если x отрицательное - метод сразу вернёт 0 и остановится. До строки return x * 2; дело не дойдёт. Если положительное - сработает вторая строка.

Это очень удобный приём: сначала «отсекаем» неподходящие случаи ранним return, потом работаем с основным.

Области видимости

Один важный момент, который часто сбивает новичков. Переменные, созданные внутри метода, видны только внутри него. Снаружи их не существует.

static void Test(){    int secret = 42;    Console.WriteLine(secret);}

Если после этого попробовать обратиться к secret из Main - программа не скомпилируется. Переменной secret для Main не существует.

То же самое с параметрами. Параметр name в методе Greet существует только внутри Greet. Из другого метода его не видно.

Аналогия

Метод - как отдельная комната. Внутри неё лежат свои вещи. Когда вы выходите, эти вещи остаются в комнате, и снаружи их не достать. Если нужно передать что-то наружу - используйте return. Если нужно занести что-то внутрь - передавайте через параметры.

Это не баг, а очень удобная особенность: методы изолированы друг от друга, и изменения внутри одного метода не влияют на другие. Именно поэтому код получается надёжным.

Main - это тоже метод

Помните, мы говорили в первом уроке, что Main - это «точка входа»? Теперь вы можете смотреть на него по-новому: Main - это такой же метод, как и все остальные. Просто особенный - с него начинает работу программа.

Смотрите на знакомую запись:

static void Main(string[] args)

Всё то же самое: static, void, имя Main, параметр string[] args. Если бы мы написали его сами, мы бы сказали: «метод, который ничего не возвращает, называется Main, и принимает массив строк». Просто C# договорились, что программу начинает именно этот метод.

А значит, Main тоже может вызывать другие методы и получать от них значения - что мы и делаем весь урок.

Перегрузка методов

А теперь - интересный и очень полезный приём. В C# можно создавать несколько методов с одинаковым именем, но разными параметрами. Это называется «перегрузка».

Посмотрите:

static int Sum(int a, int b){    return a + b;}static int Sum(int a, int b, int c){    return a + b + c;}static double Sum(double a, double b){    return a + b;}

Три разных метода, у всех одно имя - Sum. Как C# понимает, какой именно вызвать? По количеству и типам аргументов:

  • Sum(3, 4) - подходит первый, для двух int.
  • Sum(3, 4, 5) - сработает второй, для трёх int.
  • Sum(1.5, 2.5) - а вот тут вызовется третий, для double.

Компилятор сам подбирает подходящий вариант. Нам не надо придумывать разные имена вроде Sum2, Sum3, SumDouble. Просто Sum.

Аналогия

Представьте глагол «открыть» в русском языке. Можно открыть дверь, открыть банку, открыть глаза. Слово одно, а действия разные - и мы понимаем, что имеется в виду, из контекста. Перегрузка методов работает так же: имя одно, а конкретное поведение зависит от того, что мы передали.

Кстати, Console.WriteLine - тоже перегруженный метод. У него есть версия для string, для int, для double, для bool и так далее. Именно поэтому он умеет печатать что угодно - компилятор подбирает подходящую версию.

Шпаргалка

Самое важное в одном месте:

  • static void Name() метод без параметров и возврата
  • static void Name(int x) метод с параметром
  • static int Name(int a, int b) метод с возвратом значения
  • return value; вернуть значение
  • Name(); вызов метода
  • Sum(3, 4) вызов с аргументами

Если что-то не работает

Методы - тема, где легко запутаться в мелочах. Проверьте по списку:

  • «The name 'Greet' does not exist in the current context». Метод не найден. Проверьте: он объявлен внутри класса, но за пределами Main? И не забыли ли вы слово static? Без него Main просто не увидит метод.
  • «An object reference is required». Это тоже про static. Пока мы работаем внутри одного класса - все методы должны быть static. Подробнее про это - в уроке про классы.
  • «No overload for method takes 1 arguments». Вы вызвали метод с другим количеством аргументов, чем он принимает. Например, метод просит два числа, а вы передали одно.
  • «Cannot implicitly convert type 'void' to...». Вы пытаетесь положить результат void-метода в переменную. Но void ничего не возвращает. Если нужен результат - метод должен иметь тип возврата и return.
  • «Not all code paths return a value». Метод с возвратом содержит не все пути с return. Например, у вас есть if, после которого return есть только внутри одного блока. Компилятор подскажет, где именно нужен дополнительный return.
  • «Use of unassigned local variable». Переменная внутри метода создана, но не заполнена значением. Убедитесь, что перед использованием переменная получила значение.
  • Изменение переменной внутри метода не видно снаружи. Это не ошибка, а особенность. Метод работает со своими локальными переменными и параметрами. Если нужно поменять что-то снаружи - используйте return.

Если ничего не помогло - напишите нам в Telegram, поможем разобраться.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя. Сначала обязательно попробуйте сами.

Задача 1. Приветствие по имени

Напишите метод Greet, который принимает имя и выводит «Привет, [имя]!». Вызовите его для трёх разных имён.

Подсказка

Метод возвращает void - он ничего не отдаёт, только печатает. Параметр один: string name. Внутри - один Console.WriteLine с интерполяцией. А в Main три раза вызовете метод с разными именами.

Решение учителя 
static void Greet(string name){    Console.WriteLine($"Привет, {name}!");}static void Main(string[] args){    Greet("Алексей");    Greet("Мария");    Greet("Иван");}

Обратите внимание: метод объявлен до Main. На самом деле C# неважно, в каком порядке идут методы в классе - можно объявить Greet и после Main. Главное, чтобы он был внутри класса Program.

Задача 2. Сумма и произведение

Напишите два метода: Sum(a, b) и Multiply(a, b). Оба принимают два целых числа и возвращают целое число. Вызовите оба и выведите результаты.

Подсказка

Тип возврата - int. Внутри метода - команда return. Например, для суммы: return a + b;. А для произведения: return a * b;. Результат можно сразу выводить через Console.WriteLine(Sum(3, 4));.

Решение учителя 
static int Sum(int a, int b){    return a + b;}static int Multiply(int a, int b){    return a * b;}static void Main(string[] args){    Console.WriteLine(Sum(3, 4));    Console.WriteLine(Multiply(3, 4));}

Программа выведет 7 и 12. Оба метода возвращают результат, и мы сразу передаём его в Console.WriteLine. Можно было и сохранить в переменные, а потом выводить - разницы нет.

Задача 3. Максимум из трёх

Напишите метод MaxOfThree, который принимает три числа и возвращает наибольшее из них.

Подсказка 1

Три параметра типа int, возврат тоже int. Внутри можно использовать цепочку условий if / else if / else, которую мы разбирали в четвёртом уроке начального уровня.

Подсказка 2

Не забудьте, что return работает не только для возврата значения, но и для выхода из метода. Удобно сначала проверить случай a >= b && a >= c, потом остальные. Или наоборот: сравнить a и b между собой, потом результат сравнить с c.

Решение учителя 
static int MaxOfThree(int a, int b, int c){    int max = a;    if (b > max)    {        max = b;    }    if (c > max)    {        max = c;    }    return max;}

Такой подход - «взять одно значение за максимум и обновлять его при необходимости» - мы уже использовали в уроке про массивы. Он короче, чем три ветки if / else if / else, и легко расширяется до четырёх и более чисел.

Задача 4. Таблица умножения

Напишите метод PrintTable, который принимает число и выводит таблицу умножения на это число от 1 до 10. Вызовите метод из Main три раза с разными числами.

Подсказка 1

Метод возвращает void - он ничего не отдаёт, только печатает. Один параметр типа int. Внутри - цикл for от 1 до 10 из пятого урока начального уровня.

Подсказка 2

Чтобы таблицы не слипались, добавьте в конце метода пустой Console.WriteLine();. Он просто переведёт курсор на новую строку перед следующей таблицей.

Решение учителя 
static void PrintTable(int n){    for (int i = 1; i <= 10; i++)    {        Console.WriteLine($"{n} × {i} = {n * i}");    }    Console.WriteLine();}static void Main(string[] args){    PrintTable(3);    PrintTable(5);    PrintTable(7);}

Программа выведет три таблицы подряд: на 3, на 5 и на 7. Обратите внимание, как компактно: метод описан один раз, а вызывается три раза. Если завтра понадобится таблица на 9 - просто добавите ещё одну строчку PrintTable(9);.

Что мы узнали и что дальше

Сегодня мы сделали большой шаг вперёд - научились писать методы. Это фундамент всего дальнейшего курса. Разобрались, что методы бывают двух видов: void (просто выполняют действие) и с возвратом значения (отдают результат). Узнали про параметры и команду return. Поняли, как работают области видимости. И познакомились с перегрузкой - одной из самых удобных возможностей C#.

Теперь наш код может быть коротким и структурированным. Один раз написали действие - вызываем его по имени, где нужно. Не надо копировать одни и те же строки по десять раз.

В следующем уроке мы закрепим методы на практике: будем брать код из старых уроков и переписывать его с использованием методов. Это называется рефакторинг - очень полезный навык, который отличает опытного программиста от новичка. А заодно подробнее разберём методы с возвратом значений и параметрами.
