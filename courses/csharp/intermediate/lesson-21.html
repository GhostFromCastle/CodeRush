Исключения

~35 минут Средний уровень Теория и Практика

В третьем уроке начального уровня мы договорились: «пользователь вводит только цифры, иначе программа упадёт». Тогда это было нормально - мы только учились. Но сейчас мы пишем серьёзные программы, и «упасть с красной ошибкой» - это неприемлемо. Представьте банкомат, который выключается, если вы случайно нажали букву вместо цифры.

Сегодня мы научим программу справляться с неожиданностями. Этот механизм называется обработкой исключений. И это, пожалуй, самая практическая тема на всём среднем уровне.

Что такое исключение

Исключение (по-английски Exception) - это особая ситуация, когда программа не может выполнить команду и вынуждена остановиться. Как если бы вы ехали на машине и вдруг загорелась красная лампочка «проверь двигатель».

Когда в C# возникает ошибка, программа «выбрасывает» (throw) исключение. Если его никто не поймал, программа аварийно завершается и показывает нам ту самую пугающую красную стену текста.

Самые частые исключения, с которыми мы уже сталкивались:

  • FormatException - пытаемся превратить текст в число, но текст не является числом (например, int.Parse("привет")).
  • DivideByZeroException - пытаемся поделить на ноль.
  • IndexOutOfRangeException - обращаемся к элементу массива, которого нет (например, arr[100], когда в массиве 10 элементов).
  • NullReferenceException - пытаемся вызвать метод у объекта, который не создан (равен null).

Конструкция try / catch

Чтобы программа не падала, мы можем «поймать» исключение и сделать что-то полезное. Для этого используется конструкция try / catch (попробовать / поймать).

Синтаксис простой:

try{    // Опасный код, где может произойти ошибка}catch{    // Что делать, если ошибка случилась}

Программа пытается выполнить блок try. Если всё прошло гладко - блок catch пропускается. Если внутри try произошло исключение - выполнение try прерывается, и управление переходит в блок catch.

Давайте решим нашу давнюю проблему с вводом числа:

Console.Write("Введите число: ");string input = Console.ReadLine();try{    int number = int.Parse(input);    Console.WriteLine($"Вы ввели {number}");}catch{    Console.WriteLine("Ошибка! Нужно было ввести число.");}Console.WriteLine("Программа продолжает работу.");

Что здесь произойдёт:

  • Если пользователь ввёл «25», программа выведет «Вы ввели 25».
  • Если пользователь ввёл «двадцать», int.Parse не сможет превратить это в число. Он выбросит FormatException. Программа не упадёт, а перейдет в блок catch и выведет «Ошибка!».
  • В любом случае в конце выведется «Программа продолжает работу».

Ловим конкретные типы ошибок

Блок catch без параметров ловит вообще любую ошибку. Но иногда мы хотим по-разному реагировать на разные исключения. Для этого в скобках после catch указывают тип исключения:

try{    int a = int.Parse(Console.ReadLine());    int b = int.Parse(Console.ReadLine());    Console.WriteLine(a / b);}catch (FormatException){    Console.WriteLine("Ошибка: введено не число.");}catch (DivideByZeroException){    Console.WriteLine("Ошибка: деление на ноль невозможно.");}

Программа сначала попробует выполнить блок try. Если пользователь введёт букву, возникнет FormatException и сработает первый catch. Если пользователь введёт корректные числа, но второе будет нулём, возникнет DivideByZeroException и сработает второй catch. Так программа даёт точные и понятные сообщения.

Блок finally

Иногда есть код, который нужно выполнить в любом случае: и если ошибка была, и если не было. Для этого есть блок finally.

try{    // Опасный код}catch{    // Обработка ошибки}finally{    // Выполнится всегда}

Где это полезно? Например, при работе с файлами: вы открыли файл, что-то в нём сделали (и, возможно, произошла ошибка), но файл обязательно нужно закрыть. Код закрытия пишут в finally.

Для консольных программ это нужно редко, но знать о существовании такого блока полезно.

Создание своих исключений (throw)

Иногда встроенные исключения нас не устраивают. Например, в прошлом уроке (Инкапсуляция) мы сделали свойство, которое просто игнорировало отрицательный возраст. Но что, если мы хотим громко сообщить об ошибке, чтобы её заметили?

Для этого используют команду throw (выбросить).

public int Age{    get { return age; }    set    {        if (value < 0)        {            throw new ArgumentException("Возраст не может быть отрицательным");        }        age = value;    }}

Теперь, если кто-то попытается написать student.Age = -5;, программа выбросит исключение ArgumentException с нашим текстом. Это заставит другого разработчика (или нас самих) немедленно заметить ошибку и исправить код, который передает неправильные данные.

Когда использовать throw

Используйте throw, когда нарушено правило, которое программа не может проигнорировать. Если пользователь ввёл неверный пароль - это не исключение (это нормальный ход вещей). А вот если в метод расчёта зарплаты передали отрицательную ставку - это исключительная ситуация.

Шпаргалка

Самое важное в одном месте:

  • try / catch поймать ошибку и не упасть
  • catch (FormatException) ловить конкретный тип
  • finally выполнится всегда
  • throw new Exception("...") создать свою ошибку
  • ArgumentException неверный аргумент
  • DivideByZeroException деление на ноль

Если что-то не работает

Обработка ошибок - тема, где легко допустить логическую ошибку. Проверьте по списку:

  • Ошибка всё равно появляется. Проверьте, что опасный код находится внутри блока try. Если код до него или после него - исключение не поймается.
  • «Unreachable catch block». Вы написали catch (Exception) (или просто catch) выше, чем catch (FormatException). Поскольку любая ошибка является Exception, она перехватится первым блоком, и до конкретного дело не дойдёт. Сначала ловите конкретные ошибки, потом общие.
  • «Use of unassigned local variable» после try/catch. Если вы объявили переменную внутри try, то за пределами этого блока её не существует. Объявляйте переменные до try.
  • Программа падает с ошибкой в блоке catch. Код внутри catch тоже может содержать ошибки! Например, вы пытаетесь вывести на экран переменную, которая не была инициализирована, потому что программа упала раньше.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Безопасный ввод

Напишите программу, которая просит у пользователя целое число. Если пользователь вводит текст, программа должна вывести «Ошибка ввода» и не падать.

Подсказка

Оберните int.Parse(Console.ReadLine()) в блок try. В блоке catch напишите Console.WriteLine("Ошибка ввода");.

Решение учителя 
Console.Write("Введите число: ");string input = Console.ReadLine();try{    int number = int.Parse(input);    Console.WriteLine($"Успех! Вы ввели {number}");}catch (FormatException){    Console.WriteLine("Ошибка ввода");}
Задача 2. Математика без падений

Спросите у пользователя два числа и выполните деление первого на второе. Обработайте два случая: если введено не число, и если второе число равно нулю. Выведите соответствующие сообщения.

Подсказка

Используйте два блока catch: один для FormatException, второй для DivideByZeroException. Не забудьте, что тип int.Parse создает риск для первого исключения.

Решение учителя 
try{    Console.Write("Первое число: ");    int a = int.Parse(Console.ReadLine());    Console.Write("Второе число: ");    int b = int.Parse(Console.ReadLine());    Console.WriteLine($"Результат: {a / b}");}catch (FormatException){    Console.WriteLine("Ошибка: введено не число.");}catch (DivideByZeroException){    Console.WriteLine("Ошибка: деление на ноль невозможно.");}
Задача 3. Доступ к массиву

Создайте массив из трёх имён. Попросите пользователя ввести индекс от 0 до 2 и выведите имя по этому индексу. Если индекс вне диапазона - выведите «Неверный индекс».

Подсказка

Исключение при выходе за границы массива называется IndexOutOfRangeException. Оберните обращение к массиву в try.

Решение учителя 
string[] names = { "Алексей", "Мария", "Иван" };try{    Console.Write("Введите индекс (0-2): ");    int index = int.Parse(Console.ReadLine());    Console.WriteLine($"Имя: {names[index]}");}catch (IndexOutOfRangeException){    Console.WriteLine("Неверный индекс");}catch (FormatException){    Console.WriteLine("Введите число!");}
Задача 4. Улучшаем банковский счёт

Вернитесь к классу BankAccount из прошлого урока. Переделайте метод Withdraw так, чтобы при нехватке средств он выбрасывал исключение через throw new Exception("Недостаточно средств"), а не просто выводил текст.

Подсказка

В методе Withdraw проверьте условие. Если денег не хватает - используйте throw new Exception("Недостаточно средств");. Программа, которая вызывает этот метод, должна обернуть вызов в try/catch.

Решение учителя 
class BankAccount{    private double balance;    public double Balance    {        get { return balance; }    }    public void Deposit(double amount)    {        if (amount > 0)        {            balance += amount;        }    }    public void Withdraw(double amount)    {        if (amount > balance)        {            throw new Exception("Недостаточно средств");        }        balance -= amount;    }}static void Main(string[] args){    BankAccount account = new BankAccount();    account.Deposit(100);    try    {        account.Withdraw(200);    }    catch (Exception ex)    {        Console.WriteLine($"Ошибка: {ex.Message}");    }}

Теперь метод Withdraw сам не решает, что делать с ошибкой. Он просто сообщает: «Ребята, проблема!». А тот, кто вызывал этот метод (в нашем случае Main), решает, как на это реагировать - вывести текст, записать в лог или предложить ввести сумму заново. Это делает код гораздо гибче.

Что мы узнали и что дальше

Сегодня мы научили наши программы выживать. Разобрались с конструкцией try / catch, узнали про finally и научились выбрасывать собственные исключения через throw.

Теперь программа не упадёт, если пользователь ошибётся с вводом. Она вежливо попросит ввести данные заново и продолжит работу. Это уровень настоящих, профессиональных приложений.
