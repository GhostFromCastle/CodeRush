Проект: Менеджер задач

~45 минут Средний уровень Проект

Сегодня мы соберём наш первый настоящий проект, в котором не будет пошаговых инструкций «напиши это, потом это». Мы дадим вам техническое задание, и вы попробуете собрать приложение сами, используя всё, чему научились. Но сначала мы разберём архитектуру и покажем ключевые куски кода.

Мы будем делать консольный Менеджер задач (To-Do List). Это классическое приложение, которое есть у каждого разработчика в портфолио. Оно отлично тренирует навыки работы с классами, списками и меню.

Техническое задание

Программа должна работать в бесконечном цикле, показывая пользователю меню с командами:

  • 1 - Добавить задачу.
  • 2 - Показать все задачи.
  • 3 - Отметить задачу как выполненную.
  • 4 - Выход.

У каждой задачи есть:

  • Уникальный номер (ID).
  • Текст описания (например, «Купить хлеб»).
  • Статус (выполнена или нет).

И самое главное: если пользователь введёт неверный номер команды или попытается выполнить несуществующую задачу, программа не должна падать. Мы будем использовать try/catch из прошлого урока.

Шаг 1: Класс Task (Задача)

Для начала нам нужен чертёж для одной задачи. Создадим класс TaskItem. (Мы не назвали его просто Task, потому что в C# уже есть встроенный класс с таким именем, чтобы не было путаницы).

class TaskItem{    public int Id { get; }    public string Title { get; set; }    public bool IsCompleted { get; set; }    public TaskItem(int id, string title)    {        Id = id;        Title = title;        IsCompleted = false;    }    public void Print()    {        string status = IsCompleted ? "[x]" : "[ ]";        Console.WriteLine($"{status} {Id}. {Title}");    }}

Обратите внимание на свойство Id { get; }. У задачи не может измениться номер после создания - поэтому мы сделали его доступным только для чтения. А вот Title и IsCompleted можно менять.

Метод Print использует тернарный оператор (урок 12) для вывода квадратных скобочек: если задача выполнена - [x], если нет - [ ].

Шаг 2: Хранилище (Список)

В Main мы создаём список для хранения наших задач и переменную для следующего ID:

var tasks = new List<TaskItem>();int nextId = 1;

Каждый раз, когда пользователь добавляет задачу, мы создаём новый объект TaskItem с номером nextId, добавляем в список и увеличиваем счётчик nextId++.

Шаг 3: Меню

Сердце программы - это бесконечный цикл с меню:

while (true){    Console.WriteLine("\nМеню:");    Console.WriteLine("1. Добавить задачу");    Console.WriteLine("2. Показать задачи");    Console.WriteLine("3. Выполнить задачу");    Console.WriteLine("4. Выход");    Console.Write("Выберите действие: ");    string choice = Console.ReadLine();    switch (choice)    {        case "1":            AddTask(tasks, ref nextId);            break;        case "2":            ShowTasks(tasks);            break;        case "3":            CompleteTask(tasks);            break;        case "4":            return;        default:            Console.WriteLine("Неизвестная команда.");            break;    }}

Чтобы Main не раздувался, мы вынесли каждое действие в отдельный метод: AddTask, ShowTasks и CompleteTask. Обратите внимание на ref nextId - мы передаём переменную по ссылке, чтобы метод мог её изменить (увеличить счётчик).

Шаг 4: Реализация методов

1. Добавление задачи

static void AddTask(List<TaskItem> tasks, ref int nextId){    Console.Write("Введите описание задачи: ");    string title = Console.ReadLine();    if (string.IsNullOrWhiteSpace(title))    {        Console.WriteLine("Описание не может быть пустым.");        return;    }    TaskItem newTask = new TaskItem(nextId, title);    tasks.Add(newTask);    nextId++;    Console.WriteLine($"Задача #{newTask.Id} добавлена.");}

Здесь мы используем метод string.IsNullOrWhiteSpace, чтобы проверить, не ввёл ли пользователь пустую строку или одни пробелы. Это встроенный метод C#, который отлично подходит для проверки ввода.

2. Показ задач

static void ShowTasks(List<TaskItem> tasks){    if (tasks.Count == 0)    {        Console.WriteLine("Список задач пуст.");        return;    }    Console.WriteLine("Ваши задачи:");    foreach (TaskItem task in tasks)    {        task.Print();    }}

3. Выполнение задачи (с исключениями)

А вот и наш долгожданный try/catch. Здесь пользователь вводит номер задачи, и мы должны найти её в списке.

static void CompleteTask(List<TaskItem> tasks){    if (tasks.Count == 0)    {        Console.WriteLine("Список задач пуст.");        return;    }    Console.Write("Введите номер задачи для выполнения: ");        try    {        int id = int.Parse(Console.ReadLine());                TaskItem taskToComplete = tasks.Find(t => t.Id == id);                if (taskToComplete == null)        {            throw new Exception("Задача с таким номером не найдена.");        }                taskToComplete.IsCompleted = true;        Console.WriteLine($"Задача #{id} выполнена!");    }    catch (FormatException)    {        Console.WriteLine("Ошибка: нужно ввести число.");    }    catch (Exception ex)    {        Console.WriteLine($"Ошибка: {ex.Message}");    }}

Разберём этот код:

  • tasks.Find(t => t.Id == id) - это встроенный метод списка. Он ищет первый элемент, который удовлетворяет условию. В данном случае мы ищем задачу, у которой поле Id равно введённому числу. (Запись t => t.Id == id называется лямбда-выражением - мы разберём их на продвинутом уровне, а пока просто используйте этот синтаксис для поиска).
  • Если Find ничего не находит, он возвращает null.
  • Если задача не найдена, мы сами выбрасываем исключение через throw new Exception("...").
  • Блок catch (FormatException) ловит случай, когда пользователь ввёл букву.
  • Блок catch (Exception ex) ловит наш кастомный throw (и любые другие ошибки). Внутри мы выводим ex.Message - текст, который мы передали в исключение.

Если что-то не работает

  • «The name 'TaskItem' does not exist». Класс TaskItem должен быть объявлен внутри класса Program, но за пределами Main. И не забудьте, что методы AddTask, ShowTasks и CompleteTask должны быть static.
  • Программа падает при поиске задачи. Проверьте, что вы используете tasks.Find(...), а не tasks.FindIndex(...). Find возвращает сам объект, а FindIndex - только его номер.
  • Счётчик ID не увеличивается. Убедитесь, что в методе AddTask вы написали ref int nextId в параметрах, а при вызове из Main - AddTask(tasks, ref nextId).

Практика

Проект готов, но его можно сделать ещё лучше. Вот три задачи для самостоятельного улучшения кода (решения не прилагаются, попробуйте сами):

Задача 1. Удаление задачи

Добавьте в меню пункт «5. Удалить задачу». Напишите метод DeleteTask, который спрашивает номер задачи и удаляет её из списка. Используйте метод tasks.Remove(task). Не забудьте обработать ситуацию, когда задача не найдена.

Задача 2. Фильтр задач

Добавьте пункт «6. Показать только невыполненные». При выборе этого пункта программа должна вывести только те задачи, у которых IsCompleted == false. Для этого используйте цикл foreach и условие if.

Задача 3. Изменение названия

Добавьте пункт «7. Редактировать задачу». Программа спрашивает номер задачи, находит её и просит ввести новое название. Если задача найдена, присвойте её свойству Title новое значение.

Что мы узнали и что дальше

Поздравляем! Вы написали первое полноценное приложение с интерактивным меню, хранением данных в списке и обработкой ошибок. Теперь у вас есть отличный проект для портфолио.

Мы закрепили классы, инкапсуляцию (свойство Id только для чтения), списки, методы, switch и try/catch. Это именно тот набор, который требуется на начальных позициях в IT.
