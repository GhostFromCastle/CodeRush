Полиморфизм: один интерфейс - разное поведение

~35 минут Средний уровень Теория и Практика

В прошлом уроке наследники получили методы родителя, но вызывали их по-своему только после override. Сегодня разберемся, как это работает и почему это одна из самых полезных возможностей ООП.

В этом уроке мы:

  • Поймем, что такое virtual и override.
  • Научимся хранить разные объекты в одной коллекции.
  • Разберем разницу между override и new.
  • Освоим проверки типов через is, as и switch.
Аналогия

Один пульт - разные устройства: кнопка «включить» есть у телевизора, лампы и колонки, но ведут они себя по-разному.

Одна ссылка - разные объекты

Главная идея полиморфизма: переменная базового типа может хранить объект любого наследника.

Person person = new Student();

Это работает, потому что студент является человеком. Обратное неверно:

Student student = new Person(); // ошибка компиляции

Человек не обязательно студент, поэтому компилятор такое запрещает.

virtual и override

C# 
class Person
{
    public string Name { get; set; }

    public virtual void Introduce()
    {
        Console.WriteLine($"Я {Name}");
    }
}

class Student : Person
{
    public string Group { get; set; }

    public override void Introduce()
    {
        Console.WriteLine($"Я {Name}, учусь в группе {Group}");
    }
}

class Teacher : Person
{
    public string Subject { get; set; }

    public override void Introduce()
    {
        Console.WriteLine($"Я {Name}, преподаю {Subject}");
    }
}

Теперь соберем разных людей в один список и вызовем один и тот же метод:

var people = new List<Person>{    new Student { Name = "Алексей", Group = "П-21" },    new Teacher { Name = "Мария", Subject = "Математика" },    new Person  { Name = "Гость" }};foreach (var person in people){    person.Introduce();}

Результат:

Я Алексей, учусь в группе П-21Я Мария, преподаю МатематикуЯ Гость

Вызов один - person.Introduce(), а поведение разное. Компилятор смотрит на тип переменной, а среда выполнения - на реальный тип объекта. Это и есть полиморфизм.

Зачем это нужно

Представьте расчет зарплаты: у штатного сотрудника одна формула, у подрядчика другая, у менеджера - оклад плюс бонус. Без полиморфизма пришлось бы писать if (тип == ...) в десяти местах. С полиморфизмом достаточно вызвать CalculatePay().

new вместо override

Можно «спрятать» метод базового класса без переопределения:

class Student : Person{    public new void Introduce()    {        Console.WriteLine("Я студент");    }}

Разница проявляется при вызове через базовый тип:

Person person = new Student();person.Introduce();                 // вызовется версия Person((Student)person).Introduce();      // вызовется версия Student

С override в обоих случаях вызвалась бы версия студента. new почти всегда ошибка: он ломает полиморфизм и ведет себя неожиданно. Компилятор предупреждает о таком коде - не игнорируйте предупреждение.

is и as

Иногда нужно узнать реальный тип объекта:

foreach (var person in people){    if (person is Student student)    {        Console.WriteLine($"Студент группы {student.Group}");    }}

Конструкция is Тип переменная одновременно проверяет тип и создает переменную, если проверка прошла. Это безопаснее, чем приведение вручную.

as возвращает null, если приведение невозможно:

Student maybe = person as Student;if (maybe != null){    Console.WriteLine(maybe.Group);}

Для значимых типов (числа, структуры) as не работает - используйте is.

switch по типу

Современный C# умеет выбирать поведение по типу в switch:

foreach (var person in people){    switch (person)    {        case Student s:            Console.WriteLine($"Студент: {s.Group}");            break;        case Teacher t:            Console.WriteLine($"Преподаватель: {t.Subject}");            break;        default:            Console.WriteLine("Гость");            break;    }}

Читается лучше цепочки if (x is ...), хотя внутри все равно остается проверка типов. Хороший дизайн - когда таких проверок нет вовсе: поведение задается виртуальными методами.

Полиморфизм в реальном коде

abstract class Shape{    public abstract double Area();}class Circle : Shape{    public double Radius { get; set; }    public override double Area() => Math.PI * Radius * Radius;}class Rectangle : Shape{    public double Width { get; set; }    public double Height { get; set; }    public override double Area() => Width * Height;}var shapes = new List<Shape> { new Circle { Radius = 2 }, new Rectangle { Width = 3, Height = 4 } };foreach (var shape in shapes){    Console.WriteLine(shape.Area());}

Код, который считает площадь, не знает, с какой фигурой работает. Добавили треугольник - старый код не меняется.

Шпаргалка

  • virtual разрешить переопределение
  • override переопределить
  • new спрятать (опасно)
  • is проверка типа
  • as приведение или null

Если что-то не работает

  • Вызывается метод базового класса. В наследнике забыли override или использовали new.
  • «No suitable method found to override». В базовом классе нет virtual.
  • «Cannot convert type». Приводите объект к типу, которым он не является. Проверяйте через is.
  • «Use of unassigned local variable» после as. Нужна проверка на null.
  • Поведение зависит от того, как объявлена переменная. Это признак new вместо override.

Практика

Задача 1. Фигуры

Создайте базовый класс Shape с виртуальным методом Area() и наследников Circle, Rectangle, Triangle. Посчитайте суммарную площадь списка фигур.

Подсказка

Список List<Shape>, цикл foreach и накопление суммы через +=.

Решение учителя 
var shapes = new List<Shape>{    new Circle { Radius = 2 },    new Rectangle { Width = 3, Height = 4 },    new Triangle { Base = 6, Height = 2 }};double total = 0;foreach (var shape in shapes){    total += shape.Area();}Console.WriteLine($"Суммарная площадь: {total:F2}");
Задача 2. Зарплаты

Базовый класс Employee с виртуальным CalculatePay(). Наследники: FullTimeEmployee (оклад), Contractor (ставка × часы), Manager (оклад + бонус). Выведите ведомость.

Подсказка

Каждый наследник переопределяет CalculatePay по своей формуле. В цикле вызывайте только базовый метод.

Решение учителя
C# 
abstract class Employee
{
    public string Name { get; set; }
    public abstract decimal CalculatePay();
}

class FullTimeEmployee : Employee
{
    public decimal Salary { get; set; }
    public override decimal CalculatePay() => Salary;
}

class Contractor : Employee
{
    public decimal Rate { get; set; }
    public int Hours { get; set; }
    public override decimal CalculatePay() => Rate * Hours;
}

class Manager : Employee
{
    public decimal Salary { get; set; }
    public decimal Bonus { get; set; }
    public override decimal CalculatePay() => Salary + Bonus;
}
Задача 3. Проверка типа

В списке людей найдите только студентов и выведите их группы. Используйте is с переменной.

Подсказка

if (person is Student student) - внутри блока переменная student уже нужного типа.

Решение учителя 
foreach (var person in people){    if (person is Student student)    {        Console.WriteLine($"{student.Name}: {student.Group}");    }}
Задача 4. Найдите ошибку

Код компилируется, но в цикле всегда вызывается версия базового класса. Почему?

class Person{    public void Introduce() => Console.WriteLine("Я человек");}class Student : Person{    public void Introduce() => Console.WriteLine("Я студент");}
Подсказка

Метод не помечен virtual в базовом классе и override в наследнике - используется скрытие.

Решение учителя 
class Person{    public virtual void Introduce() => Console.WriteLine("Я человек");}class Student : Person{    public override void Introduce() => Console.WriteLine("Я студент");}

Что мы узнали и что дальше

Теперь вы понимаете второй принцип ООП. Вы знаете:

  • Как virtual и override дают разное поведение.
  • Почему ссылка базового типа может хранить наследника.
  • Чем new отличается от override и почему первое опасно.
  • Как безопасно проверять тип через is и as.
