Наследование классов

~35 минут Средний уровень Теория и Практика

В прошлом уроке мы научились прятать поля за свойствами. Но есть другая проблема: в программе появляются классы, которые почти одинаковые. Студент и преподаватель - оба люди, у обоих есть имя и возраст, оба здороваются. Копировать код из класса в класс - плохая идея: исправление придется делать в двух местах.

В этом уроке мы:

  • Поймем, зачем нужно наследование.
  • Научимся создавать производные классы и вызывать base().
  • Разберем protected и переопределение ToString().
  • Узнаем, когда наследование вредит и лучше выбрать композицию.
Аналогия

Семья: у всех есть фамилия и общие правила дома, но у каждого свои увлечения. Базовый класс - общее, наследник - своё.

Проблема дублирования

Посмотрите на два класса. Они отличаются одной строкой, а остальное повторяется:

class Student{    public string Name { get; set; }    public int Age { get; set; }    public void Greet()    {        Console.WriteLine($"Привет, я {Name}, мне {Age}");    }}class Teacher{    public string Name { get; set; }    public int Age { get; set; }    public void Greet()    {        Console.WriteLine($"Привет, я {Name}, мне {Age}");    }}

Теперь представьте, что приветствие нужно изменить. Придется править оба класса, а через месяц появится третий - и снова копировать. Наследование позволяет вынести общее в один класс.

Базовый и производный класс

class Person{    public string Name { get; set; }    public int Age { get; set; }    public void Greet()    {        Console.WriteLine($"Привет, я {Name}, мне {Age}");    }}class Student : Person{    public string Group { get; set; }}

Запись class Student : Person читается как «Student является Person» и получает все поля, свойства и методы базового класса. Проверим:

var student = new Student();student.Name = "Алексей";student.Age = 20;student.Group = "П-21";student.Greet(); // Привет, я Алексей, мне 20

Студент не объявлял Name и Greet - он их унаследовал. При этом собственное свойство Group осталось только у студента.

Наследование - это «является»

Проверка простая: если фраза «Студент является человеком» звучит верно - наследование уместно. Если «Автомобиль является двигателем» - нет, здесь нужна композиция: автомобиль содержит двигатель. Об этом ниже.

Конструкторы и base

Если у базового класса есть конструктор с параметрами, производный должен его вызвать:

class Person{    public string Name { get; }    public int Age { get; }    public Person(string name, int age)    {        Name = name;        Age = age;    }}class Student : Person{    public string Group { get; }    public Student(string name, int age, string group)        : base(name, age)    {        Group = group;    }}

: base(name, age) передает значения в конструктор Person. Без этого компилятор попытается вызвать конструктор без параметров, не найдет его и выдаст ошибку.

Создание объекта:

var student = new Student("Алексей", 20, "П-21");Console.WriteLine($"{student.Name}, группа {student.Group}");

protected

Мы уже знаем public и private. Есть третий уровень доступа - protected: поле видно самому классу и его наследникам, но не снаружи.

class Person{    protected int _energy = 100;    public void Rest()    {        _energy = 100;    }}class Student : Person{    public void Study()    {        _energy -= 20; // доступно, потому что protected        Console.WriteLine($"Осталось сил: {_energy}");    }}

Снаружи student._energy уже не прочитать. Это компромисс: наследник получает доступ к внутренностям, а посторонний код - нет.

Не делайте поля protected без нужды

protected сильнее связывает классы: наследник начинает зависеть от внутреннего устройства родителя. Если можно обойтись private и защищенным свойством - выбирайте это.

Переопределение ToString

Метод ToString() есть у любого объекта - он унаследован от object. По умолчанию он выводит имя типа, что бесполезно. Его можно переопределить:

class Person{    public string Name { get; set; }    public int Age { get; set; }    public override string ToString()    {        return $"{Name} ({Age})";    }}var person = new Person { Name = "Анна", Age = 25 };Console.WriteLine(person); // Анна (25)

Ключевое слово override сообщает компилятору: мы заменяем унаследованную реализацию. Если написать его без virtual в базовом классе, будет ошибка.

sealed: запрет наследования

Иногда класс не должен иметь наследников - например, когда важно сохранить его поведение неизменным:

sealed class Logger{    public void Log(string message) => Console.WriteLine(message);}

Попытка унаследоваться от Logger не скомпилируется. sealed можно применять и к отдельному переопределенному методу.

Композиция вместо наследования

Наследование - мощный, но жесткий инструмент: производный класс навсегда связан с базовым. Часто лучше «содержать» объект, чем наследоваться от него:

class Engine{    public void Start() => Console.WriteLine("Двигатель запущен");}// плохо: автомобиль не является двигателемclass Car : Engine { }// хорошо: автомобиль содержит двигательclass Car{    private readonly Engine _engine = new Engine();    public void Start() => _engine.Start();}

Композиция дает гибкость: двигатель можно заменить, протестировать отдельно, у автомобиля не появляются лишние методы вроде Start() от двигателя.

Шпаргалка

  • class B : A наследование
  • : base(...) вызов конструктора родителя
  • protected доступно наследникам
  • override переопределить метод
  • sealed запретить наследование

Если что-то не работает

  • «There is no argument given that corresponds to the required parameter». Не вызван base(...) в конструкторе наследника.
  • «Cannot access protected member». protected-поле читают снаружи класса. Нужно свойство или метод.
  • «No suitable method found to override». В базовом классе метод не помечен virtual.
  • «Cannot derive from sealed type». Класс закрыт для наследования.
  • Наследник «не видит» поле. Оно объявлено private - используйте protected или свойство.

Практика

Задача 1. Животные

Создайте класс Animal с именем и методом Speak(), который выводит «...». Затем классы Dog и Cat, наследующие его, со своим звуком.

Подсказка

В базовом классе объявите public virtual void Speak(), в наследниках - public override void Speak().

Решение учителя
C# 
class Animal
{
    public string Name { get; set; }

    public virtual void Speak()
    {
        Console.WriteLine($"{Name} издает звук");
    }
}

class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine($"{Name} говорит: гав!");
    }
}

class Cat : Animal
{
    public override void Speak()
    {
        Console.WriteLine($"{Name} говорит: мяу!");
    }
}
Задача 2. Сотрудники

Есть Employee с именем и окладом. Создайте Manager с дополнительным полем Bonus и методом GetTotalPay(), который возвращает оклад плюс бонус.

Подсказка

Оклад в базовом классе сделайте protected или public со свойством только для чтения, затем вызовите base(name, salary).

Решение учителя 
class Employee{    public string Name { get; }    protected decimal Salary { get; }    public Employee(string name, decimal salary)    {        Name = name;        Salary = salary;    }}class Manager : Employee{    public decimal Bonus { get; }    public Manager(string name, decimal salary, decimal bonus)        : base(name, salary)    {        Bonus = bonus;    }    public decimal GetTotalPay() => Salary + Bonus;}
Задача 3. Переопределите ToString

Добавьте в Employee переопределение ToString(), которое возвращает «Имя - оклад ₽», и проверьте вывод в консоли.

Подсказка

Сигнатура: public override string ToString(). Затем достаточно Console.WriteLine(employee) - метод вызовется автоматически.

Решение учителя 
public override string ToString(){    return $"{Name} - {Salary} ₽";}
Задача 4. Найдите ошибку

Код не компилируется. Найдите две ошибки и исправьте.

class Person{    public string Name { get; set; }    public Person(string name)    {        Name = name;    }}class Student : Person{    public string Group { get; set; }}
Подсказка

У Person нет конструктора без параметров, а Student его не вызывает. Нужно добавить конструктор в наследника и вызвать base(name).

Решение учителя 
class Student : Person{    public string Group { get; set; }    public Student(string name, string group) : base(name)    {        Group = group;    }}

Что мы узнали и что дальше

Вы освоили первый принцип ООП после инкапсуляции. Теперь вы знаете:

  • Зачем нужно наследование и как проверить его уместность.
  • Как работают base() и protected.
  • Как переопределить ToString() и запретить наследование через sealed.
  • Почему композиция часто лучше наследования.
