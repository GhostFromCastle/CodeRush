Инкапсуляция

~35 минут Средний уровень Теория и Практика

В прошлом уроке мы научились создавать классы и объекты. У нашего студента появились поля Name, Age и Gpa, а также конструктор для их заполнения. Но мы оставили одну важную проблему.

Сейчас все поля нашего класса объявлены как public. Это значит, что любой код снаружи может их изменить. Случайно или намеренно.

Например, мы можем написать в Main вот такую строку:

alexey.Age = -100;

Программа скомпилируется и запустится. Но возраст в минус сто лет - это бессмыслица. В реальной жизни мы бы такого не допустили, но наш код позволяет это сделать.

Сегодня мы научимся защищать данные объекта от таких ошибок. Этот механизм называется инкапсуляцией.

Что такое инкапсуляция

Слово «инкапсуляция» происходит от латинского capsula - «коробочка». Смысл простой: мы прячем внутреннее устройство объекта и предоставляем безопасный интерфейс для работы с ним.

Представьте телевизор. Внутри него сотни микросхем, проводов и сложных механизмов. Но вам не нужно знать, как они устроены, чтобы посмотреть новости. Вы просто нажимаете кнопку на пульте. Кнопка - это и есть «безопасный интерфейс». А микросхемы - «внутреннее устройство», спрятанное от вас.

В программировании то же самое. Мы прячем поля объекта, чтобы никто не мог положить в них некорректные данные, а доступ предоставляем через специальные «кнопки» - свойства и методы.

Главная мысль

Инкапсуляция - это не просто «сделать поля приватными». Это принцип: никто снаружи не должен иметь возможности сломать объект. Все изменения проходят через контролируемые двери.

Модификаторы доступа

Чтобы прятать данные, в C# есть модификаторы доступа. Нам пока нужны только два:

  • public - «публичный». Доступен всем. Снаружи класса можно свободно читать и менять.
  • private - «приватный». Доступен только внутри этого класса. Снаружи даже не видно, что такое поле существует.

По умолчанию, если не писать ничего, в C# поля считаются приватными. Но лучше писать private явно - так код понятнее.

Давайте посмотрим, что будет, если сделать поле Age приватным:

class Student{    public string Name;    private int Age;    public double Gpa;}

Теперь если в Main написать alexey.Age = 20;, Visual Studio подчеркнет эту строку красным и скажет: «Age is inaccessible due to its protection level» (поле недоступно из-за уровня защиты).

Мы защитили поле. Но теперь мы не можем ни прочитать возраст, ни задать его. Получилась коробка без крышки и без дна. Как быть?

Свойства (Properties)

На помощь приходят свойства. Это специальный механизм C#, который позволяет безопасно читать и записывать приватные поля.

Свойство выглядит как поле, но внутри содержит логику. Вот как это делается:

class Student{    private int age;    public int Age    {        get { return age; }        set        {            if (value >= 0)            {                age = value;            }        }    }}

Давайте разберем эту конструкцию по частям:

  • private int age; - настоящее хранилище данных. Оно спрятано от всех.
  • public int Age - «дверь», через которую можно попасть к age.
  • get { return age; } - блок геттер. Срабатывает, когда мы читаем значение. Возвращает то, что лежит в приватном поле.
  • set { ... } - блок сеттер. Срабатывает, когда мы записываем значение.
  • value - ключевое слово. Это то значение, которое мы пытаемся присвоить.

Самое интересное здесь - это проверка if (value >= 0). Если кто-то попытается записать отрицательный возраст, сеттер просто проигнорирует это. Данные не изменятся, и объект останется в целости.

Аналогия с банкоматом

Свойство - это как банкомат. Вы не можете просто залезть в сейф банка и взять деньги. Вы вставляете карту, вводите пин-код, и банкомат (свойство set) проверяет, можно ли вам снять деньги. Если баланс отрицательный - операция не пройдет. Так и свойства защищают данные от некорректных операций.

Зачем это нужно

Может показаться, что мы просто усложняем код. Вместо одной строки объявления поля пишем десять. Но на самом деле это дает огромные преимущества:

  • Валидация данных. Мы можем проверять, что возраст не отрицательный, имя не пустое, а оценка не больше пяти.
  • Гибкость. Завтра мы решим, что при изменении возраста нужно записывать это в лог. Мы просто добавим строчку в сеттер, и ничего не сломается снаружи.
  • Безопасность. Мы контролируем, какие данные попадают в наш объект.

Автосвойства

Писать столько кода ради одного поля быстро надоедает. Если нам не нужна валидация, а нужно просто дать доступ к полю, в C# есть короткая форма записи:

public string Name { get; set; }

Эта строка означает: «Создай скрытое приватное поле и автоматически сделай для него геттер и сеттер». Мы не видим, как называется это скрытое поле, но можем читать и писать через свойство.

Это называется автосвойством. Оно используется в реальном коде в 90% случаев, когда сложная логика не нужна.

Если мы хотим, чтобы снаружи можно было только читать, но не записывать, мы оставляем только геттер: 

public string Name { get; }

Такое свойство можно заполнить только внутри конструктора. После создания объекта изменить имя нельзя. Это называется «свойство только для чтения» и отлично подходит для данных, которые не должны меняться (например, ID пользователя или дата создания).

Собираем всё вместе

Давайте перепишем нашего студента из прошлого урока, применяя инкапсуляцию:

class Student{    public string Name { get; set; }    private int age;    public int Age    {        get { return age; }        set        {            if (value >= 0)            {                age = value;            }        }    }    public double Gpa { get; set; }    public Student(string name, int age, double gpa)    {        Name = name;        Age = age;        Gpa = gpa;    }    public void Print()    {        Console.WriteLine($"{Name}, {Age} лет, средний балл {Gpa}");    }}

Теперь:

  • Name и Gpa - автосвойства. Снаружи выглядят как обычные поля, но на самом деле защищены.
  • Age - свойство с логикой. Не даст записать отрицательное число.

В конструкторе мы присваиваем Age = age;. Здесь срабатывает сеттер свойства Age. То есть при создании объекта тоже проходит проверка. Если передать в конструктор -5, возраст просто не запишется и останется 0.

Итоговая программа

Посмотрим, как это работает в деле:

static void Main(string[] args){    Student alexey = new Student("Алексей", 20, 4.5);    alexey.Print();    alexey.Age = 21;    alexey.Print();    alexey.Age = -100;    alexey.Print();}

Программа выведет:

Алексей, 20 лет, средний балл 4.5
Алексей, 21 лет, средний балл 4.5
Алексей, 21 лет, средний балл 4.5

В третьем случае мы попытались записать отрицательный возраст. Но свойство Age заблокировало это изменение. Значение осталось прежним (21), и программа продолжила работать корректно.

Шпаргалка

Самое важное в одном месте:

  • private доступно только внутри класса
  • public доступно всем
  • { get; set; } автосвойство для чтения и записи
  • { get; } свойство только для чтения
  • get { return x; } блок чтения
  • set { x = value; } блок записи
  • value входящее значение

Если что-то не работает

Свойства и инкапсуляция - место, где легко запутаться в мелочах. Проверьте по списку:

  • «The name 'age' does not exist». Вы случайно написали age с маленькой буквы в блоке Main. Помните: снаружи доступно только свойство Age (с большой буквы). Приватное поле age снаружи не видно.
  • «Property or indexer must have at least one accessor». У свойства нет ни get, ни set. Например, вы написали public int Age { }. Нужно добавить хотя бы один блок.
  • «Cannot assign to 'Name' because it is read-only». Вы пытаетесь изменить свойство, у которого есть только геттер (get;). Такие свойства можно заполнять только в конструкторе.
  • «Use of unassigned local variable». Если у вас есть свойство только для чтения ({ get; }) и вы не заполнили его в конструкторе, компилятор подскажет, что значение не задано.
  • Свойство не работает так, как вы ожидали. Помните, что внутри блока set вы работаете с ключевым словом value. Нельзя написать Age = Age; - получится рекурсия. Правильно: age = value;.

Если ничего не помогло - напишите нам в Telegram, поможем разобраться.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Переделайте Book

Возьмите класс Book из прошлого урока. Замените все три публичных поля на автосвойства ({ get; set; }). Проверьте, что код продолжает работать.

Подсказка

Вместо public string Title; напишите public string Title { get; set; }. Сделайте так для всех трёх полей. Остальной код (конструктор, метод Print, Main) менять не нужно.

Решение учителя 
class Book{    public string Title { get; set; }    public string Author { get; set; }    public int Year { get; set; }    public Book(string title, string author, int year)    {        Title = title;        Author = author;        Year = year;    }    public void Print()    {        Console.WriteLine($"{Author}, \"{Title}\" ({Year})");    }}

Для внешнего кода ничего не изменилось. Мы по-прежнему можем читать и записывать Title, Author и Year. Но теперь внутри класса у этих данных есть скрытая защита.

Задача 2. Валидация оценки

Создайте класс Review с полем Rating (оценка). Сделайте свойство так, чтобы оценка могла быть только от 1 до 5. Если передать число вне диапазона - оно не сохраняется (оценка остается прежней или 0).

Подсказка 1

Вам понадобится приватное поле private int rating; и публичное свойство Rating с полным блоком get и set. В set проверяйте условие value >= 1 && value <= 5.

Решение учителя 
class Review{    private int rating;    public int Rating    {        get { return rating; }        set        {            if (value >= 1 && value <= 5)            {                rating = value;            }        }    }}

Теперь review.Rating = 10; не сработает. Оценка не изменится.

Задача 3. Свойство только для чтения

Создайте класс User с полями Id и Name. Сделайте так, чтобы Id задавался только при создании объекта через конструктор и больше никогда не мог измениться. Name должен быть доступен для изменения.

Подсказка

Для Id используйте автосвойство с геттером: public int Id { get; }. Для Name - обычное автосвойство: public string Name { get; set; }. Не забудьте задать Id в конструкторе.

Решение учителя 
class User{    public int Id { get; }    public string Name { get; set; }    public User(int id, string name)    {        Id = id;        Name = name;    }}

Теперь user.Id = 10; вызовет ошибку компиляции. А user.Name = "Новое имя"; сработает без проблем.

Задача 4. Банковский счёт

Создайте класс BankAccount с приватным полем balance (баланс). Сделайте свойство Balance доступным только для чтения (без сеттера). Добавьте методы Deposit(amount) (пополнить) и Withdraw(amount) (снять). Снятие не должно проходить, если на счёте недостаточно денег.

Подсказка 1

Поле balance сделайте приватным. Свойство: public double Balance { get { return balance; } } - без сеттера. В методах Deposit и Withdraw меняйте значение balance.

Подсказка 2

В методе Withdraw сначала проверьте условие if (amount <= balance). Если денег хватает - вычитайте, иначе выведите сообщение об ошибке.

Решение учителя 
class BankAccount{    private double balance;    public double Balance    {        get { return balance; }    }    public void Deposit(double amount)    {        if (amount > 0)        {            balance += amount;        }    }    public void Withdraw(double amount)    {        if (amount > 0 && amount <= balance)        {            balance -= amount;        }        else        {            Console.WriteLine("Недостаточно средств");        }    }}

Снаружи нельзя напрямую изменить balance. Можно только прочитать его через свойство Balance. А все изменения происходят через методы, которые контролируют логику.

Что мы узнали и что дальше

Сегодня мы освоили инкапсуляцию - один из трех главных принципов ООП. Научились прятать поля с помощью private и открывать к ним безопасный доступ через public-свойства с блоками get и set. Узнали, как валидировать данные прямо в момент записи и как делать свойства, доступные только для чтения.

Теперь наши объекты не просто хранят данные, они защищают их от некорректных изменений. Код стал надежнее и безопаснее.

В следующем уроке мы разберемся с исключениями. Это механизм, который позволяет программе не «падать» с красной ошибкой при встрече с чем-то неожиданным (например, когда пользователь ввел текст вместо числа), а красиво обрабатывать такие ситуации и продолжать работу.
