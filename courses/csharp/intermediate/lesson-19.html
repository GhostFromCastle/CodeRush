Интерфейсы

~35 минут Средний уровень Теория и Практика

Наследование отвечает на вопрос «кем является объект». Интерфейс отвечает на другой вопрос: «что объект умеет». И это оказывается гораздо гибче.

В этом уроке мы:

  • Разберемся, зачем нужны интерфейсы.
  • Научимся объявлять и реализовывать их.
  • Поймем, как класс может реализовать несколько интерфейсов.
  • Познакомимся с IComparable и IDisposable.
Аналогия

Розетка: неважно, что включено - чайник или зарядка, важен стандарт вилки. Интерфейс - это стандарт розетки.

Контракт без реализации

interface IShape{    double Area();    double Perimeter();}

Интерфейс описывает, что должен уметь класс, но не говорит, как. Никаких полей и готового кода - только сигнатуры. Класс принимает на себя обязательство:

class Circle : IShape{    public double Radius { get; set; }    public double Area() => Math.PI * Radius * Radius;    public double Perimeter() => 2 * Math.PI * Radius;}

Если класс объявил интерфейс, но не реализовал хотя бы один метод, код не скомпилируется. Это и есть главная ценность: контракт нельзя забыть выполнить.

Почему I в начале

Соглашение C#: имена интерфейсов начинаются с I. IShape, IDisposable, IComparable. Так сразу видно, что перед вами контракт, а не класс.

Несколько интерфейсов

В отличие от класса, интерфейсов можно реализовать сколько угодно:

interface IPrintable{    void Print();}interface IExportable{    string ToCsv();}class Report : IPrintable, IExportable{    public string Title { get; set; }    public void Print() => Console.WriteLine(Title);    public string ToCsv() => $"\"{Title}\"";}

Именно поэтому интерфейсы называют «множественным наследованием поведения»: класс может быть и печатаемым, и экспортируемым, и сравнимым одновременно.

Полиморфизм через интерфейс

var printables = new List<IPrintable>{    new Report { Title = "Отчёт за март" },    new Invoice { Number = "A-42" }};foreach (var item in printables){    item.Print();}

Report и Invoice могут быть совсем из разных иерархий, но оба умеют печататься. Код цикла ничего не знает об их устройстве.

Явная реализация

Если метод нужен только через интерфейс, его можно реализовать явно:

class Report : IPrintable{    void IPrintable.Print()    {        Console.WriteLine("Печать отчёта");    }}

Теперь report.Print() не скомпилируется - метод доступен только через ссылку типа IPrintable. Полезно, когда класс реализует два интерфейса с одинаковым именем метода и нужно разное поведение.

Стандартные интерфейсы

Платформа .NET построена на интерфейсах. Три самых частых:

IComparable

class Product : IComparable<Product>{    public string Title { get; set; }    public decimal Price { get; set; }    public int CompareTo(Product other)    {        return Price.CompareTo(other.Price);    }}var products = new List<Product>{    new Product { Title = "Ноутбук", Price = 75000 },    new Product { Title = "Мышь", Price = 1500 }};products.Sort();

После реализации CompareTo список сортируется сам - без отдельной функции сравнения.

IDisposable

class FileLogger : IDisposable{    private readonly StreamWriter _writer;    public FileLogger(string path)    {        _writer = new StreamWriter(path, append: true);    }    public void Log(string message) => _writer.WriteLine(message);    public void Dispose()    {        _writer.Dispose();    }}

Класс с IDisposable можно использовать в using, и ресурсы закроются автоматически даже при исключении:

using (var logger = new FileLogger("log.txt")){    logger.Log("Программа запущена");}

Интерфейсы в LINQ

IEnumerable<T> и IList<T> позволяют принимать в методы любые коллекции, а не конкретный List:

static int CountEven(IEnumerable<int> numbers){    int count = 0;    foreach (var n in numbers)    {        if (n % 2 == 0) count++;    }    return count;}

Такой метод примет массив, список, результат LINQ-запроса - что угодно, по чему можно пройти циклом.

Интерфейс или абстрактный класс

ИнтерфейсАбстрактный класс
Сколько можноМногоТолько один родитель
Код внутриОбычно нетДа, общая логика
ПоляНетДа
Смысл«Умеет»«Является»

Практическое правило: если нужен контракт для разных классов - берите интерфейс. Если нужна общая реализация для родственных классов - абстрактный класс. Часто используют оба: абстрактный класс реализует интерфейс и дает базу наследникам.

Шпаргалка

  • interface IShape объявить контракт
  • : IShape реализовать
  • A, B несколько интерфейсов
  • IComparable сравнение и сортировка
  • IDisposable освобождение ресурсов

Если что-то не работает

  • «Does not implement interface member». Не реализован один из методов контракта.
  • Метод не виден снаружи. Реализован явно (void IPrintable.Print()) - вызывать нужно через интерфейс.
  • Нельзя создать экземпляр интерфейса. new IShape() невозможно: интерфейс не содержит реализации.
  • «Cannot convert type». Класс не реализует интерфейс. Проверьте объявление.
  • Сортировка не работает. CompareTo возвращает 0 всегда или сравнивает не те поля.

Практика

Задача 1. Фигуры через интерфейс

Опишите интерфейс IShape с методами Area() и Perimeter(). Реализуйте его в Circle и Rectangle и посчитайте общую площадь.

Подсказка

Список List<IShape>, цикл, накопление суммы. Каждый класс реализует оба метода.

Решение учителя 
interface IShape{    double Area();    double Perimeter();}class Circle : IShape{    public double Radius { get; set; }    public double Area() => Math.PI * Radius * Radius;    public double Perimeter() => 2 * Math.PI * Radius;}class Rectangle : IShape{    public double Width { get; set; }    public double Height { get; set; }    public double Area() => Width * Height;    public double Perimeter() => 2 * (Width + Height);}
Задача 2. Сортируемый товар

Реализуйте IComparable<Product> так, чтобы товары сортировались по цене, а при равной цене - по названию.

Подсказка

Сначала сравните цены. Если результат 0 - верните string.Compare(Title, other.Title).

Решение учителя 
public int CompareTo(Product other){    int byPrice = Price.CompareTo(other.Price);    if (byPrice != 0) return byPrice;    return string.Compare(Title, other.Title, StringComparison.Ordinal);}
Задача 3. Два интерфейса

Создайте IPrintable и ISaveable. Класс Document реализует оба: печатает заголовок и сохраняет его в псевдо-файл (вывод в консоль).

Подсказка

Объявление: class Document : IPrintable, ISaveable. Затем реализуйте оба метода.

Решение учителя 
interface IPrintable { void Print(); }interface ISaveable { void Save(); }class Document : IPrintable, ISaveable{    public string Title { get; set; }    public void Print() => Console.WriteLine($"Печать: {Title}");    public void Save()  => Console.WriteLine($"Сохранено: {Title}");}
Задача 4. Найдите ошибку

Почему этот код не компилируется?

interface IShape{    double Area();}class Square : IShape{    public double Side { get; set; }    public double GetArea() => Side * Side;}
Подсказка

Имя метода не совпадает с контрактом: нужен Area(), а не GetArea().

Решение учителя 
class Square : IShape{    public double Side { get; set; }    public double Area() => Side * Side;}

Что мы узнали и что дальше

Интерфейсы дали коду гибкость. Теперь вы знаете:

  • Как объявить контракт и что будет, если его не выполнить.
  • Как реализовать несколько интерфейсов одним классом.
  • Зачем нужны IComparable, IDisposable и IEnumerable<T>.
  • Чем интерфейс отличается от абстрактного класса.

Остался последний элемент ООП-конструктора - абстрактные классы. Они занимают промежуточное место: это уже класс, но создать его экземпляр нельзя.
