Методы с возвратом

~30 минут Средний уровень Теория и Практика

Добро пожаловать во второй урок среднего уровня! В прошлом уроке мы познакомились с методами: научились писать void-методы, которые просто что-то делают, и методы с возвратом, которые отдают результат через return. Это была база. Сегодня мы углубимся именно в возврат значений - разберём несколько приёмов, без которых невозможно представить настоящий код.

Если урок 13 был про то, "как вообще объявлять методы", то этот - про то, "как делать это красиво и по-взрослому". Поехали.

Быстрое напоминание

Давайте на одну минуту вспомним, что было в прошлом уроке. Метод - это как кнопка на пульте от телевизора. Мы один раз описываем действие, даём ему имя, а потом вызываем по имени, когда нужно. Нам не важно, как он устроен внутри, - важно, что он делает.

Методы бывают двух видов:

  • void - просто выполняют действие, ничего не отдают.
  • С типом (int, string, bool и так далее) - возвращают значение через команду return.

Пример метода, который складывает два числа и отдаёт результат:

static int Sum(int a, int b){    return a + b;}

А вот как им пользуются:

int result = Sum(3, 4);Console.WriteLine(result);

Метод вернул число 7, и мы положили его в переменную result. Как будто в том месте, где стоит Sum(3, 4), после выполнения появляется число 7, и дальше код работает с ним как с обычным числом.

Всё это мы уже знаем. Но есть несколько приёмов, которые делают работу с return ещё удобнее. О них и поговорим сегодня.

return может сработать раньше, чем вы думаете

В прошлом уроке мы часто писали так: сначала что-то посчитать, а в самом конце вернуть. Но return - это не просто "последняя строчка метода". Это команда, которая означает: выйди из метода прямо сейчас и вот тебе значение.

Давайте посмотрим на такой метод:

static int Check(int x){    if (x < 0)    {        return 0;    }    return x * 2;}

Что здесь происходит? Если x отрицательный - метод на первой же строчке return отдаёт 0 и тут же заканчивается. До второй строчки дело не дойдёт. Если x положительный - первая проверка не сработала, и метод спокойно доходит до return x * 2.

У метода целых два return, но выполнится только один. Как только сработал один - метод закрылся, второй уже не проверяется.

Как это запомнить

Представьте, что вы идёте по коридору, а на каждой двери написано "выход". Как только вы открыли одну и вышли - вы уже снаружи, и остальные двери вам не важны. Так же работает return: первый сработавший завершает метод, и до остальных дело не доходит.

Сторожевые проверки

Раз мы теперь знаем, что return может сработать где угодно, давайте разберём очень полезный приём. Он называется "guard clauses", что по-русски значит "сторожевые проверки".

Идея такая: в самом начале метода мы проверяем, можно ли вообще продолжать. Если нельзя - сразу возвращаем что-то и выходим. А если можно - спокойно работаем дальше, уже не отвлекаясь на плохие случаи.

Вот пример:

static double Divide(double a, double b){    if (b == 0)    {        return 0;    }    return a / b;}

Сначала проверяем: не делим ли мы на ноль? Если делим - отдаём 0 и выходим. Если всё в порядке - считаем по-настоящему.

Зачем так писать? Ведь можно было бы сделать через обычный if / else:

static double Divide(double a, double b){    if (b == 0)    {        return 0;    }    else    {        return a / b;    }}

Оба варианта работают одинаково. Но первый читается легче. Мы сначала "отсекаем" плохой случай, а потом работаем с хорошим. И не надо задумываться, что код находится внутри else.

Когда таких проверок в методе много, разница становится огромной. Сравните два варианта:

static string Describe(int age){    if (age < 0)    {        return "Неверный возраст";    }    if (age < 3)    {        return "Малыш";    }    if (age < 18)    {        return "Школьник";    }    return "Взрослый";}

Каждая проверка отсекает свой случай. Если дошли до конца - значит, человек взрослый. Никаких вложенных условий, никаких лишних отступов. Читается как список правил сверху вниз.

Аналогия

Представьте охранника на входе в клуб. Он смотрит на вас и говорит: "Тебе меньше 18? Тогда не заходи". Если вы подходите - охранник отступает, и вы идёте дальше. Он не загораживает проход всем подряд, он просто отсекает тех, кому нельзя. Сторожевые проверки работают так же.

Методы, которые отвечают "да" или "нет"

Самый частый тип возврата после чисел - это bool. Такой метод возвращает true или false. Это как ответ на вопрос.

Такие методы особенно удобно вставлять прямо в условия if. Посмотрите:

static bool IsEven(int number){    return number % 2 == 0;}

Этот метод отвечает на вопрос: "число чётное?" Если да - вернёт true. Если нет - false.

Теперь можно писать вот так:

if (IsEven(10)){    Console.WriteLine("Число чётное");}

Читается как обычная фраза: "если IsEven от 10 - то...". Гораздо понятнее, чем писать в лоб if (10 % 2 == 0). Согласитесь, первое звучит по-человечески.

Такие методы-вопросы встречаются в реальном коде постоянно. Названия у них обычно начинаются на Is, Has или Can. Вот ещё примеры:

static bool IsAdult(int age){    return age >= 18;}static bool IsEmpty(string text){    return text.Length == 0;}static bool HasDigit(string text){    for (int i = 0; i < text.Length; i++)    {        if (char.IsDigit(text[i]))        {            return true;        }    }    return false;}

В последнем примере метод HasDigit проходит по всей строке. Если найдёт хоть одну цифру - сразу вернёт true и завершится. Если пройдёт всю строку и не найдёт - вернёт false. Это классический приём: "нашли - сразу выходим".

Возвращаем что угодно

Возвращать можно не только числа и bool. Можно возвращать строки, массивы, списки - всё, что угодно. Главное правило: тип возврата в объявлении метода должен совпадать с тем, что отдаётся через return.

Возвращаем строку:

static string GetGreeting(string name){    return $"Привет, {name}!";}string hello = GetGreeting("Алексей");Console.WriteLine(hello);

Возвращаем массив:

static int[] GetNumbers(){    return new int[] { 1, 2, 3, 4, 5 };}

Возвращаем список:

static List<string> GetShoppingList(){    return new List<string> { "Хлеб", "Молоко", "Сыр" };}

Возвращать можно всё, что может храниться в переменной. Если вы можете написать int[] arr = ..., то и метод может вернуть int[]. Если можете написать List<string> list = ... - метод может вернуть List<string>.

Параметры со значением по умолчанию

А теперь интересная возможность C#. Оказывается, у параметров метода могут быть значения по умолчанию. Тогда при вызове их можно не указывать - C# подставит то, что вы задали в объявлении.

Вот пример:

static void Greet(string name, string greeting = "Привет"){    Console.WriteLine($"{greeting}, {name}!");}

Здесь у параметра greeting стоит = "Привет". Это и есть значение по умолчанию. Теперь метод можно вызывать двумя способами:

Greet("Алексей");Greet("Алексей", "Здравствуй");

Первый вызов даст "Привет, Алексей!". Второй - "Здравствуй, Алексей!". Если мы не указываем второе значение - C# сам подставит "Привет".

Аналогия

Представьте, что вы заказываете пиццу. По умолчанию вам принесут среднюю с сыром. Но вы можете сказать: "Большую!" - и размер поменяется. Или промолчать - и получите стандартную. Значения по умолчанию работают так же: если не сказали - берётся то, что заранее договорились.

Важное правило: параметры со значением по умолчанию должны идти после обычных параметров. Нельзя сначала сделать необязательный, а потом обязательный - C# запутается. Вот так неправильно:

static void Greet(string greeting = "Привет", string name)

Компилятор подчеркнёт это красным и скажет: "Optional parameters must appear after all required parameters". Просто помните: обязательные - сначала, необязательные - в конце.

Именованные аргументы

Ещё одна маленькая полезность, которая часто идёт рука об руку со значениями по умолчанию. Обычно мы передаём аргументы в том порядке, в котором они идут в объявлении. Но их можно передавать по имени.

Greet(greeting: "Здравствуй", name: "Алексей");

Результат тот же, что и при обычном вызове. Но теперь порядок неважен - мы явно говорим, что есть что. Это удобно, когда параметров много и легко запутаться, какой за что отвечает.

Особенно полезно это в связке со значениями по умолчанию. Можно пропустить необязательный параметр в середине:

static void Describe(string name, int age = 0, string city = "неизвестно"){    Console.WriteLine($"{name}, {age} лет, из {city}");}Describe("Алексей", city: "Москва");

Мы не указали возраст, но указали город. Без именованных аргументов так бы не получилось - пришлось бы писать Describe("Алексей", 0, "Москва"), хотя возраст нам неважен.

Короткая запись методов

А теперь про синтаксический сахар. Если метод состоит из одной команды return, его можно записать короче. Вместо фигурных скобок пишем стрелочку =>.

Было:

static int Sum(int a, int b){    return a + b;}

Стало:

static int Sum(int a, int b) => a + b;

Смысл абсолютно тот же, но кода меньше. Это называется "метод-выражение" (по-английски expression-bodied method).

То же самое работает и для void-методов, если у них одно действие:

static void SayHello() => Console.WriteLine("Привет!");

Такой стиль в C# встречается очень часто. Поначалу может казаться непривычным, но постепенно вы привыкнете. Многие короткие методы в реальных проектах пишут именно так.

Когда использовать

Стрелочную запись удобно применять для методов, которые умещаются в одну строку. Как только в методе становится больше одной команды, возвращайтесь к обычным фигурным скобкам - так код читается легче.

Шпаргалка

Самое важное в одном месте:

  • static int Name(...) метод с возвратом
  • return value; вернуть значение и выйти
  • return true; метод-вопрос
  • if (bad) return 0; сторожевая проверка
  • param = value значение по умолчанию
  • Name(param: value) именованный аргумент
  • => expression короткая запись метода

Если что-то не работает

Методы с возвратом - место, где ошибки бывают особенно частыми. Проверьте по списку:

  • "Not all code paths return a value". Не все ветки метода возвращают значение. Например, у вас есть if без else, и return стоит только внутри if. Компилятор не знает, что делать, если условие ложно. Добавьте return в конце метода.
  • "Cannot implicitly convert type 'X' to 'Y'". Тип возвращаемого значения не совпадает с тем, что вы вернули. Например, метод объявлен как int, а вы пытаетесь вернуть строку. Проверьте, что в объявлении стоит тот же тип, что и после return.
  • "Use of unassigned local variable". Переменная создана, но не заполнена значением. Убедитесь, что перед использованием вы присвоили ей что-то.
  • "No overload for method takes N arguments". Вы вызвали метод с неправильным числом аргументов. Проверьте объявление метода и количество значений в вызове.
  • "Named argument specifications must appear after all fixed arguments". Именованные аргументы должны идти после обычных. Если пишете Greet(name: "Алексей", "Привет") - C# не поймёт, какой из них какой.
  • "Optional parameters must appear after all required parameters". Параметры со значением по умолчанию должны идти в самом конце. Нельзя сначала сделать необязательный, потом обязательный.
  • Метод возвращает не то, что ожидали. Проверьте, какой именно return сработал. Помните: первый сработавший завершает метод, до остальных дело не доходит. Если у вас несколько return - убедитесь, что логика условий правильная.
  • Стрелочная запись не компилируется. Проверьте, что после => идёт выражение, которое действительно возвращает нужный тип. Если у вас больше одной команды - используйте обычные фигурные скобки.

Если ничего не помогло - напишите нам в Telegram, поможем разобраться.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя. Сначала обязательно попробуйте сами.

Задача 1. Проверка на чётность

Напишите метод IsEven, который принимает число и возвращает true, если оно чётное, и false - если нет. Проверьте его на нескольких числах.

Подсказка

Тип возврата - bool. Внутри метода одна строка: return number % 2 == 0;. Обратите внимание: здесь нет if - сравнение само по себе даёт true или false, и его можно сразу вернуть.

Решение учителя 
static bool IsEven(int number){    return number % 2 == 0;}static void Main(string[] args){    Console.WriteLine(IsEven(4));    Console.WriteLine(IsEven(7));    Console.WriteLine(IsEven(0));}

Программа выведет True, False, True. Кстати, ноль - чётное число, поэтому IsEven(0) возвращает true. Это правило математики: ноль делится на два без остатка.

Задача 2. Максимум из массива

Напишите метод FindMax, который принимает массив чисел и возвращает наибольшее значение. Используйте приём "взять первый элемент как стартовый максимум" из урока про массивы.

Подсказка 1

Тип возврата - int, параметр - int[] numbers. Создайте переменную max и положите туда numbers[0]. Потом цикл for от 1 до конца массива. Внутри - if, который обновляет max. В конце - return max;.

Подсказка 2

Почему цикл начинается с 1, а не с 0? Потому что нулевой элемент мы уже взяли как стартовый максимум. Сравнивать его с самим собой нет смысла.

Решение учителя 
static int FindMax(int[] numbers){    int max = numbers[0];    for (int i = 1; i < numbers.Length; i++)    {        if (numbers[i] > max)        {            max = numbers[i];        }    }    return max;}static void Main(string[] args){    int[] data = { 15, 42, 8, 99, 23 };    Console.WriteLine(FindMax(data));}

Программа выведет 99. Обратите внимание: метод принимает массив, а возвращает одно число. Это очень частый сценарий - "получить коллекцию, вернуть её характеристику".

Задача 3. Опиши число

Напишите метод DescribeNumber, который принимает число и возвращает строку: "положительное", "отрицательное" или "ноль". Используйте сторожевые проверки - каждая проверка отсекает свой случай.

Подсказка 1

Тип возврата - string, параметр - int number. Используйте три отдельных if, каждый со своим return. Никаких else не нужно - как только сработает один return, метод завершится.

Подсказка 2

Порядок проверок важен. Сначала проверьте ноль - это отдельный случай. Потом больше нуля. Потом меньше нуля. Каждый раз возвращайте нужную строку сразу.

Решение учителя 
static string DescribeNumber(int number){    if (number == 0)    {        return "ноль";    }    if (number > 0)    {        return "положительное";    }    return "отрицательное";}

В последней строке нет if - если дошли до неё, значит, число не ноль и не больше нуля. Остаётся только один вариант - отрицательное. C# сам понимает, что других вариантов нет, и не требует проверки.

Задача 4. Приветствие с настройками

Напишите метод MakeGreeting, который принимает имя, приветствие (по умолчанию "Привет") и восклицательный знак (по умолчанию true). Метод возвращает готовую строку. Вызовите его несколькими способами - с разными наборами аргументов.

Подсказка 1

Тип возврата - string. Три параметра: string name, string greeting = "Привет", bool exclamation = true. Внутри метода - тернарный оператор из урока 12: если exclamation равно true - добавить "!", иначе - ничего.

Подсказка 2

Можно записать так: string sign = exclamation ? "!" : ""; - а потом вставить sign в общую строку через интерполяцию. Или сразу внутри интерполяции использовать тернарник.

Решение учителя 
static string MakeGreeting(string name, string greeting = "Привет", bool exclamation = true){    string sign = exclamation ? "!" : "";    return $"{greeting}, {name}{sign}";}static void Main(string[] args){    Console.WriteLine(MakeGreeting("Алексей"));    Console.WriteLine(MakeGreeting("Мария", "Здравствуй"));    Console.WriteLine(MakeGreeting("Иван", exclamation: false));    Console.WriteLine(MakeGreeting("Ольга", "Добрый день", false));}

Программа выведет:

Привет, Алексей!
Здравствуй, Мария!
Привет, Иван
Добрый день, Ольга

Обратите внимание на третий вызов: мы передали имя и сразу указали exclamation: false, пропустив greeting. Это работает именно благодаря именованным аргументам - без них пришлось бы писать MakeGreeting("Иван", "Привет", false).

Что мы узнали и что дальше

Сегодня мы углубились в методы с возвратом значений. Разобрали несколько важных приёмов: как использовать несколько return в одном методе, как писать сторожевые проверки в начале метода, как делать методы-вопросы с bool, как возвращать строки и коллекции. Плюс познакомились со значениями по умолчанию, именованными аргументами и короткой стрелочной записью методов.

Теперь у вас есть не просто "умение писать методы", а целый инструментарий. Вы можете делать код чистым, коротким и понятным - и именно это отличает программиста, который пишет "чтобы работало", от программиста, который пишет "чтобы читалось".

В следующем уроке нас ждёт большой шаг - классы и объекты. До этого мы пользовались только готовыми типами: int, string, List. А теперь научимся создавать свои собственные типы данных. Это начало объектно-ориентированного программирования, и это одна из самых интересных тем в C#.
