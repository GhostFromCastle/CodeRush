Абстрактные классы

~35 минут Средний уровень Теория и Практика

Мы уже видели abstract в примерах прошлых уроков. Пора разобраться, что это такое, зачем нужен абстрактный метод и когда выбирать абстрактный класс вместо интерфейса.

В этом уроке мы:

  • Поймем, почему нельзя создать экземпляр абстрактного класса.
  • Разберем абстрактные и виртуальные методы.
  • Освоим шаблонный метод.
  • Научимся выбирать между абстрактным классом и интерфейсом.
Аналогия

Инструкция «приготовить кофе»: шаги общие, но сорт и способ выбирает конкретная кофемашина. Абстрактный класс задаёт шаги, наследник - рецепт.

Недостающий объект

Слово «фигура» - это общее понятие. Можно нарисовать круг, квадрат, треугольник, но нельзя нарисовать «просто фигуру». В коде это выражается абстрактным классом:

abstract class Shape{    public string Color { get; set; }    public abstract double Area();}

Две вещи делают класс абстрактным: ключевое слово abstract и хотя бы один абстрактный метод. Такой класс нельзя создать напрямую:

var shape = new Shape(); // ошибка компиляции

Зато можно создать наследника, который реализует Area():

class Circle : Shape{    public double Radius { get; set; }    public override double Area() => Math.PI * Radius * Radius;}Shape shape = new Circle { Radius = 2, Color = "red" };

Абстрактный метод

У абстрактного метода нет тела - только сигнатура и точка с запятой:

public abstract double Area();

Это обязательство: каждый наследник должен реализовать метод через override. Если наследник тоже абстрактный, он может переложить обязанность дальше.

abstract несовместим с private

Абстрактный метод должен быть переопределен, поэтому он не может быть private. Обычно его делают public или protected.

virtual - «можешь переопределить, но есть поведение по умолчанию». abstract - «обязан реализовать, общего поведения нет».

Шаблонный метод

Абстрактный класс может содержать готовый алгоритм, который использует абстрактные шаги. Наследники заполняют только отличия:

abstract class ReportGenerator{    public void Generate()    {        Prepare();        var data = LoadData();        var formatted = Format(data);        Save(formatted);    }    protected virtual void Prepare()    {        Console.WriteLine("Подготовка...");    }    protected abstract string LoadData();    protected abstract string Format(string data);    protected abstract void Save(string content);}

Наследник не может случайно нарушить порядок шагов - он задает только их реализацию:

class CsvReport : ReportGenerator{    protected override string LoadData() => "1,2,3";    protected override string Format(string data) => data.Replace(",", ";");    protected override void Save(string content) => Console.WriteLine($"CSV: {content}");}

Это называется шаблонным методом: каркас алгоритма в базовом классе, детали - в наследниках. Так устроены многие классы в .NET.

Абстрактный класс или интерфейс

Оба задают контракт. Выбор зависит от того, что вы хотите передать наследникам:

  • Есть общее состояние и код - абстрактный класс. Например, у всех сотрудников есть имя и метод PrintBadge(), а расчет зарплаты отличается.
  • Нужно только «умеет», без общей реализации - интерфейс. IDisposable, IComparable.
  • Нужно и то, и другое - абстрактный класс реализует интерфейс, а наследники получают и контракт, и базу.
interface IPayable{    decimal CalculatePay();}abstract class Employee : IPayable{    public string Name { get; set; }    public abstract decimal CalculatePay();    public void PrintPayslip()    {        Console.WriteLine($"{Name}: {CalculatePay():F2} ₽");    }}

Здесь IPayable позволяет работать с любым плательщиком, а Employee добавляет общее имя и готовую печать квитанции.

Когда абстрактный класс неуместен

Не стоит делать класс абстрактным «на всякий случай». Это усложняет тестирование и мешает создавать заглушки. Если у класса есть полноценное поведение по умолчанию и нет обязательных к реализации частей - оставьте его обычным.

Также помните: у класса только один родитель. Если абстракция нужна разным, не связанным между собой классам, - интерфейс подходит лучше.

Шпаргалка

  • abstract class нельзя создать объект
  • abstract method обязателен к реализации
  • override реализация в наследнике
  • protected abstract шаг алгоритма для наследников
  • virtual необязательное переопределение

Если что-то не работает

  • «Cannot create an instance of the abstract class». Создавайте наследника, а не базовый класс.
  • «Does not implement inherited abstract member». Наследник не реализовал абстрактный метод.
  • «Cannot declare instance members in an interface». Поля допустимы только в классах, не в интерфейсах.
  • Наследник не компилируется из-за new. Абстрактный метод переопределяют через override.
  • Слишком много абстракции. Если проще передать данные в функцию - не создавайте иерархию ради иерархии.

Практика

Задача 1. Фигуры

Создайте абстрактный класс Shape с абстрактным Area() и виртуальным Describe(). Реализуйте Circle, Rectangle и Triangle.

Подсказка

Describe() в базовом классе выводит площадь, наследники могут переопределить его, добавив свои детали.

Решение учителя 
abstract class Shape{    public abstract double Area();    public virtual void Describe()    {        Console.WriteLine($"Площадь: {Area():F2}");    }}class Circle : Shape{    public double Radius { get; set; }    public override double Area() => Math.PI * Radius * Radius;}class Rectangle : Shape{    public double Width { get; set; }    public double Height { get; set; }    public override double Area() => Width * Height;}
Задача 2. Шаблонный метод

Реализуйте абстрактный Exporter с методом Export(), который вызывает Open(), Write(string) и Close(). Наследники: ConsoleExporter и FileExporter.

Подсказка

Export() - обычный метод с фиксированным порядком вызовов, три шага - абстрактные.

Решение учителя 
abstract class Exporter{    public void Export()    {        Open();        Write("данные");        Close();    }    protected abstract void Open();    protected abstract void Write(string content);    protected abstract void Close();}class ConsoleExporter : Exporter{    protected override void Open() => Console.WriteLine("--- начало ---");    protected override void Write(string content) => Console.WriteLine(content);    protected override void Close() => Console.WriteLine("--- конец ---");}
Задача 3. Сотрудники

Сделайте абстрактный Employee, реализующий IPayable, с готовым методом PrintPayslip(). Наследники считают зарплату по-разному.

Подсказка

PrintPayslip вызывает CalculatePay() - сам он абстрактный, поэтому вызовется версия наследника.

Решение учителя 
abstract class Employee : IPayable{    public string Name { get; set; }    public abstract decimal CalculatePay();    public void PrintPayslip()    {        Console.WriteLine($"{Name}: {CalculatePay():F2} ₽");    }}
Задача 4. Выберите инструмент

Для трех случаев выберите интерфейс или абстрактный класс: (а) разные классы умеют сохраняться в файл; (б) у всех сотрудников есть имя и общий метод печати пропуска; (в) нужно и то, и другое.

Подсказка

Смотрите, есть ли общее состояние и готовая логика. Если нет - интерфейс.

Решение учителя

(а) интерфейс ISaveable; (б) абстрактный класс Employee; (в) абстрактный класс, реализующий интерфейс - Employee : IPayable.
