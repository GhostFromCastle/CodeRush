Списки и словари

~35 минут Начальный уровень Теория и Практика

В прошлом уроке мы познакомились с массивами - и это был большой шаг. Массив позволяет хранить много однотипных данных в одной переменной. Но у него есть один серьёзный недостаток, который вы, наверное, уже заметили: размер массива нельзя изменить.

Создали массив на 5 элементов - значит, там всегда будет ровно 5 ячеек. Добавить шестую нельзя. Если нужно больше - придётся создавать новый массив, копировать туда старые значения и выбрасывать старый. Согласитесь, это неудобно.

В реальных программах данные почти всегда приходят «порциями»: пользователь добавляет товары в корзину, бот получает сообщения, программа читает строки из файла. Заранее неизвестно, сколько их будет. Поэтому в C# есть списки и словари - две самые используемые коллекции. Сегодня мы с ними и познакомимся.

List - «резиновый массив»

List (читается «лист», от английского «список») - это как массив, только гибкий. Его размер может меняться: добавляйте элементы - список растёт, удаляйте - сжимается. Идеально для случаев, когда количество данных заранее неизвестно.

Чтобы использовать List, нужна одна подготовительная строка - подключить специальное пространство имён. Помните using System; в самом начале файла? Так вот, для списков нужно добавить ещё одно:

using System.Collections.Generic;

Скорее всего, Visual Studio уже добавила её за вас. Если нет - допишите в самый верх файла, рядом с другими using. Без неё компилятор не поймёт, что такое List.

Создание списка

Синтаксис создания списка похож на массив, но с угловыми скобками:

List<int> numbers = new List<int>();

Разберём:

  • List<int> - тип «список целых чисел». В угловых скобках указывается тип элементов.
  • numbers - имя переменной.
  • new List<int>() - команда «создай новый пустой список целых чисел».

После этой строки у нас пустой список. Внутри него пока ноль элементов. И в отличие от массива, мы можем сразу начинать добавлять.

А с var короче

Так как тип очевиден из правой части, можно записать через var: var numbers = new List<int>();. Так делают почти все - код получается чище. Мы тоже будем использовать этот стиль дальше.

Добавляем элементы: .Add()

У списка есть метод .Add() - «добавить». Передаёте ему значение, и оно встаёт в конец списка:

var numbers = new List<int>();numbers.Add(10);numbers.Add(20);numbers.Add(30);

Теперь внутри numbers три числа: 10, 20 и 30. Каждый вызов Add добавляет новый элемент в конец. Список автоматически растёт - нам не нужно заранее знать, сколько элементов будет.

Можно добавить сразу несколько значений - либо в цикле, либо через другую форму инициализации:

var numbers = new List<int> { 10, 20, 30, 40, 50 };

Фигурные скобки работают так же, как у массивов - список сразу заполняется значениями. Тип справа (new List<int>) определяет, что внутри будут целые числа.

Сколько элементов? .Count

У массива была .Length, у списка - .Count («количество»). Смысл тот же, но название другое:

var numbers = new List<int> { 10, 20, 30 };Console.WriteLine(numbers.Count);

Программа выведет 3. Да, это одна из мелочей, к которой надо привыкнуть: у массива .Length, у списка .Count. Оба показывают «сколько элементов внутри», но называются по-разному.

Обращение по индексу

Список тоже работает с индексами, как массив. Нумерация с нуля:

var fruits = new List<string> { "Яблоко", "Банан", "Апельсин" };Console.WriteLine(fruits[0]);Console.WriteLine(fruits[2]);fruits[1] = "Груша";

В первых двух строках мы выводим первый и третий элементы. В третьей - заменяем «Банан» на «Грушу». Всё работает точно так же, как с массивом. Просто у списка возможностей больше.

Удаление элементов: .Remove() и .RemoveAt()

Здесь начинается настоящее преимущество списка перед массивом. Удалить элемент можно двумя способами:

var fruits = new List<string> { "Яблоко", "Банан", "Апельсин" };fruits.Remove("Банан");fruits.RemoveAt(0);

После этих строк в списке остался только «Апельсин».

.Remove(значение) ищет первый элемент с таким значением и удаляет его. .RemoveAt(индекс) удаляет элемент по его номеру. Оба метода сразу сдвигают оставшиеся элементы - в списке не остаётся «дырок».

Что если элемента нет?

Если попытаться удалить значение, которого в списке нет, - ничего страшного не произойдёт. .Remove() просто вернёт false и оставит список как есть. А вот .RemoveAt() с несуществующим индексом вызовет ошибку - программа упадёт.

Другие полезные методы

У списка их много. Вот самые нужные:

  • .Add(x) добавить в конец
  • .Insert(i, x) вставить на позицию i
  • .Remove(x) удалить по значению
  • .RemoveAt(i) удалить по индексу
  • .Contains(x) есть ли элемент (bool)
  • .IndexOf(x) индекс элемента или −1
  • .Clear() удалить всё
  • .Count сколько элементов

Цикл foreach - перебор коллекций

Мы уже умеем перебирать массив через for и индексы. Но для списков и других коллекций есть более удобный цикл - foreach («фо-рич», от «for each» - «для каждого»). Он проходит по всем элементам, не требуя работы с индексами.

var fruits = new List<string> { "Яблоко", "Банан", "Апельсин" };foreach (string fruit in fruits){    Console.WriteLine(fruit);}

Смысл этой конструкции: «для каждого fruit в коллекции fruits - выполни то, что в теле». На каждой итерации переменная fruit содержит очередной элемент списка.

Сравните с обычным for:

for (int i = 0; i < fruits.Count; i++){    Console.WriteLine(fruits[i]);}foreach (string fruit in fruits){    Console.WriteLine(fruit);}

Результат один и тот же. Но foreach короче и читается легче. Особенно когда нам не нужен индекс - просто хотим пройти по всем элементам и что-то с ними сделать.

Когда for, а когда foreach

foreach - когда нужно пройти по всем элементам и нам не важен порядковый номер.
for - когда нужен индекс (например, чтобы изменить элемент по позиции) или когда нужно идти не с начала, а с середины, или в обратном порядке.

Имя переменной в foreach

В foreach (string fruit in fruits) имя fruit - это просто «как мы будем называть очередной элемент внутри тела цикла». Можно назвать как угодно:

foreach (string f in fruits)foreach (string item in fruits)foreach (string яблоко in fruits)

Все три варианта правильные. Главное - чтобы имя было понятным и не конфликтовало с другими переменными в этом же месте.

Dictionary - «словарь»

Второй тип коллекции, с которым стоит познакомиться, - Dictionary («дикшенери», от английского «словарь»). Он хранит данные не по номерам, а по ключам.

Аналогия - обычный бумажный словарь. У вас есть слово (ключ) и его значение. Чтобы найти перевод, вы ищете не по номеру страницы, а по самому слову. В Dictionary то же самое: у каждого значения есть свой ключ, по которому его можно мгновенно найти.

Примеры из реальной жизни, где удобен словарь:

  • Имя ученика → его оценка.
  • Логин пользователя → пароль.
  • Название товара → его цена.
  • Код страны → название страны.

Везде есть «ключ» (по чему ищем) и «значение» (что находим).

Создание словаря

Синтаксис похож на список, только в угловых скобках теперь два типа - сначала ключ, потом значение:

var scores = new Dictionary<string, int>();

Здесь string - тип ключа, int - тип значения. То есть «словарь, где ключи - строки, а значения - целые числа». Например, имя ученика → его оценка.

Добавление пар: .Add()

У словаря тоже есть метод .Add(), но принимает он два аргумента - ключ и значение:

var scores = new Dictionary<string, int>();scores.Add("Алексей", 5);scores.Add("Мария", 4);scores.Add("Иван", 3);

Теперь в словаре три пары. Ключ «Алексей» связан со значением 5, «Мария» - с 4, «Иван» - с 3.

Ключи уникальны

В словаре не может быть двух одинаковых ключей. Если попытаться добавить ещё одного «Алексея», C# выдаст ошибку. Это логично: если бы в словаре было два слова «стол», по какому из них искать перевод? Если нужно изменить значение для существующего ключа - используйте не .Add(), а присваивание (см. ниже).

Чтение значений

Чтобы достать значение, обращаемся к словарю по ключу в квадратных скобках:

Console.WriteLine(scores["Алексей"]);Console.WriteLine(scores["Мария"]);

Программа выведет 5 и 4. Очень удобно: не надо искать по индексу, бегать по всему массиву - сразу получаем нужное значение по ключу. Внутри словарь устроен так, что поиск происходит моментально, даже если внутри миллион записей.

Изменение значения

Чтобы изменить оценку существующего ученика, просто присваиваем новое значение по ключу:

scores["Мария"] = 5;

Никаких .Add() - если ключ уже есть, значение просто заменится. Если ключа нет - он добавится. Кстати, эту форму можно использовать и вместо .Add() вообще:

scores["Пётр"] = 5;

Так часто даже удобнее - не надо думать, есть ключ или нет.

Проверка наличия ключа: .ContainsKey()

Если обратиться к словарю по ключу, которого в нём нет, - программа упадёт с ошибкой. Поэтому перед чтением иногда полезно проверить, существует ли ключ:

if (scores.ContainsKey("Мария")){    Console.WriteLine(scores["Мария"]);}else{    Console.WriteLine("Такого ученика нет");}

Метод .ContainsKey() возвращает true или false - есть такой ключ или нет. Идеально сочетается с условиями из четвёртого урока.

Перебор словаря через foreach

Словарь тоже можно перебрать циклом foreach. Только на каждой итерации мы получаем не одно значение, а пару «ключ-значение». Для этого используется специальный тип KeyValuePair:

foreach (var pair in scores){    Console.WriteLine($"{pair.Key}: {pair.Value}");}

На каждой итерации pair содержит две части: .Key - ключ и .Value - значение. Программа выведет что-то вроде:

Алексей: 5
Мария: 4
Иван: 3
Пётр: 5

Порядок может быть любым - словарь не гарантирует последовательность, в отличие от списка. Это связано с тем, как он устроен внутри.

Когда что использовать

Мы познакомились с тремя коллекциями. Давайте соберём в одном месте, что и когда применять.

Коллекция Особенность Когда использовать
Массив Фиксированный размер Когда количество элементов известно заранее и не меняется
List<T> Растущий список по индексам По умолчанию для любой коллекции. Когда важно хранить порядок и нужен доступ по номеру
Dictionary<K,V> Поиск по ключу Когда нужно быстро находить значение по имени, коду, идентификатору

Проще говоря: 90% задач решает List. Если только вам не нужен поиск по ключу - тогда Dictionary. Массивы же используются реже, в основном там, где размер действительно фиксирован.

А как же производительность?

Может показаться, что List медленнее массива, ведь он «резиновый». На самом деле разница незаметна почти во всех задачах. Не думайте об этом на начальном уровне - используйте List везде, где он удобен.

Шпаргалка

Самое важное в одном месте:

  • new List<int>() создать список
  • list.Add(x) добавить элемент
  • list.Remove(x) удалить по значению
  • list[i] элемент по индексу
  • list.Count количество элементов
  • new Dictionary<string, int>() создать словарь
  • dict.Add(key, value) добавить пару
  • dict[key] значение по ключу
  • dict.ContainsKey(key) есть ли ключ
  • foreach (var x in collection) перебор всех элементов

Если что-то не работает

Списки и словари - тема, где ошибки часто связаны с одним-двумя конкретными местами. Проверьте по списку:

  • «The type or namespace name 'List' could not be found». Забыли using System.Collections.Generic; в начале файла. Без него ни List, ни Dictionary не распознаются.
  • «Cannot implicitly convert type 'List<int>' to 'int[]'». Список и массив - разные типы. Их нельзя присвоить друг другу. Если нужно передать данные из одного в другой - используйте цикл или метод .ToArray().
  • «ArgumentOutOfRangeException». Обратились к элементу списка по индексу, которого нет. Последний индекс - это .Count - 1, а не .Count. Если в списке 5 элементов, индексы идут от 0 до 4.
  • «An item with the same key has already been added». Пытаетесь добавить в словарь ключ, который уже есть. Помните: ключи уникальны. Если нужно обновить значение - используйте dict[key] = value вместо .Add().
  • «The given key was not present in the dictionary». Обратились к словарю по ключу, которого в нём нет. Проверьте через .ContainsKey() перед чтением, или используйте .TryGetValue() (это уже тема среднего уровня).
  • Изменили коллекцию внутри foreach. Нельзя добавлять или удалять элементы из списка прямо во время перебора циклом foreach - программа упадёт с ошибкой. Если нужно удалить элементы - используйте обычный for или сначала сохраните нужные данные в отдельный список.
  • Порядок элементов в словаре не совпадает с порядком добавления. Это нормально - Dictionary не гарантирует порядок. Если порядок важен - используйте список, а не словарь.

Если ничего не помогло - напишите нам в Telegram, поможем разобраться.

Практика

Четыре задачи по возрастающей сложности. У каждой - подсказка и решение учителя.

Задача 1. Список покупок

Создайте список из пяти продуктов и выведите их на экран через foreach. Каждый продукт - на новой строке.

Подсказка

Создайте список через new List<string> { ... }, заполнив его сразу. Затем пройдитесь циклом foreach (string item in list) и внутри выведите каждый элемент.

Решение учителя 
var products = new List<string> { "Хлеб", "Молоко", "Сыр", "Яйца", "Масло" };foreach (string product in products){    Console.WriteLine(product);}

Обратите внимание, как компактно получилось: список создали и заполнили в одну строку, а вывод - тремя строками цикла. С массивом было бы почти так же, но у списка ещё остаётся возможность добавлять и удалять элементы.

Задача 2. Список с вводом

Спросите у пользователя пять чисел и добавьте их в список. Затем выведите сумму всех чисел и среднее арифметическое.

Подсказка 1

Создайте пустой список целых чисел. В цикле for от 0 до 4 спрашивайте число и добавляйте его через list.Add(...).

Подсказка 2

Для суммы пригодится аккумулятор из пятого урока. Пройдитесь по списку через foreach, прибавляя каждый элемент к sum. Потом разделите на list.Count с приведением к double.

Решение учителя 
var numbers = new List<int>();for (int i = 0; i < 5; i++){    Console.Write($"Число {i + 1}: ");    numbers.Add(int.Parse(Console.ReadLine()));}int sum = 0;foreach (int num in numbers){    sum += num;}double average = (double)sum / numbers.Count;Console.WriteLine($"Сумма: {sum}");Console.WriteLine($"Среднее: {average}");

Обратите внимание: мы не указываем заранее, сколько чисел будет в списке. Просто создали пустой List и добавляли по мере ввода. Это и есть главное преимущество списка перед массивом.

Задача 3. Словарь оценок

Создайте словарь с именами трёх учеников и их оценками. Спросите у пользователя имя и выведите оценку этого ученика. Если такого нет - сообщите об этом.

Подсказка

Тип словаря - Dictionary<string, int>. Заполните его через .Add(имя, оценка) или через инициализацию в фигурных скобках. Для проверки наличия имени используйте .ContainsKey().

Решение учителя 
var scores = new Dictionary<string, int>{    { "Алексей", 5 },    { "Мария", 4 },    { "Иван", 3 }};Console.Write("Введи имя: ");string name = Console.ReadLine();if (scores.ContainsKey(name)){    Console.WriteLine($"Оценка {name}: {scores[name]}");}else{    Console.WriteLine("Такого ученика нет");}

Обратите внимание на форму инициализации словаря - пары в фигурных скобках через запятую. Каждая пара тоже в своих фигурных скобках.

Задача 4. Телефонная книга

Создайте словарь «имя → номер телефона» с пятью записями. Выведите книгу на экран через foreach, а затем найдите номер конкретного человека, спросив имя у пользователя.

Подсказка 1

Тип словаря - Dictionary<string, string> (ключ и значение оба строки). Имена - по одному слову, чтобы не путаться. Номера - например, «+7-900-123-45-67» или короче.

Подсказка 2

Для вывода словаря используйте foreach (var pair in book) и обращайтесь к pair.Key и pair.Value. Поиск номера - через .ContainsKey() и book[name].

Решение учителя 
var book = new Dictionary<string, string>{    { "Алексей", "+7-900-123-45-67" },    { "Мария",   "+7-900-765-43-21" },    { "Иван",    "+7-900-111-22-33" },    { "Ольга",   "+7-900-444-55-66" },    { "Пётр",    "+7-900-777-88-99" }};Console.WriteLine("Телефонная книга:");foreach (var pair in book){    Console.WriteLine($"{pair.Key}: {pair.Value}");}Console.Write("Чей номер найти? ");string name = Console.ReadLine();if (book.ContainsKey(name)){    Console.WriteLine($"Телефон {name}: {book[name]}");}else{    Console.WriteLine("Такого человека нет в книге");}

Программа выведет все записи, затем спросит имя, и если оно есть - покажет номер. Именно так работают настоящие телефонные книги: миллионы записей, но поиск занимает доли секунды, потому что он идёт по ключу, а не перебором.

Что мы узнали и что дальше

Сегодня мы познакомились с двумя самыми используемыми коллекциями C#. Разобрались, что List - это «резиновый массив» с методами Add, Remove, Contains и свойством Count. А Dictionary - это словарь с парами «ключ → значение», где поиск идёт мгновенно по ключу. Освоили цикл foreach, который делает перебор коллекций коротким и читаемым.

С этого момента у вас есть полный набор инструментов для работы с данными: одна переменная для одного значения, массив для фиксированного набора, список для растущей коллекции и словарь для быстрого поиска по ключу.

В следующем уроке мы познакомимся с ещё одной конструкцией из мира условий - switch. Это альтернатива длинным цепочкам if / else if, когда вариантов много, а условия простые: «если пользователь ввёл 1 - сделай одно, если 2 - другое, если 3 - третье». Такой код switch делает в разы короче и читаемее.
