Все типы данных под капотом

~25 минут Начальный уровень Теория

Мы прошли почти весь начальный уровень, но до сих пор использовали всего четыре типа: int, double, string, bool и один раз - char. На самом деле в C# их гораздо больше. И это не «для галочки»: разница между ними реальна и важна. Если выбрать неверный тип - программа может выдать неправильный результат или вообще упасть с ошибкой.

Сегодня мы заглянем «под капот» и разберёмся, сколько в C# основных типов, чем они отличаются и когда какой использовать. Постараемся разложить всё по полочкам - с таблицами, чтобы можно было возвращаться к этому уроку как к справочнику.

Зачем вообще нужны разные типы

Компьютер хранит данные в ячейках памяти, и у каждой ячейки есть размер. Один тип занимает 1 байт, другой - 4, третий - 8. Если нам нужно хранить число от 0 до 255 (например, возраст человека), глупо выделять под него 8 байт - хватит и одного. А если нужно хранить население Земли - 8 миллиардов - то один байт не подойдёт: в него влезает максимум 255.

Поэтому в C# существует много числовых типов: для каждого диапазона свой. Плюс отдельные типы для текста, символов, дробных чисел и логических значений.

Понимание типов - это как понимание размеров коробок на складе. Можно, конечно, всё сваливать в один большой ящик. Но лучше подобрать подходящий под каждую задачу.

Целые числа

Начнём с целых чисел - тех, что без дробной части. Это самая большая группа типов. Все они отличаются друг от друга размером и диапазоном. Есть знаковые (могут быть отрицательными) и беззнаковые (только положительные).

Тип Размер Диапазон Когда использовать
byte 1 байт 0 … 255 Возраст, счётчики, мелкие числа
sbyte 1 байт −128 … 127 Редко используется
short 2 байта −32 768 … 32 767 Когда byte не хватает, но int - избыточен
ushort 2 байта 0 … 65 535 Редко используется
int 4 байта −2 147 483 648 … 2 147 483 647 По умолчанию для целых чисел
uint 4 байта 0 … 4 294 967 295 Когда нужны только положительные
long 8 байт ±9 223 372 036 854 775 807 Очень большие числа: банковские счета, население
ulong 8 байт 0 … 18 446 744 073 709 551 615 Редко используется

Скорее всего, вы будете использовать только два из них - int и long. Остальные встречаются редко, но знать о них полезно: вы точно увидите их в чужом коде.

Знаковый и беззнаковый

Буква u в начале названия (uint, ulong, ushort) означает unsigned - «беззнаковый». Такие типы не могут быть отрицательными, зато влезает вдвое больше положительных чисел. То есть у uint верхняя граница примерно в два раза выше, чем у int.

Что делать, если число не влезает в int

Есть простой способ проверить максимальное значение любого типа - обратиться к константе MaxValue. Например: 

Console.WriteLine(int.MaxValue);Console.WriteLine(long.MaxValue);

Программа выведет:

2147483647
9223372036854775807

Если вам нужно хранить очень большое число, а int не хватает - используйте long. У него верхняя граница в 4 миллиарда раз выше. Если совсем не хватает - придётся работать со специальным типом BigInteger из пространства имён System.Numerics. Это уже тема не начального уровня, но знать о его существовании полезно.

Про BigInteger

BigInteger - это тип без ограничений по размеру: он может хранить числа хоть в тысячу цифр. Но он живёт в отдельной библиотеке. Чтобы им пользоваться, в начало файла придётся добавить строку using System.Numerics;. В большинстве версий Visual Studio она добавляется автоматически, но если вдруг увидите ошибку «The type or namespace 'BigInteger' could not be found» - вспомните про эту строку.

Дробные числа

С дробными числами (их ещё называют «числа с плавающей точкой») ситуация интереснее. Их всего три, но выбрать между ними важно - особенно когда речь идёт о деньгах.

Тип Размер Точность Когда использовать
float 4 байта ~7 знаков Игры, физика - где точность не критична
double 8 байт ~15–17 знаков По умолчанию для дробных
decimal 16 байт 28–29 знаков Деньги, финансы - где важна точность

Названия говорят сами за себя: float - «одинарная точность», double - «двойная точность» (вдвое точнее), decimal - «десятичное», специально для денег.

Почему для денег не используют double

double - это числа с плавающей точностью. У них есть неприятное свойство: некоторые десятичные дроби нельзя представить точно. Например, 0.1 в double хранится как очень близкое, но не равное число. Если сложить 0.1 + 0.2 - можно получить не 0.3, а 0.30000000000000004. Для физики это незаметно, а для бухгалтерии - катастрофа. Поэтому для денег используют decimal.

Как пишутся литералы

По умолчанию любое дробное число в коде C# воспринимает как double. Если нужен float или decimal - добавляем специальную букву в конце: 

double pi = 3.14;float piShort = 3.14f;decimal price = 19.99m;

Первая строка - обычный double, он используется по умолчанию. Вторая - тип float, о чём говорит буква f в конце. Третья - decimal с буквой m. Эти буквы - не для красоты. Без них компилятор не поймёт, что мы хотим другой тип, и подчеркнёт строку красным.

Логический тип

Всего один тип, зато незаменимый:

Тип Размер Значения Когда использовать
bool 1 байт true / false Флаги, проверки, условия

Мы уже знакомы с ним с самого начала курса - во втором уроке и во всех условиях. bool - это ответ «да» или «нет». Больше о нём сказать особо нечего.

Текст и символы

Два типа для работы с текстом:

Тип Размер Что хранит Пример
char 2 байта Один символ 'A', '7', '!'
string зависит от длины Набор символов "Привет, мир!"

Про char и string мы подробно говорили в шестом уроке. Разница простая: char - один символ в одинарных кавычках, string - строка в двойных кавычках. string занимает столько памяти, сколько в нём символов (плюс немного служебных данных), поэтому фиксированного размера у него нет.

Тип string: ссылочный, а не значимый

Здесь мы выходим на важную концепцию. Все типы, которые мы разбирали выше - int, long, double, bool, char - это значимые типы (value types). Они хранят само значение прямо в переменной.

А string - ссылочный тип (reference type). Переменная string хранит не сам текст, а ссылку на него - что-то вроде адреса в памяти. Это тонкая, но важная разница, которая объясняет много поведения C#.

Практическое следствие: если вы передаёте int в метод, копируется само число. Если передаёте string - копируется ссылка, и метод работает с той же строкой. Впрочем, для начального уровня это скорее интересный факт, чем что-то, что нужно срочно применять. Подробнее поговорим на среднем уровне.

Сводная таблица

Соберём самое важное в одном месте - для быстрого напоминания:

Категория Тип Используйте, когда…
Целые int по умолчанию для целых чисел
long число больше 2 миллиардов
Дробные double по умолчанию для дробных
decimal деньги, финансы
Текст char один символ
string любой текст
Логика bool да / нет, проверки

Если запомнить только эти семь строк - уже можно смело писать код. Остальные типы вы будете встречать редко и постепенно их запомните.

Ключевое слово var

А теперь - небольшое отступление от типов, которое, впрочем, тесно связано с ними. В C# есть специальное ключевое слово var, которое встречается настолько часто, что без него ваш код будет выглядеть странно для других программистов. Давайте разберёмся, что это такое.

Когда мы объявляем переменную, мы обычно пишем тип слева и значение справа:

string name = "Алексей";int age = 25;double price = 199.9;

Но компилятор C# и так видит, что справа стоит строка, число или дробное. Он может сам догадаться о типе. И вот тут приходит на помощь var:

var name = "Алексей";var age = 25;var price = 199.9;

Результат абсолютно тот же. Компилятор смотрит на правую часть, определяет, что это за тип, и подставляет его автоматически. Слово var - это как сказать: «выведи тип сам, мне лень писать».

var - это не тип

Важно понимать: var - не новый тип данных. Это сокращённая запись объявления. После компиляции var name = "Алексей" превращается в string name = "Алексей". Никакого «типа var» не существует. Это просто способ не писать тип вручную, когда он и так очевиден.

Тип всё равно фиксируется

Есть искушение подумать: «раз var - это универсально, значит переменная может менять тип на ходу». Нет, это не так. Тип определяется один раз, при создании, и после этого изменить его нельзя. Ровно как если бы вы написали тип явно.

var number = 10;number = 20;number = "текст";

Первая строка создаст переменную типа int. Вторая - сработает, потому что 20 тоже целое число. А вот третья строка вызовет ошибку: мы пытаемся положить строку в переменную, которая уже объявлена как int. Компилятор остановит нас и подчеркнёт строку красным.

Когда var удобен, а когда мешает

Хорошее правило: используйте var, когда тип очевиден из правой части. Тогда код становится чище и короче, а читаемость не страдает.

var name = "Алексей";var count = 42;var price = 199.99m;var isStudent = true;

В каждой строке сразу видно, что за тип получится. Строка справа, число, дробное, логическое значение - всё понятно без дополнительных пояснений.

А вот случай, когда var только запутает. Представьте, что у нас есть метод, который возвращает какое-то значение. Мы не знаем, что именно он возвращает, и с var код становится загадочным: 

var result = GetValue();

Что внутри result? Число? Строка? Непонятно. Если вместо var написать тип явно - код становится читаемым сразу:

int result = GetValue();

Теперь ясно, что метод вернул число. Поэтому правило простое: тип виден из правой части - используйте var; не виден - пишите тип явно. Опытные программисты интуитивно чувствуют эту грань, вы тоже научитесь.

Дальше в курсе

С этого момента мы будем иногда использовать var - когда тип очевиден. Это не правило языка, а стиль написания кода. Если вам удобнее всегда писать тип явно - тоже правильно. Главное - чтобы код читался легко.

Если что-то не работает

Разные типы - место, где легко ошибиться по невнимательности. Проверьте по списку:

  • «Cannot implicitly convert type 'double' to 'decimal'». Забыли букву m в конце дробного числа для decimal. Пишите 19.99m, а не 19.99.
  • «Literal of type double cannot be implicitly converted to type 'float'». Забыли букву f для float. Пишите 3.14f.
  • «Cannot implicitly convert type 'string' to 'int'». Пытаетесь положить текст в переменную для чисел или наоборот. Проверьте, что тип соответствует тому, что вы присваиваете.
  • Число «не влезает» и превращается во что-то странное. Например, вместо большого числа выводится отрицательное. Это переполнение: число вышло за границы диапазона. Проверьте, какой тип вы используете - возможно, нужен long, а не int.
  • «The type or namespace name 'BigInteger' could not be found». Используете BigInteger, но не подключили using System.Numerics;. Добавьте эту строку в начало файла.
  • Дробное число выводится с кучей нулей. Это нормальное поведение double - он хранит приближённое значение. Если нужна точность до копейки - используйте decimal.
  • var не даёт поменять тип. Это не ошибка, а особенность: тип фиксируется при создании переменной и изменить его нельзя. Если нужен другой тип - создайте новую переменную.

Если ничего не помогло - напишите нам в Telegram, поможем разобраться.

Практика

Три задачи. У каждой - подсказка и решение. Сначала попробуйте сами.

Задача 1. Информация о типах

Выведите на экран максимальное и минимальное значение для типов int, long и double. Подпишите каждое значение.

Подсказка

У каждого числового типа есть константы MaxValue и MinValue. Пишутся так: int.MaxValue. Используйте интерполяцию, чтобы подписать каждое значение.

Решение учителя 
Console.WriteLine($"int:    {int.MinValue} … {int.MaxValue}");Console.WriteLine($"long:   {long.MinValue} … {long.MaxValue}");Console.WriteLine($"double: {double.MinValue} … {double.MaxValue}");

Вы увидите те самые числа, которые мы разбирали в таблицах. Например, int.MaxValue - 2 147 483 647. Константы MinValue и MaxValue полезны, когда нужно понять, влезет ли число в тип.

Задача 2. Деньги

Создайте переменную типа decimal со значением 1999.99. Выведите её на экран. Обратите внимание, что нужна буква m в конце числа.

Подсказка

Объявление выглядит так: decimal price = 1999.99m;. Без буквы m компилятор подумает, что это double - и не даст присвоить значение переменной типа decimal.

Решение учителя 
decimal price = 1999.99m;Console.WriteLine($"Цена: {price} руб.");

Программа выведет «Цена: 1999.99 руб.». Если убрать букву m - Visual Studio сразу подчеркнёт строку и покажет ошибку. Это её способ сказать: «я не уверена, что ты хочешь именно decimal».

Задача 3. Выбор типа

Для каждой ситуации выберите подходящий тип и обоснуйте свой выбор:

  • Количество учеников в классе.
  • Возраст человека.
  • Цена товара в магазине.
  • Название города.
  • Ответ на вопрос «Согласны?».
  • Население страны.
  • Температура тела человека.
Подсказка

Задайте себе три вопроса: число или текст? Если число - целое или дробное? Если целое - может ли оно быть очень большим или отрицательным? Если дробное - это деньги или обычное измерение?

Решение учителя
  • Учеников в классе - int (до 40, всегда положительное).
  • Возраст - int (до 120, положительное).
  • Цена товара - decimal (деньги, точность важна).
  • Название города - string (текст).
  • Ответ «Согласны?» - bool (да или нет).
  • Население страны - long (миллиарды - не влезет в int).
  • Температура тела - double (дробное, не деньги).

Заметьте: для цены - именно decimal, потому что 1 копейка разницы в бухгалтерии - это уже проблема. А для температуры - double, потому что точность до 15 знаков там избыточна, но денежной точности тоже не нужно.

Что мы узнали и что дальше

Сегодня мы заглянули под капот C# и разобрались со всеми основными типами данных. Их не так много, как кажется: несколько целочисленных, три дробных, один логический, два для текста. Плюс важная концепция значимых и ссылочных типов. И познакомились с ключевым словом var, которое позволяет не писать тип вручную, когда он и так очевиден.

Самый главный вывод: при выборе типа не надо усложнять. По умолчанию - int для целых, double для дробных, string для текста, bool для «да/нет». Меняем тип только тогда, когда есть конкретная причина: число не влезает в int или речь идёт о деньгах.

А теперь - самое интересное. До этого момента у нас в переменной всегда хранилось одно значение: одно число, одна строка, один флаг. Но что делать, если нужно хранить 30 оценок ученика? Заводить 30 переменных? Конечно же нет. В следующем уроке мы познакомимся с массивами - способом хранить целую коллекцию однотипных данных под одним именем. Это следующий большой шаг в программировании.
