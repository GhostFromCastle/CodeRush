Generics и делегаты

~45 минут Продвинутый уровень Теория и Практика

Добро пожаловать на продвинутый уровень. До этого мы писали код, который работал с конкретными типами: либо с числами, либо со строками, либо с нашими классами. Но в реальной разработке часто возникает задача написать что-то универсальное, что подходило бы для любого типа данных.

Сегодня мы разберём две мощнейшие концепции C#: Generics (обобщения) и делегаты. Именно на них строится LINQ (о котором мы поговорим в следующем уроке) и большинство современных библиотек.

Часть 1: Проблема дублирования

Представьте, что мы пишем класс для хранения коробки с данными. Пока это просто число:

class IntBox{    public int Value;}

А теперь нам нужна такая же коробка, но для строк. Что делать? Копировать код и менять тип:

class StringBox{    public string Value;}

А если понадобится коробка для даты, для пользователя, для массива? Получается, нам нужно написать десятки одинаковых классов, которые отличаются только одной строчкой. Это нарушает главное правило программиста - DRY (Don't Repeat Yourself).

Что такое Generics (Обобщения)

Generics позволяют создавать классы и методы, которые работают с любым типом данных, не теряя при этом строгую типизацию. Вы как бы оставляете «пустое место» под тип, который определится позже.

Обозначается это угловыми скобками <T> (от слова Type). Вот как выглядит наша универсальная коробка:

class Box<T>{    public T Value;}

Разберём эту магию:

  • Box<T> - мы объявили класс Box, который является обобщённым. Буква T - это просто заглушка (шаблон).
  • public T Value; - здесь мы говорим: «Тип поля Value будет таким же, как и T, который мы передадим при создании объекта».

Теперь при создании объекта мы сами указываем, что это будет за коробка:

Box<int> intBox = new Box<int>();intBox.Value = 42;Box<string> stringBox = new Box<string>();stringBox.Value = "Привет";

Обратите внимание: у нас один класс, но он используется для разных типов. Если попытаться положить строку в intBox - компилятор сразу выдаст ошибку. Это и есть безопасность типов.

Вспомните List

Мы уже использовали List<int> или List<string>. Это точно такой же обобщённый класс, который написали разработчики C#, чтобы мы могли хранить списки любого типа без дублирования кода.

Обобщённые методы

Generics работают не только с классами, но и с методами. Допустим, мы хотим написать метод, который выводит что-то на экран в квадратных скобках.

static void PrintBox<T>(T item){    Console.WriteLine($"[ {item} ]");}

Метод PrintBox<T> принимает параметр item неизвестного типа T и выводит его. Вызывать его можно с чем угодно:

PrintBox(100);PrintBox("Слово");PrintBox(3.14);

C# достаточно умён, чтобы самому догадаться, какой тип вы передали, поэтому писать PrintBox<int>(100) не обязательно.

Часть 2: Что такое делегаты

Представьте, что вы нанимаете строителя. Вам неважно, как его зовут и какие у него инструменты. Вам важно, чтобы он умел выполнять работу по определённому чертежу (принимал кирпичи и строил стену).

Делегат - это тип данных, который хранит в себе не число и не строку, а ссылку на метод. Это как контракт: мы говорим, что метод должен принимать такие-то аргументы и возвращать такой-то результат.

Зачем это нужно? Чтобы передавать методы в другие методы как аргументы.

Как объявить делегат

Объявление делегата похоже на объявление метода, но со словом delegate и без тела:

delegate void MessageDelegate(string text);

Этот контракт говорит: «Любой метод, который принимает string и ничего не возвращает (void), может быть записан в эту переменную».

Давайте создадим такой метод:

static void ShowMessage(string msg){    Console.WriteLine($"Сообщение: {msg}");}

И теперь используем делегат:

MessageDelegate del = ShowMessage;del("Привет, делегаты!");

Строка MessageDelegate del = ShowMessage; кладёт метод ShowMessage в переменную del. А вызов del(...) фактически вызывает этот метод.

Встроенные делегаты: Action и Func

Создавать свои делегаты через слово delegate - это долго и неудобно. Разработчики C# придумали два универсальных делегата, которые покрывают 99% задач.

Action

Action используется для методов, которые ничего не возвращают (void). Он может принимать до 16 параметров.

Action<string> action = ShowMessage;action("Работает!");

Func

Func используется для методов, которые возвращают результат. Последний тип в угловых скобках - это то, что метод возвращает. Всё, что до него - аргументы.

static int Square(int x){    return x * x;}Func<int, int> func = Square;int result = func(5);Console.WriteLine(result);

Здесь Func<int, int> означает: метод принимает int и возвращает int.

Зачем передавать методы в методы

Представьте, что вы пишете метод, который фильтрует массив чисел. В одном случае вам нужно оставить только чётные числа, в другом - только положительные, в третьем - числа больше 10.

Писать три разных метода фильтрации? Нет. Мы можем написать один метод, а логику проверки передать через делегат Func:

static void FilterAndPrint(int[] numbers, Func<int, bool> condition){    foreach (int n in numbers)    {        if (condition(n))        {            Console.Write(n + " ");        }    }    Console.WriteLine();}

Второй параметр - Func<int, bool> - это функция, которая принимает число и возвращает true или false (подходит число или нет).

Теперь мы можем делать так:

int[] data = { 1, 2, 3, 4, 5, 6, 7, 8 };FilterAndPrint(data, n => n % 2 == 0);FilterAndPrint(data, n => n > 5);

Запись n => n % 2 == 0 называется лямбда-выражением. Это короткий способ создать анонимный метод прямо на месте. Читается как: «Берём n и возвращаем результат выражения n % 2 == 0». Мы ещё подробнее разберём их в следующем уроке, но выглядит это очень элегантно.

Шпаргалка

Самое важное в одном месте:

  • class Box<T> обобщённый класс
  • void Print<T>(T x) обобщённый метод
  • Action<T> делегат без возврата
  • Func<T, TResult> делегат с возвратом
  • n => n * 2 лямбда-выражение
  • Delegate ссылка на метод

Если что-то не работает

Разберём типичные ошибки при работе с обобщениями и делегатами.

  • «The type or namespace name 'T' could not be found». Вы используете букву T в классе или методе, но забыли указать её в угловых скобках при объявлении. Например, написали class Box вместо class Box<T>.
  • «Cannot create an instance of the variable type 'T'». Нельзя написать new T() внутри обобщённого метода без специальных ограничений. C# не знает заранее, есть ли у типа T конструктор без параметров.
  • Неверная сигнатура делегата. Если Action требует один аргумент, а ваш метод принимает два - компилятор выдаст ошибку. Типы и количество аргументов должны строго совпадать.
  • «NullReferenceException» при вызове делегата. Если вы объявили переменную делегата, но не присвоили ей никакой метод (она равна null), вызов вызовет ошибку. Всегда проверяйте на null или присваивайте метод сразу при объявлении.
  • Путаница в Func. В Func<int, string, bool> первые два типа - это аргументы, а последний - возвращаемое значение. Если метод ничего не возвращает - используйте Action, а не Func.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Обобщённый метод

Напишите обобщённый метод Swap<T>, который принимает два параметра типа T по ссылке (ref) и меняет их значения местами. Проверьте его на двух числах и двух строках.

Подсказка

Для обмена значениями используйте временную переменную типа T: T temp = a; a = b; b = temp;. Не забудьте про ref в параметрах, чтобы изменения сохранились.

Решение учителя 
static void Swap<T>(ref T a, ref T b){    T temp = a;    a = b;    b = temp;}static void Main(string[] args){    int x = 1;    int y = 2;    Swap(ref x, ref y);    Console.WriteLine($"{x}, {y}");    string s1 = "Привет";    string s2 = "Мир";    Swap(ref s1, ref s2);    Console.WriteLine($"{s1}, {s2}");}
Задача 2. Обобщённый класс

Создайте обобщённый класс Pair<T1, T2>, который хранит два значения разных типов: First и Second. Создайте объект, где First - это строка (имя), а Second - это число (возраст).

Подсказка

Класс объявляется как class Pair<T1, T2>. Внутри создайте два публичных поля: public T1 First; и public T2 Second;. При создании объекта укажите типы явно: new Pair<string, int>().

Решение учителя 
class Pair<T1, T2>{    public T1 First;    public T2 Second;}static void Main(string[] args){    Pair<string, int> person = new Pair<string, int>();    person.First = "Алексей";    person.Second = 25;    Console.WriteLine($"{person.First}, {person.Second} лет");}
Задача 3. Знакомство с Action

Создайте метод PrintUpperCase, который принимает строку и выводит её в верхнем регистре. Используйте делегат Action<string>, чтобы вызвать этот метод.

Подсказка

Метод PrintUpperCase должен возвращать void и принимать один аргумент string. Для перевода в верхний регистр используйте .ToUpper().

Решение учителя 
static void PrintUpperCase(string text){    Console.WriteLine(text.ToUpper());}static void Main(string[] args){    Action<string> action = PrintUpperCase;    action("привет, мир");}
Задача 4. Знакомство с Func

Создайте метод IsPositive, который принимает число и возвращает true, если оно больше нуля. Используйте делегат Func<int, bool>, чтобы сохранить ссылку на этот метод, а затем вызовите его для числа -5.

Подсказка

Метод IsPositive принимает int и возвращает bool (через return x > 0;). Делегат будет выглядеть как Func<int, bool> func = IsPositive;.

Решение учителя 
static bool IsPositive(int number){    return number > 0;}static void Main(string[] args){    Func<int, bool> func = IsPositive;    bool result = func(-5);    Console.WriteLine($"Число положительное: {result}");}

Что мы узнали и что дальше

Сегодня мы прикоснулись к магии обобщённого программирования. Узнали, что Generics позволяют писать код, который работает с любыми типами, не дублируя его. А делегаты (Action и Func) дают нам возможность передавать методы как аргументы, делая код гибким и расширяемым.

Именно эти две концепции являются фундаментом для всего современного C#. Без них не существовало бы ни наших любимых списков (List<T>), ни LINQ.

В следующем уроке мы как раз займёмся LINQ - языком запросов, который позволяет фильтровать, сортировать и преобразовывать коллекции одной короткой строчкой. И вы увидите, как делегаты и лямбда-выражения делают этот процесс невероятно элегантным.
