Проект: Telegram-бот

~60 минут Продвинутый уровень Проект

Теория - это отлично. Мы прошли generics, LINQ, асинхронность, паттерны, тесты. Но настоящий навык появляется, когда садишься и делаешь что-то работающее своими руками. Сегодня - именно такой урок.

Мы создадим Telegram-бота с нуля. Не просто «привет, мир», а рабочую программу, которая запускается на сервере (или на вашем компьютере), отвечает на команды, обрабатывает сообщения и может быть расширена в полноценный сервис. Такой бот - это первая работа, которую можно смело показывать в портфолио.

Что умеет Telegram Bot API

Telegram-боты - это специальные аккаунты, которыми управляет программа, а не человек. С точки зрения Telegram это обычный пользователь, но за него отвечает ваш код.

Ботов используют для всего:

  • Уведомления. Боты сообщают о заказах, статусах сборки, сбоях в системе.
  • Поддержка. Помогают пользователям отвечать на типовые вопросы.
  • Игры. Простые текстовые и кнопочные игры.
  • Интеграции. Бот получает данные от одного сервиса и отправляет в Telegram.
  • Автоматизация. Бот напоминает о задачах, ведёт списки покупок, отслеживает цены.

Мы сделаем основу, из которой можно вырастить любое из этих направлений.

Шаг 1. Получаем токен через BotFather

Чтобы программа могла управлять ботом, ей нужен токен - длинная строка вида 123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ. Это как пароль от бота: кто знает токен, тот и управляет.

Получить его можно через специального бота @BotFather в Telegram. Это официальный бот от Telegram, через который создают всех ботов.

Процесс простой:

  1. Открываете Telegram, ищете @BotFather, начинаете с ним диалог.
  2. Пишете команду /newbot.
  3. Он спрашивает имя бота - это отображаемое имя, например «Мой первый бот».
  4. Он спрашивает username - это уникальное имя с суффиксом _bot, например my_first_coderush_bot. Оно должно быть свободно.
  5. Если всё хорошо - BotFather присылает токен. Сохраните его в надёжное место, это единственный экземпляр.
Не публикуйте токен

Токен - это ключ от вашего бота. Если он попадёт в открытый доступ (например, вы закоммитите его в GitHub), любой сможет управлять вашим ботом. Никогда не храните токен в исходном коде напрямую. О правильном хранении - чуть ниже.

Шаг 2. Создаём проект и подключаем библиотеку

Создайте новый консольный проект:

dotnet new console -o MyFirstBotcd MyFirstBot

Теперь установите официальную (ну, почти - поддерживается сообществом) библиотеку для работы с Telegram Bot API. Она называется Telegram.Bot: 

dotnet add package Telegram.Bot

Это добавит зависимость в .csproj и подтянет все нужные пакеты. На момент этого урока актуальная версия - 22.x.

Шаг 3. Хранение токена

Правильный способ - не писать токен в код, а хранить в конфигурации или переменной окружения. Это защищает от случайной публикации и позволяет легко менять токен в разных окружениях.

Самый простой вариант - файл appsettings.json. Создайте его рядом с программой:

{  "BotToken": "123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ"}

И добавьте в проект NuGet-пакет для чтения конфигурации:

dotnet add package Microsoft.Extensions.Configuration.Json

А в проекте пропишите, что этот файл нужно копировать в папку с приложением:

<ItemGroup>    <None Update="appsettings.json">        <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>    </None></ItemGroup>

И не забудьте добавить appsettings.json в .gitignore, если используете Git.

Шаг 4. Простой эхо-бот

Теперь - код. Начнём с самого простого: бот отвечает на любое сообщение тем же текстом. Так мы убедимся, что связь работает.

using Microsoft.Extensions.Configuration;using Telegram.Bot;using Telegram.Bot.Polling;using Telegram.Bot.Types;using Telegram.Bot.Types.Enums;var config = new ConfigurationBuilder()    .AddJsonFile("appsettings.json")    .Build();string token = config["BotToken"];var bot = new TelegramBotClient(token);using var cts = new CancellationTokenSource();var options = new ReceiverOptions{    AllowedUpdates = new[] { UpdateType.Message }};bot.StartReceiving(    updateHandler: HandleUpdateAsync,    errorHandler: HandleErrorAsync,    receiverOptions: options,    cancellationToken: cts.Token);var me = await bot.GetMe();Console.WriteLine($"Бот @{me.Username} запущен. Нажмите Enter для остановки.");Console.ReadLine();cts.Cancel();async Task HandleUpdateAsync(ITelegramBotClient client, Update update, CancellationToken ct){    if (update.Message is not { Text: { } text } message) return;    await client.SendMessage(message.Chat.Id, text, cancellationToken: ct);}async Task HandleErrorAsync(ITelegramBotClient client, Exception ex, CancellationToken ct){    Console.WriteLine($"Ошибка: {ex.Message}");    await Task.CompletedTask;}

Разберём, что происходит:

  • ConfigurationBuilder читает токен из appsettings.json.
  • new TelegramBotClient(token) - создаём клиента, через которого будем общаться с Telegram.
  • ReceiverOptions ограничивает типы событий - нам интересны только сообщения.
  • StartReceiving запускает фоновый цикл, который слушает Telegram и вызывает наш HandleUpdateAsync при каждом новом сообщении.
  • GetMe() - получаем информацию о боте (его username), чтобы убедиться, что токен рабочий.
  • HandleUpdateAsync - главный обработчик. Через pattern matching проверяем, что пришло именно текстовое сообщение, и отвечаем тем же текстом.

Запустите программу, откройте своего бота в Telegram, напишите что угодно - и он ответит тем же. Поздравляем, вы только что написали своего первого бота!

Шаг 5. Обработка команд

Эхо-бот - это хорошо, но настоящий бот понимает команды. В Telegram команды начинаются с косой черты: /start, /help, /stop и так далее. Обычно на /start бот приветствует пользователя и рассказывает, что умеет.

Обновим обработчик:

async Task HandleUpdateAsync(ITelegramBotClient client, Update update, CancellationToken ct){    if (update.Message is not { Text: { } text } message) return;    long chatId = message.Chat.Id;    string reply = text switch    {        "/start" => "Привет! Я простой бот. Напиши что-нибудь, и я повторю.",        "/help" => "Доступные команды:\n/start - приветствие\n/help - справка",        _ => $"Ты написал: {text}"    };    await client.SendMessage(chatId, reply, cancellationToken: ct);}

Обратите внимание на switch expression - это современный синтаксис C# для обработки нескольких случаев. Читается гораздо лучше, чем цепочка из if / else if.

Проверьте: при /start бот должен здороваться, при /help - показывать справку, а на всё остальное - повторять текст с приставкой «Ты написал:».

Шаг 6. Отправка сообщений с разметкой

Telegram поддерживает разные форматы сообщений: жирный текст, курсив, код, ссылки. Чтобы их использовать, нужно передать параметр parseMode: 

string reply = "Это <b>жирный</b> и <i>курсивный</i> текст.";await client.SendMessage(    chatId,    reply,    parseMode: ParseMode.Html,    cancellationToken: ct);

Основные теги:

  • <b>...</b> - жирный.
  • <i>...</i> - курсив.
  • <code>...</code> - моноширинный (для кода).
  • <pre>...</pre> - блок кода.
  • <a href="...">...</a> - ссылка.

Также можно использовать Markdown через ParseMode.MarkdownV2, но у него более капризный синтаксис - нужно экранировать многие символы. HTML проще.

Шаг 7. Хранение состояния

Что если бот должен помнить, что пользователь сказал раньше? Например, вести список покупок или викторину. Простое поле класса подойдёт только для одного пользователя, а если их сотни - нужно хранить состояние для каждого.

Классический способ - словарь в памяти:

var states = new Dictionary<long, int>();async Task HandleUpdateAsync(ITelegramBotClient client, Update update, CancellationToken ct){    if (update.Message is not { Text: { } text } message) return;    long chatId = message.Chat.Id;    if (!states.ContainsKey(chatId))    {        states[chatId] = 0;    }    states[chatId]++;    await client.SendMessage(chatId, $"Ты написал {states[chatId]} сообщений.", cancellationToken: ct);}

Для серьёзных ботов состояния хранят в базе данных или Redis, чтобы они не терялись при перезапуске. Но для простых сценариев словарь в памяти - отличное начало.

Память не бесконечна

Словарь в памяти растёт с каждым новым пользователем. Если у бота тысячи пользователей - словарь займёт много памяти, а при перезапуске всё состояние потеряется. Для продакшена - база данных, файлы или Redis. Для учебного проекта словарь - нормально.

Как это работает под капотом

Стоит понимать, что происходит, когда бот получает сообщение. Telegram Bot API работает по двум схемам:

  • Long Polling - ваш бот сам спрашивает Telegram: «Есть новые сообщения?». Если есть - получает и обрабатывает, если нет - ждёт несколько секунд и спрашивает снова. Просто, но чуть менее эффективно.
  • Webhook - Telegram сам отправляет сообщения на ваш сервер по указанному URL. Быстрее, но требует публичного адреса и HTTPS.

Библиотека Telegram.Bot по умолчанию использует long polling - именно поэтому наш код «просто работает» без всяких серверов. Для учебного проекта этого достаточно. Для настоящего продакшена чаще выбирают webhook, но это уже тема для отдельного разговора.

Шпаргалка

Самое важное в одном месте:

  • @BotFather создание бота и получение токена
  • Telegram.Bot библиотека для работы с API
  • TelegramBotClient основной класс клиента
  • StartReceiving запуск получения сообщений
  • HandleUpdateAsync обработчик входящих
  • SendMessage отправка сообщения
  • ParseMode.Html разметка в сообщениях

Если что-то не работает

Разберём типичные проблемы при работе с Telegram-ботами.

  • «401 Unauthorized». Токен неверный или устарел. Проверьте, что скопировали его полностью, без лишних пробелов и переносов. Если сомневаетесь - зайдите в @BotFather и отзовите старый токен через /revoke, потом создайте новый.
  • «409 Conflict: terminated by other getUpdates request». Бот запущен в двух местах одновременно. Например, вы забыли закрыть прошлый экземпляр программы, а теперь запустили новый. Telegram не позволяет двум программам одновременно читать сообщения одного бота. Закройте старую программу.
  • «Бот не отвечает на сообщения». Проверьте по порядку: 1) программа запущена и не упала; 2) в консоли есть сообщение «Бот @username запущен»; 3) вы пишете именно этому боту (по username), а не в общий чат; 4) в логах не появляется ошибок. Если всё так - попробуйте перезапустить программу.
  • «StartReceiving ничего не делает». Возможно, вы забыли Console.ReadLine() в конце - программа сразу завершается, не успев обработать ни одного сообщения. Или не создали CancellationTokenSource - тогда отмена невозможна, но приём сообщений работает.
  • «Не работает кириллица в коде». Убедитесь, что файл сохранён в кодировке UTF-8. Visual Studio делает это автоматически, но при копировании через блокнот кодировка может сбиться.
  • «Токен попал в GitHub». Немедленно отзовите его через @BotFather командой /revoke. Бот получит новый токен, старый перестанет работать. Удалите коммит с токеном из истории через git filter-repo или специальные инструменты вроде BFG Repo-Cleaner.
  • «Сообщения приходят с задержкой». Long polling использует интервал ожидания (обычно 30 секунд). Иногда это даёт задержку до нескольких секунд. Для мгновенной реакции используют webhook, но для учебных проектов задержка в 1-2 секунды незаметна.

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя. Все задачи - продолжение нашего эхо-бота.

Задача 1. Команда /time

Добавьте команду /time, которая отвечает текущим временем в формате ЧЧ:мм:сс. Время должно быть в момент отправки ответа, а не при запуске бота.

Подсказка

В switch expression добавьте новый case "/time". В нём вызовите DateTime.Now.ToString("HH:mm:ss"). Обратите внимание: строка формируется при каждом вызове обработчика, а не один раз при старте.

Решение учителя 
string reply = text switch{    "/start" => "Привет! Я простой бот.",    "/help" => "Команды:\n/start\n/help\n/time",    "/time" => $"Сейчас {DateTime.Now:HH:mm:ss}",    _ => $"Ты написал: {text}"};

Формат HH:mm:ss - 24-часовой, с ведущими нулями. Для 12-часового используйте hh:mm:ss вместе с tt для AM/PM.

Задача 2. Трансформация текста

Добавьте две команды: /upper и /lower. После них пользователь пишет текст, и бот возвращает этот текст в верхнем или нижнем регистре. Например: /upper привет → ПРИВЕТ.

Подсказка

Команды со аргументами проверяются через StartsWith. Например: if (text.StartsWith("/upper ")). Дальше отрезаете префикс командой text.Substring(7) и применяете ToUpper(). Для /lower - аналогично с ToLower().

Решение учителя 
string reply;if (text.StartsWith("/upper ")){    reply = text.Substring(7).ToUpper();}else if (text.StartsWith("/lower ")){    reply = text.Substring(7).ToLower();}else{    reply = text switch    {        "/start" => "Привет! Я умею менять регистр: /upper текст и /lower текст",        _ => $"Ты написал: {text}"    };}await client.SendMessage(chatId, reply, cancellationToken: ct);

Обратите внимание на порядок: сначала проверяем команды с аргументами (через StartsWith), потом точные команды через switch. Такой подход позволяет легко расширять список команд.

Задача 3. Случайный факт

Добавьте команду /fact, которая при каждом вызове возвращает случайный факт из заранее подготовленного списка. Например, про котиков или про программирование - на ваш выбор. Подготовьте минимум пять фактов.

Подсказка

Создайте массив строк с фактами. Для получения случайного используйте Random.Shared - это потокобезопасный экземпляр Random, который не нужно создавать заново. Индекс - Random.Shared.Next(facts.Length).

Решение учителя 
string[] facts = new[]{    "Первый факт про котиков.",    "Второй факт про программирование.",    "Третий факт про космос.",    "Четвёртый факт про историю.",    "Пятый факт про еду."};string reply = text switch{    "/fact" => facts[Random.Shared.Next(facts.Length)],    _ => $"Ты написал: {text}"};

Массив можно объявить как локальную переменную в Main или как статическое поле класса. Для простого бота сойдёт и локальная переменная. Random.Shared доступен с .NET 6 и не требует создания экземпляра.

Задача 4. Логирование в файл

Добавьте логирование: при каждом входящем сообщении записывайте в файл bot_log.txt строку в формате [дата и время] @username: текст. Если у пользователя нет username (бывает, если он его не задал), пишите id:12345 вместо @username.

Подсказка

Используйте File.AppendAllText из урока 28. Дата - DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss"). Username в объекте сообщения лежит в message.From.Username. Если он null - используйте message.From.Id.

Решение учителя 
async Task HandleUpdateAsync(ITelegramBotClient client, Update update, CancellationToken ct){    if (update.Message is not { Text: { } text } message) return;    string user = message.From?.Username is { } name        ? $"@{name}"        : $"id:{message.From?.Id}";    string logLine = $"[{DateTime.Now:yyyy-MM-dd HH:mm:ss}] {user}: {text}\n";    File.AppendAllText("bot_log.txt", logLine);    long chatId = message.Chat.Id;    string reply = text switch    {        "/start" => "Привет! Я бот с логированием.",        _ => $"Ты написал: {text}"    };    await client.SendMessage(chatId, reply, cancellationToken: ct);}

Обратите внимание: логирование стоит до отправки ответа. Если отправка упадёт (например, из-за проблем с сетью), мы всё равно зафиксируем входящее сообщение. Это стандартная практика - сначала логировать событие, потом действовать.
