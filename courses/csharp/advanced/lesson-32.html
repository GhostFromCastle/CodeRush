Работа с файлами

~45 минут Продвинутый уровень Теория и Практика

До этого момента все наши программы жили только в оперативной памяти. Запустили программу, ввели данные, посмотрели результат, закрыли - и всё, что было, исчезло. Как будто записали что-то мелом на доске, а потом её протёрли.

Но реальным приложениям нужно запоминать состояние. Настройки пользователя, логи, сохранённые игры, историю операций, списки задач - всё это должно где-то храниться между запусками. И самое простое, самое универсальное хранилище - это файлы.

Сегодня разберёмся, как читать и записывать файлы, как работать с директориями и путями, и как делать это безопасно - так, чтобы программа не падала при малейшей проблеме с диском.

Файл как блокнот

Прежде чем говорить о коде, давайте разберёмся, что такое файл в понимании программы. Представьте блокнот. В нём есть текст, он лежит на полке (на диске), и у него есть название (имя файла). Всё.

У файла есть три ключевые характеристики:

  • Имя - например, data.txt.
  • Путь - где именно на диске он лежит.
  • Содержимое - байты, которые в нём записаны (текст, картинка, что угодно).

С точки зрения программы нет никакой разницы между текстовым файлом, картинкой или видео. Везде - просто последовательность байтов. Различие в том, как мы эти байты интерпретируем: читаем как текст, показываем как изображение или воспроизводим как звук.

Класс File: простые операции

В C# для работы с файлами есть несколько инструментов. Самый простой и удобный - класс File. Это набор статических методов, которые выполняют базовые операции за одну строку кода.

Запись текста

Самый простой способ записать текст в файл - метод File.WriteAllText:

string text = "Привет, файл!";File.WriteAllText("hello.txt", text);

Что произошло?

  • Если файла hello.txt не было - он создан.
  • Если файл был - его старое содержимое стёрто, записано новое.
  • Файл появился в папке с программой (рядом с .exe).

Если файл нужно не перезаписать, а дополнить, используют File.AppendAllText:

File.AppendAllText("log.txt", "Строка 1\n");File.AppendAllText("log.txt", "Строка 2\n");File.AppendAllText("log.txt", "Строка 3\n");

После этих трёх строк в файле log.txt будет три строки, а не одна последняя. Именно так пишут логгеры: каждый раз добавляют новую запись в конец файла, не трогая предыдущие.

Чтение текста

Обратная операция - File.ReadAllText:

string content = File.ReadAllText("hello.txt");Console.WriteLine(content);

Метод читает весь файл целиком и возвращает строку. Если файла нет - будет выброшено исключение FileNotFoundException.

Чтение построчно

Если файл большой (например, лог на миллион строк), читать его целиком в память - плохая идея. Используйте File.ReadLines - он возвращает строки по одной, не загружая всё сразу:

foreach (string line in File.ReadLines("log.txt")){    Console.WriteLine(line);}

Аналогия: вместо того чтобы тащить домой весь мешок картошки, вы берёте из него по одной картофелине. Память не забивается, а результат тот же.

Асинхронные версии

Помните урок 25 про асинхронность? У всех методов чтения и записи есть асинхронные версии с суффиксом Async: File.ReadAllTextAsync, File.WriteAllTextAsync, File.AppendAllTextAsync. В реальных приложениях (особенно в ASP.NET и десктопных приложениях с интерфейсом) всегда используйте асинхронные версии. Диск может тормозить, а синхронные операции блокируют поток, делая интерфейс «замороженным».

Классы FileInfo и DirectoryInfo

Статические методы File удобны для одноразовых операций. Но когда нужно работать с файлом многократно (проверить, есть ли, узнать размер, потом прочитать, потом скопировать), удобнее использовать объект FileInfo.

Аналогия: File.ReadAllText - это как попросить библиотекаря «принеси мне вон ту книгу». А FileInfo - это как взять в руки карточку из каталога, где написано всё о книге: год издания, количество страниц, полка, где она стоит.

FileInfo info = new FileInfo("data.txt");if (info.Exists){    Console.WriteLine($"Размер: {info.Length} байт");    Console.WriteLine($"Создан: {info.CreationTime}");    Console.WriteLine($"Изменён: {info.LastWriteTime}");}

Свойство Exists проверяет, существует ли файл. Свойство Length возвращает размер в байтах. CreationTime и LastWriteTime - даты создания и изменения.

У FileInfo есть и методы для действий:

  • Create() - создаёт пустой файл.
  • Delete() - удаляет.
  • CopyTo(path) - копирует.
  • MoveTo(path) - перемещает (или переименовывает).

Аналогично для папок есть класс DirectoryInfo:

DirectoryInfo dir = new DirectoryInfo("logs");if (!dir.Exists){    dir.Create();}FileInfo[] files = dir.GetFiles("*.txt");foreach (var f in files){    Console.WriteLine(f.Name);}

Здесь мы создаём папку logs, если её нет, а потом ищем в ней все файлы с расширением .txt.

Класс Path: работа с путями

Путь к файлу - это строка, но не простая. Windows использует обратные слеши (C:\folder\file.txt), Linux и macOS - прямые (/folder/file.txt). Склеивать пути вручную через плюс или + - плохая идея, потому что можно легко ошибиться с разделителем.

Для этого есть класс Path:

string fullPath = Path.Combine("data", "users", "list.txt");string fileName = Path.GetFileName(fullPath);string extension = Path.GetExtension(fullPath);string directory = Path.GetDirectoryName(fullPath);

Что делает каждая строка:

  • Combine - склеивает части пути, автоматически подставляя правильный разделитель под операционную систему.
  • GetFileName - возвращает имя файла (list.txt).
  • GetExtension - возвращает расширение (.txt).
  • GetDirectoryName - возвращает папку, в которой лежит файл.
Текущая папка программы

Если вы не указали полный путь, файл создастся в рабочей директории программы. Это папка, откуда запущено приложение, и она может отличаться от папки, где лежит .exe. Проверить её можно через Directory.GetCurrentDirectory().

Что может пойти не так

Работа с файлами - это всегда работа с чем-то внешним. Диск может быть переполнен, файл может быть занят другой программой, у пользователя может не быть прав. Поэтому практически всегда операции с файлами нужно оборачивать в try / catch.

Основные исключения:

  • FileNotFoundException - файла нет по указанному пути.
  • DirectoryNotFoundException - папки нет.
  • UnauthorizedAccessException - нет прав на чтение или запись.
  • IOException - общая ошибка ввода-вывода (например, файл занят другой программой).

Пример правильной обработки:

try{    string content = File.ReadAllText("config.txt");    Console.WriteLine(content);}catch (FileNotFoundException){    Console.WriteLine("Файл не найден, используем настройки по умолчанию");}catch (UnauthorizedAccessException){    Console.WriteLine("Нет прав на чтение файла");}catch (IOException ex){    Console.WriteLine($"Ошибка чтения: {ex.Message}");}

Обратите внимание: разные типы исключений обрабатываются по-разному. «Файла нет» - это нормальная ситуация, можно просто использовать дефолтные значения. «Нет прав» - уже проблема, о ней стоит сообщить. «Файл занят» - возможно, стоит попробовать ещё раз через секунду.

Пример: простой дневник

Соберём всё вместе в маленькой программе - дневнике. Она спрашивает у пользователя заметку и дописывает её в файл с датой.

static void Main(string[] args){    string path = Path.Combine("diary", "notes.txt");    Directory.CreateDirectory("diary");    while (true)    {        Console.Write("Заметка (или exit): ");        string input = Console.ReadLine();        if (input == "exit") break;        string entry = $"[{DateTime.Now:yyyy-MM-dd HH:mm}] {input}\n";        File.AppendAllText(path, entry);    }    Console.WriteLine("\nВаш дневник:");    foreach (string line in File.ReadLines(path))    {        Console.WriteLine(line);    }}

Разберём шаги:

  • Path.Combine - собираем путь до файла diary/notes.txt.
  • Directory.CreateDirectory("diary") - создаём папку, если её нет (если есть - ничего не произойдёт, метод не выдаёт ошибку).
  • В цикле спрашиваем заметку, добавляем дату и дописываем в файл через AppendAllText.
  • После выхода из цикла читаем весь файл построчно и выводим на экран.

Всего 20 строк - а получилось настоящее приложение, которое сохраняет данные между запусками.

Шпаргалка

Самое важное в одном месте:

  • File.ReadAllText прочитать файл целиком
  • File.ReadLines читать построчно
  • File.WriteAllText записать (перезаписать)
  • File.AppendAllText дописать в конец
  • FileInfo / DirectoryInfo информация о файле или папке
  • Path.Combine склеить путь
  • try / catch обязательно вокруг операций с файлами

Если что-то не работает

Разберём типичные ошибки и заблуждения при работе с файлами.

  • «Программа работает, но файла не видно». Скорее всего, файл создан в рабочей директории программы, а не там, где вы его ищете. Проверьте Directory.GetCurrentDirectory() - там точно есть ваш файл. Или используйте полный путь через Path.Combine.
  • «Файл занят другим процессом». Классика: вы открыли файл в блокноте, а программа пытается в него записать. Windows блокирует файл, пока его кто-то держит открытым. Закройте блокнот или используйте FileShare.ReadWrite через FileStream (но это уже сложнее).
  • «Я прочитал файл - и получил кракозябры». Проблема с кодировкой. По умолчанию File.ReadAllText использует UTF-8, но если файл сохранён в другой кодировке (например, Windows-1251), символы отобразятся неправильно. Решение - явно указать кодировку: File.ReadAllText(path, Encoding.GetEncoding(1251)).
  • «Файл создаётся, но пустой». Проверьте, что вы точно вызываете WriteAllText или AppendAllText - иногда забывают вызвать саму запись, а только создают FileInfo или открывают StreamWriter, но не пишут в него.
  • «Программа падает на File.ReadAllText». Файла нет. Всегда оборачивайте чтение в try / catch или предварительно проверяйте File.Exists(path).
  • «Не работает на Linux / Mac». Обратные слеши в путях (C:\folder\file.txt) - это Windows-специфика. Используйте Path.Combine - он автоматически подставит правильный разделитель под систему.
  • «Можно ли писать в файлы рядом с .exe?» Обычно да, но если программа установлена в Program Files - система может запретить запись. Лучше писать в специальные папки для данных приложения (Environment.GetFolderPath(SpecialFolder.ApplicationData)).

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Запись и чтение

Напишите программу, которая:

  1. Спрашивает у пользователя три строки.
  2. Записывает их в файл notes.txt, каждую с новой строки.
  3. Читает файл обратно и выводит содержимое на экран.

Подсказка

Используйте Console.ReadLine() в цикле или трижды. Для записи - File.WriteAllText или File.AppendAllText. Для чтения - File.ReadAllText.

Решение учителя 
static void Main(string[] args){    string path = "notes.txt";    Console.WriteLine("Введите три строки:");    string s1 = Console.ReadLine();    string s2 = Console.ReadLine();    string s3 = Console.ReadLine();    File.WriteAllText(path, $"{s1}\n{s2}\n{s3}\n");    Console.WriteLine("\nСодержимое файла:");    Console.WriteLine(File.ReadAllText(path));}
Задача 2. Счётчик запусков

Напишите программу, которая считает, сколько раз её запускали. При каждом запуске она должна выводить «Это запуск номер N» и увеличивать счётчик. Храните число в файле counter.txt.

Подсказка

Проверьте через File.Exists, есть ли файл. Если нет - счётчик равен 0. Если есть - прочитайте число через int.Parse. Увеличьте на 1 и запишите обратно через File.WriteAllText.

Решение учителя 
static void Main(string[] args){    string path = "counter.txt";    int count = 0;    if (File.Exists(path))    {        string content = File.ReadAllText(path);        int.TryParse(content, out count);    }    count++;    File.WriteAllText(path, count.ToString());    Console.WriteLine($"Это запуск номер {count}");}

Обратите внимание на int.TryParse вместо int.Parse. Если файл повреждён (например, кто-то вписал туда буквы), Parse выбросит исключение, а TryParse просто вернёт 0. Надёжнее.

Задача 3. Поиск в логе

Дан файл log.txt, в котором каждая строка начинается с даты в формате yyyy-MM-dd (например, 2025-03-15 Ошибка подключения). Напишите программу, которая просит у пользователя дату и выводит все строки за эту дату.

Подсказка

Используйте File.ReadLines - он читает файл построчно и не загружает всё в память. Внутри цикла проверяйте, начинается ли строка с введённой даты через StartsWith. Не забудьте проверить File.Exists.

Решение учителя 
static void Main(string[] args){    string path = "log.txt";    if (!File.Exists(path))    {        Console.WriteLine("Файл лога не найден");        return;    }    Console.Write("Введите дату (yyyy-MM-dd): ");    string date = Console.ReadLine();    Console.WriteLine($"\nСтроки за {date}:");    foreach (string line in File.ReadLines(path))    {        if (line.StartsWith(date))        {            Console.WriteLine(line);        }    }}

Здесь важно, что мы не читаем весь файл в память через ReadAllText. Если лог на гигабайт - ReadLines справится, а ReadAllText положит программу.

Задача 4. Резервная копия

Напишите метод BackupFile(string source, string backupFolder), который копирует указанный файл в папку backupFolder, добавляя к имени текущую дату. Например, файл data.txt превращается в backup/data_2025-03-15.txt. Обработайте случай, когда исходного файла нет, и случай, когда папки для бэкапа ещё не существует.

Подсказка

Используйте File.Exists для проверки исходного файла. Directory.CreateDirectory создаст папку, если её нет (и не выдаст ошибку, если уже есть). Для формирования нового имени - Path.GetFileNameWithoutExtension, Path.GetExtension и DateTime.Now. Для копирования - File.Copy.

Решение учителя 
static void BackupFile(string source, string backupFolder){    if (!File.Exists(source))    {        Console.WriteLine($"Файл {source} не найден");        return;    }    Directory.CreateDirectory(backupFolder);    string name = Path.GetFileNameWithoutExtension(source);    string ext = Path.GetExtension(source);    string date = DateTime.Now.ToString("yyyy-MM-dd");    string target = Path.Combine(backupFolder, $"{name}_{date}{ext}");    File.Copy(source, target, overwrite: true);    Console.WriteLine($"Копия создана: {target}");}static void Main(string[] args){    BackupFile("data.txt", "backup");}

Параметр overwrite: true в File.Copy означает, что если копия за сегодня уже есть - она будет перезаписана. Если не хотите перезаписывать - уберите параметр, и при попытке копирования поверх существующего файла File.Copy выбросит исключение.

Что мы узнали и что дальше

Сегодня мы научились работать с файлами - одним из самых базовых и самых нужных инструментов любого разработчика. Разобрали:

  • Простые операции через класс File: ReadAllText, WriteAllText, AppendAllText.
  • Чтение больших файлов построчно через File.ReadLines.
  • Информацию о файлах и папках через FileInfo и DirectoryInfo.
  • Работу с путями через класс Path - чтобы код работал и на Windows, и на Linux, и на macOS.
  • Обработку ошибок: FileNotFoundException, UnauthorizedAccessException, IOException.

Теперь ваши программы умеют сохранять состояние между запусками. Это огромный шаг: любое серьёзное приложение - от простого блокнота до крупного сервиса - что-то хранит на диске.

Но текстовый формат - не всегда удобен. Если нужно сохранить сложный объект с десятками полей (пользователя, заказ, настройки), писать парсеры вручную - это боль. К счастью, для этого есть JSON - универсальный формат данных, который понимают все языки программирования. О нём и поговорим в следующем уроке: научимся превращать объекты C# в JSON и обратно одной строкой кода.
