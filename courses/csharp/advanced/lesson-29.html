Асинхронность

~45 минут Продвинутый уровень Теория и Практика

Представьте, что вы открыли программу, нажали кнопку «Загрузить файл», и... окно замерло. Курсор мыши не двигается, кнопки не нажимаются. Программа зависла на 10 секунд, пока файл качался. Это классический пример синхронного выполнения - когда одна долгая операция блокирует всё остальное.

В современном мире такое недопустимо. Пользователь не должен ждать. Именно для этого придумали асинхронность. Это способ выполнять долгие операции в фоне, не блокируя основной поток программы.

Синхронный официант против Асинхронного

Представьте ресторан.

Синхронный официант принимает заказ у столика №1, идёт на кухню, стоит там, пока повар готовит (10 минут), забирает еду, несёт клиенту. Всё это время столик №2 и №3 ждут, потому что официант занят. Это блокирующий вызов.

Асинхронный официант принимает заказ у столика №1, передаёт его на кухню и сразу идёт к столику №2. Пока повар готовит еду для первого, официант обслуживает других. Когда еда готова, повар зовёт официанта, и тот несёт её клиенту. Никто не ждёт впустую.

Главная мысль

Асинхронность не ускоряет саму операцию (файл всё равно будет качаться 10 секунд). Она позволяет не блокировать основной поток и заниматься другими делами, пока операция выполняется в фоне.

Класс Task

В C# за асинхронные операции отвечает класс Task (задача). Это как квитанция, которую вам выдают, когда вы сдаёте вещи в химчистку. Вещи пока не готовы, но у вас есть квитанция (Task), по которой вы можете проверить статус или забрать результат.

  • Task - асинхронная операция, которая ничего не возвращает.
  • Task<T> - асинхронная операция, которая возвращает результат типа T.

Самый простой способ создать задачу - использовать Task.Delay(), который имитирует долгую работу (ожидание).

static async Task Main(string[] args){    Console.WriteLine("Начинаю готовить...");    await Task.Delay(3000); // Ждём 3 секунды    Console.WriteLine("Ужин готов!");}

Магия async и await

Синтаксис асинхронности в C# строится на двух ключевых словах:

  • async - ставится перед методом. Оно говорит компилятору: «Этот метод может содержать асинхронные операции».
  • await - ставится перед вызовом асинхронной операции. Оно говорит: «Подожди, пока задача выполнится, но пока ждёшь - не блокируй поток. Пусть другие задачи работают».

Посмотрите на пример выше. Метод Main помечен как async. Внутри мы вызываем Task.Delay(3000) и ставим перед ним await. Что происходит:

  1. Программа выводит «Начинаю готовить...».
  2. Встречает await. Запускается таймер на 3 секунды, но основной поток освобождается. Он может заниматься другими делами (если они есть).
  3. Через 3 секунды таймер срабатывает, управление возвращается в метод.
  4. Программа выводит «Ужин готов!».

Асинхронный метод, возвращающий результат

Если метод должен вернуть значение, используется Task<T>. А в самом методе мы возвращаем результат через return, но тип метода всё равно указываем асинхронным.

static async Task<int> DownloadFileAsync(){    Console.WriteLine("Скачивание началось...");    await Task.Delay(2000);    return 1024; // размер файла в КБ}static async Task Main(string[] args){    int size = await DownloadFileAsync();    Console.WriteLine($"Размер файла: {size} КБ");}

Обратите внимание: когда мы вызываем DownloadFileAsync(), мы не получаем сразу число. Мы получаем Task<int>. И только когда ставим await, мы дожидаемся завершения задачи и достаём из неё значение int.

Запуск нескольких задач одновременно

Асинхронность позволяет запустить несколько долгих операций параллельно. Для этого используется метод Task.WhenAll.

static async Task Main(string[] args){    Task task1 = LongOperationAsync("Задача 1", 2000);    Task task2 = LongOperationAsync("Задача 2", 3000);    Task task3 = LongOperationAsync("Задача 3", 1000);    // Запускаем все три и ждём, пока они ВСЕ завершатся    await Task.WhenAll(task1, task2, task3);    Console.WriteLine("Все задачи завершены!");}static async Task LongOperationAsync(string name, int delay){    await Task.Delay(delay);    Console.WriteLine($"{name} выполнена");}

В этом примере все три операции начнутся почти одновременно. Общее время выполнения будет равно самой долгой задаче (3 секунды), а не сумме всех трёх (6 секунд).

Золотые правила асинхронности

Асинхронность - это мощно, но требует дисциплины. Вот три правила, которые нельзя нарушать.

1. Не используйте .Result и .Wait()

Если у вас есть асинхронный метод, никогда не пытайтесь получить его результат синхронно через свойство .Result или метод .Wait(). Это блокирует поток и может привести к взаимной блокировке (deadlock). Всегда используйте await.

2. Не используйте async void

Асинхронные методы должны возвращать Task или Task<T>. Тип async void существует только для обработчиков событий (например, кнопок). Если использовать его в обычных методах, вы не сможете отследить завершение задачи или поймать исключение.

3. Добавляйте суффикс Async

По соглашению об именовании, асинхронные методы должны заканчиваться на Async (например, DownloadFileAsync). Это сразу подсказывает другим разработчикам, что метод нужно вызывать с await.

Шпаргалка

Самое важное в одном месте:

  • async модификатор асинхронного метода
  • await ожидание задачи без блокировки
  • Task задача без результата
  • Task<T> задача с результатом
  • Task.Delay() асинхронная пауза
  • Task.WhenAll() параллельное выполнение

Если что-то не работает

Разберём типичные ошибки при работе с асинхронностью.

  • Программа всё равно зависает. Проверьте, что перед всеми асинхронными методами стоит await. Если вы просто вызываете DownloadFileAsync() без await, задача запустится в фоне, но программа не будет её ждать.
  • «Cannot implicitly convert type 'Task<int>' to 'int'». Вы забыли поставить await перед вызовом метода. Без await вы получаете не число, а саму задачу.
  • Приложение зависло намертво (Deadlock). Скорее всего, вы использовали .Result или .Wait() вместо await. В консольных приложениях это редкость, но в Windows Forms или WPF - частая проблема.
  • Исключение внутри асинхронного метода не ловится. Если вы используете async void, исключение не передастся в вызывающий код. Убедитесь, что метод возвращает Task.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Простой асинхронный метод

Напишите асинхронный метод PrintWithDelay, который принимает строку и число (задержку в миллисекундах). Метод должен выводить строку на экран после указанной паузы.

Подсказка

Метод должен возвращать Task. Внутри используйте await Task.Delay(ms);, а затем Console.WriteLine(text);. Не забудьте вызвать его из Main с await.

Решение учителя 
static async Task PrintWithDelay(string text, int ms){    await Task.Delay(ms);    Console.WriteLine(text);}static async Task Main(string[] args){    Console.WriteLine("Старт");    await PrintWithDelay("Прошло 2 секунды", 2000);}
Задача 2. Возврат результата

Напишите асинхронный метод CalculateSumAsync, который принимает два числа, ждёт 1 секунду и возвращает их сумму. Вызовите метод и выведите результат.

Подсказка

Метод должен возвращать Task<int>. Внутри после await Task.Delay(1000) напишите return a + b;.

Решение учителя 
static async Task<int> CalculateSumAsync(int a, int b){    await Task.Delay(1000);    return a + b;}static async Task Main(string[] args){    int result = await CalculateSumAsync(5, 10);    Console.WriteLine($"Сумма: {result}");}
Задача 3. Параллельный запуск

Создайте три задачи, которые выводят разные сообщения с разными задержками (1 сек, 2 сек, 3 сек). Запустите их одновременно с помощью Task.WhenAll. Убедитесь, что сообщение о завершении всех задач выводится последним.

Подсказка

Сохраните каждый вызов PrintWithDelay в переменную типа Task. Затем вызовите await Task.WhenAll(t1, t2, t3);. После этого выведите финальное сообщение.

Решение учителя 
static async Task Main(string[] args){    Task t1 = PrintWithDelay("Задача 1 (3 сек)", 3000);    Task t2 = PrintWithDelay("Задача 2 (1 сек)", 1000);    Task t3 = PrintWithDelay("Задача 3 (2 сек)", 2000);    await Task.WhenAll(t1, t2, t3);    Console.WriteLine("Все задачи завершены!");}

Результат будет: сначала «Задача 2», потом «Задача 3», и в конце «Задача 1». А только после этого - финальное сообщение.

Задача 4. Скачивание файлов

Напишите метод DownloadFileAsync(string name, int size), который имитирует скачивание файла. Метод должен вывести «Начало скачивания [name]», подождать size миллисекунд и вывести «[name] скачан. Размер: [size]». Запустите скачивание трёх файлов параллельно.

Подсказка

Используйте Task.WhenAll так же, как в предыдущей задаче. Обратите внимание, что сообщение «Начало скачивания» должно появиться сразу у всех трёх файлов, а не по очереди.

Решение учителя 
static async Task DownloadFileAsync(string name, int size){    Console.WriteLine($"Начало скачивания {name}");    await Task.Delay(size);    Console.WriteLine($"{name} скачан. Размер: {size}");}static async Task Main(string[] args){    Task f1 = DownloadFileAsync("Фото.jpg", 2000);    Task f2 = DownloadFileAsync("Музыка.mp3", 4000);    Task f3 = DownloadFileAsync("Видео.mp4", 6000);    await Task.WhenAll(f1, f2, f3);    Console.WriteLine("Все файлы скачаны!");}

Что мы узнали и что дальше

Вы прикоснулись к одной из самых сложных и важных тем в C#. Теперь вы знаете, что такое Task, зачем нужны async и await, и как заставить программу выполнять несколько дел одновременно, не зависая.

Это базовый уровень асинхронности, достаточный для 90% повседневных задач. Теперь ваши программы могут скачивать данные, работать с базами данных и обрабатывать файлы, оставаясь отзывчивыми к действиям пользователя.
