JOIN: соединяем таблицы

~35 минут Средний уровень Теория и Практика

В реальной базе данные разложены по таблицам: пользователи отдельно, заказы отдельно, товары отдельно. Чтобы получить осмысленный ответ, их нужно соединить. За это отвечает JOIN - самая важная тема в SQL после SELECT.

В этом уроке мы:

  • Поймём, зачем нужно соединение и как работает ON.
  • Разберём INNER, LEFT, RIGHT и FULL.
  • Научимся соединять таблицу с самой собой.
  • Разберём три ловушки, из-за которых результат получается неверным.
Аналогия

Два списка: гости и рассадка. JOIN сшивает их по имени гостя, чтобы за столом оказался нужный человек.

Две таблицы

users.idusers.name
1Анна
2Борис
3Вера
orders.idorders.customer_idorders.price
10175000
11130000

У Веры заказов нет. Если написать SELECT * FROM orders, мы увидим только номера клиентов, но не имена. Нужно соединить таблицы по правилу orders.customer_id = users.id.

INNER JOIN

SELECT    users.name,    orders.id   AS order_id,    orders.priceFROM ordersINNER JOIN users ON users.id = orders.customer_id;
nameorder_idprice
Анна1075000
Анна1130000
Борис121500

INNER JOIN оставляет только те пары строк, для которых условие выполнено. Вера не попала в результат: у неё нет заказов. Анна попала дважды: у неё два заказа.

Ключевое слово INNER можно опустить - JOIN по умолчанию означает именно внутреннее соединение.

Алиасы таблиц

Когда таблиц несколько, писать полные имена утомительно. Дадим короткие псевдонимы:

SELECT    u.name,    o.id AS order_id,    o.priceFROM orders AS oJOIN users AS u ON u.id = o.customer_id;

Обратите внимание: AS для таблиц пишут почти всегда, даже если имя короткое. В запросах на пять таблиц это спасает читаемость.

LEFT JOIN

Если нужны все пользователи, включая тех, кто ничего не купил, используется левое соединение:

SELECT    u.name,    o.id AS order_idFROM users AS uLEFT JOIN orders AS o ON o.customer_id = u.id;
nameorder_id
Анна10
Анна11
Борис12
ВераNULL

LEFT JOIN берёт все строки из левой таблицы и подставляет совпадения из правой. Если совпадений нет - вместо них NULL.

Найти клиентов без заказов можно так:

SELECT u.nameFROM users AS uLEFT JOIN orders AS o ON o.customer_id = u.idWHERE o.id IS NULL;

RIGHT и FULL

RIGHT JOIN - зеркальный: все строки из правой таблицы. На практике его почти не используют: любой правый join переписывается как левый с перестановкой таблиц, а читать слева направо привычнее.

FULL OUTER JOIN возвращает все строки из обеих таблиц, подставляя NULL там, где пары нет. В SQLite он появился только в версии 3.39, в MySQL его нет - эмулируют через UNION левого и правого соединений.

Соединение таблицы с собой

Иногда связь идёт внутри одной таблицы. Пример: у сотрудника есть руководитель, который тоже сотрудник.

SELECT    e.name  AS employee,    m.name  AS managerFROM employees AS eLEFT JOIN employees AS m ON m.id = e.manager_id;

Без алиасов база не поймёт, о каком employees идёт речь. Псевдонимы e и m делают запрос однозначным.

Три таблицы и больше

Соединения выстраиваются цепочкой. Каждый следующий JOIN присоединяется к результату предыдущих:

SELECT    u.name,    o.id          AS order_id,    p.title,    oi.quantityFROM orders AS oJOIN users AS u       ON u.id = o.customer_idJOIN order_items AS oi ON oi.order_id = o.idJOIN products AS p     ON p.id = oi.product_id;

Читается так: «взять заказы, добавить к ним клиента, затем позиции заказа, затем товар для каждой позиции».

Три ловушки JOIN

1. Забыли ON - получили декартово произведение: каждая строка с каждой. На тысячах строк это миллионы результатов и зависший сервер. 2. Условие на правую таблицу написали в WHERE вместо ON - и LEFT JOIN превратился во внутренний. 3. Соединили «один ко многим» и считаете сумму - строка заказа размножилась по позициям, и сумма задвоилась.

Шпаргалка

  • JOIN ... ON внутреннее соединение
  • LEFT JOIN все строки левой таблицы
  • IS NULL найти отсутствующие связи
  • AS u алиас таблицы
  • FULL JOIN все строки обеих таблиц

Если что-то не работает

  • Слишком много строк. Скорее всего, пропущено условие ON или связь неверная.
  • LEFT JOIN ведёт себя как INNER. Условие по правой таблице стоит в WHERE - перенесите его в ON.
  • «Ambiguous column name». Столбец есть в обеих таблицах - укажите алиас: u.id, o.id.
  • Суммы завышены. Дубли из-за связи «один ко многим». Считайте через подзапрос или DISTINCT.
  • FULL JOIN не работает. В MySQL его нет, в старом SQLite - тоже. Используйте UNION.
  • «После JOIN сумма удвоилась». Один заказ соединили с пятью позициями - и его сумма посчиталась пять раз. Считайте деньги на уровне заказа, а не позиции.

Практика

Задача 1. Заказы с именами

Выведите имя клиента, номер заказа и цену для всех заказов, отсортировав по цене от большей к меньшей.

Подсказка

FROM orders o JOIN users u ON u.id = o.customer_id, затем ORDER BY o.price DESC.

Решение учителя 
SELECT u.name, o.id AS order_id, o.priceFROM orders AS oJOIN users AS u ON u.id = o.customer_idORDER BY o.price DESC;
Задача 2. Клиенты без покупок

Найдите всех пользователей, у которых нет ни одного заказа.

Подсказка

LEFT JOIN от пользователей к заказам и условие WHERE o.id IS NULL.

Решение учителя 
SELECT u.id, u.nameFROM users AS uLEFT JOIN orders AS o ON o.customer_id = u.idWHERE o.id IS NULL;
Задача 3. Сумма по клиентам

Посчитайте сумму заказов каждого клиента, включая тех, у кого заказов нет (у них должно быть 0, а не NULL).

Подсказка

LEFT JOIN + GROUP BY u.id, u.name + COALESCE(SUM(o.price), 0).

Решение учителя 
SELECT    u.name,    COALESCE(SUM(o.price), 0) AS totalFROM users AS uLEFT JOIN orders AS o ON o.customer_id = u.idGROUP BY u.id, u.nameORDER BY total DESC;
Задача 4. Товары в категориях

Выведите название категории и количество товаров в ней, включая пустые категории.

Подсказка

LEFT JOIN от категорий к товарам и COUNT(p.id), чтобы пустая категория дала 0, а не 1.

Решение учителя 
SELECT    c.title,    COUNT(p.id) AS products_countFROM categories AS cLEFT JOIN products AS p ON p.category_id = c.idGROUP BY c.id, c.titleORDER BY products_count DESC;

Что мы узнали и что дальше

Соединения больше не пугают. Теперь вы знаете:

  • Как работает JOIN ... ON и чем отличается от LEFT JOIN.
  • Как найти строки без пары через IS NULL.
  • Как соединять таблицу с собой и строить цепочки из нескольких таблиц.
  • Какие три ошибки чаще всего портят результат.
