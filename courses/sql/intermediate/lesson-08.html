Подзапросы и EXISTS

~30 минут Средний уровень Теория и Практика

Иногда ответ нельзя получить одним плоским запросом: сначала нужно посчитать одно, потом использовать это в другом. Для этого существуют подзапросы - запрос внутри запроса.

В этом уроке мы:

  • Разберём скалярные подзапросы.
  • Научимся использовать IN и EXISTS.
  • Поймём, что такое коррелированный подзапрос.
  • Сравним подзапросы с соединениями.
Аналогия

Матрёшка: внутри одного запроса живёт другой, поменьше.

Скалярный подзапрос

Подзапрос в скобках возвращает одно значение и может стоять в любом месте, где допустимо значение:

SELECT title, priceFROM productsWHERE price > (SELECT AVG(price) FROM products);

Сначала выполняется внутренний запрос - получаем среднюю цену. Затем внешний сравнивает с ней каждую строку. Результат: товары дороже среднего.

Такой подзапрос можно использовать и в SELECT:

SELECT    title,    price,    price - (SELECT AVG(price) FROM products) AS diff_from_avgFROM products;

IN и NOT IN

Подзапрос может вернуть столбец значений - тогда его используют со списком:

SELECT nameFROM usersWHERE id IN (    SELECT customer_id FROM orders WHERE price > 50000);

Читается: «пользователи, чей id есть среди клиентов с крупными заказами».

NOT IN и NULL

Если подзапрос вернёт хотя бы один NULL, NOT IN не вернёт ничего. Причина - логика трёхзначности. Надёжнее использовать NOT EXISTS или добавить WHERE customer_id IS NOT NULL внутри подзапроса.

EXISTS

EXISTS проверяет не значения, а факт наличия строк:

SELECT u.nameFROM users AS uWHERE EXISTS (    SELECT 1    FROM orders AS o    WHERE o.customer_id = u.id);

Результат: пользователи, у которых есть хотя бы один заказ. Внутри SELECT 1 - традиция: конкретные столбцы не важны, проверяется сам факт.

Обратная задача - клиенты без заказов:

SELECT u.nameFROM users AS uWHERE NOT EXISTS (    SELECT 1 FROM orders AS o WHERE o.customer_id = u.id);

Коррелированный подзапрос

В примерах выше подзапрос ссылается на u.id из внешнего запроса. Такой подзапрос называется коррелированным: он выполняется для каждой строки внешнего запроса.

SELECT    u.name,    (SELECT COUNT(*) FROM orders o WHERE o.customer_id = u.id) AS orders_countFROM users AS u;

Для каждого пользователя база считает его заказы. Результат тот же, что у LEFT JOIN + GROUP BY, но записан иначе.

Подзапрос в FROM

Подзапрос может заменить таблицу - получается «производная таблица»:

SELECT    customer_id,    totalFROM (    SELECT        customer_id,        SUM(price) AS total    FROM orders    GROUP BY customer_id) AS totalsWHERE total > 50000;

Сначала считается агрегат по клиентам, затем внешний запрос фильтрует результат. Псевдоним AS totals обязателен: у производной таблицы должно быть имя.

Подзапрос или JOIN?

Многие задачи решаются обоими способами. Ориентируйтесь на читаемость:

  • Подзапрос лучше, когда нужен один агрегат или проверка существования.
  • JOIN лучше, когда нужны столбцы из второй таблицы.
  • По производительности современные СУБД часто преобразуют одно в другое - не оптимизируйте вслепую, смотрите план запроса.

Шпаргалка

  • (SELECT ...) подзапрос
  • IN значение из набора
  • EXISTS есть ли строки
  • NOT EXISTS строк нет
  • FROM (SELECT ...) AS t производная таблица

Если что-то не работает

  • «Subquery returns more than one row». Скалярный подзапрос вернул несколько значений - добавьте LIMIT 1 или используйте IN.
  • NOT IN ничего не находит. В подзапросе есть NULL. Замените на NOT EXISTS.
  • Запрос очень медленный. Коррелированный подзапрос выполняется для каждой строки. Попробуйте переписать через JOIN.
  • «Every derived table must have its own alias». Забыли AS имя после подзапроса в FROM.
  • «Подзапрос вернул несколько строк». Скалярный подзапрос должен возвращать одно значение. Если значений много - используйте IN или EXISTS.

Практика

Задача 1. Дороже среднего

Выведите товары, цена которых выше средней по всей таблице. В результате покажите название, цену и разницу со средней.

Подсказка

Среднее: (SELECT AVG(price) FROM products). Его можно использовать и в WHERE, и в SELECT.

Решение учителя 
SELECT    title,    price,    price - (SELECT AVG(price) FROM products) AS diffFROM productsWHERE price > (SELECT AVG(price) FROM products);
Задача 2. Покупатели

Найдите имена пользователей, сделавших хотя бы один заказ дороже 50 000. Решите задачу через IN и через EXISTS.

Подсказка

Через IN: id IN (SELECT customer_id FROM orders WHERE price > 50000). Через EXISTS - подзапрос с условием на u.id и цену.

Решение учителя 
SELECT name FROM usersWHERE id IN (SELECT customer_id FROM orders WHERE price > 50000);SELECT u.name FROM users AS uWHERE EXISTS (    SELECT 1 FROM orders AS o    WHERE o.customer_id = u.id AND o.price > 50000);
Задача 3. Клиенты без заказов

Решите задачу из прошлого урока через NOT EXISTS и сравните с вариантом через LEFT JOIN ... IS NULL.

Подсказка

WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = u.id). Результат должен совпасть.

Решение учителя 
SELECT u.nameFROM users AS uWHERE NOT EXISTS (    SELECT 1 FROM orders AS o WHERE o.customer_id = u.id);

Оба варианта дают одинаковый результат. NOT EXISTS обычно читается яснее и не ломается на NULL.

Задача 4. Дороже среднего в категории

Найдите товары, цена которых выше средней цены в их собственной категории.

Подсказка

Нужен коррелированный подзапрос: средняя цена считается для category_id текущей строки.

Решение учителя 
SELECT p.title, p.price, p.category_idFROM products AS pWHERE p.price > (    SELECT AVG(p2.price)    FROM products AS p2    WHERE p2.category_id = p.category_id);
