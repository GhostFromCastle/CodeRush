Финальный проект: база интернет-магазина

~45 минут Продвинутый уровень Теория и Практика

Это финальный урок курса. Мы соберём базу интернет-магазина целиком: спроектируем схему, наполним её данными и напишем шесть аналитических запросов, которые встречаются в реальной работе.

В этом уроке мы:

  • Спроектируем схему из пяти таблиц.
  • Создадим её с ключами и ограничениями.
  • Наполним тестовыми данными.
  • Напишем отчёты: выручка, топ товаров, средний чек, LTV и не только.
Аналогия

Сборка мебели: сначала чертёж (схема), потом детали (данные), потом инструкция (запросы). Пропущенный чертёж гарантирует лишние болты.

Требования

Магазин продаёт товары из категорий. Клиенты оформляют заказы, в каждом заказе несколько позиций. Нужно уметь отвечать на вопросы:

  • Сколько выручки принёс каждый месяц?
  • Какие товары продаются лучше всего?
  • Какой средний чек?
  • Сколько потратил каждый клиент за всё время?
  • Какие товары ни разу не покупали?
  • Как менялась выручка месяц к месяцу?

Схема

categories ──< products ──< order_items >── orders >── customers
  • categories - справочник категорий.
  • products - товары, ссылаются на категорию.
  • customers - клиенты.
  • orders - заказы, ссылаются на клиента.
  • order_items - позиции заказа, связывают заказ и товар.

Таблица order_items - классический пример связи «многие ко многим»: один заказ содержит много товаров, один товар встречается во многих заказах.

Шаг 1. Создаём таблицы

SQL 
CREATE TABLE categories (
    id    INTEGER PRIMARY KEY,
    title TEXT NOT NULL UNIQUE
);

CREATE TABLE products (
    id          INTEGER PRIMARY KEY,
    category_id INTEGER NOT NULL,
    title       TEXT    NOT NULL,
    price       INTEGER NOT NULL CHECK (price >= 0),
    FOREIGN KEY (category_id) REFERENCES categories (id)
);

CREATE TABLE customers (
    id    INTEGER PRIMARY KEY,
    name  TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE
);

CREATE TABLE orders (
    id          INTEGER PRIMARY KEY,
    customer_id INTEGER NOT NULL,
    created_at  TEXT    NOT NULL,
    status      TEXT    NOT NULL DEFAULT 'paid'
                CHECK (status IN ('new', 'paid', 'cancelled')),
    FOREIGN KEY (customer_id) REFERENCES customers (id)
);

CREATE TABLE order_items (
    order_id   INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    quantity   INTEGER NOT NULL CHECK (quantity > 0),
    price      INTEGER NOT NULL CHECK (price >= 0),
    PRIMARY KEY (order_id, product_id),
    FOREIGN KEY (order_id)   REFERENCES orders (id)   ON DELETE CASCADE,
    FOREIGN KEY (product_id) REFERENCES products (id)
);

Цена хранится и в products, и в order_items. Это осознанное решение: цена товара может измениться, а в заказе должна остаться та, по которой покупали.

Запрос 1. Выручка по месяцам

SELECT    STRFTIME('%Y-%m', o.created_at) AS month,    SUM(oi.quantity * oi.price)     AS revenueFROM orders AS oJOIN order_items AS oi ON oi.order_id = o.idWHERE o.status = 'paid'GROUP BY monthORDER BY month;

Обратите внимание на WHERE status = 'paid': отменённые заказы не должны попадать в выручку. Это первое, что забывают уточнить в реальных задачах.

Запрос 2. Топ товаров

SELECT    p.title,    SUM(oi.quantity) AS sold,    SUM(oi.quantity * oi.price) AS revenueFROM order_items AS oiJOIN products AS p ON p.id = oi.product_idJOIN orders AS o   ON o.id = oi.order_idWHERE o.status = 'paid'GROUP BY p.id, p.titleORDER BY sold DESC;

Запрос 3. Средний чек

WITH order_totals AS (    SELECT        o.id,        SUM(oi.quantity * oi.price) AS total    FROM orders AS o    JOIN order_items AS oi ON oi.order_id = o.id    WHERE o.status = 'paid'    GROUP BY o.id)SELECT ROUND(AVG(total), 2) AS avg_order_valueFROM order_totals;

Средний чек - это среднее от суммы заказа, а не среднее по позициям. Поэтому сначала считаем итог каждого заказа, потом усредняем.

Запрос 4. Сколько потратил каждый клиент

SELECT    c.name,    COALESCE(SUM(oi.quantity * oi.price), 0) AS lifetime_valueFROM customers AS cLEFT JOIN orders AS o      ON o.customer_id = c.id AND o.status = 'paid'LEFT JOIN order_items AS oi ON oi.order_id = o.idGROUP BY c.id, c.nameORDER BY lifetime_value DESC;

LEFT JOIN нужен, чтобы клиенты без покупок тоже попали в отчёт с нулём. Условие status = 'paid' стоит в ON, а не в WHERE - иначе левое соединение превратится во внутреннее.

Запрос 5. Товары без продаж

SELECT p.titleFROM products AS pLEFT JOIN order_items AS oi ON oi.product_id = p.idWHERE oi.product_id IS NULL;

Запрос 6. Динамика месяц к месяцу

WITH monthly AS (    SELECT        STRFTIME('%Y-%m', o.created_at) AS month,        SUM(oi.quantity * oi.price)     AS revenue    FROM orders AS o    JOIN order_items AS oi ON oi.order_id = o.id    WHERE o.status = 'paid'    GROUP BY month)SELECT    month,    revenue,    revenue - LAG(revenue) OVER (ORDER BY month) AS diff,    ROUND(        100.0 * (revenue - LAG(revenue) OVER (ORDER BY month))        / LAG(revenue) OVER (ORDER BY month),        1    ) AS growth_percentFROM monthlyORDER BY month;

Что можно улучшить

  • Индексы. orders(customer_id), order_items(product_id), orders(created_at).
  • Статусы. Вынести в отдельную таблицу-справочник вместо CHECK.
  • Мягкое удаление. Столбец deleted_at вместо физического удаления клиентов.
  • История цен. Отдельная таблица product_prices с датами действия.
  • Представления. Сохранить готовые отчёты как VIEW.

Шпаргалка

  • JOIN ... ON связать таблицы по ключу
  • GROUP BY итоги по группам
  • HAVING фильтр групп
  • LEFT JOIN ... IS NULL найти отсутствующие связи
  • WITH разбить запрос на шаги
  • LAG сравнить с предыдущей строкой
  • WHERE status = 'paid' не забыть про отменённые заказы

Если что-то не работает

  • «Суммы завышены в два раза». Соединили заказы с позициями и посчитали ' SUM(price) по строкам заказа. Сначала считайте итог заказа в подзапросе.
  • «В отчёте меньше клиентов, чем в базе». Использован INNER JOIN: ' 'клиенты без заказов отсеклись. Для полного списка нужен LEFT JOIN.
  • «LEFT JOIN превратился в обычный». Условие по правой таблице попало в ' 'WHERE - перенесите его в ON.
  • «Выручка не сходится с бухгалтерией». Не исключены отменённые заказы или ' 'не учтены возвраты. Проверяйте статусы в каждом отчёте.
  • «Запрос на миллионе строк не возвращается». Нет индексов по ' created_at и customer_id. Посмотрите EXPLAIN.
  • «Отчёт не учитывает отменённые заказы». В выручке они не должны участвовать, а в истории клиента - должны. Статус нужно проверять осознанно в каждом отчёте, а не копировать условие из соседнего запроса.

Практика

Задача 1. Продажи по категориям

Посчитайте выручку по категориям за оплаченные заказы. Отсортируйте по убыванию.

Подсказка

Соедините order_items → products → categories, сгруппируйте по categories.title.

Решение учителя 
SELECT    c.title AS category,    SUM(oi.quantity * oi.price) AS revenueFROM order_items AS oiJOIN products AS p   ON p.id = oi.product_idJOIN categories AS c ON c.id = p.category_idJOIN orders AS o     ON o.id = oi.order_idWHERE o.status = 'paid'GROUP BY c.id, c.titleORDER BY revenue DESC;
Задача 2. Средний чек по клиенту

Выведите имя клиента и его средний чек. Клиенты без заказов должны быть в отчёте со значением 0.

Подсказка

Сначала CTE с суммой каждого заказа, затем соединение с клиентами и COALESCE(AVG(total), 0).

Решение учителя 
WITH order_totals AS (    SELECT        o.id,        o.customer_id,        SUM(oi.quantity * oi.price) AS total    FROM orders AS o    JOIN order_items AS oi ON oi.order_id = o.id    WHERE o.status = 'paid'    GROUP BY o.id, o.customer_id)SELECT    c.name,    COALESCE(ROUND(AVG(t.total), 2), 0) AS avg_checkFROM customers AS cLEFT JOIN order_totals AS t ON t.customer_id = c.idGROUP BY c.id, c.name;

Подсказка

Начните с вопросов, на которые хотите отвечать. Таблицы появятся сами: сущности - это то, что упоминается в вопросах, связи - то, что их соединяет.

Решение учителя

Универсального решения нет. Проверьте себя: есть ли первичные ключи, нет ли дублей, не хранится ли в ячейке список, работают ли отчёты на пустой базе.

Задача 4. Купленные однажды

Найдите товары, которые покупали ровно один раз (в оплаченных заказах).

Подсказка

Сгруппируйте позиции по товару и оставьте те, где SUM(quantity) = 1 или COUNT(DISTINCT order_id) = 1.

Решение учителя 
SELECT    p.title,    COUNT(DISTINCT oi.order_id) AS orders_countFROM order_items AS oiJOIN products AS p ON p.id = oi.product_idJOIN orders AS o   ON o.id = oi.order_idWHERE o.status = 'paid'GROUP BY p.id, p.titleHAVING COUNT(DISTINCT oi.order_id) = 1;
