Оконные функции

~35 минут Продвинутый уровень Теория и Практика

Обычная группировка сворачивает строки: было сто заказов - осталась одна строка на клиента. Но часто нужно и сохранить каждую строку, и добавить к ней расчёт по группе: место в рейтинге, накопительную сумму, разницу с предыдущим днём. Для этого есть оконные функции.

В этом уроке мы:

  • Разберём синтаксис OVER и PARTITION BY.
  • Освоим ROW_NUMBER, RANK и DENSE_RANK.
  • Научимся считать накопительные итоги.
  • Познакомимся с LAG и LEAD.
Аналогия

Классный журнал: оценки остаются у каждого ученика, но рядом можно посчитать средний балл по классу, не убирая сами оценки.

Чем отличается от GROUP BY

SELECT    customer_id,    id,    price,    SUM(price) OVER (PARTITION BY customer_id) AS customer_totalFROM orders;

В результате остаются все заказы, и у каждого появляется сумма по его клиенту. С GROUP BY мы получили бы по одной строке на клиента и потеряли детали.

Синтаксис OVER

функция(...) OVER (    PARTITION BY столбец   -- разбить на группы    ORDER BY столбец       -- порядок внутри группы)

PARTITION BY - это «разделить на окна», аналог GROUP BY, но строки не схлопываются. ORDER BY внутри окна задаёт порядок расчёта.

Нумерация строк

SELECT    customer_id,    id,    price,    ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY price DESC) AS row_num,    RANK()       OVER (PARTITION BY customer_id ORDER BY price DESC) AS rank_num,    DENSE_RANK() OVER (PARTITION BY customer_id ORDER BY price DESC) AS dense_numFROM orders;

Разница видна на одинаковых значениях. Пусть цены заказов: 75000, 30000, 30000, 1500.

  • ROW_NUMBER всегда даёт уникальные номера.
  • RANK при равенстве даёт одинаковый номер и пропускает следующий.
  • DENSE_RANK не пропускает: 1, 2, 2, 3.

Типичная задача «последний заказ каждого клиента»:

SELECT *FROM (    SELECT        o.*,        ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY created_at DESC) AS rn    FROM orders AS o) AS tWHERE rn = 1;

Агрегаты как оконные функции

SELECT    id,    customer_id,    price,    SUM(price) OVER (PARTITION BY customer_id) AS total_by_customer,    SUM(price) OVER ()                        AS grand_total,    ROUND(        100.0 * price / SUM(price) OVER (PARTITION BY customer_id),        1    ) AS percent_of_customerFROM orders;
  • OVER () - окно на всю таблицу.
  • PARTITION BY - окно на группу.
  • Агрегат не сворачивает строки, а повторяется в каждой.

Накопительный итог

ORDER BY внутри окна превращает агрегат в накопительный:

SELECT    created_at,    price,    SUM(price) OVER (ORDER BY created_at) AS running_totalFROM ordersORDER BY created_at;

Именно так строят графики выручки, где каждая точка - сумма с начала периода.

LAG и LEAD

Позволяют заглянуть в предыдущую или следующую строку:

SELECT    created_at,    price,    LAG(price)  OVER (ORDER BY created_at) AS prev_price,    LEAD(price) OVER (ORDER BY created_at) AS next_price,    price - LAG(price) OVER (ORDER BY created_at) AS diffFROM ordersORDER BY created_at;

Так считают рост выручки месяц к месяцу и находят аномальные скачки.

Окно вычисляется после WHERE

Нельзя фильтровать по результату оконной функции в WHERE: она вычисляется позже. Оборачивайте запрос в подзапрос или CTE и фильтруйте снаружи - как в примере с rn = 1.

Шпаргалка

  • OVER () окно на всю таблицу
  • PARTITION BY разбить на группы
  • ROW_NUMBER уникальный номер
  • RANK / DENSE_RANK рейтинг с повторами
  • LAG / LEAD предыдущая / следующая строка
  • ORDER BY в OVER накопительный итог

Если что-то не работает

  • «Window function not allowed here». Оконная функция стоит в WHERE. Используйте подзапрос.
  • ROW_NUMBER выдаёт не тот порядок. Проверьте ORDER BY внутри OVER.
  • Накопительный итог скачет. Даты с одинаковым временем дают неопределённый порядок. Добавьте второй столбец в ORDER BY.
  • Оконные функции недоступны. В очень старых версиях MySQL и SQLite их не было. Обновите СУБД.
  • «Отчёт по месяцам считает не то». Группировали по дате со временем: каждая секунда стала отдельной группой. Обрежьте дату до месяца.

Практика

Задача 1. Топ заказов клиента

Для каждого клиента пронумеруйте заказы по убыванию цены и выведите только два самых дорогих.

Подсказка

ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY price DESC) в подзапросе, затем фильтр WHERE rn <= 2.

Решение учителя 
SELECT customer_id, id, price, rnFROM (    SELECT        id,        customer_id,        price,        ROW_NUMBER() OVER (            PARTITION BY customer_id ORDER BY price DESC        ) AS rn    FROM orders) AS tWHERE rn <= 2;
Задача 2. Доля в выручке

Для каждого заказа выведите его цену и процент от общей суммы всех заказов, округлённый до одного знака.

Подсказка

ROUND(100.0 * price / SUM(price) OVER (), 1). Именно 100.0, чтобы деление было дробным.

Решение учителя 
SELECT    id,    price,    ROUND(100.0 * price / SUM(price) OVER (), 1) AS percentFROM ordersORDER BY price DESC;
Задача 3. Динамика по месяцам

Посчитайте выручку по месяцам и разницу с предыдущим месяцем через LAG.

Подсказка

Сначала агрегируйте по месяцу в CTE, затем примените LAG(revenue) OVER (ORDER BY month).

Решение учителя 
WITH monthly AS (    SELECT        STRFTIME('%Y-%m', created_at) AS month,        SUM(price) AS revenue    FROM orders    GROUP BY month)SELECT    month,    revenue,    revenue - LAG(revenue) OVER (ORDER BY month) AS diffFROM monthlyORDER BY month;
Задача 4. Доля в накопительной выручке

Для каждого заказа выведите накопительную сумму по дате и её долю от общей выручки в процентах.

Подсказка

Два окна: одно с ORDER BY для накопления, второе OVER () для общего итога.

Решение учителя 
SELECT    id,    created_at,    price,    SUM(price) OVER (ORDER BY created_at, id) AS running_total,    ROUND(        100.0 * SUM(price) OVER (ORDER BY created_at, id)        / SUM(price) OVER (),        1    ) AS percentFROM ordersWHERE status = 'paid'ORDER BY created_at, id;
