Установка и первый запрос

~25 минут Начальный уровень Теория и Практика

Теория закончилась: пора запустить настоящую базу. В этом уроке мы поставим SQLite, создадим таблицу и выполним первый запрос. Всё, что нужно, - браузер или бесплатная программа.

В этом уроке мы:

  • Поставим SQLite и клиент для работы с ним.
  • Создадим таблицу и наполним её данными.
  • Выполним первый SELECT и прочитаем результат.
  • Разберёмся с регистром, точкой с запятой и комментариями.
Аналогия

Кухня: сначала ставят плиту, потом готовят. Сначала СУБД, потом запросы.

Два способа начать

Способ 1. Онлайн-песочница. Ничего устанавливать не нужно: откройте SQLite Online в браузере, нажмите «Create table» и работайте. Подходит для первых экспериментов.

Способ 2. Локально. Скачайте DB Browser for SQLite - бесплатную программу с графическим интерфейсом. Создайте новый файл базы, например shop.db, и перейдите на вкладку «Execute SQL».

Почему SQLite

SQLite не требует сервера: вся база - один файл. Это идеально для обучения и для небольших приложений. Синтаксис почти совпадает с PostgreSQL и MySQL, поэтому перейти на них потом будет легко.

Создаём таблицу

CREATE TABLE users (    id      INTEGER PRIMARY KEY,    name    TEXT    NOT NULL,    email   TEXT    UNIQUE,    age     INTEGER);

Что здесь написано:

  • CREATE TABLE users - создать таблицу с именем users.
  • id INTEGER PRIMARY KEY - целое число, уникальный идентификатор строки.
  • name TEXT NOT NULL - текст, обязательное поле.
  • email TEXT UNIQUE - текст, значения не должны повторяться.
  • age INTEGER - целое число, может быть пустым.

Подробно типы и ограничения разберём на среднем уровне. Пока достаточно понимать, что таблица - это описание столбцов с правилами.

Добавляем данные

INSERT INTO users (name, email, age) VALUES    ('Анна',  'anna@example.com',  25),    ('Борис', 'boris@example.com', 31),    ('Вера',  'vera@example.com',  19),    ('Глеб',  'gleb@example.com',  NULL);

Поле id мы не указывали - база сама присвоит номера 1, 2, 3, 4. У Глеба возраст неизвестен, поэтому NULL - «значение отсутствует».

Первый запрос

SELECT * FROM users;

Звёздочка означает «все столбцы». Результат:

idnameemailage
1Аннаanna@example.com25
2Борисboris@example.com31
3Вераvera@example.com19
4Глебgleb@example.comNULL

Запрос состоит из двух частей: SELECT * - что взять, FROM users - откуда. Дальше мы будем добавлять условия, сортировку и группировку.

Регистр, точки с запятой и комментарии

SQL не чувствителен к регистру команд: select, SELECT и Select - одно и то же. Но имена таблиц в некоторых СУБД учитывают регистр, поэтому договоримся писать команды заглавными, а имена - строчными.

-- однострочный комментарий/*   Многострочный комментарий*/SELECT name FROM users;  -- точка с запятой завершает запрос

Точка с запятой нужна, если вы выполняете несколько запросов подряд. В клиентах с кнопкой «Execute» она часто необязательна, но привычка полезна: без неё ошибки появляются в самый неподходящий момент.

Что вернула база

Результат SELECT - это всегда таблица, даже если в ней одна строка или ноль строк. Ноль строк - не ошибка: значит, под условие ничего не подошло.

SELECT * FROM users WHERE age > 100;

Результат: пустая таблица с теми же столбцами. Это важно запомнить: «нет данных» и «ошибка» - разные вещи.

Шпаргалка

  • CREATE TABLE создать таблицу
  • INSERT INTO добавить строки
  • SELECT * все столбцы
  • FROM users источник данных
  • NULL отсутствующее значение
  • -- комментарий

Если что-то не работает

  • «Table users already exists». Таблица уже создана. Удалите её (DROP TABLE users;) или используйте другое имя.
  • «NOT NULL constraint failed». Пытаетесь вставить строку без обязательного поля.
  • «UNIQUE constraint failed». Такой email уже есть - ограничение сработало правильно.
  • Русский текст превратился в кракозябры. Файл базы или клиент сохранён не в UTF-8. В онлайн-песочнице такого обычно нет.
  • Запрос выполнился, но данных нет. Возможно, вы вставили строки в другую базу или не нажали «Write changes» в DB Browser.
  • «Клиент открыл базу, а таблиц нет». Он смотрит другой файл: SQLite хранит всё в одном .db, и его нужно открыть именно тот, с которым работали вы.

Практика

Задача 1. Первая таблица

Создайте таблицу products с полями: id (ключ), title (текст, обязательное), price (целое число) и добавьте три товара.

Подсказка

Структура как у users, только другие столбцы. В INSERT перечислите title и price, а id база заполнит сама.

Решение учителя 
CREATE TABLE products (    id    INTEGER PRIMARY KEY,    title TEXT NOT NULL,    price INTEGER);INSERT INTO products (title, price) VALUES    ('Ноутбук', 75000),    ('Мышь', 1500),    ('Монитор', 30000);SELECT * FROM products;
Задача 2. Пустой результат

Выполните SELECT * FROM products WHERE price > 100000;. Объясните, почему результат пустой и почему это не ошибка.

Подсказка

Ни один товар не дороже 100 000. База честно вернула ноль строк.

Решение учителя

Пустая таблица в ответе означает «под условие ничего не подошло». Ошибка выглядела бы иначе: например, «no such column» или «syntax error».

Задача 3. NULL

Добавьте в users пользователя без возраста. Затем выполните два запроса: WHERE age = NULL и WHERE age IS NULL. Объясните разницу.

Подсказка

NULL - это не значение, а отсутствие значения. Сравнение с ним через = не даёт истины.

Решение учителя 
INSERT INTO users (name, email) VALUES ('Дина', 'dina@example.com');SELECT * FROM users WHERE age = NULL;   -- 0 строкSELECT * FROM users WHERE age IS NULL;  -- Дина и Глеб

Для проверки на NULL используют только IS NULL и IS NOT NULL. Подробнее - в уроке про WHERE.

Задача 4. Пересоздать таблицу

Удалите таблицу products и создайте заново, заменив цену на REAL (дробную).

Подсказка

Используйте DROP TABLE и CREATE TABLE. Помните: данные удалятся вместе с таблицей.

Решение учителя 
DROP TABLE products;CREATE TABLE products (    id    INTEGER PRIMARY KEY,    title TEXT NOT NULL,    price REAL);

Что мы узнали и что дальше

База работает, данные на месте. Вы знаете:

  • Как поставить SQLite и открыть клиент.
  • Как создать таблицу с ключом и ограничениями.
  • Как добавить строки и выбрать их через SELECT.
  • Что пустой результат - это не ошибка.

Следующий шаг - научиться выбирать не всё подряд. Разберём, как брать нужные столбцы, переименовывать их, убирать дубли и сортировать результат.
