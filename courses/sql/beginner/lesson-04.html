WHERE: фильтруем строки

~30 минут Начальный уровень Теория и Практика

Выборка всех строк нужна редко. Обычно требуется «заказы за март», «пользователи старше 18», «товары дешевле 5000». За это отвечает WHERE.

В этом уроке мы:

  • Разберём операторы сравнения.
  • Научимся комбинировать условия через AND, OR, NOT.
  • Освоим BETWEEN, IN и LIKE.
  • Поймём, почему NULL ломает обычные сравнения.
Аналогия

Фильтр в кофемашине: пропускает только то, что подходит под условие, остальное остаётся в контейнере.

Сравнения

SELECT name, ageFROM usersWHERE age >= 18;

Доступны привычные операторы:

=       равно<>      не равно (можно !=)>       больше<       меньше>=      больше или равно<=      меньше или равно

Текст заключается в одинарные кавычки. Двойные в стандартном SQL означают имена столбцов, и запрос может неожиданно сломаться:

SELECT * FROM users WHERE name = 'Анна';

Несколько условий

SELECT *FROM productsWHERE price > 1000 AND price < 40000;

AND требует, чтобы выполнялись оба условия, OR - хотя бы одно. NOT инвертирует:

SELECT *FROM productsWHERE NOT price > 1000;

Приоритет: NOT → AND → OR. Поэтому скобки важны:

-- неправильно: найдёт все товары дешевле 5000 ИЛИ любой ноутбукWHERE price < 5000 OR title = 'Ноутбук' AND stock > 0-- правильно: явно группируемWHERE (price < 5000 OR title = 'Ноутбук') AND stock > 0
Правило скобок

Если в условии смешаны AND и OR - ставьте скобки, даже когда кажется, что приоритет понятен. Через месяц вы сами не вспомните, что имели в виду, а база выполнит не то, что вы ждали.

Диапазон: BETWEEN

SELECT *FROM productsWHERE price BETWEEN 1000 AND 40000;

BETWEEN включает границы: это то же самое, что price >= 1000 AND price <= 40000. С датами работает так же, но с оговоркой: если время хранится с часами и минутами, верхняя граница «2026-10-30» отсечёт всё после полуночи. Надёжнее сравнивать с < следующим днём.

Список: IN

SELECT *FROM usersWHERE name IN ('Анна', 'Борис', 'Вера');

Это короче, чем три раза писать OR. Внутри IN может быть и подзапрос - об этом в среднем уровне.

NOT IN исключает список, но с ним есть ловушка:

SELECT * FROM users WHERE age NOT IN (25, 31);

Строки, где age IS NULL, в результат не попадут. Причина - логика трёхзначности: сравнение с NULL даёт не «истину» и не «ложь», а «неизвестно».

Поиск по шаблону: LIKE

SELECT * FROM users WHERE name LIKE 'А%';    -- начинается на АSELECT * FROM users WHERE email LIKE '%@example.com'; -- заканчивается наSELECT * FROM users WHERE name LIKE '_нна';  -- ровно один символ перед "нна"
  • % - любое количество символов, включая ноль.
  • _ - ровно один символ.

Важная разница между СУБД: в SQLite и MySQL LIKE по умолчанию не учитывает регистр для латиницы, в PostgreSQL - учитывает. Для надёжности приводите обе стороны к одному регистру:

SELECT * FROM users WHERE LOWER(name) LIKE 'а%';

NULL

NULL - это не «ноль» и не «пустая строка», а отсутствие значения. Поэтому:

SELECT * FROM users WHERE age = NULL;      -- 0 строк, всегдаSELECT * FROM users WHERE age IS NULL;     -- правильноSELECT * FROM users WHERE age IS NOT NULL; -- есть возраст

Любая арифметика с NULL даёт NULL: NULL + 5 - это NULL. Агрегаты ведут себя особым образом - об этом в следующем уроке.

Порядок условий и производительность

Современные базы сами переставляют условия, поэтому «поставить более строгое первым» не даёт выигрыша. Важнее другое: не применять функции к столбцу в условии, если хотите использовать индекс.

-- индекс по email не поможетWHERE LOWER(email) = 'anna@example.com'-- поможет, если данные уже в нижнем регистреWHERE email = 'anna@example.com'

Индексы разберём отдельно на среднем уровне.

Шпаргалка

  • WHERE фильтр строк
  • AND / OR / NOT логика условий
  • BETWEEN диапазон включительно
  • IN значение из списка
  • LIKE поиск по шаблону
  • IS NULL проверка отсутствия

Если что-то не работает

  • «No such column: Анна». Текст в двойных кавычках. Строки - только в одинарных.
  • WHERE age = NULL ничего не находит. Так и должно быть. Используйте IS NULL.
  • Условие с OR находит лишнее. Не хватает скобок: AND выполняется раньше OR.
  • LIKE не находит слово в другом регистре. В PostgreSQL нужен ILIKE или LOWER().
  • NOT IN пропускает строки. В списке или в столбце есть NULL - добавьте AND age IS NOT NULL.
  • «Поиск по имени не находит клиента». В базе «анна», а ищут «Анна». В SQLite LIKE обычно не учитывает регистр, в PostgreSQL - учитывает. Надёжнее приводить обе стороны к одному регистру.

Практика

Задача 1. Совершеннолетние

Выведите имена пользователей от 18 до 30 лет включительно, отсортированные по возрасту.

Подсказка

Подойдёт BETWEEN 18 AND 30 или два сравнения через AND.

Решение учителя 
SELECT name, ageFROM usersWHERE age BETWEEN 18 AND 30ORDER BY age;
Задача 2. Поиск по почте

Найдите всех пользователей, чья почта заканчивается на @example.com, и тех, чьё имя начинается на «А» или «Б».

Подсказка

Два условия: email LIKE '%@example.com' и (name LIKE 'А%' OR name LIKE 'Б%').

Решение учителя 
SELECT name, emailFROM usersWHERE email LIKE '%@example.com'  AND (name LIKE 'А%' OR name LIKE 'Б%');
Задача 3. Товары в наличии

Добавьте в products столбец stock (если ещё нет) и найдите товары дешевле 20 000, которые есть на складе. Товары с NULL в остатке считайте отсутствующими.

Подсказка

Условие: price < 20000 AND stock > 0. Именно > 0, а не <> 0: NULL не пройдёт ни то, ни другое, но > 0 честнее по смыслу.

Решение учителя 
ALTER TABLE products ADD COLUMN stock INTEGER DEFAULT 0;UPDATE products SET stock = 5 WHERE title = 'Мышь';SELECT title, price, stockFROM productsWHERE price < 20000 AND stock > 0;
Задача 4. Ноутбуки или дешёвые

Найдите товары, в названии которых есть «Ноут», либо цену меньше 1000. Отсортируйте по цене.

Подсказка

Смешаны OR и LIKE - скобки помогут не запутаться.

Решение учителя 
SELECT title, priceFROM productsWHERE title LIKE '%Ноут%' OR price < 1000ORDER BY price;
