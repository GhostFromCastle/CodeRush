SELECT: столбцы, псевдонимы, сортировка

~25 минут Начальный уровень Теория и Практика

SELECT * удобен, пока таблица маленькая. В реальной базе столбцов десятки, строк - миллионы, и тянуть всё подряд бессмысленно. Учимся выбирать точно.

В этом уроке мы:

  • Научимся указывать нужные столбцы и переименовывать их.
  • Разберём DISTINCT и вычисляемые столбцы.
  • Освоим сортировку ORDER BY и ограничение LIMIT.
  • Поймём порядок, в котором база выполняет запрос.
Аналогия

Меню: можно заказать только нужные блюда, а не всё подряд. SELECT с перечислением столбцов работает так же.

Нужные столбцы

SELECT name, emailFROM users;

Вместо звёздочки перечисляем поля через запятую. Это не только экономит трафик: запрос становится понятнее, а база может не читать лишние данные.

Почему SELECT * в коде - плохая привычка

Сегодня в таблице пять столбцов, завтра добавили десятый с большим текстом - и старый запрос внезапно стал тяжёлым. Кроме того, код, который рассчитывает на порядок столбцов, ломается при изменении схемы. Перечисляйте поля явно.

Псевдонимы

Столбцу можно дать другое имя в результате - через AS:

SELECT    name  AS "Имя",    email AS "Почта"FROM users;

Кавычки нужны, если в имени есть пробелы или русские буквы. Псевдоним существует только в результате запроса - в таблице столбец по-прежнему называется name.

Псевдонимы пригодятся и для вычисляемых столбцов:

SELECT    title,    price,    price * 0.2 AS taxFROM products;

Вычисления и склейка

SELECT    title,    price,    price * 1.2 AS price_with_vatFROM products;

Для строк в SQLite, PostgreSQL и Oracle работает оператор ||:

SELECT name || ' <' || email || '>' AS contactFROM users;

В MySQL вместо него используют CONCAT(). Если планируете переносить код между СУБД, держите это в голове.

Убираем дубли: DISTINCT

SELECT DISTINCT ageFROM users;

Если несколько пользователей одного возраста, в результате он появится один раз. DISTINCT применяется ко всей строке результата, а не к одному столбцу:

SELECT DISTINCT age, nameFROM users;

Здесь дубли будут убираться по паре «возраст + имя», поэтому строк станет почти столько же, сколько было.

Сортировка: ORDER BY

SELECT name, ageFROM usersORDER BY age;

По умолчанию сортировка по возрастанию. Явно это записывают как ASC, обратная - DESC:

SELECT name, ageFROM usersORDER BY age DESC;

Можно сортировать по нескольким столбцам. Первый - главный, второй решает ничьи:

SELECT name, ageFROM usersORDER BY age DESC, name ASC;

NULL в SQLite и PostgreSQL при сортировке по возрастанию идут первыми, в MySQL - последними. Если порядок важен, задавайте его явно:

SELECT name, ageFROM usersORDER BY age IS NULL, age;

Ограничение строк: LIMIT

SELECT name, ageFROM usersORDER BY age DESCLIMIT 2;

Получим двух самых взрослых. LIMIT без ORDER BY почти бессмыслен: база вправе вернуть любые строки, и результат будет меняться от запуска к запуску.

Для постраничного вывода используют OFFSET:

SELECT nameFROM usersORDER BY idLIMIT 2 OFFSET 2;   -- третья и четвёртая строки

В MySQL вместо LIMIT 2 OFFSET 2 пишут LIMIT 2, 2, в SQL Server - OFFSET ... FETCH.

Порядок выполнения

Запрос пишется в одном порядке, а выполняется в другом:

FROM      -- 1. берём таблицуWHERE     -- 2. фильтруем строкиSELECT    -- 3. выбираем и вычисляем столбцыORDER BY  -- 4. сортируемLIMIT     -- 5. ограничиваем количество

Поэтому псевдоним из SELECT нельзя использовать в WHERE (его ещё не существует), но можно в ORDER BY (он уже вычислен).

Шпаргалка

  • SELECT col1, col2 выбрать столбцы
  • AS name псевдоним
  • DISTINCT убрать дубли
  • ORDER BY сортировка
  • DESC по убыванию
  • LIMIT / OFFSET сколько строк и с какой

Если что-то не работает

  • «No such column: Имя». Псевдоним в двойных кавычках, а обращение без них - или наоборот. Имена с пробелами и русскими буквами всегда в кавычках.
  • LIMIT возвращает разные строки. Нет ORDER BY - порядок не гарантирован.
  • DISTINCT не убрал дубли. Выбрано несколько столбцов: уникальность проверяется по всей строке.
  • Сортировка «неправильная». Число хранится как текст: тогда 10 идёт раньше 2. Проверьте тип столбца.
  • Псевдоним не виден в WHERE. Так и должно быть: WHERE выполняется раньше SELECT. Повторите выражение или используйте подзапрос.
  • «Отчёт сломался после добавления столбца». В запросе стоял SELECT *, и код ожидал прежний порядок колонок. Перечисляйте поля явно.

Практика

Задача 1. Витрина товаров

Выведите название и цену товаров, переименовав столбцы в «Товар» и «Цена, ₽», отсортируйте по цене от дорогих к дешёвым.

Подсказка

SELECT title AS "Товар", price AS "Цена, ₽" FROM products ORDER BY price DESC;

Решение учителя 
SELECT title AS "Товар", price AS "Цена, ₽"FROM productsORDER BY price DESC;
Задача 2. Уникальные значения

Выведите список уникальных возрастов пользователей, отсортированный по возрастанию. Сколько строк получилось?

Подсказка

SELECT DISTINCT age FROM users ORDER BY age;. Строк будет столько, сколько разных возрастов, включая NULL.

Решение учителя 
SELECT DISTINCT ageFROM usersORDER BY age;
Задача 3. Страница 2

Выведите вторую страницу списка пользователей: по два человека на страницу, сортировка по id. То есть строки 3 и 4.

Подсказка

LIMIT 2 OFFSET 2: пропустить первые две строки и взять следующие две.

Решение учителя 
SELECT id, nameFROM usersORDER BY idLIMIT 2 OFFSET 2;
Задача 4. Цена упаковки

Выведите название, цену за штуку и цену упаковки из 6 штук. Столбец назовите «Упаковка».

Подсказка

Умножьте цену на 6 и дайте псевдоним в кавычках.

Решение учителя 
SELECT    title,    price,    price * 6 AS "Упаковка"FROM products;

  • Как сортировать и ограничивать результат.
  • В каком порядке база выполняет части запроса.
