Агрегаты, GROUP BY и HAVING

~30 минут Начальный уровень Теория и Практика

До сих пор мы смотрели на отдельные строки. Но чаще нужны итоги: сколько пользователей, какая средняя цена, сколько заказов у каждого клиента. Для этого в SQL есть агрегатные функции и группировка.

В этом уроке мы:

  • Освоим COUNT, SUM, AVG, MIN, MAX.
  • Поймём, как NULL влияет на подсчёты.
  • Научимся группировать строки через GROUP BY.
  • Разберём разницу между WHERE и HAVING.
Аналогия

Бухгалтерия: не важно, сколько чеков в пачке, - важен итог по пачке. GROUP BY собирает чеки в такие пачки.

Пять агрегатов

SELECT    COUNT(*)   AS total_users,    AVG(age)   AS avg_age,    MIN(age)   AS min_age,    MAX(age)   AS max_ageFROM users;
total_usersavg_agemin_agemax_age
425.01931
  • COUNT(*) - количество строк.
  • SUM - сумма значений.
  • AVG - среднее.
  • MIN / MAX - минимум и максимум.

Агрегат без GROUP BY всегда возвращает ровно одну строку - даже если в таблице ноль записей.

COUNT(*) и COUNT(column)

Разница принципиальная:

SELECT    COUNT(*)      AS rows_total,    COUNT(age)    AS ages_filledFROM users;
rows_totalages_filled
42

COUNT(*) считает строки, COUNT(age) - только непустые значения. Все агрегаты, кроме COUNT(*), игнорируют NULL. Поэтому AVG(age) делит на количество известных возрастов, а не на количество строк.

Среднее по NULL

Если из десяти пользователей возраст известен у трёх, AVG(age) посчитает среднее по трём. Иногда это именно то, что нужно, а иногда - нет. Если пустые значения надо считать нулями, используйте AVG(COALESCE(age, 0)).

GROUP BY

Группировка разбивает строки на группы и считает агрегат для каждой:

SELECT    customer_id,    COUNT(*)  AS orders_count,    SUM(price) AS totalFROM ordersGROUP BY customer_id;
customer_idorders_counttotal
12105000
211500

Правило, которое нельзя нарушать: в SELECT могут быть только столбцы из GROUP BY и агрегаты.

-- ошибка: name не входит в группировкуSELECT name, COUNT(*)FROM usersGROUP BY age;

Логика простая: в группе из пяти строк пять разных имён, и база не знает, какое показать. Некоторые СУБД (MySQL в старых настройках, SQLite) молча вернут случайное - и это худший вариант, потому что ошибка не видна.

HAVING

WHERE фильтрует строки до группировки, HAVING - группы после:

SELECT    customer_id,    SUM(price) AS totalFROM ordersWHERE price > 1000          -- отбрасываем дешёвые заказыGROUP BY customer_idHAVING SUM(price) > 50000;  -- оставляем только крупных клиентов

Порядок выполнения запроса:

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

Отсюда следует: агрегат нельзя использовать в WHERE (он ещё не посчитан), но можно в HAVING.

Сортировка групп

SELECT    customer_id,    SUM(price) AS totalFROM ordersGROUP BY customer_idORDER BY total DESCLIMIT 1;

Так находят лучшего клиента. Обратите внимание: сортируем по псевдониму total - в ORDER BY это допустимо.

Полезные приёмы

Количество уникальных значений:

SELECT COUNT(DISTINCT customer_id) AS active_customersFROM orders;

Несколько агрегатов по разным столбцам:

SELECT    COUNT(*)          AS orders,    SUM(price)        AS revenue,    ROUND(AVG(price)) AS avg_check,    MIN(price)        AS cheapest,    MAX(price)        AS most_expensiveFROM orders;

ROUND округляет результат - подробнее в уроке про функции.

Шпаргалка

  • COUNT(*) число строк
  • SUM сумма
  • AVG среднее
  • MIN / MAX минимум и максимум
  • GROUP BY группировка
  • HAVING фильтр групп

Если что-то не работает

  • «Column must appear in GROUP BY». В SELECT есть столбец, которого нет в группировке. Добавьте его в GROUP BY или уберите из выборки.
  • «Misuse of aggregate function». Агрегат в WHERE. Нужен HAVING.
  • AVG считает не то. Часть значений - NULL. Проверьте COUNT(column) против COUNT(*).
  • COUNT(DISTINCT ...) медленный. Это нормально на больших таблицах; помогает индекс.
  • Группировка по дате не работает. Дата хранится со временем - сначала обрежьте до дня через DATE(created_at).
  • «Средний чек посчитали неправильно». Усреднили позиции, а не заказы: заказ из пяти дешёвых товаров весит столько же, сколько заказ из одного дорогого. Сначала считайте сумму заказа, потом среднее.

Практика

Задача 1. Статистика пользователей

Выведите одним запросом: общее число пользователей, число известных возрастов, средний и максимальный возраст.

Подсказка

Четыре агрегата в одном SELECT: COUNT(*), COUNT(age), AVG(age), MAX(age).

Решение учителя 
SELECT    COUNT(*)   AS total,    COUNT(age) AS known_ages,    AVG(age)   AS avg_age,    MAX(age)   AS max_ageFROM users;
Задача 2. Выручка по клиентам

Посчитайте для каждого customer_id количество заказов и общую сумму. Отсортируйте по сумме от большей к меньшей.

Подсказка

GROUP BY customer_id, агрегаты COUNT(*) и SUM(price), затем ORDER BY total DESC.

Решение учителя 
SELECT    customer_id,    COUNT(*)   AS orders_count,    SUM(price) AS totalFROM ordersGROUP BY customer_idORDER BY total DESC;
Задача 3. Крупные клиенты

Оставьте только клиентов, у которых больше одного заказа и сумма покупок выше 50 000.

Подсказка

Оба условия относятся к группам, значит нужен HAVING: HAVING COUNT(*) > 1 AND SUM(price) > 50000.

Решение учителя 
SELECT    customer_id,    COUNT(*)   AS orders_count,    SUM(price) AS totalFROM ordersGROUP BY customer_idHAVING COUNT(*) > 1 AND SUM(price) > 50000;
Задача 4. Средняя цена по категориям

Выведите category_id, количество товаров и среднюю цену, округлённую до целого.

Подсказка

Группировка по category_id, агрегаты COUNT(*) и ROUND(AVG(price)).

Решение учителя 
SELECT    category_id,    COUNT(*)           AS products_count,    ROUND(AVG(price))  AS avg_priceFROM productsGROUP BY category_id;
