INSERT, UPDATE, DELETE

~30 минут Начальный уровень Теория и Практика

Читать данные - половина работы. Вторая половина - их менять: добавлять заказы, править цены, удалять устаревшее. В этом уроке освоим три команды, с которыми нужно обращаться особенно аккуратно.

В этом уроке мы:

  • Научимся добавлять одну и несколько строк.
  • Разберём UPDATE и правило «всегда с WHERE».
  • Поймём, чем опасен DELETE без условия.
  • Узнаем, как вернуть удалённое через транзакцию.
Аналогия

Редактор документа: добавить абзац, исправить, удалить. Но без «Сохранить» (WHERE) можно случайно стереть весь текст.

INSERT

INSERT INTO products (title, price, stock)VALUES ('Клавиатура', 3500, 10);

Порядок значений должен совпадать с порядком столбцов в скобках. Столбцы, которые не указаны, получают значение по умолчанию или NULL. id обычно заполняется автоматически.

Несколько строк одной командой - быстрее, чем несколько отдельных:

INSERT INTO products (title, price, stock) VALUES    ('Наушники', 4500, 7),    ('Веб-камера', 5200, 3),    ('Кабель USB', 400, 50);
INSERT ... SELECT

Можно вставить результат другого запроса: INSERT INTO archive (id, title) SELECT id, title FROM products WHERE stock = 0;. Так делают резервные копии и перенос данных между таблицами.

UPDATE

UPDATE productsSET price = 3990WHERE title = 'Клавиатура';

Обновлять можно несколько полей сразу:

UPDATE productsSET price = price * 1.1,    stock = stock - 1WHERE id = 2;

Обратите внимание: в правой части можно использовать текущее значение столбца.

Правило номер один

UPDATE и DELETE без WHERE меняют всю таблицу

UPDATE products SET price = 0; обнулит цены у всех товаров. DELETE FROM products; удалит все строки. СУБД не спросит подтверждения - она просто выполнит команду. Перед запуском всегда проверяйте то же условие через SELECT.

Рабочий приём: сначала посмотреть, что попадёт под условие, и только потом менять.

-- 1. ПроверяемSELECT * FROM products WHERE title = 'Клавиатура';-- 2. Убедились, что строка одна - обновляемUPDATE products SET price = 3990 WHERE title = 'Клавиатура';

DELETE

DELETE FROM productsWHERE stock = 0;

Удаляет строки, подходящие под условие. Если нужно очистить таблицу полностью, есть отдельная команда TRUNCATE TABLE products; (в SQLite её нет - там используют DELETE FROM products;).

Важно: DELETE удаляет строки, но не саму таблицу. Для таблицы есть DROP TABLE.

RETURNING

В PostgreSQL и SQLite можно сразу увидеть, что изменилось:

INSERT INTO products (title, price) VALUES ('Мышка', 1200)RETURNING id, title;UPDATE products SET price = 1200 WHERE title = 'Мышка'RETURNING id, price;DELETE FROM products WHERE id = 7RETURNING *;

В MySQL аналога нет: после вставки читают LAST_INSERT_ID(), после изменения - делают отдельный SELECT.

Ошибся? Откат

Если клиент поддерживает транзакции, ошибку можно отменить:

BEGIN;DELETE FROM products;-- поняли, что сделали глупостьROLLBACK;

Транзакции подробно разберём на продвинутом уровне. Пока запомните: BEGIN начинает, COMMIT фиксирует, ROLLBACK отменяет всё с момента начала.

Upsert: вставить или обновить

Часто нужно «добавить, а если уже есть - обновить». В SQLite и PostgreSQL:

INSERT INTO products (id, title, price)VALUES (1, 'Ноутбук', 79000)ON CONFLICT (id) DO UPDATE SET price = excluded.price;

В MySQL это INSERT ... ON DUPLICATE KEY UPDATE. Приём полезен при синхронизации данных из внешних источников.

Шпаргалка

  • INSERT INTO добавить строки
  • UPDATE ... SET изменить значения
  • DELETE FROM удалить строки
  • WHERE обязательно для правок
  • RETURNING показать изменённое
  • ROLLBACK отменить транзакцию

Если что-то не работает

  • «NOT NULL constraint failed». Не передано обязательное поле.
  • «UNIQUE constraint failed». Такое значение уже есть. Проверьте ключ или уникальный столбец.
  • Обновились все строки. Забыли WHERE. Откатите транзакцию, если она была открыта, или восстанавливайте из резервной копии.
  • «FOREIGN KEY constraint failed». Удаляете строку, на которую ссылаются другие таблицы. Сначала уберите зависимые записи или настройте каскад.
  • UPDATE не нашёл строк. Условие не совпало: проверьте регистр, пробелы и тип значения.
  • «Обновились все товары». Забыли WHERE - и UPDATE прошёлся по всей таблице. Привычка сначала выполнить тот же фильтр через SELECT спасает от таких историй.

Практика

Задача 1. Новый товар

Добавьте товар «Микрофон» с ценой 6500 и остатком 4, затем выведите его через SELECT.

Подсказка

После INSERT выполните SELECT * FROM products WHERE title = 'Микрофон';

Решение учителя 
INSERT INTO products (title, price, stock)VALUES ('Микрофон', 6500, 4);SELECT * FROM products WHERE title = 'Микрофон';
Задача 2. Подорожание

Поднимите цену всех товаров дешевле 1000 на 15%. Сначала проверьте через SELECT, какие строки попадут под условие.

Подсказка

SET price = price * 1.15 и условие WHERE price < 1000. Округление можно сделать через ROUND(price * 1.15).

Решение учителя 
SELECT title, price FROM products WHERE price < 1000;UPDATE productsSET price = ROUND(price * 1.15)WHERE price < 1000;
Задача 3. Безопасное удаление

Удалите товары без остатка. Перед удалением посчитайте их количество, а после - убедитесь, что остальные товары на месте. Выполните всё в транзакции.

Подсказка

BEGIN; → SELECT COUNT(*) → DELETE ... WHERE stock = 0 OR stock IS NULL → SELECT COUNT(*) → COMMIT;.

Решение учителя 
BEGIN;SELECT COUNT(*) AS before_delete FROM products;DELETE FROM productsWHERE stock = 0 OR stock IS NULL;SELECT COUNT(*) AS after_delete FROM products;COMMIT;
Задача 4. Изменить и вернуть

Поднимите цену товара с id = 3 на 10% и сразу выведите новое значение через RETURNING.

Подсказка

Синтаксис: UPDATE ... SET ... WHERE ... RETURNING ....

Решение учителя 
UPDATE productsSET price = ROUND(price * 1.1)WHERE id = 3RETURNING id, title, price;

Что мы узнали и что дальше

Вы умеете менять данные. Теперь вы знаете:

  • Как вставлять одну строку и пачку строк.
  • Как обновлять поля, используя их текущие значения.
  • Почему WHERE - обязательная часть UPDATE и DELETE.
  • Как откатить опасную операцию транзакцией.

Начальный уровень закончен: вы можете создавать таблицы, наполнять их, выбирать, фильтровать, считать и менять данные. Дальше - самое важное в SQL: соединение таблиц. В реальной базе данные всегда разложены по нескольким таблицам, и JOIN собирает их обратно.
