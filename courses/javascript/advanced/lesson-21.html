Ошибки, отладка и модули

~30 минут Продвинутый уровень Теория и Практика

Ошибки - не признак плохого разработчика. Плохой разработчик - тот, чья программа падает с непонятным сообщением и молча ломается у пользователя. В этом уроке научимся обрабатывать сбои, находить причины и структурировать код.

В этом уроке мы:

  • Освоим try/catch/finally и throw.
  • Разберём типы ошибок и что делать с сообщением.
  • Научимся отлаживать через DevTools.
  • Разобьём проект на ES-модули.
Аналогия

Пожарная сигнализация: датчик замечает дым (throw), сирена предупреждает (catch), журнал хранит причину. Без журнала пожар был, а разбираться не с чем.

try/catch

try {    const data = JSON.parse("{ некорректный json }");    console.log(data);} catch (error) {    console.error("Не удалось разобрать JSON:", error.message);} finally {    console.log("Блок завершён");}
  • try - код, который может упасть.
  • catch - что делать, если упало. Ошибка приходит аргументом.
  • finally - выполнится в любом случае: закрыть соединение, скрыть спиннер, снять блокировку.

Важно: try/catch ловит только синхронные ошибки. Ошибка внутри setTimeout или отклонённый промис без await в этот блок не попадёт:

try {    setTimeout(() => {        throw new Error("Эта ошибка не будет поймана");    }, 0);} catch (error) {    console.log("Сюда не попадём");}

throw и свои ошибки

Вы можете выбрасывать ошибки сами - например, при нарушении бизнес-правила:

function withdraw(balance, amount) {    if (amount <= 0) {        throw new RangeError("Сумма должна быть положительной");    }    if (amount > balance) {        throw new Error("Недостаточно средств");    }    return balance - amount;}try {    withdraw(100, 500);} catch (error) {    console.log(error.name);    // "Error"    console.log(error.message); // "Недостаточно средств"}

Встроенные типы ошибок: Error, TypeError, RangeError, SyntaxError, ReferenceError. Для прикладных ситуаций часто создают свой класс:

class ValidationError extends Error {    constructor(field, message) {        super(message);        this.name = "ValidationError";        this.field = field;    }}
Не глотайте ошибки

catch (e) {} без единой строки - худшее, что можно сделать. Ошибка исчезает, а причина бага остаётся. Как минимум логируйте её через console.error. Если ошибка не обрабатывается осмысленно - дайте ей всплыть выше.

Отладка в DevTools

Кроме console.log есть инструменты, которые экономят часы:

console.table(users);        // массив объектов в виде таблицыconsole.group("Загрузка");   // сгруппировать выводconsole.log("шаг 1");console.groupEnd();console.time("запрос");      // замер времениconsole.timeEnd("запрос");console.trace();             // стек вызовов

Но главный инструмент - точки останова. В DevTools откройте вкладку Sources, найдите файл и кликните на номер строки. Выполнение остановится, и вы сможете посмотреть значения переменных, пройти код по шагам и понять, где именно всё пошло не так.

В коде можно поставить и жёсткую остановку:

function calculate(a, b) {    debugger; // выполнение остановится здесь при открытых DevTools    return a + b;}

Не забудьте удалить debugger перед публикацией - иначе браузер с открытыми инструментами будет останавливаться у каждого пользователя.

Строгий режим

В строгом режиме некоторые неаккуратные конструкции становятся ошибками: присваивание необъявленной переменной, удаление переменной, дублирование параметров. Включается директивой в начале файла:

"use strict";// name = "Алексей"; // ReferenceError вместо создания глобальной переменной

В ES-модулях и классах строгий режим включён автоматически, поэтому отдельная директива нужна только в старых скриптах.

ES-модули

Пока весь код лежит в одном файле, проект растёт в неуправляемую свалку. Модули решают это: каждый файл отвечает за своё, а связи описаны явно.

// js/utils.jsexport function formatPrice(value) {    return `${value.toLocaleString("ru-RU")} ₽`;}export const TAX_RATE = 0.2;
// js/cart.jsimport { formatPrice, TAX_RATE } from "./utils.js";export function calculateTotal(items) {    const sum = items.reduce((total, item) => total + item.price, 0);    return formatPrice(sum * (1 + TAX_RATE));}
// js/main.jsimport { calculateTotal } from "./cart.js";console.log(calculateTotal([{ price: 1000 }, { price: 500 }]));

Подключение в HTML:

<script type="module" src="js/main.js"></script>

Правила, о которых легко забыть:

  • Атрибут type="module" обязателен. Без него import вызовет синтаксическую ошибку.
  • Расширение .js в пути нужно указывать. "./utils" не сработает.
  • Модули подключаются по HTTP, а не через file://. Открывайте проект через локальный сервер.
  • Модули выполняются один раз, сколько бы раз их ни импортировали.
  • Переменные модуля не попадают в window - это плюс, меньше глобального мусора.

Export default

// js/api.jsexport default function fetchUsers() {    return fetch("/api/users").then((r) => r.json());}// импортimport fetchUsers from "./api.js";

default удобен, когда модуль отдаёт одну главную сущность. Для наборов утилит лучше именованные экспорты: они подсказываются автодополнением и переименовываются автоматически.

Структура проекта

Разумный минимум для небольшого приложения:

project/├── index.html├── css/│   └── style.css└── js/    ├── main.js        точка входа    ├── api.js         запросы к серверу    ├── storage.js     работа с localStorage    ├── ui.js          рендер и DOM    └── utils.js       общие функции

Правило простое: файл должен отвечать на один вопрос. api.js знает, откуда брать данные. storage.js - как их сохранять. ui.js - как показывать. main.js связывает всё вместе.

Шпаргалка

  • try / catch поймать ошибку
  • finally выполнить всегда
  • throw выбросить ошибку
  • error.message текст ошибки
  • debugger точка останова
  • export / import модули

Если что-то не работает

  • Ошибка не ловится. Она возникла асинхронно - нужен try/catch вокруг await или .catch().
  • «Cannot use import statement outside a module». В теге <script> нет type="module".
  • «Failed to resolve module specifier». В пути нет ./ или расширения .js.
  • Модуль не грузится при открытии файла напрямую. Запустите локальный сервер: python -m http.server или расширение Live Server.
  • Ошибка «проглотилась» и ничего не видно. Пустой catch. Логируйте error целиком, а не только message - в стеке видно, откуда пришла проблема.
  • Ошибка исчезла бесследно. В обработчике стоит пустой catch {}. Программа не падает, но причина бага потеряна - логируйте error целиком.

Практика

Задача 1. Безопасный JSON

Напишите функцию safeParse(text), которая возвращает объект или null, если JSON некорректный. Ошибка не должна доходить до консоли как необработанная.

Подсказка

Оберните JSON.parse в try/catch и верните null из блока catch. Проверьте на строке "{bad}".

Решение учителя 
function safeParse(text) {    try {        return JSON.parse(text);    } catch (error) {        console.warn("Некорректный JSON:", error.message);        return null;    }}console.log(safeParse('{"ok": true}')); // { ok: true }console.log(safeParse("{bad}"));        // null
Задача 2. Своя ошибка

Создайте класс ValidationError, наследующий Error, с полем field. Напишите функцию validateAge(age), которая выбрасывает такую ошибку, если возраст меньше 0 или больше 120.

Подсказка

В конструкторе вызовите super(message) и задайте this.name = "ValidationError". Поймайте ошибку в try/catch и выведите error.field.

Решение учителя 
class ValidationError extends Error {    constructor(field, message) {        super(message);        this.name = "ValidationError";        this.field = field;    }}function validateAge(age) {    if (age < 0 || age > 120) {        throw new ValidationError("age", "Возраст должен быть от 0 до 120");    }    return true;}try {    validateAge(200);} catch (error) {    console.error(`${error.field}: ${error.message}`);}
Задача 3. Разбейте на модули

Возьмите любой свой код из предыдущих уроков и разложите его на три файла: utils.js (чистые функции), ui.js (работа с DOM) и main.js (точка входа). Подключите через type="module".

Подсказка

В utils.js поставьте export перед нужными функциями. В main.js импортируйте их и вызовите. Откройте страницу через локальный сервер, иначе модули не загрузятся.

Решение учителя 
// js/utils.jsexport function formatPrice(value) {    return `${value.toLocaleString("ru-RU")} ₽`;}// js/ui.jsimport { formatPrice } from "./utils.js";export function renderTotal(element, total) {    element.textContent = `Итого: ${formatPrice(total)}`;}// js/main.jsimport { renderTotal } from "./ui.js";const total = 4500;renderTotal(document.querySelector(".total"), total);
Задача 4. Безопасное деление

Напишите функцию safeDivide(a, b), которая выбрасывает Error с понятным текстом при делении на ноль, а иначе возвращает результат. Поймайте ошибку.

Подсказка

Проверьте b === 0 и вызовите throw new Error(...).

Решение учителя 
function safeDivide(a, b) {    if (b === 0) {        throw new Error("На ноль делить нельзя");    }    return a / b;}try {    console.log(safeDivide(10, 0));} catch (error) {    console.error(error.message);}

Что мы узнали и что дальше

Теперь ваш код умеет падать красиво и находить причины. Вы знаете:

  • Как ловить ошибки и почему пустой catch - зло.
  • Как создавать собственные типы ошибок.
  • Как отлаживать через точки останова, а не только console.log.
  • Как разбивать проект на модули.

Осталось два шага: научиться сохранять данные между перезагрузками и собрать всё вместе в настоящем приложении. В следующем уроке разберём JSON и localStorage, а также паттерн «состояние → рендер», на котором строятся современные интерфейсы.
