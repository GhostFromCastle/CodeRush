Данные в браузере: JSON и localStorage

~30 минут Продвинутый уровень Теория и Практика

Любое обновление страницы стирает состояние: список задач, выбранный фильтр, черновик сообщения. Пользователь возвращается - и всё пропало. В этом уроке научимся сохранять данные в браузере и строить приложение вокруг одного источника правды.

В этом уроке мы:

  • Разберём сериализацию через JSON.
  • Освоим localStorage и sessionStorage.
  • Поймём, какие данные хранить нельзя.
  • Разберём паттерн «состояние → рендер».
Аналогия

Блокнот на холодильнике: записи видны только в этом доме и исчезают, если блокнот выбросить.

JSON

JSON (JavaScript Object Notation) - текстовый формат обмена данными. Он похож на JavaScript-объект, но строже: ключи всегда в двойных кавычках, нет функций, нет комментариев.

const user = {    name: "Алексей",    age: 25,    skills: ["JavaScript", "CSS"],    address: { city: "Москва" }};const json = JSON.stringify(user);console.log(json);// {"name":"Алексей","age":25,"skills":["JavaScript","CSS"],"address":{"city":"Москва"}}const parsed = JSON.parse(json);console.log(parsed.name); // "Алексей"

Для читаемого вида есть третий аргумент - отступ:

console.log(JSON.stringify(user, null, 2));

Что теряется при сериализации

const data = {    fn: () => console.log("привет"),    undef: undefined,    nan: NaN,    date: new Date("2026-01-01")};console.log(JSON.stringify(data));// {"nan":null,"date":"2026-01-01T00:00:00.000Z"}
  • Функции и undefined исчезают из объекта.
  • NaN и Infinity превращаются в null.
  • Date становится строкой - при обратном разборе это уже не дата.

Поэтому правило: храните в JSON только простые данные - строки, числа, булевы значения, массивы и объекты.

localStorage

Хранилище на стороне браузера. Данные живут, пока их не удалят, - перезагрузка и закрытие вкладки им не мешают.

localStorage.setItem("theme", "dark");const theme = localStorage.getItem("theme"); // "dark"console.log(theme);localStorage.removeItem("theme");localStorage.clear(); // удалить всё

Важное ограничение: хранить можно только строки. Число превратится в строку, объект - в "[object Object]". Поэтому сложные данные прогоняют через JSON:

const settings = { theme: "dark", fontSize: 16 };localStorage.setItem("settings", JSON.stringify(settings));const raw = localStorage.getItem("settings");const restored = raw ? JSON.parse(raw) : null;console.log(restored.fontSize); // 16

Чтение с защитой

JSON.parse выбрасывает ошибку на повреждённых данных. А повреждённые данные в хранилище - реальность: пользователь мог отредактировать их вручную или старая версия приложения записала другой формат.

function loadSettings() {    const fallback = { theme: "light", fontSize: 16 };    try {        const raw = localStorage.getItem("settings");        if (!raw) return fallback;        return { ...fallback, ...JSON.parse(raw) };    } catch (error) {        console.warn("Настройки повреждены, используем значения по умолчанию");        return fallback;    }}

Обратите внимание на { ...fallback, ...JSON.parse(raw) }: если в сохранённых данных не хватает поля, подставится значение по умолчанию.

sessionStorage

Точно такой же API, но данные живут до закрытия вкладки:

sessionStorage.setItem("draft", "незаконченный текст");

Подходит для черновиков и пошаговых форм, которые не должны переживать закрытие вкладки.

Ограничения и безопасность

  • Объём - около 5 МБ на домен. Для больших данных есть IndexedDB.
  • Синхронность - операции блокируют поток. Не сохраняйте мегабайты на каждое нажатие клавиши.
  • Доступность - в приватном режиме некоторых браузеров хранилище может быть недоступно. Оборачивайте вызовы в try/catch.
  • Привязка к домену - данные одного сайта недоступны другому.
Не храните секреты

localStorage читается любым JavaScript на странице. Если злоумышленник сможет внедрить свой скрипт (XSS), он заберёт всё, что там лежит. Пароли, номера карт и долгоживущие токены авторизации там хранить нельзя. Для сессионных токенов используют HttpOnly-cookie, недоступные из JavaScript.

Паттерн «состояние → рендер»

Самая частая проблема начинающих: данные и интерфейс живут отдельно. Где-то в переменной массив задач, а в DOM - список, и они постепенно расходятся. Через неделю никто не понимает, что чему соответствует.

Решение - один источник правды и функция отрисовки:

const state = {    items: loadItems(),    filter: "all"};function render() {    const visible = filterItems(state.items, state.filter);    list.innerHTML = "";    visible.forEach((item) => {        const li = document.createElement("li");        li.textContent = item.text;        li.classList.toggle("done", item.done);        list.append(li);    });    empty.hidden = visible.length > 0;}

Правило: любое изменение данных заканчивается вызовом render(). Интерфейс никогда не правится «точечно» в обход состояния. Такой подход называется односторонним потоком данных, и именно на нём построены React, Vue и Angular.

Обновление делают неизменяемым - создавая новый массив, а не меняя старый:

// плохо: мутацияstate.items.push(newItem);// хорошо: новый массивstate.items = [...state.items, newItem];

Почему «хорошо»? Потому что так проще сравнивать состояния, откатывать изменения и понимать, что именно поменялось. Привычка пригодится в любом современном фреймворке.

Дебаунс для записи

Если сохранять данные на каждое нажатие клавиши, браузер будет писать в хранилище сотни раз в минуту. Немного терпения экономит ресурсы:

function debounce(fn, delay = 300) {    let timerId;    return (...args) => {        clearTimeout(timerId);        timerId = setTimeout(() => fn(...args), delay);    };}const saveDraft = debounce((text) => {    sessionStorage.setItem("draft", text);}, 500);input.addEventListener("input", () => saveDraft(input.value));

Шпаргалка

  • JSON.stringify объект в строку
  • JSON.parse строка в объект
  • setItem сохранить строку
  • getItem прочитать или null
  • removeItem удалить ключ
  • sessionStorage до закрытия вкладки
  • render() перерисовать из состояния

Если что-то не работает

  • В хранилище лежит [object Object]. Забыли JSON.stringify перед сохранением.
  • JSON.parse падает. В хранилище невалидный JSON или null. Всегда проверяйте, что getItem вернул не null, и оборачивайте разбор в try/catch.
  • Данные не сохраняются. Код выполняется на другом домене, в приватном режиме или хранилище переполнено. Проверьте исключение в консоли.
  • После перезагрузки интерфейс пустой, а данные есть. Забыли вызвать render() при старте приложения.
  • Изменения не видны. Вы изменили копию массива, а не состояние. Проверьте, что результат filter или map присвоен обратно.
  • Настройки пропали после очистки кэша. localStorage живёт в браузере, а не на сервере: очистка данных сайта удаляет и его. Для важных данных нужен сервер и резервные копии.

Практика

Задача 1. Сохранить настройки

Сохраните объект { theme: "dark", fontSize: 18 } в localStorage под ключом settings, затем прочитайте его обратно и выведите тему в консоль.

Подсказка

Сохраняйте строку: JSON.stringify(settings). Читайте через JSON.parse(localStorage.getItem("settings")).

Решение учителя 
const settings = { theme: "dark", fontSize: 18 };localStorage.setItem("settings", JSON.stringify(settings));const restored = JSON.parse(localStorage.getItem("settings"));console.log(restored.theme); // "dark"
Задача 2. Защищённое чтение

Напишите функцию loadList(key), которая всегда возвращает массив. Если ключа нет, данные повреждены или там лежит не массив - возвращается пустой массив.

Подсказка

Проверьте Array.isArray(parsed) после разбора. Всю логику оберните в try/catch и возвращайте [] при любой проблеме.

Решение учителя 
function loadList(key) {    try {        const raw = localStorage.getItem(key);        if (!raw) return [];        const parsed = JSON.parse(raw);        return Array.isArray(parsed) ? parsed : [];    } catch (error) {        console.warn("Повреждённые данные:", key);        return [];    }}
Задача 3. Черновик с дебаунсом

Сделайте текстовое поле, содержимое которого сохраняется в sessionStorage не чаще раза в 500 мс. При загрузке страницы текст должен восстанавливаться.

Подсказка

Используйте функцию debounce из урока. При старте прочитайте значение и присвойте его input.value.

Решение учителя 
const input = document.querySelector("#draft");function debounce(fn, delay) {    let timerId;    return (...args) => {        clearTimeout(timerId);        timerId = setTimeout(() => fn(...args), delay);    };}const save = debounce((text) => {    sessionStorage.setItem("draft", text);}, 500);input.value = sessionStorage.getItem("draft") ?? "";input.addEventListener("input", () => save(input.value));
Задача 4. Счётчик посещений

Увеличивайте счётчик в localStorage при каждой загрузке страницы и выводите его в консоль.

Подсказка

Прочитайте значение, приведите к числу, прибавьте единицу и сохраните обратно.

Решение учителя 
const key = "visits";const current = Number(localStorage.getItem(key)) || 0;const next = current + 1;localStorage.setItem(key, String(next));console.log(`Вы заходили ${next} раз`);

  • Как работать с localStorage и безопасно читать из него.
  • Почему секреты нельзя хранить в браузере.
