Тестирование и инструменты

~35 минут Продвинутый уровень Теория и Практика

Пока проект маленький, ошибку видно сразу. Когда файлов десятки, изменение в одном месте ломает другое - и узнаёте вы об этом от пользователя. Тесты и инструменты решают эту проблему: они проверяют код за вас и делают это за секунды.

В этом уроке мы:

  • Поймём, зачем нужны тесты и какие они бывают.
  • Напишем первые тесты на Vitest.
  • Разберёмся с package.json, npm и Vite.
  • Настроим линтер и форматтер.
Аналогия

Контролёр в автобусе: он сверяет каждый билет со списком, а не «на глаз». Тест делает то же самое с кодом.

Зачем тесты

Тест - это код, который проверяет другой код. Звучит странно, но выгода огромная:

  • Уверенность при изменениях. Переписали функцию - запустили тесты, увидели, что ничего не сломалось.
  • Документация. Тест показывает, как функция должна себя вести в необычных случаях.
  • Ловит краевые случаи. Пустой массив, ноль, отрицательное число, null - то, что забывают проверить руками.

Какие бывают тесты

  • Юнит-тесты - проверяют одну функцию или модуль в изоляции. Быстрые, их пишут чаще всего.
  • Интеграционные - проверяют, как несколько частей работают вместе: форма, состояние, рендер.
  • E2E (end-to-end) - запускают настоящий браузер и проходят сценарий пользователя: открыть страницу, ввести текст, нажать кнопку, проверить результат.

Начинать стоит с юнит-тестов: они дешёвые и сразу дают пользу.

Что легко тестировать

Лучше всего тестируются чистые функции - те, что зависят только от аргументов и не трогают DOM, сеть или localStorage:

// utils.jsexport function formatPrice(value) {    return `${value.toLocaleString("ru-RU")} ₽`;}export function calculateTotal(items) {    return items.reduce((sum, item) => sum + item.price * item.count, 0);}export function isValidEmail(value) {    return /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/.test(value);}

Именно такие функции проще всего покрыть тестами - и именно они содержат основную логику.

Первый тест на Vitest

Создайте проект и установите Vitest:

npm init -ynpm install -D vitest

В package.json добавьте скрипт:

{  "scripts": {    "test": "vitest run",    "test:watch": "vitest"  }}

Теперь сам тест:

JavaScript 
// utils.test.js
import { describe, it, expect } from "vitest";
import { calculateTotal, isValidEmail, formatPrice } from "./utils.js";

describe("calculateTotal", () => {
    it("складывает цену, умноженную на количество", () => {
        const items = [
            { price: 1000, count: 2 },
            { price: 500, count: 1 }
        ];

        expect(calculateTotal(items)).toBe(2500);
    });

    it("возвращает 0 для пустой корзины", () => {
        expect(calculateTotal([])).toBe(0);
    });
});

describe("isValidEmail", () => {
    it("принимает корректный адрес", () => {
        expect(isValidEmail("alex@example.com")).toBe(true);
    });

    it("отклоняет адрес без домена", () => {
        expect(isValidEmail("alex@example")).toBe(false);
    });
});

Запуск: npm test. Vitest выполнит все файлы *.test.js и покажет отчёт.

Основные проверки

expect(value).toBe(5);            // строгое равенство (для примитивов)expect(object).toEqual({ a: 1 }); // глубокое сравнениеexpect(array).toHaveLength(3);expect(value).toBeTruthy();expect(value).toBeNull();expect(fn).toThrow("Сообщение");expect(text).toContain("Москва");expect(number).toBeGreaterThan(10);

toBe сравнивает по ссылке, поэтому для объектов и массивов нужен toEqual. Это одна из первых ошибок, которая сбивает с толку.

Хороший тест проверяет поведение

Плохой тест: «функция вызвана один раз». Хороший: «при пустой корзине возвращается ноль». Проверяйте результат, а не внутреннее устройство - иначе любая правка реализации будет ломать тесты без причины.

Краевые случаи

Помимо «обычного» сценария, проверяйте границы:

it("не падает на отрицательном количестве", () => {    expect(() => calculateTotal([{ price: 100, count: -1 }])).not.toThrow();});it("обрабатывает пустую строку", () => {    expect(isValidEmail("")).toBe(false);});

Список типичных краевых случаев: пустое значение, ноль, отрицательное число, очень большое число, null, строка вместо числа, массив без элементов, дубликаты.

npm и package.json

npm - менеджер пакетов. package.json описывает проект: имя, зависимости, скрипты.

npm init -y                 # создать package.jsonnpm install vite            # установить зависимостьnpm install -D vitest       # установить dev-зависимостьnpm run dev                 # запустить скрипт dev

Каталог node_modules в репозиторий не коммитят - он восстанавливается командой npm install. В .gitignore должны быть node_modules и dist.

Vite

Vite - инструмент разработки: запускает локальный сервер, перезагружает страницу при изменениях и собирает проект для публикации.

npm create vite@latest my-appcd my-appnpm installnpm run dev

Для проекта без фреймворка выбирайте шаблон vanilla. Vite понимает ES-модули, поддерживает горячую перезагрузку и не требует настройки для большинства задач.

ESLint и Prettier

ESLint ищет проблемы в коде: неиспользуемые переменные, забытые await, потенциальные ошибки.

Prettier приводит код к единому виду: отступы, кавычки, переносы.

npm install -D eslint prettiernpm run lintnpx prettier --write .

В команде это обязательно: иначе каждый коммит содержит споры о пробелах вместо изменений по существу.

Git в двух словах

Тесты и инструменты имеют смысл вместе с контролем версий:

git status          # что измененоgit add .           # подготовить измененияgit commit -m "feat: добавил валидацию формы"git log --oneline   # история

Коммит - это точка, к которой можно вернуться. Небольшие частые коммиты с понятными сообщениями спасают часы работы.

Шпаргалка

  • describe / it группировка и тест
  • expect().toBe() проверка значения
  • toEqual глубокое сравнение
  • npm run dev запуск проекта
  • npm test прогон тестов
  • eslint / prettier качество и стиль

Если что-то не работает

  • «Cannot find module». Модуль не установлен или путь неверный. Проверьте npm install и расширение .js в импорте.
  • Тест падает на объекте. Используйте toEqual, а не toBe.
  • Тест проходит, но приложение падает. Тест проверяет не то поведение или не покрывает реальный сценарий. Проверяйте результат, а не реализацию.
  • Vite не видит файлы. Проверьте структуру: index.html должен лежать в корне проекта.
  • ESLint ругается на глобальные переменные. Настройте окружение browser в конфиге.
  • Тесты зелёные, а пользователи находят баг. Тесты проверяли реализацию, а не реальный сценарий. Пишите проверки от поведения: «при пустой корзине сумма 0».

Практика

Задача 1. Первые тесты

Напишите функцию isEven(n) и покройте её тестами: чётное число, нечётное, ноль, отрицательное.

Подсказка

Четыре it внутри одного describe. Для отрицательного числа проверьте, что результат такой же, как для положительного.

Решение учителя 
import { describe, it, expect } from "vitest";import { isEven } from "./math.js";describe("isEven", () => {    it("чётное", () => expect(isEven(4)).toBe(true));    it("нечётное", () => expect(isEven(7)).toBe(false));    it("ноль чётный", () => expect(isEven(0)).toBe(true));    it("отрицательное", () => expect(isEven(-2)).toBe(true));});
Задача 2. Тест на ошибку

Функция withdraw(balance, amount) выбрасывает ошибку, если сумма больше баланса. Напишите тест, который это проверяет.

Подсказка

Оберните вызов в стрелочную функцию: expect(() => withdraw(100, 500)).toThrow(). Без обёртки ошибка выбросится до того, как expect её поймает.

Решение учителя 
it("не даёт снять больше баланса", () => {    expect(() => withdraw(100, 500)).toThrow("Недостаточно средств");});
Задача 3. Запустите Vite

Создайте проект на Vite, перенесите в него TODO-приложение из прошлых уроков и убедитесь, что горячая перезагрузка работает: измените заголовок в HTML и посмотрите на страницу без ручного обновления.

Подсказка

npm create vite@latest todo -- --template vanilla, затем npm install и npm run dev. Файлы кладите в корень, а не в отдельную папку js - или поправьте пути.

Решение учителя 
npm create vite@latest todo -- --template vanillacd todonpm installnpm run dev

Откройте адрес из терминала (обычно http://localhost:5173), измените текст в index.html - страница обновится сама.

Задача 4. Граничные значения

Напишите тесты для функции toNumber(value): обычное число, запятая вместо точки, пустая строка, мусор.

Подсказка

Четыре it внутри describe. Для мусора ожидайте null.

Решение учителя 
describe("toNumber", () => {    it("обычное число", () => expect(toNumber("42")).toBe(42));    it("запятая", () => expect(toNumber("3,14")).toBe(3.14));    it("пустая строка", () => expect(toNumber("")).toBe(0));    it("мусор", () => expect(toNumber("abc")).toBeNull());});
