Анимации и requestAnimationFrame

~30 минут Продвинутый уровень Теория и Практика

Анимация - это не украшение, а способ объяснить интерфейс: показать, откуда пришло окно, подтвердить нажатие, провести взгляд к важному. В браузере есть три инструмента: CSS-переходы, CSS-анимации и JavaScript с requestAnimationFrame.

В этом уроке мы:

  • Поймём, когда хватает CSS, а когда нужен JavaScript.
  • Освоим requestAnimationFrame и время кадра.
  • Сделаем движение, не зависящее от частоты обновления экрана.
  • Познакомимся с Web Animations API и доступностью.
Аналогия

Киноплёнка: кадры сменяют друг друга через равные промежутки времени. Если шаг разный, движение начинает дёргаться.

Три способа анимировать

CSS-переход - когда нужно плавно изменить свойство по событию:

.card {    transition: transform 0.2s ease;}.card:hover {    transform: translateY(-4px);}

CSS-анимация - когда есть последовательность состояний:

@keyframes pulse {    0%   { opacity: 1; }    50%  { opacity: 0.4; }    100% { opacity: 1; }}.skeleton {    animation: pulse 1.2s infinite;}

JavaScript нужен, когда анимация зависит от данных: счётчик, прогресс загрузки, движение за курсором, физика, прокрутка.

Правило выбора

Если анимацию можно описать CSS - описывайте CSS. Браузер выполняет такие анимации в отдельном потоке, и они не тормозят, даже когда JavaScript занят. JS берите только там, где нужны вычисления на каждом кадре.

Почему не setInterval

Первая идея новичка - двигать элемент таймером:

// так делать не надоsetInterval(() => {    position += 2;    box.style.transform = `translateX(${position}px)`;}, 16);

Проблемы: таймер не синхронизирован с экраном, кадры могут пропускаться, а на вкладке в фоне он продолжает работать. Правильный инструмент - requestAnimationFrame.

requestAnimationFrame

function animate(timestamp) {    // timestamp - время с момента открытия страницы, в миллисекундах    console.log(timestamp);    requestAnimationFrame(animate);}requestAnimationFrame(animate);

Браузер вызывает функцию перед перерисовкой кадра - обычно 60 раз в секунду, но на мониторах 120 Гц чаще. Поэтому двигать объект «на 2 пикселя за кадр» неправильно: на разных экранах скорость будет разной.

Время кадра

Считать нужно в единицах времени, а не в кадрах. Разница между кадрами называется delta:

let position = 0;let lastTime = null;const speed = 120; // пикселей в секундуfunction move(timestamp) {    if (lastTime === null) lastTime = timestamp;    const delta = (timestamp - lastTime) / 1000; // секунды    lastTime = timestamp;    position += speed * delta;    box.style.transform = `translateX(${position}px)`;    if (position < 400) {        requestAnimationFrame(move);    }}requestAnimationFrame(move);

Теперь скорость одинакова и на 60 Гц, и на 120 Гц, и при просадках производительности.

Плавное появление: easing

Линейное движение выглядит механически. Функция плавности делает старт и финиш мягче:

function easeOutCubic(t) {    return 1 - Math.pow(1 - t, 3);}function animateOpacity(element) {    const duration = 400;    const start = performance.now();    function frame(now) {        const progress = Math.min((now - start) / duration, 1);        element.style.opacity = easeOutCubic(progress);        if (progress < 1) requestAnimationFrame(frame);    }    requestAnimationFrame(frame);}

progress всегда от 0 до 1. Функция плавности превращает его в другое число от 0 до 1, но с нужной кривой. Тот же приём используют CSS-функции ease-in-out, cubic-bezier.

Остановка анимации

requestAnimationFrame возвращает идентификатор, который можно отменить:

let frameId;function loop() {    // ...    frameId = requestAnimationFrame(loop);}function stop() {    cancelAnimationFrame(frameId);}

Обязательно останавливайте цикл, когда он больше не нужен: при уходе со страницы, закрытии модалки, достижении цели. Иначе браузер будет считать кадры впустую.

Web Animations API

Современная альтернатива - метод element.animate. Он даёт управление анимацией из JS, но выполняет её браузер:

const animation = box.animate(    [        { transform: "translateX(0)", opacity: 1 },        { transform: "translateX(300px)", opacity: 0.5 }    ],    {        duration: 600,        easing: "ease-out",        fill: "forwards"    });animation.pause();animation.play();animation.reverse();animation.finished.then(() => console.log("Готово"));

Для большинства задач «показать/скрыть/подвинуть» этого достаточно, и код получается короче, чем ручной цикл.

Доступность

Не все любят анимацию. Некоторым движение вызывает головокружение, у других включён режим экономии энергии. Уважайте системную настройку:

@media (prefers-reduced-motion: reduce) {    * {        animation-duration: 0.01ms !important;        transition-duration: 0.01ms !important;    }}

В JavaScript проверить настройку можно так:

const reduced = window.matchMedia("(prefers-reduced-motion: reduce)").matches;

Производительность

  • Анимируйте transform и opacity. Они не вызывают пересчёт вёрстки.
  • Избегайте width, top, left, margin. Каждый кадр будет пересчитывать layout.
  • Не читайте и не пишите DOM вперемешку. Сначала все чтения, потом все записи - иначе браузер вынужден пересчитывать layout на каждом шаге.
  • Останавливайте невидимые анимации. Вкладка в фоне и так тормозит таймеры, но JS-цикл всё равно расходует ресурсы.

Шпаргалка

  • requestAnimationFrame кадр перед перерисовкой
  • cancelAnimationFrame остановить цикл
  • delta время между кадрами
  • element.animate анимация через API
  • transform / opacity дешёвые свойства
  • prefers-reduced-motion уважение к настройкам

Если что-то не работает

  • Анимация дёргается. Используется setInterval или анимируются свойства, вызывающие layout.
  • На одном компьютере быстрее, чем на другом. Скорость задана «в пикселях за кадр», а не в секунду.
  • Цикл продолжает работать после закрытия окна. Нет cancelAnimationFrame.
  • Элемент «прыгает» в конце. Значение не ограничено единицей: используйте Math.min(progress, 1).
  • Анимация не запускается. Функция вызывается, но не передаётся в requestAnimationFrame, либо элемент имеет display: none.
  • Анимация тормозит на слабом ноутбуке. Анимируются width или top - браузер пересчитывает вёрстку каждый кадр. transform и opacity дешевле.

Практика

Задача 1. Прогресс-бар

Сделайте полосу, которая заполняется от 0 до 100% за две секунды. Используйте requestAnimationFrame, а не CSS-переход.

Подсказка

Запомните время старта через performance.now(), считайте прогресс как отношение прошедшего времени к длительности и ограничивайте его единицей.

Решение учителя 
const bar = document.querySelector(".bar");const duration = 2000;const start = performance.now();function frame(now) {    const progress = Math.min((now - start) / duration, 1);    bar.style.width = `${progress * 100}%`;    if (progress < 1) requestAnimationFrame(frame);}requestAnimationFrame(frame);
Задача 2. Плавный счётчик

Число на странице должно плавно увеличиваться от 0 до 1000 за полторы секунды. В конце должно остаться ровно 1000.

Подсказка

Считайте прогресс, умножайте на 1000 и округляйте через Math.round. Не забудьте про финальное значение при progress === 1.

Решение учителя 
const counter = document.querySelector(".counter");const duration = 1500;const start = performance.now();function frame(now) {    const progress = Math.min((now - start) / duration, 1);    counter.textContent = Math.round(progress * 1000);    if (progress < 1) requestAnimationFrame(frame);}requestAnimationFrame(frame);
Задача 3. Плавное появление

Напишите функцию fadeIn(element), которая плавно меняет прозрачность от 0 до 1 за 300 мс с замедлением в конце. Если у пользователя включён режим уменьшенной анимации - показывайте сразу.

Подсказка

Проверьте matchMedia("(prefers-reduced-motion: reduce)"). Для кривой подойдёт 1 - (1 - t) ** 3.

Решение учителя 
function fadeIn(element) {    const reduced = matchMedia("(prefers-reduced-motion: reduce)").matches;    if (reduced) {        element.style.opacity = 1;        return;    }    const start = performance.now();    const duration = 300;    function frame(now) {        const progress = Math.min((now - start) / duration, 1);        element.style.opacity = 1 - Math.pow(1 - progress, 3);        if (progress < 1) requestAnimationFrame(frame);    }    requestAnimationFrame(frame);}
Задача 4. Пульсация кнопки

Сделайте так, чтобы кнопка при нажатии плавно уменьшалась и возвращалась обратно.

Подсказка

Подойдёт element.animate с двумя кадрами и fill: "none".

Решение учителя 
const button = document.querySelector(".pulse");button.addEventListener("click", () => {    button.animate(        [{ transform: "scale(1)" }, { transform: "scale(0.92)" }, { transform: "scale(1)" }],        { duration: 250, easing: "ease-out" }    );});
