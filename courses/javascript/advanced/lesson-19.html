Замыкания, область видимости и this

~35 минут Продвинутый уровень Теория и Практика

Начинающие разработчики пишут код, который работает. Опытные - код, который они понимают. Граница проходит здесь: в понимании области видимости, замыканий и this. Именно эти темы чаще всего спрашивают на собеседованиях - и именно они объясняют поведение, которое иначе кажется магией.

В этом уроке мы:

  • Разберём, как JavaScript ищет переменные.
  • Поймём, что такое hoisting и временная мёртвая зона.
  • Освоим замыкания - и увидим, где они применяются.
  • Разберёмся, чему равно this в разных ситуациях.
Аналогия

Рюкзак: функция уносит с собой переменные из места рождения и достаёт их позже, даже когда это место уже закрыто.

Область видимости

У переменной есть область, в которой она доступна. В JavaScript таких областей две: глобальная и блочная (внутри {...}).

const global = "я везде";function outer() {    const fromOuter = "я в функции";    function inner() {        const fromInner = "я только здесь";        console.log(global);     // доступна        console.log(fromOuter);  // доступна        console.log(fromInner);  // доступна    }    inner();    // console.log(fromInner); // ReferenceError}

Когда код обращается к переменной, движок сначала ищет её в текущем блоке, затем в родительском, затем выше - вплоть до глобальной области. Эта цепочка называется цепочкой областей видимости.

Ключевой момент: функция видит переменные того места, где она объявлена, а не того, откуда её вызвали. Это называется лексической областью видимости.

var, let и const

Разница не только в возможности переприсваивания:

if (true) {    var oldStyle = "видна снаружи блока";    let blockScoped = "только внутри блока";}console.log(oldStyle);    // работаетconsole.log(blockScoped); // ReferenceError

var игнорирует блоки {} и поднимается до уровня функции. Именно поэтому он приводит к трудноуловимым багам - и поэтому в современном коде его не используют.

Hoisting и временная мёртвая зона

Перед выполнением кода движок проходит по нему и регистрирует объявления. Это называется поднятием (hoisting). Но ведёт себя оно по-разному:

console.log(a); // undefined - объявление поднято, значение нетvar a = 1;// console.log(b); // ReferenceError: Cannot access 'b' before initializationlet b = 2;

С let и const переменная существует с начала блока, но до строки объявления находится в временной мёртвой зоне (TDZ). Обращение к ней - ошибка. Это сделано специально: лучше упасть сразу, чем получить undefined и искать причину через десять строк.

Функции, объявленные через function, поднимаются целиком - их можно вызывать до объявления:

sayHi(); // работаетfunction sayHi() {    console.log("Привет");}// sayBye(); // TypeError: sayBye is not a functionconst sayBye = () => console.log("Пока");

Замыкание

Замыкание - это функция, которая запоминает переменные из места своего создания, даже после того как внешняя функция завершилась.

function createCounter() {    let count = 0;    return function () {        count += 1;        return count;    };}const counter = createCounter();console.log(counter()); // 1console.log(counter()); // 2console.log(counter()); // 3

createCounter уже завершилась, но count жив: возвращённая функция держит на него ссылку. Никакой другой код не может изменить эту переменную напрямую - получается приватное состояние.

Где замыкания в реальном коде

Обработчики событий, колбэки таймеров, функции-обработчики запросов - всё это замыкания. Когда вы пишете button.addEventListener("click", () => count++), стрелочная функция замыкает переменную count. Вы пользуетесь этим постоянно, просто не называли это словом «замыкание».

Замыкание и циклы

Классическая задача. Что выведет этот код?

for (var i = 0; i < 3; i++) {    setTimeout(() => console.log(i), 0);}

Ответ: 3, 3, 3. var создаёт одну переменную на весь цикл, и к моменту выполнения колбэков она уже равна трём.

С let всё иначе: для каждой итерации создаётся своя переменная.

for (let i = 0; i < 3; i++) {    setTimeout(() => console.log(i), 0);}// 0, 1, 2

Это одна из главных причин, почему let заменил var.

Модули через замыкание

До появления ES-модулей приватность делали так:

const storage = (function () {    const items = [];    return {        add(item) {            items.push(item);        },        getAll() {            return [...items];        },        count() {            return items.length;        }    };})();storage.add("яблоко");console.log(storage.count()); // 1console.log(storage.items);   // undefined - снаружи не достать

Функция вызывает себя сразу (IIFE) и возвращает только публичный интерфейс. Массив items остаётся внутри замыкания. Современный аналог - модули, о которых поговорим через два урока.

this: четыре ситуации

this - ссылка на контекст вызова. Значение зависит не от того, где функция объявлена, а от того, как она вызвана.

1. Метод объекта

const user = {    name: "Алексей",    greet() {        console.log(this.name);    }};user.greet(); // "Алексей"

Если функция вызвана как метод - this указывает на объект перед точкой.

2. Обычный вызов

function show() {    console.log(this);}show(); // в строгом режиме undefined, иначе window

Модули и код классов работают в строгом режиме, поэтому там this будет undefined.

3. Стрелочная функция

Своё this стрелочные функции не создают - они берут его из внешнего контекста:

const user = {    name: "Алексей",    greet: () => {        console.log(this.name); // undefined    }};user.greet();

Поэтому методы объекта стрелочными не делают. Исключение - когда нужно специально сохранить внешний this внутри колбэка:

const timer = {    seconds: 0,    start() {        setInterval(() => {            this.seconds++; // this из start            console.log(this.seconds);        }, 1000);    }};

4. Явная привязка

Методы call, apply и bind позволяют задать this вручную:

function introduce(greeting, punctuation) {    console.log(`${greeting}, ${this.name}${punctuation}`);}const user = { name: "Алексей" };introduce.call(user, "Привет", "!");introduce.apply(user, ["Привет", "!"]);const bound = introduce.bind(user, "Привет");bound("!"); // "Привет, Алексей!"

call принимает аргументы через запятую, apply - массивом, bind возвращает новую функцию с навсегда привязанным контекстом.

Потеря this

Самая частая ошибка - передать метод как колбэк:

const user = {    name: "Алексей",    greet() {        console.log(this.name);    }};setTimeout(user.greet, 100); // undefinedsetTimeout(() => user.greet(), 100);        // "Алексей"setTimeout(user.greet.bind(user), 100);     // "Алексей"

В первом случае функция вызвана без объекта - this потерян. Лечится обёрткой-стрелкой или bind.

Шпаргалка

  • let / const блочная область видимости
  • var функциональная, устаревшая
  • TDZ нельзя читать до объявления
  • closure функция помнит своё окружение
  • this зависит от способа вызова
  • bind жёстко привязать this

Если что-то не работает

  • «Cannot access before initialization». Временная мёртвая зона: переменная используется до объявления.
  • В цикле все колбэки выводят последнее значение. Счётчик объявлен через var. Замените на let.
  • this равно undefined. Метод вызван без объекта, записан стрелочной функцией или передан как колбэк. Используйте bind или обёртку.
  • Счётчик в замыкании «сбрасывается». Функция создаётся заново при каждом вызове внешней функции - состояние нужно выносить наружу.
  • Мутация массива из замыкания видна снаружи. Возвращайте копию: [...items], иначе внешний код сможет менять внутреннее состояние.
  • Все кнопки показывают одно и то же число. Обработчики в цикле замкнули одну переменную. С let в заголовке цикла у каждой итерации своя переменная - проблема исчезает.

Практика

Задача 1. Счётчик

Напишите функцию createCounter(start = 0), которая возвращает объект с методами increment(), decrement() и value(). Внутреннее число не должно быть доступно напрямую.

Подсказка

Объявите let count = start внутри функции и верните объект с методами, которые его меняют. Это и есть замыкание.

Решение учителя 
function createCounter(start = 0) {    let count = start;    return {        increment: () => ++count,        decrement: () => --count,        value: () => count    };}const counter = createCounter(5);counter.increment();console.log(counter.value()); // 6console.log(counter.count);   // undefined
Задача 2. Ошибка с var

Код ниже выводит три тройки вместо 0, 1, 2. Объясните почему и исправьте его двумя способами: через let и через замыкание с var.

for (var i = 0; i < 3; i++) {    setTimeout(() => console.log(i), 0);}
Подсказка

var создаёт одну переменную на весь цикл. Второй способ - обернуть тело цикла в функцию, которая вызывается сразу с текущим значением: (function (j) { ... })(i).

Решение учителя 
// Способ 1: let создаёт переменную на каждую итерациюfor (let i = 0; i < 3; i++) {    setTimeout(() => console.log(i), 0);}// Способ 2: замыканиеfor (var j = 0; j < 3; j++) {    (function (value) {        setTimeout(() => console.log(value), 0);    })(j);}
Задача 3. Потерянный this

Метод user.greet передали в таймер, и он вывел undefined. Исправьте код так, чтобы вывелось имя, не меняя сам объект и не переписывая метод стрелкой.

const user = {    name: "Алексей",    greet() {        console.log(this.name);    }};setTimeout(user.greet, 100);
Подсказка

Либо оберните вызов в стрелочную функцию, которая сохраняет контекст, либо привяжите его через bind(user).

Решение учителя 
setTimeout(() => user.greet(), 100);// илиsetTimeout(user.greet.bind(user), 100);
Задача 4. Один раз

Напишите функцию once(fn), которая возвращает обёртку: исходная функция выполняется только при первом вызове, дальше возвращается сохранённый результат.

Подсказка

Запомните результат в замыкании и проверяйте флаг.

Решение учителя 
function once(fn) {    let called = false;    let result;    return (...args) => {        if (!called) {            called = true;            result = fn(...args);        }        return result;    };}
