Безопасность и производительность

~35 минут Продвинутый уровень Теория и Практика

Фронтенд-разработчик отвечает не только за красоту, но и за безопасность пользователя. Большинство атак на веб-приложения начинаются с доверия к пользовательскому вводу. В этом уроке - базовый минимум, который обязан знать любой разработчик.

В этом уроке мы:

  • Разберём XSS - самую частую уязвимость интерфейсов.
  • Научимся безопасно вставлять пользовательские данные.
  • Поймём, что такое CSP и почему HTTPS обязателен.
  • Разберём производительность: debounce, throttle, ленивую загрузку.
Аналогия

Дом: замок на двери (CSP), ключи не под ковриком (секреты в localStorage), гостей проверяем на входе (валидация).

XSS: внедрение кода

XSS (Cross-Site Scripting) - ситуация, когда злоумышленник заставляет страницу выполнить свой JavaScript. Самый простой путь - innerHTML с пользовательским текстом:

const input = document.querySelector(".comment");// ОПАСНОcommentBox.innerHTML = input.value;

Если пользователь введёт <img src=x onerror="alert(document.cookie)">, код выполнится в браузере всех, кто откроет страницу. Так крадут токены, подменяют содержимое и уводят пользователей на фальшивые формы.

Как защищаться

1. Используйте textContent вместо innerHTML. Текст останется текстом, теги не выполнятся:

commentBox.textContent = input.value; // безопасно

2. Не склеивайте HTML из данных. Если нужна разметка - создавайте элементы и задавайте свойства:

const link = document.createElement("a");link.href = url;link.textContent = title;

3. Проверяйте адреса. Ссылка с javascript: в href тоже выполнит код:

function isSafeUrl(value) {    try {        const url = new URL(value, location.origin);        return url.protocol === "http:" || url.protocol === "https:";    } catch {        return false;    }}

4. Санитизация. Если HTML всё-таки нужен (редактор, комментарии с разметкой), используйте проверенную библиотеку вроде DOMPurify. Писать свой «чистильщик» регулярками нельзя: обход находится за пару минут.

Никогда не доверяйте клиенту

Любая проверка в браузере - только удобство. Пользователь может открыть DevTools, изменить данные и отправить запрос напрямую. Валидация, проверка прав и лимиты обязаны быть на сервере.

CSP

Content Security Policy - заголовок, который запрещает выполнять сторонние скрипты. Даже если XSS-вставка произошла, браузер её заблокирует:

Content-Security-Policy: default-src 'self'; script-src 'self'; img-src 'self' https:;

Настраивается на сервере или в мета-теге. Начинать стоит с отчётов о нарушениях, а не с жёсткого запрета всего - иначе сломается половина сайта.

Что ещё важно

  • HTTPS. Без него данные передаются открытым текстом, а браузер помечает сайт как небезопасный.
  • Секреты не в коде. Токены и ключи API не хранят в JavaScript: любой посетитель увидит их в исходниках.
  • localStorage не для токенов. Он доступен любому скрипту на странице. Для сессий используют HttpOnly-cookie.
  • Не используйте eval. Он выполняет произвольный код и ломает оптимизации движка.
  • Обновляйте зависимости. npm audit показывает известные уязвимости в пакетах.

Производительность: с чего начать

Оптимизировать нужно то, что измерено. Откройте DevTools → Lighthouse и посмотрите на реальные цифры. Обычно самые большие проблемы - картинки, блокирующий JS и лишние перерисовки.

debounce и throttle

Два приёма, которые экономият запросы и вычисления:

function debounce(fn, delay = 300) {    let timerId;    return (...args) => {        clearTimeout(timerId);        timerId = setTimeout(() => fn(...args), delay);    };}function throttle(fn, limit = 200) {    let waiting = false;    return (...args) => {        if (waiting) return;        fn(...args);        waiting = true;        setTimeout(() => { waiting = false; }, limit);    };}

Разница на пальцах:

  • debounce - «подожди, пока пользователь закончит». Поиск с автодополнением, проверка имени.
  • throttle - «не чаще одного раза в N мс». Прокрутка, движение мыши, изменение размера окна.
const search = document.querySelector("#search");search.addEventListener("input", debounce((event) => {    console.log("Ищем:", event.target.value);}, 400));

Ленивая загрузка

Браузер умеет откладывать загрузку изображений без библиотек:

<img src="photo.jpg" loading="lazy" width="600" height="400" alt="...">

Атрибуты width и height обязательны: они резервируют место и не дают странице «прыгать» при загрузке. Это называется layout shift.

Батчинг DOM-операций

Каждое изменение DOM может вызвать пересчёт layout. Дешевле собрать всё и вставить один раз:

const fragment = document.createDocumentFragment();items.forEach((item) => {    const li = document.createElement("li");    li.textContent = item;    fragment.append(li);});list.append(fragment); // одна вставка вместо сотни

Ещё лучше - вообще не трогать DOM в цикле: собрать HTML-строку из безопасных данных и вставить один раз, либо использовать виртуализацию для больших списков.

Правило трёх секунд

Пользователь уходит, если страница не показала контент за несколько секунд. Поэтому критичный CSS инлайнят, шрифты подключают с font-display: swap, а тяжёлые скрипты - с defer. Сначала покажите хоть что-то, потом догружайте остальное.

Шпаргалка

  • textContent безопасная вставка текста
  • DOMPurify санитизация HTML
  • CSP политика загрузки ресурсов
  • debounce после паузы
  • throttle не чаще раза в N мс
  • loading="lazy" отложенная загрузка

Если что-то не работает

  • Пользовательский текст сломал вёрстку. Используется innerHTML. Замените на textContent.
  • После включения CSP всё сломалось. Запрещены инлайновые скрипты и стили. Выносите их в файлы или добавляйте nonce.
  • Поиск отправляет запрос на каждую букву. Нужен debounce.
  • Страница дёргается при загрузке картинок. Не указаны width и height.
  • Lighthouse ругается на неиспользуемый JS. Подключайте модули по требованию, используйте динамический import().
  • Сайт «взломали» через комментарий. Пользовательский текст вставили через innerHTML, и чужой скрипт выполнился у всех посетителей. Это XSS, и лечится он textContent или санитизацией.

Практика

Задача 1. Безопасный комментарий

Есть поле ввода и блок для комментария. Сделайте так, чтобы текст с тегами отображался как текст, а не выполнялся.

Подсказка

Используйте textContent. Проверьте на строке <img src=x onerror=alert(1)> - она должна появиться как текст.

Решение учителя 
const input = document.querySelector(".comment-input");const box = document.querySelector(".comment-box");document.querySelector(".send").addEventListener("click", () => {    box.textContent = input.value;});
Задача 2. Поиск с задержкой

Сделайте поле поиска, которое выводит в консоль введённый текст не чаще чем через 400 мс после последнего нажатия.

Подсказка

Используйте готовую функцию debounce из урока: она очищает предыдущий таймер и запускает новый.

Решение учителя 
function debounce(fn, delay = 400) {    let timerId;    return (...args) => {        clearTimeout(timerId);        timerId = setTimeout(() => fn(...args), delay);    };}const search = document.querySelector("#search");search.addEventListener("input", debounce((event) => {    console.log("Запрос:", event.target.value);}, 400));

Задача 4. Экранирование

Напишите функцию escapeHtml(text), которая заменяет <, >, & и кавычки на HTML-сущности.

Подсказка

Воспользуйтесь replace с регуляркой и словарём замен.

Решение учителя 
function escapeHtml(text) {    const map = { "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;" };    return String(text).replace(/[&<>"]/g, (ch) => map[ch]);}console.log(escapeHtml("<b>привет</b>")); // &lt;b&gt;привет&lt;/b&gt;
