Асинхронность: таймеры и промисы

~35 минут Средний уровень Теория и Практика

JavaScript однопоточный: он выполняет одну инструкцию за раз. Но при этом страница не замирает, пока грузится картинка или идёт запрос к серверу. Секрет в асинхронности.

В этом уроке мы:

  • Разберёмся, что такое асинхронный код и зачем он нужен.
  • Познакомимся с таймерами setTimeout и setInterval.
  • Поймём, как работают промисы.
  • Научимся писать асинхронный код через async/await.
Аналогия

Очередь в кассу: кассир не бросает текущего покупателя, а берёт следующего, когда освободится. Event loop работает так же.

Проблема синхронного кода

Синхронный код выполняется по порядку и блокирует всё остальное. Представьте, что вычисление занимает две секунды:

function heavyCalculation() {    const start = Date.now();    while (Date.now() - start < 2000) {        // имитация тяжёлой работы    }    return "готово";}console.log("Старт");console.log(heavyCalculation());console.log("Финиш");

Всё это время страница не реагирует: не нажимаются кнопки, не прокручивается список, не проигрываются анимации. Один поток занят.

Асинхронный код решает проблему: тяжёлую операцию поручают браузеру, а сами продолжают работать. Когда операция завершится, браузер вернётся с результатом.

setTimeout и setInterval

Простейшие асинхронные функции - таймеры:

console.log("Первый");setTimeout(() => {    console.log("Третий - через 2 секунды");}, 2000);console.log("Второй");

Порядок вывода: «Первый», «Второй», «Третий». setTimeout не останавливает программу - он только регистрирует задачу, которую браузер выполнит позже.

setInterval повторяет вызов с заданным интервалом. Его нужно останавливать вручную, иначе он будет работать бесконечно:

let seconds = 0;const timer = setInterval(() => {    seconds++;    console.log(`${seconds} сек`);    if (seconds === 5) {        clearInterval(timer);    }}, 1000);

Как это работает: стек и очередь

У JavaScript есть стек вызовов - там выполняется текущий код - и очередь задач, куда попадают колбэки таймеров и сетевых запросов. Когда стек пустеет, движок берёт следующую задачу из очереди. Этот механизм называется event loop, цикл событий.

Отсюда классический вопрос на собеседовании:

setTimeout(() => console.log("таймер"), 0);console.log("код");

Сначала выведется «код», потом «таймер». Ноль миллисекунд не означает «прямо сейчас»: колбэк всё равно попадёт в очередь и выполнится после текущего кода.

Микрозадачи

У промисов своя очередь - очередь микрозадач. Она обрабатывается раньше таймеров, поэтому Promise.resolve().then(...) сработает до setTimeout(..., 0). На практике это важно, когда важен точный порядок вывода.

Промисы

Промис (Promise) - объект, представляющий результат операции, которая завершится в будущем. У него три состояния:

  • pending - ожидание.
  • fulfilled - успешно выполнено.
  • rejected - завершилось ошибкой.

Создать промис можно вручную - например, обернув таймер:

function delay(ms) {    return new Promise((resolve) => {        setTimeout(resolve, ms);    });}delay(1000).then(() => {    console.log("Прошла секунда");});

Функция внутри new Promise получает два колбэка: resolve (успех) и reject (ошибка). Их вызывают, когда операция завершилась.

then, catch, finally

delay(500)    .then(() => {        console.log("Шаг 1");        return delay(500);    })    .then(() => {        console.log("Шаг 2");    })    .catch((error) => {        console.error("Что-то пошло не так:", error);    })    .finally(() => {        console.log("Выполнится в любом случае");    });
  • then - обработчик успеха. Если вернуть из него промис, следующий then дождётся его завершения.
  • catch - обработчик ошибки. Ловит ошибки всей цепочки выше.
  • finally - выполняется всегда: удобно для скрытия индикатора загрузки.

Promise.all и другие комбинаторы

Если несколько операций независимы, их не нужно выполнять по очереди - это медленно. Promise.all запускает их параллельно и ждёт все:

const results = await Promise.all([    delay(1000),    delay(1000),    delay(1000)]);// итого ~1 секунда, а не 3
  • Promise.all - ждёт все; если хотя бы один упал, результат тоже ошибка.
  • Promise.allSettled - ждёт все и возвращает статус каждого, не прерываясь на ошибке.
  • Promise.race - возвращает первый завершившийся (успех или ошибку).

async и await

Цепочки then читаются тяжело. Синтаксис async/await позволяет писать асинхронный код как обычный, последовательный:

async function loadData() {    console.log("Загружаем...");    await delay(1000);    console.log("Шаг 1 готов");    await delay(1000);    console.log("Шаг 2 готов");    return "Готово";}loadData();

Правила простые:

  • async перед функцией делает её асинхронной.
  • await приостанавливает выполнение этой функции до завершения промиса, не блокируя страницу.
  • Любая async-функция всегда возвращает промис. Даже если внутри return 5, снаружи это будет Promise.

Обработка ошибок

С await ошибки ловят обычным try/catch:

function riskyTask() {    return new Promise((resolve, reject) => {        setTimeout(() => reject(new Error("Сервер недоступен")), 500);    });}async function run() {    try {        await riskyTask();        console.log("Успех");    } catch (error) {        console.error("Поймали ошибку:", error.message);    } finally {        console.log("Завершили попытку");    }}run();

Без try/catch отклонённый промис приведёт к необработанной ошибке (unhandled rejection) - в консоли появится предупреждение, а программа продолжит работу в непредсказуемом состоянии.

Не забывайте await

Если написать const data = loadData(); без await, в data окажется промис, а не результат. Ошибка тихая: код не падает, но дальше всё ломается. Если переменная ведёт себя как [object Promise] - ищите пропущенный await.

Последовательно или параллельно

// Медленно: 3 секундыconst a = await delay(1000);const b = await delay(1000);const c = await delay(1000);// Быстро: 1 секундаconst [x, y, z] = await Promise.all([    delay(1000),    delay(1000),    delay(1000)]);

Правило: если операции не зависят друг от друга - запускайте параллельно. Если вторая использует результат первой - только последовательно.

Шпаргалка

  • setTimeout выполнить один раз позже
  • setInterval повторять с интервалом
  • new Promise создать промис
  • .then / .catch обработка результата и ошибки
  • async / await асинхронный код как синхронный
  • Promise.all параллельное выполнение

Если что-то не работает

  • [object Promise] вместо данных. Пропущен await или забыт .then.
  • «await is only valid in async functions». await можно использовать только внутри async-функции (или на верхнем уровне модуля).
  • «Unhandled promise rejection». Нет catch или try/catch. Ошибку нужно обработать.
  • Код выполняется быстрее, чем приходит ответ. Асинхронный результат доступен только внутри then или после await - не после вызова функции.
  • setInterval не останавливается. Сохраните его идентификатор и вызовите clearInterval.
  • Код «побежал дальше» до получения данных. Забыли await - и в переменной оказался промис. Это не ошибка выполнения, поэтому её легко не заметить.

Практика

Задача 1. Задержка

Напишите функцию sleep(ms), которая возвращает промис и завершается через заданное время. Используйте её так: await sleep(1000); console.log("Прошла секунда");

Подсказка

Внутри new Promise вызовите setTimeout(resolve, ms). resolve можно передать как колбэк напрямую.

Решение учителя 
function sleep(ms) {    return new Promise((resolve) => setTimeout(resolve, ms));}async function run() {    await sleep(1000);    console.log("Прошла секунда");}run();
Задача 2. Параллельно или по очереди

Есть три задачи по одной секунде. Напишите два варианта: последовательный (около 3 секунд) и параллельный (около 1 секунды). Замерьте время через Date.now().

Подсказка

В последовательном варианте три await sleep(1000) подряд. В параллельном - await Promise.all([...]) с тремя вызовами сразу.

Решение учителя 
function sleep(ms) {    return new Promise((resolve) => setTimeout(resolve, ms));}async function sequential() {    const start = Date.now();    await sleep(1000);    await sleep(1000);    await sleep(1000);    console.log(`Последовательно: ${Date.now() - start} мс`);}async function parallel() {    const start = Date.now();    await Promise.all([sleep(1000), sleep(1000), sleep(1000)]);    console.log(`Параллельно: ${Date.now() - start} мс`);}sequential().then(parallel);
Задача 3. Поймать ошибку

Напишите функцию riskyLoad(), которая через секунду отклоняет промис с ошибкой «Нет соединения». Обработайте ошибку через try/catch и выведите сообщение, а в finally - «Загрузка завершена».

Подсказка

Внутри промиса вызовите reject(new Error("Нет соединения")). В catch доступно свойство error.message.

Решение учителя 
function riskyLoad() {    return new Promise((resolve, reject) => {        setTimeout(() => reject(new Error("Нет соединения")), 1000);    });}async function run() {    try {        await riskyLoad();        console.log("Данные получены");    } catch (error) {        console.error("Ошибка:", error.message);    } finally {        console.log("Загрузка завершена");    }}run();
Задача 4. Таймаут для промиса

Напишите функцию withTimeout(promise, ms), которая отклоняется с ошибкой «Таймаут», если промис не завершился за указанное время.

Подсказка

Сравните два промиса через Promise.race: исходный и таймер, который отклоняется.

Решение учителя 
function withTimeout(promise, ms) {    const timeout = new Promise((_, reject) => {        setTimeout(() => reject(new Error("Таймаут")), ms);    });    return Promise.race([promise, timeout]);}
