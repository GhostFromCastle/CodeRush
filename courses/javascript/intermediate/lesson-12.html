Формы и валидация

~30 минут Средний уровень Теория и Практика

Формы - главный способ получить данные от пользователя: регистрация, поиск, оформление заказа. Браузер умеет многое сам, но без JavaScript не обойтись: нужно проверить ввод, показать понятную ошибку и отправить данные без перезагрузки страницы.

В этом уроке мы:

  • Научимся читать значения из разных полей.
  • Разберём встроенную HTML-валидацию и свои проверки.
  • Покажем ошибки так, чтобы их понял любой пользователь.
  • Соберём данные формы через FormData.
Аналогия

Бланк в поликлинике: пока не заполнены обязательные поля, регистратор документ не примет. Форма ведёт себя так же.

Чтение значений

<form class="form">    <input type="text" name="name" class="field-name">    <input type="email" name="email" class="field-email">    <input type="checkbox" name="agree" class="field-agree">    <button type="submit">Отправить</button></form>
const form = document.querySelector(".form");form.addEventListener("submit", (event) => {    event.preventDefault();    const name = form.elements.name.value;    const email = form.elements.email.value;    const agree = form.elements.agree.checked;    console.log({ name, email, agree });});

Ключевой момент: form.elements даёт доступ к полям по атрибуту name. Без name поле не попадёт ни в elements, ни в отправленные данные - это одна из самых частых причин «пустой формы».

У разных полей разные свойства:

  • text, email, password, textarea, select - .value.
  • checkbox, radio - .checked (логическое значение).
  • file - .files (список файлов).

События формы

  • submit - нажали кнопку отправки или Enter в поле.
  • input - значение меняется на каждом нажатии клавиши.
  • change - значение изменилось и поле потеряло фокус (для select и checkbox срабатывает сразу).
  • focus / blur - поле получило или потеряло фокус.

Для живой проверки обычно используют input, для финальной - submit.

Всегда preventDefault

По умолчанию submit отправляет форму на сервер и перезагружает страницу. Если вы обрабатываете данные в JavaScript, вызовите event.preventDefault() в самом начале обработчика. Иначе результат работы исчезнет вместе со страницей.

Встроенная валидация

Браузер проверяет форму сам, если заданы атрибуты:

<form class="signup">    <input type="text" name="name" required minlength="2" maxlength="30">    <input type="email" name="email" required>    <input type="password" name="password" required minlength="8">    <input type="number" name="age" min="18" max="120">    <input type="text" name="phone" pattern="\+7\d{10}" title="Формат: +79991234567">    <button type="submit">Зарегистрироваться</button></form>
  • required - поле обязательно.
  • type="email" - браузер проверит формат адреса.
  • minlength / maxlength - длина текста.
  • min / max - диапазон для чисел.
  • pattern - регулярное выражение для проверки.

Проверить программно можно методами формы и поля:

const input = form.elements.name;console.log(form.checkValidity());   // вся форма валидна?console.log(input.checkValidity());  // конкретное полеconsole.log(input.validationMessage); // текст ошибки от браузераinput.reportValidity(); // показать подсказку браузера

Свои сообщения об ошибках

Браузерные сообщения зависят от языка системы и не всегда понятны. Свой текст задают через setCustomValidity:

function validatePassword(input) {    if (input.value.length < 8) {        input.setCustomValidity("Пароль должен быть не короче 8 символов");    } else if (!/[A-Za-z]/.test(input.value)) {        input.setCustomValidity("Добавьте хотя бы одну букву");    } else {        input.setCustomValidity(""); // ошибки нет    }}const password = form.elements.password;password.addEventListener("input", () => {    validatePassword(password);    password.reportValidity();});

Пустая строка в setCustomValidity обязательна: пока там есть текст, поле считается невалидным навсегда.

Своя проверка и понятный интерфейс

Часто нужна не всплывающая подсказка, а текст под полем. Схема простая: проверяем, показываем сообщение, помечаем поле классом.

JavaScript 
function showError(input, message) {
    const error = input.closest(".field").querySelector(".field-error");

    if (message) {
        error.textContent = message;
        input.classList.add("is-invalid");
        input.setAttribute("aria-invalid", "true");
    } else {
        error.textContent = "";
        input.classList.remove("is-invalid");
        input.removeAttribute("aria-invalid");
    }
}

form.addEventListener("submit", (event) => {
    event.preventDefault();

    const name = form.elements.name.value.trim();
    const email = form.elements.email.value.trim();

    let isValid = true;

    if (name.length < 2) {
        showError(form.elements.name, "Введите имя - минимум 2 символа");
        isValid = false;
    } else {
        showError(form.elements.name, "");
    }

    if (!email.includes("@")) {
        showError(form.elements.email, "Проверьте адрес почты");
        isValid = false;
    } else {
        showError(form.elements.email, "");
    }

    if (!isValid) return;

    console.log("Отправляем:", { name, email });
});

Принципы хорошей валидации:

  • Проверяйте на сервере тоже. Всё, что делает браузер, можно обойти через DevTools. Клиентская валидация нужна для удобства, серверная - для безопасности.
  • Говорите, что именно не так. «Ошибка» бесполезна, «пароль короче 8 символов» - понятна.
  • Не ругайте пользователя до того, как он закончил. Проверяйте поле на blur или при отправке, а не на каждом нажатии клавиши.
  • Переносите фокус на первое проблемное поле. Так пользователь не ищет ошибку глазами.

FormData

FormData собирает все поля формы автоматически - с учётом name:

form.addEventListener("submit", (event) => {    event.preventDefault();    const data = new FormData(form);    console.log(data.get("name"));    console.log(data.get("email"));    const values = Object.fromEntries(data.entries());    console.log(values); // { name: "Алексей", email: "..." }});
  • get(name) - первое значение поля.
  • getAll(name) - все значения (для чекбоксов с одинаковым именем, например).
  • entries() - пары «имя: значение» для перебора.

Object.fromEntries превращает пары в обычный объект - удобно для отправки через fetch в виде JSON.

Сброс и фокус

form.reset();          // вернуть поля к исходным значениямinput.focus();         // поставить курсорinput.select();        // выделить текст

После успешной отправки логично очистить форму и поставить фокус в первое поле - так пользователю проще ввести следующую запись.

Шпаргалка

  • form.elements.name поле по имени
  • .value значение поля
  • .checked состояние чекбокса
  • preventDefault не перезагружать страницу
  • checkValidity проверка по правилам HTML
  • setCustomValidity своё сообщение об ошибке
  • new FormData(form) все данные формы

Если что-то не работает

  • form.elements.name равно undefined. У поля нет атрибута name или имя написано иначе.
  • Страница перезагружается при отправке. Нет event.preventDefault() или обработчик повешен на click кнопки вместо submit формы.
  • Чекбокс всегда true. Прочитано .value вместо .checked: у чекбокса value - это строка "on".
  • Валидация «застряла». В setCustomValidity не сбросили текст в пустую строку при исправлении.
  • FormData пустая. У полей нет name, или поля лежат вне этой формы.
  • Нажали «Отправить» - страница моргнула и всё пропало. Форма ушла на сервер и перезагрузилась. Без event.preventDefault() браузер ведёт себя так по умолчанию, и это не баг.

Практика

Задача 1. Регистрация

Соберите данные формы регистрации (имя, почта, возраст) через FormData и выведите объект в консоль. Форма не должна перезагружать страницу.

Подсказка

Слушайте submit, вызовите preventDefault(), создайте new FormData(form) и превратите его в объект через Object.fromEntries(data.entries()).

Решение учителя 
const form = document.querySelector(".signup");form.addEventListener("submit", (event) => {    event.preventDefault();    const data = new FormData(form);    const values = Object.fromEntries(data.entries());    console.log(values);});
Задача 2. Пароль и повтор

Два поля: пароль и повтор пароля. При отправке проверьте, что пароль не короче 8 символов и оба значения совпадают. Выведите ошибку под соответствующим полем.

Подсказка

Сравнивайте password.value === confirm.value. Для вывода ошибки используйте элемент с классом .field-error рядом с полем и closest(".field").

Решение учителя 
form.addEventListener("submit", (event) => {    event.preventDefault();    const password = form.elements.password.value;    const confirm = form.elements.confirm.value;    if (password.length < 8) {        showError(form.elements.password, "Минимум 8 символов");        return;    }    if (password !== confirm) {        showError(form.elements.confirm, "Пароли не совпадают");        return;    }    console.log("Форма валидна");});
Задача 3. Живой счётчик символов

В textarea с ограничением 200 символов показывайте, сколько осталось. Если осталось меньше 20 - подсветите счётчик красным классом.

Подсказка

Слушайте input, считайте maxLength - value.length и переключайте класс через classList.toggle("is-low", left < 20).

Решение учителя 
const textarea = document.querySelector(".message");const counter = document.querySelector(".counter");const max = 200;textarea.addEventListener("input", () => {    const left = max - textarea.value.length;    counter.textContent = `Осталось: ${left}`;    counter.classList.toggle("is-low", left < 20);});
Задача 4. Показать пароль

Добавьте кнопку «Показать пароль», которая переключает тип поля между password и text.

Подсказка

Меняйте input.type и текст кнопки в одном обработчике.

Решение учителя 
const input = document.querySelector(".password");const toggle = document.querySelector(".toggle-password");toggle.addEventListener("click", () => {    const hidden = input.type === "password";    input.type = hidden ? "text" : "password";    toggle.textContent = hidden ? "Скрыть" : "Показать";});

Что мы узнали и что дальше

Формы больше не чёрный ящик. Вы знаете:

  • Как читать значения полей разных типов.
  • Как работает встроенная валидация и чем она ограничена.
  • Как показывать понятные ошибки и не раздражать пользователя.
  • Как собрать данные через FormData.

Дальше - современный синтаксис: деструктуризация, spread, опциональная цепочка и коллекции Map и Set. Эти приёмы встречаются в каждом втором файле реального проекта.
