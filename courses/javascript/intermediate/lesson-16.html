Fetch и работа с API

~35 минут Средний уровень Теория и Практика

Данные редко лежат в самом коде. Курсы валют, погода, список товаров, сообщения - всё это приходит с сервера. В браузере за это отвечает fetch.

В этом уроке мы:

  • Разберём, как устроен HTTP-запрос.
  • Научимся получать данные через fetch.
  • Поймём, как правильно обрабатывать ошибки.
  • Покажем загруженные данные на странице.
Аналогия

Курьер: вы даёте адрес, ждёте посылку и обязательно проверяете накладную. Сам факт, что кто-то приехал, ещё не значит, что привезли нужное.

Как устроен запрос

Браузер общается с сервером по протоколу HTTP. У каждого запроса есть:

  • Метод - что мы хотим сделать: GET (получить), POST (создать), PUT (обновить), DELETE (удалить).
  • URL - адрес ресурса.
  • Заголовки - служебная информация: формат данных, токен авторизации.
  • Тело - данные запроса (для POST и PUT).

Ответ содержит статус и тело. Статусы делятся на группы:

200-299 - успех300-399 - перенаправление400-499 - ошибка на стороне клиента (404 - не найдено, 401 - не авторизован)500-599 - ошибка на сервере

Первый запрос

async function loadUsers() {    const response = await fetch("https://jsonplaceholder.typicode.com/users");    const users = await response.json();    console.log(users);}

Обратите внимание: два await. Первый ждёт, пока сервер ответит заголовками. Второй - пока тело ответа прочитается и превратится в JavaScript-объект.

response.json() - только один из способов прочитать тело. Есть ещё text() для обычного текста и blob() для файлов. Тело можно прочитать только один раз.

Проверка статуса

Главная ловушка fetch: он не считает ошибкой ответы 404 или 500. Промис успешно завершается, просто данные оказываются не теми:

const response = await fetch("/api/missing");console.log(response.ok);     // falseconsole.log(response.status); // 404

Поэтому статус проверяют вручную:

async function loadUsers() {    const response = await fetch("https://jsonplaceholder.typicode.com/users");    if (!response.ok) {        throw new Error(`Ошибка ${response.status}: ${response.statusText}`);    }    return response.json();}

Теперь catch поймает и сетевую ошибку, и ответ 500.

fetch не выбрасывает ошибку на 404

Это самая частая причина багов в первых проектах: код пытается прочитать response.json() у страницы ошибки, получает исключение парсинга и показывает пользователю что-то невнятное. Проверка response.ok - обязательный шаг.

Полный пример с обработкой ошибок

JavaScript 
async function loadUsers() {
    const status = document.querySelector(".status");
    const list = document.querySelector(".users");

    status.textContent = "Загрузка...";
    list.innerHTML = "";

    try {
        const response = await fetch("https://jsonplaceholder.typicode.com/users");

        if (!response.ok) {
            throw new Error(`Сервер ответил ${response.status}`);
        }

        const users = await response.json();

        users.forEach((user) => {
            const item = document.createElement("li");
            item.textContent = `${user.name} (${user.email})`;
            list.append(item);
        });

        status.textContent = `Загружено: ${users.length}`;
    } catch (error) {
        status.textContent = "Не удалось загрузить данные";
        console.error(error);
    }
}

loadUsers();

Обратите внимание на три состояния интерфейса: загрузка, успех и ошибка. Пользователь всегда должен понимать, что происходит.

Отправка данных

Для POST нужен второй аргумент с настройками:

async function createUser(user) {    const response = await fetch("https://jsonplaceholder.typicode.com/users", {        method: "POST",        headers: {            "Content-Type": "application/json"        },        body: JSON.stringify(user)    });    if (!response.ok) {        throw new Error(`Не удалось создать пользователя: ${response.status}`);    }    return response.json();}createUser({ name: "Алексей", email: "alex@example.com" })    .then((created) => console.log("Создан:", created))    .catch((error) => console.error(error));

JSON.stringify превращает объект в строку, потому что по сети передаются именно строки. Заголовок Content-Type сообщает серверу формат.

Отмена запроса

Если пользователь ушёл со страницы или ввёл новый запрос, старый ответ уже не нужен. Для отмены используется AbortController:

const controller = new AbortController();fetch("https://jsonplaceholder.typicode.com/users", {    signal: controller.signal})    .then((response) => response.json())    .then((data) => console.log(data))    .catch((error) => {        if (error.name === "AbortError") {            console.log("Запрос отменён");        } else {            console.error(error);        }    });// например, через 100 мсsetTimeout(() => controller.abort(), 100);

Это особенно полезно в поиске с автодополнением: пока пользователь печатает, предыдущий запрос отменяется, и на страницу не приходит устаревший ответ.

CORS

Браузер запрещает странице обращаться к чужим доменам, если сервер это не разрешил. Такая защита называется CORS. В консоли это выглядит так:

Access to fetch at 'https://example.com/api' from origin 'http://localhost'has been blocked by CORS policy

Важно понимать: это ограничение браузера, а не ошибка вашего кода. Решается оно на стороне сервера - он должен прислать заголовок Access-Control-Allow-Origin. Обойти его из JavaScript нельзя, и это правильно: иначе любой сайт мог бы читать ваши данные.

Где тренироваться

Для учебных запросов удобны публичные API: jsonplaceholder.typicode.com для тестовых данных и api.github.com для реальных. Оба отдают JSON и разрешают запросы с любого домена.

Шпаргалка

  • fetch(url) отправить GET-запрос
  • response.ok статус 200-299
  • response.json() прочитать JSON
  • method: "POST" отправка данных
  • JSON.stringify объект в строку
  • AbortController отмена запроса

Если что-то не работает

  • «Unexpected token < in JSON». Сервер вернул HTML (например, страницу 404), а вы пытаетесь прочитать её как JSON. Проверяйте response.ok до response.json().
  • «Failed to fetch». Нет сети, неверный адрес или запрос заблокирован CORS. Откройте вкладку Network в DevTools - там видно реальную причину.
  • «Body has already been read». json() или text() вызваны дважды. Тело читается один раз - сохраните результат в переменную.
  • Данные пришли, но список пустой. Проверьте структуру ответа: часто данные лежат не в корне, а в поле вроде data.items.
  • Запрос уходит при каждом нажатии клавиши. Добавьте задержку (debounce) и AbortController.
  • Сервер вернул 404, а catch не сработал. fetch не считает HTTP-ошибку исключением. Проверяйте response.ok вручную - иначе приложение будет уверено, что всё хорошо.

Практика

Задача 1. Список пользователей

Загрузите пользователей с https://jsonplaceholder.typicode.com/users и выведите их имена в <ul class="users">.

Подсказка

После await response.json() у вас массив объектов. Пройдитесь по нему forEach, создавая li через createElement.

Решение учителя 
async function loadUsers() {    const response = await fetch("https://jsonplaceholder.typicode.com/users");    if (!response.ok) {        throw new Error(`Ошибка ${response.status}`);    }    const users = await response.json();    const list = document.querySelector(".users");    users.forEach((user) => {        const item = document.createElement("li");        item.textContent = user.name;        list.append(item);    });}loadUsers().catch((error) => console.error(error));
Задача 2. Обработать плохой статус

Сделайте запрос на несуществующий адрес https://jsonplaceholder.typicode.com/nothing-here и выведите в консоль понятное сообщение об ошибке, а не «Unexpected token».

Подсказка

Проверьте response.ok и выбросьте ошибку через throw new Error(...) до чтения JSON. Оберните вызов в try/catch.

Решение учителя 
async function loadMissing() {    try {        const response = await fetch(            "https://jsonplaceholder.typicode.com/nothing-here"        );        if (!response.ok) {            throw new Error(`Страница не найдена (${response.status})`);        }        const data = await response.json();        console.log(data);    } catch (error) {        console.error("Не удалось получить данные:", error.message);    }}loadMissing();
Задача 3. Индикатор загрузки

Добавьте к предыдущей задаче три состояния: во время запроса показывайте «Загрузка...», при успехе - количество пользователей, при ошибке - «Не удалось загрузить».

Подсказка

Меняйте textContent элемента статуса до запроса, после успеха и в блоке catch. Блок finally подойдёт, чтобы скрыть спиннер.

Решение учителя 
async function loadUsers() {    const status = document.querySelector(".status");    status.textContent = "Загрузка...";    try {        const response = await fetch("https://jsonplaceholder.typicode.com/users");        if (!response.ok) throw new Error(response.status);        const users = await response.json();        status.textContent = `Пользователей: ${users.length}`;    } catch (error) {        status.textContent = "Не удалось загрузить";        console.error(error);    }}loadUsers();
Задача 4. Повторить запрос

Напишите функцию fetchWithRetry(url, attempts), которая повторяет запрос при ошибке до attempts раз.

Подсказка

Оберните fetch в цикл с try/catch и пробрасывайте ошибку, если попытки закончились.

Решение учителя 
async function fetchWithRetry(url, attempts = 3) {    for (let i = 1; i <= attempts; i++) {        try {            const response = await fetch(url);            if (!response.ok) throw new Error(response.status);            return await response.json();        } catch (error) {            if (i === attempts) throw error;        }    }}

Что мы узнали и что дальше

Вы связали страницу с внешним миром. Теперь вы знаете:

  • Как устроены HTTP-запросы и статусы ответов.
  • Как получать и отправлять данные через fetch.
  • Почему response.ok обязательно проверять.
  • Как отменять запросы и показывать состояния загрузки.

Осталось две темы, без которых не обходится ни одна форма и ни один фильтр. Первая - регулярные выражения: ими проверяют телефоны, почту и форматы дат одной короткой строкой. Вторая - даты: их считают, форматируют и сравнивают в каждом проекте. Начнём с регулярок.
