Операторы и условия

~25 минут Начальный уровень Теория и Практика

Пока наши программы шли по одной линии: строка за строкой, без вариантов. Настоящая программа должна выбирать: показать скидку, если сумма большая, не пустить дальше, если пароль неверный.

В этом уроке мы:

  • Разберём арифметические операторы и сокращённую запись.
  • Научимся сравнивать значения и не попадать в ловушку ==.
  • Познакомимся с if, else if и тернарным оператором.
  • Узнаем, какие значения JavaScript считает «ложными».
Аналогия

Светофор: если красный - стоим, иначе если жёлтый - готовимся, иначе едем. Порядок проверок в коде работает так же: срабатывает первая подходящая.

Арифметические операторы

С базовой математикой всё ожидаемо:

console.log(10 + 3);   // 13console.log(10 - 3);   // 7console.log(10 * 3);   // 30console.log(10 / 3);   // 3.3333333333333335console.log(10 % 3);   // 1 - остаток от деленияconsole.log(2 ** 10);  // 1024 - возведение в степень

Оператор % - «остаток от деления» - на практике встречается постоянно. Именно он позволяет понять, чётное число или нет: n % 2 === 0.

Для изменения переменной на единицу есть короткие формы:

let count = 5;count++;          // то же, что count = count + 1count--;          // то же, что count = count - 1count += 10;      // то же, что count = count + 10count -= 2;count *= 3;

Сравнение: всегда строгое

В JavaScript есть два вида равенства, и это классическая ловушка:

console.log(5 == "5");   // true  - нестрогое, приводит типыconsole.log(5 === "5");  // false - строгое, сравнивает и тип

Всегда используйте === и !==. Нестрогое равенство приводит типы по запутанным правилам: например, 0 == "" и false == "0" оба дают true. Строгое сравнение ведёт себя предсказуемо.

Остальные сравнения работают очевидно:

console.log(10 > 3);    // trueconsole.log(10 < 3);    // falseconsole.log(10 >= 10);  // trueconsole.log(10 <= 9);   // false
Не путайте = и ===

= - присваивание, === - сравнение. Выражение if (x = 5) не сравнит x с пятёркой, а присвоит ей пять и вернёт true. Код при этом не упадёт - и ошибку будет очень трудно найти. Такие опечатки ловят линтеры, поэтому в реальных проектах их подключают с первого дня.

Логические операторы

Три оператора, которые соединяют условия:

const age = 20;const hasTicket = true;console.log(age >= 18 && hasTicket);  // true - И: нужны оба условияconsole.log(age < 18 || hasTicket);   // true - ИЛИ: достаточно одногоconsole.log(!hasTicket);              // false - НЕ: инверсия

У && и || есть полезная особенность: они возвращают не true/false, а последнее вычисленное значение. Отсюда популярный приём «значение по умолчанию»: const name = input || "Гость";. Но у него есть подвох - пустая строка и ноль считаются ложными, поэтому в современном коде для этой задачи используют ?? (разберём на среднем уровне).

Конструкция if / else

Основной инструмент ветвления:

const temperature = 5;if (temperature > 20) {    console.log("На улице тепло, можно в футболке");} else if (temperature > 0) {    console.log("Прохладно, нужна куртка");} else {    console.log("Мороз, одевайтесь теплее");}

Проверки идут сверху вниз, и срабатывает первая подходящая ветка. Остальные даже не вычисляются. Поэтому порядок важен: если сначала поставить temperature > 0, то при 25 градусах сработает именно эта ветка.

  • if - проверяет условие.
  • else if - проверяет следующее, только если предыдущее не подошло.
  • else - выполняется, если не подошло ничего.
  • Фигурные скобки - ограничивают блок кода. Их можно опустить для одной строки, но лучше не экономить: так безопаснее.

Вложенные условия

Иногда проверку нужно сделать внутри другой проверки:

const isLoggedIn = true;const isAdmin = false;if (isLoggedIn) {    if (isAdmin) {        console.log("Добро пожаловать в админку");    } else {        console.log("Добро пожаловать в личный кабинет");    }} else {    console.log("Сначала войдите в аккаунт");}

Вложенность глубже двух уровней - сигнал, что код стоит переписать. Чаще всего помогает «ранний выход»: проверить плохой случай и выйти из функции.

Тернарный оператор

Когда нужно выбрать одно из двух значений, удобна короткая запись:

const age = 20;const status = age >= 18 ? "совершеннолетний" : "несовершеннолетний";console.log(status);

Читается так: условие ? значение если истина : значение если ложь. Тернарник хорош для присваивания и вывода, но не для сложной логики: вложенные тернарники читаются ужасно.

Когда тернарник уместен

Если обе ветки - короткие выражения, тернарник делает код короче. Если внутри нужно несколько действий, используйте обычный if. Критерий простой: код должен читаться как фраза, а не как ребус.

switch

Когда вариантов много и они сравниваются с одним значением, длинная цепочка else if превращается в кашу. На помощь приходит switch:

const day = "суббота";switch (day) {    case "понедельник":        console.log("Начало рабочей недели");        break;    case "суббота":    case "воскресенье":        console.log("Выходной!");        break;    default:        console.log("Обычный день");}

Важные детали:

  • break останавливает выполнение. Без него код «провалится» в следующий case - иногда это нужно (как с субботой и воскресеньем выше), но чаще это ошибка.
  • default срабатывает, если не подошёл ни один вариант.
  • Сравнение строгое. case 5 не совпадёт со строкой "5".

Правда и ложь: truthy и falsy

В условии if можно передать не только true/false. Любое значение JavaScript приведёт к логическому. Ложных значений всего шесть:

false0-0""          // пустая строкаnullundefinedNaN

Всё остальное - правда. Даже "0" (строка с нулём) и пустой массив [] считаются истинными:

if ("0") {    console.log("Это выполнится - непустая строка истинна");}if ([]) {    console.log("Это тоже выполнится - массив не пустая строка");}

Проверка «есть ли значение» через if (value) удобна, но опасна для чисел и строк: ноль и пустая строка - вполне валидные данные. Если ноль допустим, проверяйте явно: if (value !== null && value !== undefined).

Шпаргалка

  • === строгое равенство
  • !== строгое неравенство
  • % остаток от деления
  • && логическое И
  • || логическое ИЛИ
  • ! логическое НЕ
  • ? : тернарный оператор

Если что-то не работает

  • Условие срабатывает всегда. Проверьте, не использован ли = вместо ===. Присваивание в условии почти всегда опечатка.
  • "5" === 5 даёт false. Это правильно: типы разные. Приведите значение через Number(), если приходит из формы.
  • if (0) не срабатывает. Ноль - ложное значение. Если ноль валиден, сравнивайте явно: if (value === 0).
  • switch выполняет все case подряд. Забыли break. Это называется «fallthrough» и иногда используется намеренно, но чаще это баг.
  • «Unexpected token 'else'». Скорее всего, между } и else попал другой код. else должен идти сразу за закрывающей скобкой блока.
  • Сработало «не то» условие. Классика: сначала проверяют > 0, а потом > 100 - и второе никогда не выполняется. Порядок веток - часть логики, а не оформление.

Практика

Задача 1. Чётное или нечётное

Создайте константу number с любым целым числом и выведите «чётное» или «нечётное».

Подсказка

Число чётное, если остаток от деления на 2 равен нулю: number % 2 === 0.

Решение учителя 
const number = 17;if (number % 2 === 0) {    console.log("чётное");} else {    console.log("нечётное");}
Задача 2. Билет в кино

Цена билета - 500 рублей. Детям до 12 лет - скидка 50%, пенсионерам (возраст от 65) - 30%. Выведите итоговую цену для возраста 10, 35 и 70 лет.

Подсказка

Сначала проверьте возраст меньше 12, потом - больше или равно 65, иначе полная цена. Порядок проверок имеет значение.

Решение учителя 
const basePrice = 500;function ticketPrice(age) {    if (age < 12) return basePrice * 0.5;    if (age >= 65) return basePrice * 0.7;    return basePrice;}console.log(ticketPrice(10));  // 250console.log(ticketPrice(35));  // 500console.log(ticketPrice(70));  // 350

Функции ещё не проходили, но здесь они делают код заметно понятнее: один и тот же расчёт применяется к трём возрастам.

Задача 3. День недели

Создайте переменную с номером дня недели от 1 до 7 и выведите его название через switch. Для некорректного номера выведите «Такого дня нет».

Подсказка

Семь case и default в конце. Не забудьте break после каждого вывода, иначе сработают следующие ветки.

Решение учителя 
const day = 3;switch (day) {    case 1: console.log("Понедельник"); break;    case 2: console.log("Вторник"); break;    case 3: console.log("Среда"); break;    case 4: console.log("Четверг"); break;    case 5: console.log("Пятница"); break;    case 6: console.log("Суббота"); break;    case 7: console.log("Воскресенье"); break;    default: console.log("Такого дня нет");}
Задача 4. Оценка по баллам

Выведите словесную оценку: 90 и больше - «отлично», от 70 до 89 - «хорошо», от 50 до 69 - «удовлетворительно», иначе - «надо повторить».

Подсказка

Проверки идут сверху вниз, поэтому начинайте с самого высокого порога.

Решение учителя 
const score = 82;if (score >= 90) {    console.log("отлично");} else if (score >= 70) {    console.log("хорошо");} else if (score >= 50) {    console.log("удовлетворительно");} else {    console.log("надо повторить");}

  • Почему сравнивать нужно только через ===.
  • Как строить ветвление через if, else if и switch.
