Модули и пакеты

~40 минут Средний уровень Теория и Практика

До этого момента все наши программы жили в одном файле. Это нормально для обучения, но представьте, что вам нужно написать приложение на 10 000 строк кода. Держать всё в одном файле - это как пытаться уместить всю домашнюю библиотеку в одну книгу. Найти что-то нужное будет невозможно.

Реальные проекты всегда разбиты на модули - отдельные файлы с кодом. А когда модулей становится много и они логически сгруппированы, их объединяют в пакеты. Сегодня мы научимся организовывать свой код так, чтобы он был чистым и структурированным.

Что такое модуль

Самый простой модуль - это просто файл с расширением .py. Любой ваш файл, например game.py или calculator.py - это уже модуль. Просто мы раньше не использовали его как модуль, а запускали напрямую.

Аналогия: модуль - это как инструмент в ящике (молоток, отвёртка, гаечный ключ). Пока вы просто держите инструмент в руках - это ваша программа. Но когда вы кладёте его в ящик и берёте по мере необходимости - это уже модуль.

Смысл модуля в том, что вы можете написать код один раз в отдельном файле, а затем импортировать его в другой файл и использовать. Без копирования.

Импорт модулей

Мы уже сталкивались с импортом в уроках про random и math. Синтаксис простой: пишем import и имя файла (без .py).

Допустим, у вас есть файл my_math.py с функциями:

def add(a, b):    return a + bdef multiply(a, b):    return a * b

А в другом файле main.py вы можете его подключить:

import my_mathresult = my_math.add(3, 5)print(result)   # 8

Обратите внимание: функции из модуля вызываются через точку, используя имя модуля (my_math.add).

Другие способы импорта

Иногда неудобно каждый раз писать имя модуля. Для этого есть другие варианты импорта.

Импорт конкретных функций

Если нужна только одна функция, можно импортировать её напрямую:

from my_math import addprint(add(3, 5))   # 8 (без my_math.)

А если нужно всё содержимое модуля - используйте звёздочку. Но это считается плохой практикой, потому что вы не знаете, какие именно имена попадут в вашу программу (вдруг они совпадут с вашими?):

from my_math import *

Импорт с переименованием (alias)

Если имя модуля слишком длинное, его можно сократить:

import my_math as mmprint(mm.add(2, 2))

Запуск модуля как программы

Что произойдёт, если при импорте модуля в нём есть код, который не обёрнут в функцию? Python выполнит его сразу. Представьте, что в my_math.py вы добавили тестовый print:

def add(a, b):    return a + bprint("Модуль загружен!")  # выполнится при импорте

При запуске main.py вы увидите «Модуль загружен!», даже если просто хотели использовать add. Чтобы этого избежать, используют конструкцию:

if __name__ == "__main__":    print("Этот код выполнится только при прямом запуске файла")

__name__ - это специальная переменная. Если файл запускается напрямую, она равна "__main__". Если файл импортируется как модуль, она равна имени файла (например, "my_math").

Что такое пакет

Когда модулей становится очень много, их группируют в папки. Папка с модулями называется пакетом (package).

Чтобы Python понял, что это пакет, внутри папки должен быть файл __init__.py (обычно пустой). Выглядит это так:

my_project/│├── main.py└── utils/    ├── __init__.py    ├── math_helpers.py    └── string_helpers.py

Импорт из пакета работает так же, только через точку:

from utils import math_helpersfrom utils.math_helpers import add

Сторонние пакеты и pip

В Python есть огромное количество готовых модулей и пакетов, которые написали другие разработчики. Они хранятся в репозитории PyPI (Python Package Index).

Чтобы установить чужой пакет, используется утилита pip. Она идёт в комплекте с Python. Команда вводится в терминале (не в коде!):

pip install requests

После этого пакет requests можно импортировать и использовать.

Виртуальные окружения (venv)

Представьте, что вы работаете над двумя проектами. В первом нужна библиотека для работы с сайтами версии 1.0, а во втором - версии 2.0. Если установить всё глобально, они будут конфликтовать.

Решение - виртуальное окружение. Это изолированная папка, в которой лежат свои копии Python и свои пакеты. У каждого проекта - своё окружение.

Создаётся окружение командой в терминале:

python -m venv venv

Активируется:

  • На Windows: venv\Scripts\activate
  • На macOS/Linux: source venv/bin/activate

После активации в начале строки терминала появится (venv). Теперь все pip install будут ставиться внутрь этой папки, не засоряя систему.

Шпаргалка

Самое важное в одном месте:

  • import module подключить модуль
  • from module import func импорт конкретной функции
  • import module as m сокращение имени
  • __name__ == "__main__" защита от выполнения при импорте
  • pip install pkg установка пакета
  • python -m venv venv создать окружение

Если что-то не работает

Разберём типичные ошибки при работе с модулями.

  • «ModuleNotFoundError: No module named 'my_module'». Python не нашёл файл. Проверьте, что файл лежит в той же папке, что и скрипт, и что нет опечатки в имени. Также убедитесь, что расширение именно .py.
  • «Файл с кодом выполнился при импорте». Вы забыли обернуть исполняемый код в if __name__ == "__main__":.
  • «Пакет установлен, но импорт не работает». Скорее всего, вы установили пакет в одно виртуальное окружение, а запускаете код в другом (или в глобальном Python). Проверьте, активировано ли нужное окружение в терминале.
  • «pip не является внутренней или внешней командой» (на Windows). Python не добавлен в PATH. Используйте python -m pip install ... вместо pip install ....
  • Циклический импорт. Файл A импортирует B, а B импортирует A. Python падает с ошибкой. Решение: вынести общий код в третий модуль C и импортировать его из обоих.

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Импорт math

Импортируйте модуль math под псевдонимом m. Найдите с его помощью квадратный корень из 144 и выведите результат.

Подсказка

Синтаксис импорта с псевдонимом: import math as m. Функция корня - m.sqrt().

Решение учителя 
import math as mprint(m.sqrt(144))   # 12.0
Задача 2. Выборочный импорт

Импортируйте из модуля random только функцию choice. Используйте её, чтобы выбрать случайный цвет из списка ["красный", "зелёный", "синий"] и вывести его.

Подсказка

Используйте конструкцию: from random import choice. После этого функцию можно вызывать напрямую, без префикса random..

Решение учителя 
from random import choicecolors = ["красный", "зелёный", "синий"]print(choice(colors))
Задача 3. Свой модуль

Создайте файл helpers.py с функцией say_bye(name), которая выводит «До встречи, [Имя]!». Затем в файле main.py импортируйте этот модуль и вызовите функцию.

Подсказка

В helpers.py создайте функцию через def. В main.py напишите import helpers и вызовите helpers.say_bye("Алексей").

Решение учителя

Файл helpers.py:

def say_bye(name):    print(f"До встречи, {name}!")

Файл main.py:

import helpershelpers.say_bye("Алексей")
Задача 4. Защита от импорта

Дан файл calc.py. Добавьте в него функцию add(a, b), которая возвращает сумму, и тестовый вывод print("Тест пройден!"). Сделайте так, чтобы тестовый вывод срабатывал только при прямом запуске calc.py, но не при его импорте.

Подсказка

Оберните тестовый вывод в конструкцию if __name__ == "__main__":. Всегда ставьте этот блок в конце файла.

Решение учителя 
def add(a, b):    return a + bif __name__ == "__main__":    print("Тест пройден!")    print(add(2, 3))

Теперь при импорте calc в другом файле никаких тестов не запустится. А если запустить calc.py напрямую - тест сработает.
