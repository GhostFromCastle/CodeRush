ООП: свойства

~40 минут Средний уровень Теория и Практика

В прошлых уроках мы научились создавать классы и наследовать их. Мы использовали атрибуты вроде self.name или self.balance. Но есть проблема: любой код снаружи может изменить эти атрибуты как угодно.

Например, если у нас есть банковский счёт с балансом, что мешает сделать так: account.balance = -1000? Ничего. Python позволит это сделать, и баланс уйдёт в минус, хотя логически это невозможно.

Сегодня мы разберём, как защитить данные объекта от случайной порчи, и познакомимся с декоратором @property, который делает код по-настоящему «питоновским».

Проблема открытых атрибутов

Представьте класс User с возрастом:

class User:    def __init__(self, name, age):        self.name = name        self.age = ageuser = User("Алексей", 25)user.age = -5print(user.age)   # -5

Всё работает, но возраст -5 не имеет смысла. Как разработчик класса, вы хотите контролировать, какие значения попадают в атрибут. В других языках (например, в C# или Java) для этого используют приватные поля и методы getAge() / setAge().

В Python есть соглашение: если атрибут начинается с нижнего подчёркивания (например, self._age), это значит: «не трогай меня напрямую, я для внутреннего использования». Но это только соглашение, а не жёсткий запрет.

Декоратор @property

Чтобы сделать доступ к атрибуту безопасным, но при этом оставить синтаксис простым (без вызова методов вроде user.get_age()), в Python придумали свойства (properties).

Они создаются с помощью декоратора @property. Давайте перепишем класс User:

class User:    def __init__(self, name, age):        self.name = name        self._age = age  # защищённый атрибут    @property    def age(self):        return self._age

Теперь метод age выглядит как обычный атрибут, но на самом деле это метод. Мы обращаемся к нему без скобок:

user = User("Алексей", 25)print(user.age)   # 25 (работает как атрибут)

Сеттеры: контроль изменений

Но это только чтение. Чтобы контролировать запись (установку значения), используется сеттер с декоратором @age.setter:

class User:    def __init__(self, name, age):        self.name = name        self.age = age  # здесь вызовется сеттер!    @property    def age(self):        return self._age    @age.setter    def age(self, value):        if value < 0:            raise ValueError("Возраст не может быть отрицательным")        self._age = value

Теперь магия: строка self.age = age в конструкторе не создаёт новый атрибут. Она вызывает сеттер, который проверяет значение и записывает его в _age.

Если снаружи попытаться установить отрицательный возраст:

user = User("Алексей", 25)user.age = 30    # окuser.age = -5    # ValueError: Возраст не может быть отрицательным

Аналогия: свойство - это как умный турникет. Вы проходите через него снаружи (обращаетесь к атрибуту), но турникет проверяет, есть ли у вас билет (валидное значение), прежде чем пропустить.

Свойства только для чтения

Иногда нужно, чтобы значение можно было только читать, но нельзя изменить. Для этого достаточно создать геттер (@property), но не создавать сеттер.

Например, площадь круга зависит от радиуса. Мы можем сделать свойство area, которое вычисляется на лету, но попытка его изменить приведёт к ошибке:

import mathclass Circle:    def __init__(self, radius):        self.radius = radius    @property    def area(self):        return math.pi * self.radius ** 2c = Circle(5)print(c.area)   # 78.53...c.area = 100    # AttributeError: can't set attribute

Это очень удобно: атрибут area выглядит как обычное значение, но всегда актуален, даже если радиус изменится.

Шпаргалка

Самое важное в одном месте:

  • _name защищённый атрибут (по соглашению)
  • @property превратить метод в атрибут (геттер)
  • @name.setter контроль изменения значения
  • raise ValueError() запретить плохие значения
  • только @property свойство только для чтения

Если что-то не работает

Разберём типичные ошибки при работе со свойствами.

  • «RecursionError: maximum recursion depth exceeded». Вы написали self.age = age внутри сеттера вместо self._age = value. Сеттер вызывает сам себя, и получается бесконечная рекурсия.
  • «AttributeError: can't set attribute». Вы пытаетесь изменить свойство, у которого нет сеттера (только для чтения).
  • Свойство возвращает «method object». Вы забыли поставить декоратор @property над геттером.
  • «ValueError» при создании объекта. Валидация в сеттере сработала ещё в конструкторе. Если вы задаёте значение в __init__, оно пройдёт через тот же сеттер. Это нормальное поведение - просто передавайте корректные значения.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Товар

Создайте класс Product с атрибутом price. Используйте @property и @price.setter, чтобы запретить установку отрицательной цены (выбрасывайте ValueError).

Подсказка

Создайте геттер для _price. В сеттере напишите проверку if value < 0: raise ValueError. Иначе присваивайте self._price = value.

Решение учителя 
class Product:    def __init__(self, price):        self.price = price    @property    def price(self):        return self._price    @price.setter    def price(self, value):        if value < 0:            raise ValueError("Цена не может быть отрицательной")        self._price = valuep = Product(100)p.price = 200p.price = -50
Задача 2. Форматирование имени

Создайте класс Person с атрибутом name. В сеттере сделайте так, чтобы имя всегда сохранялось с заглавной буквы (используйте .capitalize()). Если передана пустая строка - выбрасывайте ValueError.

Подсказка

В сеттере проверьте if not value: (пустая строка даёт False). Затем сохраните self._name = value.capitalize().

Решение учителя 
class Person:    def __init__(self, name):        self.name = name    @property    def name(self):        return self._name    @name.setter    def name(self, value):        if not value:            raise ValueError("Имя не может быть пустым")        self._name = value.capitalize()person = Person("алексей")print(person.name)   # Алексейperson.name = "мария"print(person.name)   # Мария
Задача 3. Вычисляемое свойство

Создайте класс Rectangle с атрибутами width и height. Добавьте свойство area только для чтения, которое возвращает площадь прямоугольника. Убедитесь, что при изменении ширины площадь пересчитывается автоматически.

Подсказка

Для area используйте только @property без сеттера. Внутри метода верните self.width * self.height.

Решение учителя 
class Rectangle:    def __init__(self, width, height):        self.width = width        self.height = height    @property    def area(self):        return self.width * self.heightr = Rectangle(5, 10)print(r.area)   # 50r.width = 10print(r.area)   # 100 (пересчиталось само)
Задача 4. Банковский счёт

Создайте класс BankAccount с защищённым атрибутом _balance (начинается с 0). Добавьте свойство balance только для чтения. Создайте методы deposit(amount) и withdraw(amount). Метод withdraw не должен позволять уйти в минус.

Подсказка

В withdraw проверяйте if amount <= self._balance:. Если денег хватает - вычитайте. Иначе выбрасывайте ValueError. Свойство balance просто возвращает self._balance.

Решение учителя 
class BankAccount:    def __init__(self):        self._balance = 0    @property    def balance(self):        return self._balance    def deposit(self, amount):        if amount <= 0:            raise ValueError("Сумма пополнения должна быть положительной")        self._balance += amount    def withdraw(self, amount):        if amount > self._balance:            raise ValueError("Недостаточно средств")        self._balance -= amountacc = BankAccount()acc.deposit(1000)acc.withdraw(500)print(acc.balance)   # 500

Попытка написать acc.balance = 1000000 приведёт к ошибке, потому что у свойства нет сеттера. Это защищает баланс от прямого изменения извне.

Что мы узнали и что дальше

Сегодня мы разобрались с инкапсуляцией и свойствами. Теперь вы умеете делать классы, которые защищают свои данные от случайной порчи, и при этом остаются удобными в использовании. Вы узнали:

  • Зачем нужно защищать атрибуты от прямого изменения.
  • Что такое соглашение об именах с нижним подчёркиванием (_name).
  • Как использовать декоратор @property для геттеров.
  • Как контролировать изменения через @name.setter.
  • Как создавать свойства только для чтения.

Свойства - это один из самых элегантных механизмов Python. Они позволяют писать чистый код, который защищает данные и при этом выглядит как обычная работа с атрибутами.

В следующем уроке мы переключимся на новую тему - генераторы и итераторы. Вы узнаете, как эффективно обрабатывать огромные последовательности данных, не загружая их целиком в память. А для этого познакомимся с волшебным словом yield. До встречи!
