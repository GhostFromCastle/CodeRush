Исключения

~55 минут Средний уровень Теория и Практика

В прошлом уроке мы научились открывать файлы и работать с JSON. И вы наверняка уже столкнулись с ситуацией, когда программа с грохотом падала с красной ошибкой FileNotFoundError, если файла не было. Или с ошибкой json.JSONDecodeError, когда файл был повреждён.

До этого момента любая ошибка в коде означала одно: программа аварийно завершается. Конечный пользователь видит страшный стек вызовов, программа закрывается, данные могут потеряться.

Но хорошее приложение должно быть устойчивым. Если пользователь ввёл букву вместо числа, программа не должна падать. Она должна сказать: «Ой, кажется, вы ошиблись, попробуйте ещё раз». Для этого в Python существует механизм исключений (exceptions). А для того чтобы записывать все важные события (и ошибки, и успешные операции) в журнал, есть модуль logging.

Что такое исключение

Аналогия: вы едете на машине, и вдруг загорается лампочка «низкий уровень масла» (исключение). Что вы делаете? Вы не выпрыгиваете из машины и не бросаете её на дороге. Вы останавливаетесь, доливаете масло и едете дальше. Лампочка - это сигнал о проблеме, который позволяет вам среагировать.

В программировании исключение - это событие, которое возникает во время выполнения программы и прерывает её нормальный ход. Но мы можем «поймать» это событие и обработать его, не давая программе упасть.

Конструкция try / except

Чтобы перехватить ошибку, используется конструкция try / except:

try:    number = int(input("Введите число: "))    print(f"Вы ввели: {number}")except:    print("Вы ввели не число!")

Как это работает:

  • try (попробовать) - здесь мы пишем «опасный» код, который может вызвать ошибку.
  • except (исключение) - этот блок выполнится только в том случае, если в блоке try произошла ошибка.

Если пользователь введёт «25», программа выведет «Вы ввели: 25». Если пользователь введёт «привет», блок try прервётся на вызове int(), произойдёт ошибка ValueError, но программа не упадёт. Управление перейдёт в блок except, и на экране появится «Вы ввели не число!».

Перехват конкретных исключений

Использовать просто except: (без указания типа) считается плохой практикой. Представьте, что вы говорите: «Если что-то пойдёт не так, делай вот это». Но что именно пошло не так? Ошибка ввода? Проблема с файлом? Деление на ноль?

Гораздо лучше указать, какую именно ошибку мы ожидаем:

try:    number = int(input("Введите число: "))except ValueError:    print("Это не число!")

Здесь мы ловим только ошибку ValueError (неправильное значение). Если случится что-то другое (например, KeyboardInterrupt, когда пользователь нажмёт Ctrl+C), программа отработает как обычно.

Самые частые исключения в Python:

  • ValueError - неправильное значение (например, int("привет")).
  • TypeError - неправильный тип (например, "5" + 5).
  • ZeroDivisionError - деление на ноль.
  • FileNotFoundError - файл не найден.
  • IndexError - выход за границы списка.
  • KeyError - несуществующий ключ словаря.
  • json.JSONDecodeError - повреждённый JSON (подкласс ValueError).

Можно обрабатывать разные ошибки по-разному, используя несколько блоков except:

try:    a = int(input("Первое число: "))    b = int(input("Второе число: "))    print(a / b)except ValueError:    print("Нужно было ввести числа")except ZeroDivisionError:    print("На ноль делить нельзя!")

Блок else и finally

У конструкции try есть ещё два необязательных блока.

Блок else выполняется только в том случае, если в try не было ошибок:

try:    number = int(input("Число: "))except ValueError:    print("Ошибка ввода")else:    print(f"Всё прошло успешно, число: {number}")

Это полезно, когда вы хотите, чтобы код после блока try выполнялся только при успехе, но при этом не находился внутри try (чтобы случайно не поймать ошибку из этого кода).

Блок finally выполняется всегда. Независимо от того, была ошибка или нет, поймали её или нет:

try:    file = open("data.txt", "r")    print(file.read())except FileNotFoundError:    print("Файла нет")finally:    print("Этот блок выполнится в любом случае")

Блок finally обычно используется для очистки ресурсов (закрыть файл, закрыть соединение с базой данных). Правда, для файлов мы уже используем конструкцию with, которая делает это автоматически. Но finally пригодится в других ситуациях.

Создание собственных исключений

Иногда нужно не просто перехватить ошибку, а вызвать её самостоятельно. Например, если пользователь ввёл отрицательный возраст, это не ошибка Python, но это ошибка с точки зрения бизнес-логики.

Для этого используется ключевое слово raise (поднять):

def set_age(age):    if age < 0:        raise ValueError("Возраст не может быть отрицательным")    print(f"Возраст установлен: {age}")

Если вызвать set_age(-5), программа остановится и выдаст ошибку ValueError с нашим сообщением. А если обернуть вызов в try/except, мы сможем эту ошибку поймать.

Свои классы исключений

В больших проектах часто создают собственные классы исключений, чтобы отделить ошибки бизнес-логики от технических сбоев. Делается это наследованием от базового класса Exception (о наследовании мы поговорим в следующих уроках):

class AgeTooSmallError(Exception):    passdef check_age(age):    if age < 18:        raise AgeTooSmallError("Вам ещё нет 18")

Теперь мы можем ловить именно AgeTooSmallError, не путая его с другими ошибками.

Логирование: замена print в серьёзных программах

Пока программы маленькие, для отладки хватает print. Но представьте: у вас бот, который работает круглосуточно. Вы не сидите рядом с консолью. Если что-то пойдёт не так в три часа ночи, вы никогда не узнаете об этом, потому что print выводит сообщение в консоль и тут же теряет его.

Для настоящих проектов существует логирование - запись событий в файл (или другое хранилище) с указанием времени, важности и источника. В Python для этого есть встроенный модуль logging.

Аналогия: print - это как крикнуть что-то в комнате. Услышат только те, кто рядом и в этот момент. Логирование - это как запись в бортовой журнал корабля. Все события фиксируются, у каждого есть время, и журнал можно прочитать потом.

Простой пример

import logginglogging.basicConfig(level=logging.INFO)logging.info("Программа запущена")logging.warning("Мало свободного места")logging.error("Не удалось подключиться к базе")

В консоль выведется примерно следующее:

INFO:root:Программа запущенаWARNING:root:Мало свободного местаERROR:root:Не удалось подключиться к базе

Уровни логирования

У сообщений есть пять уровней важности (по возрастанию):

  • DEBUG - подробная отладочная информация. Для повседневной работы слишком многословно, включают только при поиске багов.
  • INFO - обычные события: «сервер запущен», «пользователь вошёл».
  • WARNING - что-то подозрительное, но программа продолжает работать: «заканчивается память», «файл скоро устареет».
  • ERROR - операция не удалась: «не удалось сохранить файл», «неверный пароль».
  • CRITICAL - программа не может продолжать работу: «база данных недоступна», «нет прав на запись».

Параметр level=logging.INFO в basicConfig говорит: «показывай только сообщения уровня INFO и выше». То есть DEBUG будет проигнорирован. Если поставить level=logging.DEBUG, будут показаны все уровни.

Запись в файл

Главная сила логирования - в записи в файл. Один параметр в basicConfig, и всё, что вы логируете, будет сохраняться на диск:

import logginglogging.basicConfig(    filename="app.log",    level=logging.INFO,    format="%(asctime)s [%(levelname)s] %(message)s",    encoding="utf-8")logging.info("Программа запущена")

Разберём параметры:

  • filename="app.log" - куда писать. Если не указать, будет выводиться в консоль.
  • level=logging.INFO - минимальный уровень сообщений.
  • format - формат строки. Специальные «маски» вроде %(asctime)s заменяются на время, %(levelname)s - на уровень, %(message)s - на само сообщение.
  • encoding="utf-8" - чтобы русские буквы в файле не превращались в кракозябры.

Через месяц работы в файле app.log вы сможете найти всё, что происходило с программой. Каждая строка будет с датой, уровнем и текстом:

2026-10-26 14:32:11,455 [INFO] Программа запущена2026-10-26 14:32:15,102 [ERROR] Не удалось сохранить файл

Логирование с исключениями

Самый мощный приём - логировать исключение целиком, вместе со стеком вызовов. Для этого в блоке except вызывают logging.exception():

import logginglogging.basicConfig(    filename="app.log",    level=logging.ERROR,    encoding="utf-8")try:    number = int(input("Введите число: "))    print(10 / number)except ValueError:    logging.exception("Пользователь ввёл не число")except ZeroDivisionError:    logging.exception("Пользователь ввёл ноль")

logging.exception() работает так же, как logging.error(), но дополнительно записывает полный traceback - весь стек вызовов, который привёл к ошибке. В файле вы увидите не только «что-то пошло не так», но и «в какой строке, в какой функции».

print vs logging

В учебных скриптах и в print нет ничего плохого. Но как только программа выходит за пределы вашего ноутбука (Telegram-бот, веб-сервер, cron-задача) - она должна логировать свои события в файл. Вы не увидите, что произошло в три часа ночи, если программа упала и потеряла консоль. А в файле всё сохранится.

Шпаргалка

Самое важное в одном месте:

  • try: блок с опасным кодом
  • except ValueError: обработка конкретной ошибки
  • except: плохая практика
  • else: если ошибок не было
  • finally: выполняется всегда
  • raise ValueError() вызвать ошибку
  • logging.basicConfig() настроить логи
  • logging.info() обычное событие
  • logging.error() ошибка
  • logging.exception() ошибка + traceback

Если что-то не работает

Разберём типичные ошибки при обработке исключений и логировании.

  • «Программа всё равно падает, хотя есть try/except». Скорее всего, вы ловите не тот тип ошибки. Если вы написали except ValueError, а произошла ZeroDivisionError, программа упадёт. Проверьте тип ошибки в консоли.
  • Использование «голого» except. except: перехватывает все ошибки, включая системные (например, остановку программы через Ctrl+C). Это скрывает баги и мешает отладке. Всегда указывайте тип ошибки.
  • «Ошибка возникла, но except её не ловит». Возможно, код с ошибкой находится вне блока try. В блок try нужно помещать именно те строки, которые могут упасть.
  • Падение в блоке finally. Если внутри finally произойдёт ошибка, она перезапишет исходную ошибку из блока try. Будьте осторожны с кодом в finally.
  • «Мой except перехватывает ошибки, которые не должен». Вы указали слишком общий класс ошибки. Например, except Exception поймает почти всё. Старайтесь быть максимально конкретными.
  • «Логи не появляются в файле». Проверьте, что basicConfig вызван до первого logging.info. А также что вы указали нужный level (сообщения ниже его порога игнорируются).
  • «basicConfig срабатывает только один раз». Это правда. Функция basicConfig настраивает логгер только при первом вызове. Последующие вызовы игнорируются (если не передать force=True). Если нужно перенастроить - используйте logging.basicConfig(..., force=True).
  • Русские буквы в логе превращаются в кракозябры. Забыли параметр encoding="utf-8" в basicConfig.
  • «В лог попали посторонние сообщения от сторонних библиотек». Иногда сторонние библиотеки тоже пишут в корневой логгер. Можно настроить только свой логгер через logging.getLogger(__name__) или отключить чужие через logging.getLogger("urllib3").setLevel(logging.WARNING).

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Безопасное деление

Спросите у пользователя два числа и разделите первое на второе. Обработайте ошибку ZeroDivisionError, чтобы программа не падала при делении на ноль, а выводила вежливое сообщение.

Подсказка

Поместите ввод и деление внутрь try. В except укажите ZeroDivisionError. Результат выводите, если ошибки не было.

Решение учителя 
try:    a = float(input("Первое число: "))    b = float(input("Второе число: "))    result = a / b    print(f"Результат: {result}")except ZeroDivisionError:    print("Ошибка: на ноль делить нельзя!")
Задача 2. Чтение файла

Напишите программу, которая пытается прочитать файл config.txt и вывести его содержимое. Обработайте ошибку FileNotFoundError: если файла нет, выведите «Файл настроек не найден, используются настройки по умолчанию».

Подсказка

Внутри try откройте файл через with open() и прочитайте его. В except FileNotFoundError выведите сообщение об ошибке.

Решение учителя 
try:    with open("config.txt", "r", encoding="utf-8") as f:        print(f.read())except FileNotFoundError:    print("Файл настроек не найден, используются настройки по умолчанию")
Задача 3. Надёжный ввод возраста

Напишите функцию ask_age(), которая в цикле просит пользователя ввести возраст. Если пользователь вводит не число (вызывается ValueError), программа должна писать «Пожалуйста, введите число» и спрашивать снова. Если ввели число - вернуть его.

Подсказка

Используйте while True:. Внутри try пытайтесь преобразовать ввод в int и сделать return. Если поймали ValueError, просто выводите сообщение - цикл продолжится.

Решение учителя 
def ask_age():    while True:        try:            age = int(input("Введите возраст: "))            return age        except ValueError:            print("Пожалуйста, введите число")age = ask_age()print(f"Ваш возраст: {age}")

Обратите внимание: return находится внутри try. Если преобразование прошло успешно, функция завершится и вернёт число. Если нет - мы попадём в except, напечатаем ошибку и цикл начнётся заново.

Задача 4. Логирование ошибок

Настройте логирование так, чтобы все сообщения уровня ERROR и выше записывались в файл errors.log с датой и уровнем. Напишите функцию safe_divide(a, b), которая делит числа и при делении на ноль логирует ошибку через logging.exception(), а сама возвращает None. Проверьте, что в файле появилась запись.

Подсказка

В basicConfig укажите filename="errors.log", level=logging.ERROR, format="%(asctime)s [%(levelname)s] %(message)s" и encoding="utf-8". В функции используйте try/except ZeroDivisionError с logging.exception() внутри.

Решение учителя 
import logginglogging.basicConfig(    filename="errors.log",    level=logging.ERROR,    format="%(asctime)s [%(levelname)s] %(message)s",    encoding="utf-8")def safe_divide(a, b):    try:        return a / b    except ZeroDivisionError:        logging.exception(f"Попытка деления {a} на ноль")        return Noneprint(safe_divide(10, 2))   # 5.0print(safe_divide(10, 0))   # None

В файле errors.log появится запись с датой, уровнем ERROR и полным стеком вызовов, включая строку return a / b, где произошла ошибка. Даже если программа продолжит работу, вы сможете потом разобраться, что произошло.

Что мы узнали и что дальше

Теперь ваши программы умеют не падать при первой же ошибке и вести журнал событий. Вы узнали, как управлять потоком выполнения при возникновении исключительных ситуаций, и как сделать программу дружелюбной к пользователю и удобной для отладки.

В этом уроке мы разобрали:

  • Что такое исключения и зачем они нужны.
  • Конструкцию try / except и почему важно указывать конкретный тип ошибки.
  • Блоки else и finally.
  • Как генерировать собственные исключения через raise.
  • Как создавать свои классы исключений.
  • Как использовать модуль logging вместо print: уровни, запись в файл, форматирование, logging.exception.

Логирование - это тот навык, который отличает «домашний скрипт» от кода в продакшене. Начните использовать его уже в своих учебных проектах, и вы быстро оцените удобство: когда программа падает через неделю после запуска, у вас будет история событий, а не пустое окно консоли.
