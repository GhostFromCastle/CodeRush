Декораторы

~60 минут Средний уровень Теория и Практика

Представьте, что у вас есть десять разных функций. И внезапно вам понадобилось, чтобы каждая из них перед запуском выводила в консоль сообщение «Функция начала работу». Можно, конечно, открыть каждую из десяти функций и добавить туда print(). А если через неделю нужно будет это убрать? Придётся снова лезть во все функции.

Или другой пример: вы хотите замерять время выполнения разных функций, чтобы найти узкие места в программе. Писать код замера времени в начале и в конце каждой функции - утомительно и засоряет логику.

В Python для таких задач есть элегантное решение - декораторы. Это функции, которые «оборачивают» другие функции, добавляя им новое поведение без изменения их исходного кода.

Функции - это объекты

Чтобы понять декораторы, нужно вспомнить одну важную вещь из урока 9: в Python всё является объектом. И функции - не исключение. Это значит, что функцию можно:

  • Присвоить переменной.
  • Передать в другую функцию как аргумент.
  • Вернуть из другой функции как результат.
def say_hello():    print("Привет!")my_func = say_hellomy_func()   # Привет! (работает, потому что my_func теперь ссылается на функцию)

Именно на этом свойстве и строятся декораторы.

Как написать свой декоратор

Декоратор - это функция, которая принимает другую функцию и возвращает новую (обёрнутую) функцию. Давайте напишем простой декоратор, который выводит сообщение до и после вызова функции.

Шаг 1. Создаём внешнюю функцию-декоратор, которая принимает func:

def my_decorator(func):    def wrapper():        print("До вызова функции")        func()        print("После вызова функции")    return wrapper

Шаг 2. Применяем декоратор к нашей функции. Самый простой способ - вручную:

def say_hello():    print("Привет!")decorated_hello = my_decorator(say_hello)decorated_hello()

Результат:

До вызова функцииПривет!После вызова функции

Синтаксический сахар: @

Записывать decorated_hello = my_decorator(say_hello) неудобно. Поэтому в Python придумали специальный синтаксис с символом @. Он ставится прямо перед объявлением функции:

@my_decoratordef say_hello():    print("Привет!")say_hello()

Эта запись полностью эквивалентна предыдущей, но выглядит гораздо чище. Читается так: «Вызови функцию say_hello и передай её в my_decorator».

Декоратор для функции с аргументами

В примере выше функция say_hello не принимала аргументов. А что если принимает? Например, функция сложения:

def add(a, b):    return a + b

Если мы применим к ней наш простой декоратор @my_decorator, при вызове add(2, 3) возникнет ошибка, потому что внутренняя функция wrapper() не принимает аргументов.

Чтобы декоратор был универсальным, внутренняя функция должна принимать любое количество аргументов. Помните *args и **kwargs из урока 13? Вот они и пригодятся:

def my_decorator(func):    def wrapper(*args, **kwargs):        print("До вызова")        result = func(*args, **kwargs)        print("После вызова")        return result    return wrapper

Обратите внимание: мы не только передаём аргументы дальше через *args, **kwargs, но и сохраняем результат функции в переменную result и возвращаем его. Если бы мы этого не сделали, функция add возвращала бы None, потому что wrapper по умолчанию возвращает None.

Сохранение имени функции: functools.wraps

Есть одна проблема с нашим декоратором. Если мы посмотрим на имя функции после декорирования, мы увидим имя wrapper:

@my_decoratordef say_hello():    print("Привет!")print(say_hello.__name__)   # выведет "wrapper", а не "say_hello"

Это может сломать код, который полагается на имена функций (например, фреймворки или отладчики). Чтобы сохранить оригинальные метаданные функции (имя, документацию), используют декоратор @functools.wraps:

import functoolsdef my_decorator(func):    @functools.wraps(func)    def wrapper(*args, **kwargs):        print("До вызова")        result = func(*args, **kwargs)        print("После вызова")        return result    return wrapper

Теперь say_hello.__name__ останется "say_hello". Считайте это правилом хорошего тона: всегда используйте @functools.wraps при создании декораторов.

Готовые декораторы из стандартной библиотеки

Писать свои декораторы - полезный навык, но в реальной работе вы будете чаще использовать готовые. В Python есть целый набор декораторов «из коробки», которые решают типовые задачи.

Аналогия: писать свой декоратор - это как точить нож вручную. Иногда нужно, но для большинства задач достаточно взять готовый из ящика на кухне.

@functools.lru_cache: кеширование результатов

Самый популярный и полезный встроенный декоратор. Он запоминает результаты вызовов функции и при повторном вызове с теми же аргументами возвращает сохранённый результат, не вычисляя его заново.

Аналогия: это как блокнот с решениями. Если вы уже решали этот пример - зачем решать снова? Просто посмотрите в блокнот.

Классический пример - числа Фибоначчи, где наивная рекурсивная реализация катастрофически медленная:

def fib(n):    if n < 2:        return n    return fib(n - 1) + fib(n - 2)print(fib(35))   # вычисляется несколько секунд

Функция fib вызывает саму себя дважды, и каждый раз заново вычисляет уже посчитанные значения. Число fib(30) вычисляется миллионы раз. А теперь добавим один декоратор:

import functools@functools.lru_cache(maxsize=None)def fib(n):    if n < 2:        return n    return fib(n - 1) + fib(n - 2)print(fib(35))   # мгновенно

Разница - в тысячи раз. Первый вариант вычисляет fib(35) за несколько секунд, второй - за миллисекунды. А всё потому, что lru_cache запоминает каждый результат: если fib(10) уже посчитан, второй раз он не вычисляется.

Параметр maxsize задаёт, сколько последних результатов запоминать. None означает «без ограничения». Если поставить maxsize=128, кеш будет хранить только 128 последних значений, а старые будут вытесняться.

Проверить эффективность кеша можно через метод .cache_info():

print(fib.cache_info())

Вы увидите статистику: сколько попаданий в кеш (hits), сколько промахов (misses) и текущий размер кеша.

В Python 3.9+ появился ещё более простой вариант - @functools.cache (без параметров, всегда без ограничения размера):

from functools import cache@cachedef fib(n):    if n < 2:        return n    return fib(n - 1) + fib(n - 2)

Когда использовать lru_cache:

  • Функция вычисляет одно и то же значение многократно с одинаковыми аргументами.
  • Результат дорогой (сложные вычисления, запросы к внешним источникам).
  • Аргументы функции хешируемы (числа, строки, кортежи - но не списки).
Не кешируйте изменяемые данные

lru_cache работает только с хешируемыми аргументами. Если функция принимает список или словарь - кеш не сработает и будет ошибка TypeError: unhashable type. Передавайте кортежи вместо списков.

Другие готовые декораторы, с которыми вы уже встречались

Вы уже не раз пользовались встроенными декораторами, даже если не задумывались об этом. Вот они все вместе:

  • @property (урок 19) - превращает метод в атрибут для чтения. С ним obj.area работает как обычное поле, хотя под капотом вызывается метод.
  • @staticmethod (урок 17, задачник) - метод, который не получает self и не зависит от объекта. Вызывается от класса: MyClass.method().
  • @classmethod (урок 22, проект) - метод, который получает cls (класс) вместо self. Используется для альтернативных конструкторов.
  • @dataclass (урок 17) - автоматически генерирует __init__, __repr__ и __eq__ для класса данных.
  • @functools.wraps - сохраняет имя и документацию функции внутри декоратора.
  • @functools.lru_cache - кеширует результаты функции.

Все они работают по одному принципу: оборачивают функцию и добавляют ей новое поведение. Когда вы смотрите на код с декораторами, читайте значок @ как «примени вот это к функции ниже».

Декораторы во фреймворках

Когда вы дойдёте до веб-разработки (Flask, FastAPI, Django), декораторы встретятся вам повсюду. Например, типичный маршрут в Flask выглядит так:

@app.route("/hello")def hello():    return "Привет!"

Декоратор @app.route «говорит» фреймворку: «Когда пользователь откроет страницу /hello, вызови эту функцию». Функция hello ничего не знает о HTTP-запросах - она просто возвращает строку. Всю работу с маршрутизацией берёт на себя декоратор. Именно это и делает декораторы такими мощными: они отделяют логику от инфраструктуры.

Шпаргалка

Самое важное в одном месте:

  • @decorator синтаксис применения
  • def decorator(func): внешняя функция
  • def wrapper(*args, **kwargs): внутренняя функция
  • return wrapper возврат обёртки
  • @functools.wraps(func) сохранение имени функции
  • @functools.lru_cache кеширование результатов
  • .cache_info() статистика кеша
  • @property метод как атрибут
  • @staticmethod статический метод
  • @classmethod метод класса

Если что-то не работает

Разберём типичные ошибки при создании декораторов.

  • «TypeError: wrapper() takes 0 positional arguments but 2 were given». Вы забыли добавить *args, **kwargs во внутреннюю функцию wrapper, когда декорировали функцию с аргументами.
  • Декорированная функция возвращает None. Внутри wrapper вы вызвали func(), но забыли написать return func() или сохранить результат и вернуть его.
  • «AttributeError» при обращении к __name__ или __doc__. Вы не использовали @functools.wraps.
  • «TypeError: my_decorator() missing 1 required positional argument». Вы забыли вернуть wrapper из внешней функции-декоратора. Декоратор должен возвращать функцию, а не результат её вызова.
  • «TypeError: unhashable type: 'list'» при использовании @lru_cache. Функция принимает список или словарь, а кеш работает только с хешируемыми аргументами. Передавайте кортежи или frozenset вместо изменяемых коллекций.
  • lru_cache не помогает. Скорее всего, аргументы функции каждый раз разные, и попаданий в кеш просто нет. Или функция имеет побочные эффекты (пишет в файл, изменяет глобальные переменные) - тогда кешировать её нельзя.
  • «Память растёт бесконечно» при использовании @lru_cache(maxsize=None). Если функция вызывается с миллионами разных аргументов - кеш будет расти до бесконечности. Задайте maxsize, например 128, чтобы хранились только последние результаты.
  • Декоратор съел важную информацию о функции. Проверьте, что вы используете @functools.wraps(func). Без него отладчики, IDE и фреймворки будут видеть вместо вашей функции стандартную заглушку wrapper.

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Простой декоратор

Напишите декоратор log_calls, который выводит сообщение «Вызов функции...» перед выполнением любой функции. Примените его к функции say_hello(), которая просто печатает «Привет!».

Подсказка

Создайте функцию log_calls(func). Внутри определите wrapper(), которая печатает текст и вызывает func(). Не забудьте вернуть wrapper.

Решение учителя 
def log_calls(func):    def wrapper():        print("Вызов функции...")        func()    return wrapper@log_callsdef say_hello():    print("Привет!")say_hello()
Задача 2. Декоратор с аргументами

Усовершенствуйте декоратор из первой задачи, чтобы он мог оборачивать функции с любыми аргументами и возвращать их результат. Проверьте на функции add(a, b).

Подсказка

Измените def wrapper(): на def wrapper(*args, **kwargs):. Внутри верните результат: return func(*args, **kwargs). Не забудьте про @functools.wraps.

Решение учителя 
import functoolsdef log_calls(func):    @functools.wraps(func)    def wrapper(*args, **kwargs):        print("Вызов функции...")        return func(*args, **kwargs)    return wrapper@log_callsdef add(a, b):    return a + bprint(add(2, 3))
Задача 3. Декоратор времени

Напишите декоратор timer, который замеряет время выполнения функции и выводит его в секундах (например, «Функция выполнялась 0.523 сек»). Для замера используйте модуль time и функцию time.time().

Подсказка

Внутри wrapper сохраните start = time.time(), вызовите функцию, затем сохраните end = time.time(). Разница end - start - это время выполнения.

Решение учителя 
import timeimport functoolsdef timer(func):    @functools.wraps(func)    def wrapper(*args, **kwargs):        start = time.time()        result = func(*args, **kwargs)        end = time.time()        print(f"Функция выполнялась {end - start:.3f} сек")        return result    return wrapper
Задача 4. Ускоряем Фибоначчи через lru_cache

Напишите функцию fib(n), которая возвращает n-е число Фибоначчи (0, 1, 1, 2, 3, 5, 8, 13, ...). Замерьте время без кеша для fib(30), затем добавьте @functools.lru_cache и замерьте снова. Выведите статистику кеша через .cache_info() и покажите разницу во времени.

Подсказка

Сначала запустите функцию без декоратора и замерьте время через time.time(). Затем добавьте @functools.lru_cache(maxsize=None) перед def fib и замерьте снова. Статистика: fib.cache_info().

Решение учителя 
import timeimport functoolsdef fib_slow(n):    if n < 2:        return n    return fib_slow(n - 1) + fib_slow(n - 2)@functools.lru_cache(maxsize=None)def fib_fast(n):    if n < 2:        return n    return fib_fast(n - 1) + fib_fast(n - 2)start = time.time()result1 = fib_slow(30)time_slow = time.time() - startstart = time.time()result2 = fib_fast(30)time_fast = time.time() - startprint(f"Без кеша:  {time_slow:.3f} сек")print(f"С кешем:   {time_fast:.3f} сек")print(f"Ускорение: {time_slow / time_fast:.0f} раз")print(fib_fast.cache_info())

На типичном компьютере fib_slow(30) занимает около 0.3 секунды, а fib_fast(30) - тысячные доли секунды. Ускорение - сотни раз на маленьком примере и миллионы раз на fib(35). Статистика cache_info() покажет, что попаданий в кеш (hits) было гораздо больше, чем промахов (misses) - именно за счёт этого и достигается скорость.

Что мы узнали и что дальше

Декораторы - это мощнейший инструмент Python, который позволяет изменять поведение функций, не трогая их код. Они широко используются в веб-фреймворках (Flask, Django, FastAPI), в тестировании и во многих библиотеках. Вы узнали:

  • Что функции в Python являются объектами.
  • Как устроен декоратор изнутри (внешняя функция, внутренняя функция-обертка).
  • Как применять декораторы через синтаксис @.
  • Как передавать аргументы через *args, **kwargs.
  • Зачем нужен @functools.wraps.
  • Как работает @functools.lru_cache для кеширования.
  • Как читать статистику кеша через .cache_info().
  • Какие встроенные декораторы вы уже используете (@property, @staticmethod, @classmethod, @dataclass).

Декораторы - это не «экзотика для избранных», а повседневный инструмент. В любом реальном проекте на Python вы встретите их десятки раз: и свои, и из фреймворков. Понимание того, как они работают, открывает дорогу к профессиональному коду.
