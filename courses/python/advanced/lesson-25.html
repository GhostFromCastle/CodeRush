Многопоточность и GIL

~55 минут Продвинутый уровень Теория и Практика

До этого момента все наши программы работали последовательно: шаг за шагом, строка за строкой. Если программа скачивала данные из интернета, она замирала и ждала. Если считала что-то сложное, она блокировала всё остальное.

Но современные компьютеры имеют многоядерные процессоры. Было бы логично использовать их все, чтобы программа работала быстрее. Сегодня мы разберёмся, как в Python работают потоки (threads) и процессы (processes), что такое загадочный GIL, и как безопасно передавать данные между потоками через очереди (queue.Queue).

Аналогия: кухня ресторана

Представьте ресторан. Есть повар, плита и заказы.

  • Последовательная программа - это один повар, который сначала варит суп, потом жарит мясо, потом нарезает салат. Всё делает по очереди.
  • Многопоточность (Threading) - это один повар, но с несколькими руками. Он может одновременно помешивать суп и резать салат. Но спотыкается, потому что мозг (процессор) у него один.
  • Многопроцессность (Multiprocessing) - это три разных повара на трёх разных кухнях. Каждый делает своё дело независимо.

Потоки (threading)

Потоки позволяют запускать несколько задач внутри одной программы. Все они делят общую память. В Python для этого есть встроенный модуль threading.

import threadingimport timedef download_file(name):    print(f"Начинаю скачивать {name}...")    time.sleep(2)    print(f"Файл {name} скачан!")t1 = threading.Thread(target=download_file, args=("photo.jpg",))t2 = threading.Thread(target=download_file, args=("video.mp4",))t1.start()t2.start()t1.join()t2.join()

Обратите внимание на join(). Он говорит главной программе: «Подожди, пока этот поток не завершит свою работу, и только потом идём дальше».

Что такое GIL?

Вот здесь начинается самое интересное. В Python (а точнее, в стандартной реализации CPython) есть глобальная блокировка, которая называется GIL (Global Interpreter Lock).

GIL делает так, что в один момент времени только один поток может выполнять байт-код Python. Это как микрофон в комнате, который можно передавать из рук в руки, но говорить в него может только один человек.

Зачем это сделано? Для безопасности управления памятью. Без GIL два потока могли бы одновременно попытаться изменить один и тот же объект в памяти, что привело бы к катастрофе.

Главное правило Python

Из-за GIL все задачи делятся на два типа:

  • I/O-bound (ожидание ввода-вывода) - задачи, которые большую часть времени ждут: скачивание из сети, чтение файлов, запросы к базе данных. На время ожидания GIL отпускается, поэтому многопоточность работает отлично.
  • CPU-bound (вычисления) - задачи, которые нагружают процессор: сложные математические расчёты, обработка изображений. Здесь GIL не даст потокам работать параллельно. Многопоточность будет работать даже медленнее, чем обычный код, из-за затрат на переключение контекста.

Для вычислений используют модуль multiprocessing, который запускает отдельные процессы (со своей памятью и своим GIL).

Многопроцессность (multiprocessing)

Если вам нужно распараллелить тяжёлые вычисления, используйте процессы:

import multiprocessingdef heavy_calc(n):    result = sum(i * i for i in range(n))    print(f"Вычислено: {result}")if __name__ == "__main__":    p1 = multiprocessing.Process(target=heavy_calc, args=(1000000,))    p2 = multiprocessing.Process(target=heavy_calc, args=(1000000,))    p1.start()    p2.start()    p1.join()    p2.join()

Важное замечание: код с процессами обязательно должен быть обёрнут в if __name__ == "__main__":. Это нужно для корректной работы в Windows.

Безопасная передача данных: queue.Queue

Допустим, у нас есть потоки, которые производят данные (например, скачивают файлы), и потоки, которые их обрабатывают (например, сохраняют на диск). Если передавать данные через общий список, возникнет проблема: два потока одновременно могут попытаться прочитать или изменить его, и данные перепутаются. Это называется состояние гонки (race condition).

В уроке мы уже использовали Lock, чтобы защитить счётчик. Но для передачи данных между потоками есть более удобное решение - queue.Queue (очередь).

Аналогия: очередь - это как конвейер на заводе. Один рабочий кладёт деталь на ленту, другой - снимает. Лента сама заботится о том, чтобы детали не сталкивались и не терялись. Потоки могут смело класть и забирать данные - queue сделает всё за вас.

Главное свойство: Queue потокобезопасна (thread-safe). Все операции с ней атомарны, и вам не нужно вручную брать Lock.

Основные методы

  • put(item) - положить элемент в очередь (в конец).
  • get() - забрать элемент из очереди (с начала). Если очередь пуста - блокируется, пока элемент не появится.
  • qsize() - текущее количество элементов.
  • empty() - проверка, пуста ли очередь.
  • task_done() - сообщить, что один элемент обработан (нужно для join()).
  • join() - блокироваться, пока все элементы не будут обработаны.

Классический паттерн «производитель - потребитель»

Самый частый сценарий использования Queue - когда одни потоки производят задачи, а другие их выполняют. Вот как это выглядит:

import threadingimport queueimport timetask_queue = queue.Queue()def producer():    for i in range(5):        task = f"Задача {i}"        print(f"Производитель создал: {task}")        task_queue.put(task)        time.sleep(0.5)def consumer():    while True:        task = task_queue.get()        if task is None:            break        print(f"Потребитель взял: {task}")        time.sleep(1)        task_queue.task_done()p = threading.Thread(target=producer)c = threading.Thread(target=consumer)p.start()c.start()p.join()task_queue.put(None)c.join()

Разберём этот код:

  • Создаётся поток-производитель. Он кладёт в очередь 5 задач с задержкой в 0.5 секунды.
  • Создаётся поток-потребитель. Он в бесконечном цикле берёт задачи из очереди и обрабатывает их.
  • Как потребитель узнаёт, что пора заканчивать? Производитель после работы кладёт в очередь специальный сигнальный объект (None). Потребитель, увидев его, делает break и завершается.
  • task_done() сообщает очереди, что один элемент успешно обработан. Это нужно, если вы используете queue.join() для ожидания завершения всех задач.

Обратите внимание: потребитель спокойно ждёт на get(), когда очередь пуста. Как только производитель кладёт задачу, потребитель моментально просыпается и обрабатывает её. Никаких Lock, никаких ручных проверок - за нас всё делает очередь.

queue.Queue с ограничением размера

По умолчанию очередь бесконечна. Но можно задать максимальный размер. Если очередь заполнена, put() будет блокироваться, пока не освободится место:

task_queue = queue.Queue(maxsize=3)

Это удобно, когда производитель генерирует задачи быстрее, чем потребитель их выполняет. Ограничение не даст памяти переполниться.

Другие виды очередей

В модуле queue есть ещё два класса:

  • LifoQueue - «последним пришёл - первым вышел» (стек). Полезно, когда важнее обработать последние задачи.
  • PriorityQueue - очередь с приоритетами. Элементы - кортежи вида (приоритет, значение). Забираются элементы с наименьшим приоритетом.
import queuepq = queue.PriorityQueue()pq.put((3, "Низкий приоритет"))pq.put((1, "Высокий приоритет"))pq.put((2, "Средний приоритет"))while not pq.empty():    priority, task = pq.get()    print(f"{priority}: {task}")

Вывод:

1: Высокий приоритет2: Средний приоритет3: Низкий приоритет

Шпаргалка

Самое важное в одном месте:

  • threading.Thread создать поток
  • .start() запустить поток
  • .join() дождаться завершения
  • GIL глобальная блокировка Python
  • I/O-bound сеть, файлы (нужны потоки)
  • CPU-bound вычисления (нужны процессы)
  • multiprocessing.Process создать процесс
  • queue.Queue() потокобезопасная очередь
  • .put(item) положить в очередь
  • .get() забрать из очереди
  • .task_done() отметить обработку
  • PriorityQueue очередь с приоритетами

Если что-то не работает

Разберём типичные проблемы при работе с потоками и очередями.

  • «Многопоточность не ускорила вычисления». Это GIL. Потоки не подходят для математических расчётов. Используйте multiprocessing.
  • «Программа завершается сразу, не дожидаясь потоков». Вы забыли вызвать .join(). Главный поток программы не ждёт, пока дочерние потоки закончат работу.
  • «RuntimeError при запуске multiprocessing в Windows». Вы забыли обернуть код запуска в if __name__ == "__main__":.
  • «Данные изменились неправильно». При работе с общими переменными (без очереди) возникает Race Condition. Используйте threading.Lock() для счётчиков или queue.Queue для передачи данных.
  • «Потребитель никогда не завершается». Вы забыли отправить сигнальный объект (None) в очередь после окончания работы производителя. Без него цикл while True в потребителе будет вечно ждать новые задачи на get().
  • «queue.get() блокируется навсегда». Если очередь пуста, get() по умолчанию ждёт бесконечно. Если нужно с ограничением по времени - используйте get(timeout=5). Если нужно неблокирующее чтение - get(block=False) (выбросит queue.Empty, если пусто).
  • «queue.put() тоже блокируется». Если очередь создана с ограничением maxsize и заполнена, put() будет ждать, пока кто-то заберёт элемент. Используйте put(item, timeout=5) или увеличьте размер.
  • «queue.Queue vs list: зачем усложнять?». Список не является потокобезопасным. Если два потока одновременно делают list.pop(), они могут получить один и тот же элемент или упасть с IndexError. Queue решает эту проблему из коробки.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Параллельное скачивание

Напишите программу, которая создаёт два потока. Первый поток имитирует скачивание файла (ждёт 2 секунды через time.sleep), второй - имитирует загрузку данных (ждёт 3 секунды). Замерьте общее время выполнения программы.

Подсказка

Используйте модули threading и time. В начале программы сохраните start_time = time.time(), в конце выведите разницу. Не забудьте про join().

Решение учителя 
import threadingimport timedef download():    time.sleep(2)    print("Файл скачан")def upload():    time.sleep(3)    print("Данные отправлены")start = time.time()t1 = threading.Thread(target=download)t2 = threading.Thread(target=upload)t1.start()t2.start()t1.join()t2.join()print(f"Общее время: {time.time() - start:.2f} сек")

Программа выполнится примерно за 3 секунды (а не за 5), потому что оба потока ждали одновременно.

Задача 2. Многопроцессность

Создайте два процесса. Каждый процесс должен вычислить сумму квадратов чисел от 1 до 5 000 000. Выведите результат. Не забудьте обернуть запуск в проверку if __name__ == "__main__":.

Подсказка

Используйте multiprocessing.Process. Для вычисления суммы можно использовать встроенную функцию sum() и генератор списка. Не забудьте про .start() и .join().

Решение учителя 
import multiprocessingdef calc():    total = sum(i * i for i in range(5000000))    print(f"Результат: {total}")if __name__ == "__main__":    p1 = multiprocessing.Process(target=calc)    p2 = multiprocessing.Process(target=calc)    p1.start()    p2.start()    p1.join()    p2.join()
Задача 3. Producer-Consumer через Queue

Реализуйте паттерн «производитель - потребитель». Производитель кладёт в очередь числа от 1 до 10. Потребитель достаёт их и считает сумму. В конце выведите общую сумму. Используйте queue.Queue и сигнальный объект None для остановки потребителя.

Подсказка

Создайте q = queue.Queue(). Производитель в цикле делает q.put(i). После цикла кладёт q.put(None). Потребитель в цикле while True: вызывает q.get() и проверяет на None. Сумму сохраняйте в переменную и печатайте после выхода из цикла.

Решение учителя 
import threadingimport queueq = queue.Queue()total = 0def producer():    for i in range(1, 11):        q.put(i)    q.put(None)def consumer():    global total    while True:        item = q.get()        if item is None:            break        total += itemp = threading.Thread(target=producer)c = threading.Thread(target=consumer)p.start()c.start()p.join()c.join()print(f"Сумма: {total}")   # Сумма: 55

Обратите внимание: total изменяется только в одном потоке (потребителе). Поэтому Lock не нужен - гонки не будет. Если бы счётчик увеличивали несколько потребителей, пришлось бы защищать его через Lock.

Задача 4. Несколько потребителей

Усложните предыдущую задачу: запустите трёх потребителей, которые параллельно забирают задачи из одной очереди. Производитель кладёт 10 задач (числа от 1 до 10). Каждый потребитель выводит, какую задачу он взял. Проследите, что задачи распределились между потребителями. Не забудьте отправить три сигнала None - по одному на каждого потребителя.

Подсказка

Создайте список потребителей: consumers = [threading.Thread(target=consumer, args=(i,)) for i in range(3)]. После работы производителя положите в очередь три None (например, циклом for _ in range(3): q.put(None)). Каждый потребитель останавливается, когда получает None.

Решение учителя 
import threadingimport queueimport timeq = queue.Queue()def producer():    for i in range(1, 11):        print(f"Производитель создал задачу {i}")        q.put(i)        time.sleep(0.1)    for _ in range(3):        q.put(None)def consumer(worker_id):    while True:        item = q.get()        if item is None:            break        print(f"Потребитель {worker_id} взял задачу {item}")        time.sleep(0.3)p = threading.Thread(target=producer)consumers = [threading.Thread(target=consumer, args=(i,)) for i in range(3)]p.start()for c in consumers:    c.start()p.join()for c in consumers:    c.join()print("Все задачи обработаны")

Три потребителя работают параллельно: пока один обрабатывает задачу 1, второй берёт задачу 2, третий - задачу 3. Благодаря Queue ни одна задача не теряется и не обрабатывается дважды. Именно так работают веб-серверы (каждый запрос - задача в очереди) и системы обработки данных.

Что мы узнали и что дальше

Сегодня мы заглянули в мир параллельного выполнения кода. Теперь вы знаете:

  • Что такое потоки (threading) и как их запускать.
  • Что такое GIL и почему он мешает распараллеливанию вычислений.
  • Чем отличаются задачи I/O-bound от CPU-bound.
  • Как использовать multiprocessing для обхода GIL.
  • Как защитить данные от состояния гонки с помощью Lock.
  • Как безопасно передавать данные между потоками через queue.Queue.
  • Что такое паттерн «производитель - потребитель» и почему это основа большинства реальных приложений.
  • Как использовать PriorityQueue для задач с приоритетами.

Очереди - это тот инструмент, который вы будете использовать в любом серьёзном многопоточном проекте. Веб-сервер, парсер сайтов, обработчик изображений, система фоновых задач в вебе - везде работает связка «производитель задач + пул потребителей + очередь между ними».

В следующем уроке мы поговорим об асинхронности. Это ещё один способ конкурентного выполнения задач в Python, который не использует потоки и процессы, а работает в рамках одного потока с помощью событийного цикла. Это будет мощный инструмент для веб-разработки. До встречи!
