Паттерны проектирования

~45 минут Продвинутый уровень Теория и Практика

В прошлом уроке мы научились писать юнит-тесты, чтобы обезопасить наш код от случайных поломок при изменениях. Но тесты защищают от ошибок в реализации, а что насчёт самой структуры проекта?

Представьте, что вы проектируете дом. Вы можете придумывать каждую деталь с нуля, а можете взять готовый чертёж, который проверен временем. В программировании такие «чертежи» для решения типовых архитектурных задач называются паттернами проектирования.

Это не готовый код, который можно просто скопировать. Это шаблон, который описывает, как правильно организовать классы и их взаимодействие. Сегодня мы разберём три самых популярных паттерна, которые пригодятся вам в реальных проектах.

Зачем нужны паттерны?

Паттерны - это общий язык разработчиков. Когда вы говорите коллеге: «Я использовал здесь Фабрику», он сразу понимает, как устроен ваш код, не читая его. Это делает архитектуру понятной и поддерживаемой.

Кроме того, паттерны решают конкретные проблемы. Например: как создать объект, чтобы во всей программе был только один его экземпляр? Или как уведомить 10 разных систем о том, что что-то произошло, не создавая жёстких связей между ними?

1. Одиночка (Singleton)

Проблема: Вам нужно, чтобы у класса был только один экземпляр во всей программе. Например, подключение к базе данных или настройки приложения. Если создать два подключения, они начнут конфликтовать.

Решение: Паттерн Singleton гарантирует, что при попытке создать объект второй раз, вам вернётся тот же самый объект, созданный в первый раз.

Аналогия: это как президент страны. Вы можете сколько угодно говорить «вызвать президента», но он всегда один и тот же человек.

class DatabaseConnection:    _instance = None    def __new__(cls):        if cls._instance is None:            print("Создаём новое подключение")            cls._instance = super(DatabaseConnection, cls).__new__(cls)        return cls._instancedb1 = DatabaseConnection()db2 = DatabaseConnection()print(db1 is db2) # Выведет True

Мы переопределили магический метод __new__. Он вызывается перед созданием объекта. Если объект уже существует - мы возвращаем его, а не создаём новый.

2. Фабрика (Factory)

Проблема: У вас есть много классов, которые наследуются от одного родителя (например, разные виды транспорта: Машина, Мотоцикл, Самолёт). В коде вам нужно создавать их в зависимости от условия, и писать длинные цепочки if/elif каждый раз.

Решение: Вы создаёте отдельный класс-«фабрику», который берёт на себя всю логику создания объектов.

Аналогия: вы приходите в автосалон и говорите «Мне машину для города». Менеджер сам решает, что предложить (например, компактный седан). Вам не нужно знать, как её собирают.

class Car:    def drive(self):        print("Едем на машине")class Bike:    def drive(self):        print("Едем на велосипеде")class VehicleFactory:    @staticmethod    def create_vehicle(type):        if type == "car":            return Car()        elif type == "bike":            return Bike()        else:            raise ValueError("Неизвестный тип")vehicle = VehicleFactory.create_vehicle("car")vehicle.drive()

3. Наблюдатель (Observer)

Проблема: У вас есть объект (например, магазин), и при изменении его состояния нужно уведомить кучу других объектов (покупателей, бухгалтерию, склад). Жёстко связывать их все в одном методе - плохая идея.

Решение: Мы создаём список «подписчиков». Когда происходит событие, магазин просто проходит по списку и вызывает у каждого метод update().

Аналогия: это как YouTube-канал и подписчики. Автор выложил видео (событие), и платформа сама разослала уведомления всем, кто нажал «колокольчик».

class Subject:    def __init__(self):        self._observers = []    def attach(self, observer):        self._observers.append(observer)    def notify(self, message):        for obs in self._observers:            obs.update(message)class EmailNotifier:    def update(self, message):        print(f"Email: Получено сообщение - {message}")class SmsNotifier:    def update(self, message):        print(f"SMS: Получено сообщение - {message}")shop = Subject()shop.attach(EmailNotifier())shop.attach(SmsNotifier())shop.notify("Новый товар в магазине!")

Шпаргалка

Самое важное в одном месте:

  • Singleton один объект на всю программу
  • Factory создание объектов через отдельный класс
  • Observer подписка и рассылка уведомлений
  • __new__ магический метод для Singleton
  • @staticmethod статический метод фабрики

Если что-то не работает

Разберём типичные ошибки при работе с паттернами.

  • «Паттерны - это сложно и долго». Внедрять паттерны ради паттернов - плохая идея. Для простого скрипта на 50 строк Singleton будет перебором. Паттерны нужны, когда проект растёт и нужно избежать хаоса.
  • «Синглтон создаёт глобальное состояние». Это главный минус Singleton. Он по сути является глобальной переменной. Используйте его осторожно, только там, где действительно нужен один объект (например, логгер или настройки).
  • «Забыл @staticmethod в фабрике». Если не добавить декоратор, метод будет ожидать self при вызове, и VehicleFactory.create_vehicle("car") выдаст ошибку.
  • «Наблюдатель забыл отписаться». Если объект-наблюдатель больше не нужен, но остался в списке _observers, он будет продолжать получать уведомления (и занимать память). Нужно предусмотреть метод detach.

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Синглтон для настроек

Создайте класс AppSettings с использованием паттерна Singleton. В нём должен быть атрибут theme = "dark". Создайте два объекта этого класса и измените тему через первый. Проверьте, что тема изменилась и у второго объекта.

Подсказка

Используйте метод __new__ с проверкой _instance. Так как оба объекта будут ссылаться на одну и ту же область памяти, изменение атрибута через obj1 сразу отразится на obj2.

Решение учителя 
class AppSettings:    _instance = None    theme = "dark"    def __new__(cls):        if cls._instance is None:            cls._instance = super(AppSettings, cls).__new__(cls)        return cls._instances1 = AppSettings()s2 = AppSettings()s1.theme = "light"print(s2.theme) # light
Задача 2. Простая фабрика

Создайте два класса: Cat (с методом speak, который печатает «Мяу») и Dog (с методом speak, который печатает «Гав»). Напишите класс AnimalFactory со статическим методом create_animal(animal_type).

Подсказка

Внутри фабрики используйте условие if animal_type == "cat": return Cat() и так далее. Не забудьте декоратор @staticmethod.

Решение учителя 
class Cat:    def speak(self):        print("Мяу")class Dog:    def speak(self):        print("Гав")class AnimalFactory:    @staticmethod    def create_animal(animal_type):        if animal_type == "cat":            return Cat()        elif animal_type == "dog":            return Dog()        else:            raise ValueError("Неизвестное животное")my_pet = AnimalFactory.create_animal("dog")my_pet.speak()
Задача 3. Наблюдатели в чате

Создайте класс ChatRoom (Subject) и класс User (Observer). В чате есть метод send_message(text), который вызывает у всех подписчиков метод receive(text), выводящий сообщение. Добавьте двух пользователей и отправьте одно сообщение.

Подсказка

В ChatRoom создайте список users = [] и метод add_user(user). При отправке сообщения проходите циклом по списку и вызывайте user.receive(text).

Решение учителя 
class ChatRoom:    def __init__(self):        self.users = []    def add_user(self, user):        self.users.append(user)    def send_message(self, text):        print(f"Чат разослал: {text}")        for user in self.users:            user.receive(text)class User:    def __init__(self, name):        self.name = name    def receive(self, text):        print(f"{self.name} получил: {text}")chat = ChatRoom()chat.add_user(User("Алексей"))chat.add_user(User("Мария"))chat.send_message("Привет всем!")
Задача 4. Фабрика Синглтонов

Комбинированная задача. Создайте класс Logger (Синглтон), который имеет метод log(message). Создайте LoggerFactory, который всегда возвращает один и тот же экземпляр логгера. Проверьте, что через фабрику нельзя создать два разных логгера.

Подсказка

В классе Logger используйте стандартный Singleton через __new__. А в LoggerFactory просто напишите метод get_logger(), который делает return Logger(). Так как Logger - синглтон, он всегда будет возвращать один объект.

Решение учителя 
class Logger:    _instance = None    def __new__(cls):        if cls._instance is None:            cls._instance = super(Logger, cls).__new__(cls)        return cls._instance    def log(self, message):        print(f"[LOG]: {message}")class LoggerFactory:    @staticmethod    def get_logger():        return Logger()logger1 = LoggerFactory.get_logger()logger2 = LoggerFactory.get_logger()print(logger1 is logger2) # Truelogger1.log("Система запущена")

Паттерны отлично комбинируются друг с другом, решая более сложные архитектурные задачи.
