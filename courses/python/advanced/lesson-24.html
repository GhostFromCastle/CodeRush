Абстракции и протоколы

~55 минут Продвинутый уровень Теория и Практика

В прошлом уроке мы разобрали магические методы и контекстные менеджеры. Мы продолжаем говорить об объектно-ориентированном программировании и проектировании архитектуры.

Представьте, что вы пишете программу для зоопарка. У вас есть классы Слон, Тигр и Пингвин. Все они наследуются от класса Животное. Но вот незадача: слон и тигр умеют бегать, а пингвин - нет. Зато пингвин и некоторые птицы умеют плавать. Как описать эту логику, не создавая запутанную иерархию наследования?

Именно для таких ситуаций в программировании существуют абстракции и протоколы. Они позволяют описать что объект должен уметь делать, не диктуя строго, кем он при этом является. А ещё мы разберём аннотации типов - современный способ документировать код, который можно проверять автоматически.

Проблема жёсткого наследования

Если мы используем обычное наследование, мы привязываем класс к его родителям. Пингвин наследуется от Птица, а Птица - от Животное. Но что если у нас появится класс Робот-пылесос или Самолёт, которые тоже умеют «двигаться», но к животным отношения не имеют?

Нам нужен механизм, который скажет: «Мне неважно, от кого ты произошёл. Мне важно, чтобы у тебя был метод move()». В Python для этого есть два подхода: Абстрактные базовые классы (ABC) и Протоколы (Protocols).

Абстрактные базовые классы (abc)

Абстрактный класс - это «шаблон» или «контракт». Он не предназначен для создания объектов напрямую. Его задача - заставить все дочерние классы реализовать определённые методы.

Аналогия: это как техническое задание на строительство дома. Вы не можете «вселиться в ТЗ», но любой подрядчик (дочерний класс), который берётся за работу, обязан построить фундамент и крышу (реализовать методы).

Для работы с абстракциями в Python есть встроенный модуль abc (Abstract Base Classes).

import abcclass Shape(abc.ABC):    @abc.abstractmethod    def area(self):        pass    @abc.abstractmethod    def perimeter(self):        pass

Что здесь происходит:

  • Класс Shape наследуется от abc.ABC - это делает его абстрактным.
  • Декоратор @abc.abstractmethod помечает методы как обязательные для реализации.
  • У методов нет тела (стоит pass), потому что мы не знаем, как считать площадь абстрактной фигуры.

Теперь, если кто-то попытается создать экземпляр Shape, Python выдаст ошибку. А если мы создадим Circle (круг) и забудем реализовать метод perimeter, Python тоже не даст нам создать объект. Это защищает программу от недоделанных классов.

class Circle(Shape):    def __init__(self, radius):        self.radius = radius    def area(self):        return 3.14 * self.radius ** 2    def perimeter(self):        return 2 * 3.14 * self.radiusc = Circle(5)print(c.area())

Утиная типизация (Duck Typing)

В Python есть знаменитая философия, которая звучит так: «Если это выглядит как утка, плавает как утка и крякает как утка, то это и есть утка».

В отличие от строгих языков (например, C# или Java), Python не всегда требует, чтобы класс наследовался от абстрактного родителя. Python смотрит на поведение объекта.

Если ваша функция ожидает, что у объекта будет метод fly(), ей абсолютно всё равно, кто этот объект - птица, самолёт или супергерой. Главное, чтобы метод fly() у него существовал.

class Bird:    def fly(self):        print("Птица летит")class Airplane:    def fly(self):        print("Самолёт летит")def make_it_fly(entity):    entity.fly()make_it_fly(Bird())make_it_fly(Airplane())

Функция make_it_fly просто вызывает .fly(). Она не проверяет тип. Это делает код очень гибким. Но у такого подхода есть минус: если передать объект без метода fly, программа упадёт только в момент выполнения.

Протоколы (typing.Protocol)

Чтобы совместить гибкость утиной типизации и надёжность абстрактных классов, в Python 3.8 добавили Протоколы.

Протокол - это как «невидимый интерфейс». Он описывает, какие методы должны быть у объекта, но не заставляет классы явно наследоваться от него. Это нужно в первую очередь для статической проверки типов (когда вы используете инструменты вроде mypy в VS Code) и для документирования кода.

Аналогия: это как разъём для наушников (Jack 3.5). Производителю неважно, какой марки ваш телефон. Если у него есть этот разъём - наушники подойдут.

from typing import Protocolclass Flyer(Protocol):    def fly(self):        ...def make_it_fly(entity: Flyer):    entity.fly()

Здесь класс Flyer описывает протокол. Запись entity: Flyer - это аннотация типов. Она говорит редактору кода и линтерам: «Сюда можно передавать только те объекты, у которых есть метод fly». При этом сам класс Bird не обязан наследоваться от Flyer. Ему достаточно просто иметь метод fly.

Аннотации типов: зачем и как

Вы только что видели запись entity: Flyer. Это аннотация типа - способ указать, какого типа значение ожидается. Python не проверяет аннотации во время выполнения, но они помогают:

  • Редактору кода - VS Code подсвечивает ошибки прямо при наборе и подсказывает правильные методы.
  • Вам через полгода - глядя на функцию, вы сразу понимаете, что она принимает и что возвращает.
  • Коллегам - код становится самодокументируемым.
  • Инструментам вроде mypy - они проверяют типы до запуска и находят баги на этапе разработки.

Аналогия: аннотации - это как подписи на банках с крупами. Крупа внутри и без подписи остаётся крупой, но когда на полке 30 банок, подписи экономят часы поиска.

Базовые аннотации

Аннотировать можно аргументы функции и её возвращаемое значение:

def greet(name: str, age: int) -> str:    return f"{name}, {age} лет"

Здесь name: str означает, что name должен быть строкой. age: int - числом. А стрелка -> str указывает, что функция вернёт строку.

Аннотировать можно и переменные:

score: int = 0name: str = "Алексей"

Python не проверяет типы во время выполнения. Если вы передадите в функцию greet число вместо строки, программа не упадёт: аннотации - это только подсказки. Проверка происходит отдельно, через mypy или встроенный анализатор VS Code.

Контейнеры: list, dict, set, tuple

С версии Python 3.9 можно писать прямо встроенными типами:

def average(numbers: list[float]) -> float:    return sum(numbers) / len(numbers)def count_words(text: str) -> dict[str, int]:    result = {}    for word in text.split():        result[word] = result.get(word, 0) + 1    return result

В list[float] квадратные скобки означают «список, состоящий из float». В dict[str, int] - «словарь, где ключ - строка, а значение - целое число». Это не создаёт никакой новый объект, а лишь описывает содержимое.

Для старых версий Python (до 3.9) аннотации контейнеров записывались через модуль typing: List[float], Dict[str, int]. Вы можете встретить такой стиль в чужом коде.

Optional: значение или None

Очень часто функция может вернуть значение или None. Для таких случаев есть Optional:

from typing import Optionaldef find_user(user_id: int) -> Optional[str]:    if user_id == 1:        return "Алексей"    return None

Optional[str] означает «строка или None». В современном Python 3.10+ можно записать это короче: str | None:

def find_user(user_id: int) -> str | None:    if user_id == 1:        return "Алексей"    return None

Union: несколько возможных типов

Если аргумент может быть нескольких типов, используют Union:

from typing import Uniondef parse(value: Union[int, str]) -> int:    return int(value)

Или короткая форма для Python 3.10+: int | str.

Callable: функция как аргумент

Иногда мы передаём в функцию другую функцию. Для этого есть Callable. Он указывает, сколько аргументов принимает функция и что возвращает:

from typing import Callabledef apply_twice(func: Callable[[int], int], value: int) -> int:    return func(func(value))def square(x: int) -> int:    return x * xprint(apply_twice(square, 3))   # 81

Запись Callable[[int], int] означает: «функция, которая принимает int и возвращает int».

Как включить проверку типов

VS Code с расширением Python умеет подсказывать ошибки на лету, если включить проверку. Поставьте галочку в настройках: Python > Analysis: Type Checking Mode - выберите basic или strict. С этого момента редактор будет подчёркивать несоответствия, не запуская код.

Отдельный инструмент - утилита mypy. Устанавливается через pip install mypy и запускается из терминала:

mypy my_script.py

Mypy пройдётся по всем аннотациям, сверит их с реальным использованием и выдаст список проблем. Это полезно встраивать в проверку перед коммитом в Git.

Шпаргалка

Самое важное в одном месте:

  • abc.ABC создать абстрактный класс
  • @abc.abstractmethod обязательный метод
  • typing.Protocol описать интерфейс
  • ... заглушка в теле метода
  • name: str аннотация переменной
  • def f(x: int) -> int аннотация функции
  • list[int], dict[str, int] аннотация контейнеров
  • Optional[int] значение или None
  • Union[int, str] несколько типов
  • Callable[[int], str] функция-аргумент

Если что-то не работает

Разберём типичные проблемы при работе с абстракциями, протоколами и аннотациями.

  • «TypeError: Can't instantiate abstract class ... with abstract method ...». Вы пытаетесь создать объект от абстрактного класса напрямую или от дочернего класса, в котором не реализованы все методы с @abstractmethod.
  • Забыли добавить @abstractmethod. Если вы не повесите декоратор на метод в абстрактном классе, Python будет считать, что это обычный метод. Наследники смогут его не переопределять, и защита не сработает.
  • «Зачем нужны протоколы, если есть утиная типизация?». Сама программа будет работать и без них. Но протоколы делают код самодокументируемым. Открыв функцию def process(db: DatabaseProtocol), вы сразу видите, какие методы нужны от объекта db, не заглядывая в код функции.
  • «Ошибка при использовании Protocol в старых версиях Python». Модуль typing.Protocol появился в Python 3.8. Если у вас версия ниже, используйте модуль typing_extensions.
  • «Аннотации не работают, программа принимает любой тип». Так и задумано. Python не проверяет типы во время выполнения. Аннотации - это документация для людей и инструментов. Для автоматической проверки нужен mypy или встроенный анализатор VS Code.
  • «TypeError: 'type' object is not subscriptable» на list[int]. Вы используете Python 3.8 или ниже. Там запись через квадратные скобки у встроенных типов не работает. Используйте typing.List[int] или обновите Python.
  • «mypy ругается на None, хотя я проверяю if». Mypy не всегда понимает сложную логику. Либо упростите код, либо добавьте явную проверку if x is not None:, либо используйте assert x is not None перед использованием.
  • «mypy не видит мои аннотации». Возможно, у вас установлен mypy для другой версии Python. Проверьте командой mypy --version и убедитесь, что версия совпадает с вашей (например, для Python 3.12 нужен свежий mypy).

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Абстрактное животное

Создайте абстрактный класс Animal с абстрактным методом make_sound(). Создайте двух наследников: Dog и Cat, которые реализуют этот метод и печатают «Гав!» и «Мяу!» соответственно.

Подсказка

Импортируйте abc. Класс Animal должен наследоваться от abc.ABC. Не забудьте поставить @abc.abstractmethod над методом make_sound.

Решение учителя 
import abcclass Animal(abc.ABC):    @abc.abstractmethod    def make_sound(self):        passclass Dog(Animal):    def make_sound(self):        print("Гав!")class Cat(Animal):    def make_sound(self):        print("Мяу!")dog = Dog()dog.make_sound()
Задача 2. Проверка контракта

Попробуйте создать класс Fish, который наследуется от Animal из предыдущей задачи, но не реализует метод make_sound(). Запустите код и посмотрите, какую ошибку выдаст Python. Объясните, почему это происходит.

Подсказка

Ошибка возникнет не при объявлении класса, а при попытке создать его экземпляр: fish = Fish(). Python защищает нас от создания недоделанных объектов.

Решение учителя 
class Fish(Animal):    passfish = Fish()

Программа выведет: TypeError: Can't instantiate abstract class Fish with abstract method make_sound. Абстрактный класс требует, чтобы все его абстрактные методы были переопределены в наследнике. Это гарантирует, что любой объект, который мы создаём, будет полноценным.

Задача 3. Аннотируем функцию

Напишите функцию total_price(prices, discount), которая принимает список цен и скидку в процентах, а возвращает итоговую сумму со скидкой. Добавьте аннотации типов: список - это list[float], скидка - int, результат - float. Внутри используйте sum(). Проверьте на списке [100.0, 200.0, 300.0] со скидкой 10.

Подсказка

Сигнатура: def total_price(prices: list[float], discount: int) -> float:. Формула: sum(prices) * (1 - discount / 100).

Решение учителя 
def total_price(prices: list[float], discount: int) -> float:    return sum(prices) * (1 - discount / 100)print(total_price([100.0, 200.0, 300.0], 10))   # 540.0

Редактор VS Code сразу подскажет вам, что prices - список чисел, и предупредит, если вы случайно передадите туда словарь или строку.

Задача 4. Протокол для хранилища

Опишите протокол Storage с двумя методами: save(key: str, value: str) -> None и load(key: str) -> str | None. Напишите функцию save_username(storage: Storage, username: str), которая вызывает storage.save("user", username). Создайте класс MemoryStorage, который реализует протокол (хранит данные в словаре). Проверьте работу.

Подсказка

Импортируйте Protocol из typing. Опишите методы с аннотациями и заглушкой .... В MemoryStorage используйте атрибут self.data = {}. Метод load возвращает self.data.get(key).

Решение учителя 
from typing import Protocolclass Storage(Protocol):    def save(self, key: str, value: str) -> None:        ...    def load(self, key: str) -> str | None:        ...class MemoryStorage:    def __init__(self):        self.data = {}    def save(self, key: str, value: str) -> None:        self.data[key] = value    def load(self, key: str) -> str | None:        return self.data.get(key)def save_username(storage: Storage, username: str) -> None:    storage.save("user", username)storage = MemoryStorage()save_username(storage, "Алексей")print(storage.load("user"))   # Алексей

Обратите внимание: MemoryStorage не наследуется от Storage, но полностью соответствует протоколу. Редактор при этом проверяет, что методы save и load имеют правильные сигнатуры. Если завтра вы замените MemoryStorage на FileStorage, функция save_username продолжит работать без изменений.
