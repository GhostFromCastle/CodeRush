Абстракции и протоколы

~40 минут Продвинутый уровень Теория и Практика

В прошлом уроке мы разобрали магические методы и увидели, как классы могут вести себя как встроенные типы. Мы продолжаем говорить об объектно-ориентированном программировании (ООП) и проектировании архитектуры.

Представьте, что вы пишете программу для зоопарка. У вас есть классы Слон, Тигр и Пингвин. Все они наследуются от класса Животное. Но вот незадача: слон и тигр умеют бегать, а пингвин - нет. Зато пингвин и некоторые птицы умеют плавать. Как описать эту логику, не создавая запутанную иерархию наследования?

Именно для таких ситуаций в программировании существуют абстракции и протоколы. Они позволяют описать что объект должен уметь делать, не диктуя строго, кем он при этом является.

Проблема жёсткого наследования

Если мы используем обычное наследование, мы привязываем класс к его родителям. Пингвин наследуется от Птица, а Птица - от Животное. Но что если у нас появится класс Робот-пылесос или Самолёт, которые тоже умеют «двигаться», но к животным отношения не имеют?

Нам нужен механизм, который скажет: «Мне неважно, от кого ты произошёл. Мне важно, чтобы у тебя был метод move()». В Python для этого есть два подхода: Абстрактные базовые классы (ABC) и Протоколы (Protocols).

Абстрактные базовые классы (abc)

Абстрактный класс - это «шаблон» или «контракт». Он не предназначен для создания объектов напрямую. Его задача - заставить все дочерние классы реализовать определённые методы.

Аналогия: это как техническое задание на строительство дома. Вы не можете «вселиться в ТЗ», но любой подрядчик (дочерний класс), который берётся за работу, обязан построить фундамент и крышу (реализовать методы).

Для работы с абстракциями в Python есть встроенный модуль abc (Abstract Base Classes).

import abcclass Shape(abc.ABC):    @abc.abstractmethod    def area(self):        pass    @abc.abstractmethod    def perimeter(self):        pass

Что здесь происходит:

  • Класс Shape наследуется от abc.ABC - это делает его абстрактным.
  • Декоратор @abc.abstractmethod помечает методы как обязательные для реализации.
  • У методов нет тела (стоит pass), потому что мы не знаем, как считать площадь абстрактной фигуры.

Теперь, если кто-то попытается создать экземпляр Shape, Python выдаст ошибку. А если мы создадим Circle (круг) и забудем реализовать метод perimeter, Python тоже не даст нам создать объект. Это защищает программу от недоделанных классов.

class Circle(Shape):    def __init__(self, radius):        self.radius = radius    def area(self):        return 3.14 * self.radius ** 2    def perimeter(self):        return 2 * 3.14 * self.radiusc = Circle(5)print(c.area())

Утиная типизация (Duck Typing)

В Python есть знаменитая философия, которая звучит так: «Если это выглядит как утка, плавает как утка и крякает как утка, то это и есть утка».

В отличие от строгих языков (например, C# или Java), Python не всегда требует, чтобы класс наследовался от абстрактного родителя. Python смотрит на поведение объекта.

Если ваша функция ожидает, что у объекта будет метод fly(), ей абсолютно всё равно, кто этот объект - птица, самолёт или супергерой. Главное, чтобы метод fly() у него существовал.

class Bird:    def fly(self):        print("Птица летит")class Airplane:    def fly(self):        print("Самолёт летит")def make_it_fly(entity):    entity.fly()make_it_fly(Bird())make_it_fly(Airplane())

Функция make_it_fly просто вызывает .fly(). Она не проверяет тип. Это делает код очень гибким. Но у такого подхода есть минус: если передать объект без метода fly, программа упадёт только в момент выполнения.

Протоколы (typing.Protocol)

Чтобы совместить гибкость утиной типизации и надёжность абстрактных классов, в Python 3.8 добавили Протоколы.

Протокол - это как «невидимый интерфейс». Он описывает, какие методы должны быть у объекта, но не заставляет классы явно наследоваться от него. Это нужно в первую очередь для статической проверки типов (когда вы используете инструменты вроде mypy в VS Code) и для документирования кода.

Аналогия: это как разъём для наушников (Jack 3.5). Производителю неважно, какой марки ваш телефон. Если у него есть этот разъём - наушники подойдут.

from typing import Protocolclass Flyer(Protocol):    def fly(self):        ...def make_it_fly(entity: Flyer):    entity.fly()

Здесь класс Flyer описывает протокол. Запись entity: Flyer - это аннотация типов. Она говорит редактору кода и линтерам: «Сюда можно передавать только те объекты, у которых есть метод fly». При этом сам класс Bird не обязан наследоваться от Flyer. Ему достаточно просто иметь метод fly.

Шпаргалка

Самое важное в одном месте:

  • abc.ABC создать абстрактный класс
  • @abc.abstractmethod обязательный для реализации метод
  • typing.Protocol описать невидимый интерфейс
  • ... заглушка для тела метода (Ellipsis)
  • Duck Typing проверка поведения, а не типа

Если что-то не работает

Разберём типичные проблемы при работе с абстракциями и протоколами.

  • «TypeError: Can't instantiate abstract class ... with abstract method ...». Вы пытаетесь создать объект от абстрактного класса напрямую или от дочернего класса, в котором не реализованы все методы с @abstractmethod.
  • «Забыл добавить @abstractmethod». Если вы не повесите декоратор на метод в абстрактном классе, Python будет считать, что это обычный метод. Наследники смогут его не переопределять, и защита не сработает.
  • «Зачем нужны протоколы, если есть утиная типизация?». Сама программа будет работать и без них. Но протоколы делают код самодокументируемым. Открыв функцию def process(db: DatabaseProtocol), вы сразу видите, какие методы нужны от объекта db, не заглядывая в код функции.
  • «Ошибка при использовании Protocol в старых версиях Python». Модуль typing.Protocol появился в Python 3.8. Если у вас версия ниже, используйте модуль typing_extensions.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Абстрактное животное

Создайте абстрактный класс Animal с абстрактным методом make_sound(). Создайте двух наследников: Dog и Cat, которые реализуют этот метод и печатают «Гав!» и «Мяу!» соответственно.

Подсказка

Импортируйте abc. Класс Animal должен наследоваться от abc.ABC. Не забудьте поставить @abc.abstractmethod над методом make_sound.

Решение учителя 
import abcclass Animal(abc.ABC):    @abc.abstractmethod    def make_sound(self):        passclass Dog(Animal):    def make_sound(self):        print("Гав!")class Cat(Animal):    def make_sound(self):        print("Мяу!")dog = Dog()dog.make_sound()
Задача 2. Проверка контракта

Попробуйте создать класс Fish, который наследуется от Animal из предыдущей задачи, но не реализует метод make_sound(). Запустите код и посмотрите, какую ошибку выдаст Python. Объясните, почему это происходит.

Подсказка

Ошибка возникнет не при объявлении класса, а при попытке создать его экземпляр: fish = Fish(). Python защищает нас от создания недоделанных объектов.

Решение учителя 
class Fish(Animal):    passfish = Fish()

Программа выведет: TypeError: Can't instantiate abstract class Fish with abstract method make_sound. Абстрактный класс требует, чтобы все его абстрактные методы были переопределены в наследнике. Это гарантирует, что любой объект, который мы создаём, будет полноценным.

Задача 3. Утиная типизация в действии

Напишите функцию start_engine(machine), которая просто вызывает метод machine.start(). Создайте два независимых класса: Car и Lawnmower (газонокосилка). У каждого должен быть метод start(), который печатает不同的 текст. Передайте объекты обоих классов в функцию.

Подсказка

Классы могут быть совершенно не связаны друг с другом. Главное - наличие метода start. Внутри функции не нужно делать никаких проверок типа, просто вызывайте machine.start().

Решение учителя 
class Car:    def start(self):        print("Двигатель автомобиля заведён")class Lawnmower:    def start(self):        print("Газонокосилка тарахтит")def start_engine(machine):    machine.start()start_engine(Car())start_engine(Lawnmower())

Функция start_engine работает с любым объектом, у которого есть метод start. Именно так работает большинство встроенных функций Python.

Задача 4. Описываем протокол

Используя typing.Protocol, опишите протокол Database, который требует наличия двух методов: connect() и execute(query). Напишите функцию run_query(db, query), которая принимает объект, соответствующий этому протоколу, и вызывает его методы.

Подсказка

Импортируйте Protocol. Опишите класс Database(Protocol) с нужными методами (внутри можно написать ...). В функции run_query используйте аннотацию типов: db: Database.

Решение учителя 
from typing import Protocolclass Database(Protocol):    def connect(self):        ...    def execute(self, query):        ...def run_query(db: Database, query: str):    db.connect()    db.execute(query)class Postgres:    def connect(self):        print("Подключение к Postgres")    def execute(self, query):        print(f"Запрос: {query}")db = Postgres()run_query(db, "SELECT * FROM users")

Класс Postgres не наследуется от Database, но соответствует его протоколу. Редакторы кода увидят аннотацию db: Database и подскажут нам, если мы попытаемся вызвать несуществующий метод.

Что мы узнали и что дальше

Сегодня мы научились проектировать более гибкую архитектуру. Теперь вы знаете:

  • Что такое абстрактные классы (abc.ABC) и зачем нужен @abstractmethod.
  • Как утиная типизация делает Python гибким.
  • Как описывать «невидимые» интерфейсы с помощью typing.Protocol для улучшения читаемости кода.

Эти концепции являются фундаментом для написания крупных приложений, где важно, чтобы классы и модули общались друг с другом по чётким правилам, не образуя при этом запутанный клубок зависимостей.
