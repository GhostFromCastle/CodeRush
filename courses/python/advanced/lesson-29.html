Юнит-тестирование

~40 минут Продвинутый уровень Теория и Практика

Представьте, что вы написали программу на 2000 строк кода. Всё работает идеально. Но через месяц вам нужно добавить новую функцию. Вы меняете одну строчку в старой функции, запускаете программу - и внезапно всё ломается. Вы тратите часы, пытаясь понять, что именно вы сломали.

Знакомая ситуация? Именно для решения этой проблемы придумали тестирование. А его самая базовая и важная форма - это юнит-тесты (модульные тесты).

Сегодня мы научимся писать автоматические проверки для нашего кода, чтобы любые изменения можно было вносить без страха что-то сломать.

Аналогия: контроль качества на заводе

Представьте завод по сборке автомобилей.

  • Без тестов: рабочие собирают весь автомобиль целиком, а потом пытаются его завести. Если не заводится - разбирают всё обратно, чтобы найти проблему.
  • С юнит-тестами: каждый отдельный узел (двигатель, тормоза, фары) проверяется на стенде до того, как попадёт в машину. Если тормоза не работают, мы узнаём об этом сразу, а не на трассе.

Юнит-тест проверяет одну маленькую единицу кода (обычно функцию или метод). Он не лезет в базу данных и не стучится в интернет. Он просто передаёт функции входные данные и проверяет, совпадает ли результат с ожидаемым.

Модуль unittest

В Python есть встроенный модуль unittest (от слова unit - единица). Он позволяет писать тесты в виде классов. Давайте разберём это на примере.

Допустим, у нас есть файл math_utils.py с простой функцией сложения:

def add(a, b):    return a + b

Теперь создадим файл test_math_utils.py (обычно тесты называют с префиксом test_):

import unittestfrom math_utils import addclass TestMathUtils(unittest.TestCase):    def test_add_positive(self):        result = add(2, 3)        self.assertEqual(result, 5)    def test_add_negative(self):        result = add(-1, -1)        self.assertEqual(result, -2)if __name__ == '__main__':    unittest.main()

Что здесь происходит:

  • unittest.TestCase - базовый класс, от которого наследуется наш тест.
  • self.assertEqual(результат, ожидание) - это проверка (assert). Если result не равен 5, тест упадёт с ошибкой.
  • unittest.main() - запускает все тесты в файле.

Если вы запустите этот файл, консоль выведет что-то вроде: Ran 2 tests in 0.001s OK. Это значит, что обе проверки прошли успешно.

Основные методы проверки (Assertions)

Метод assertEqual - не единственный. В unittest есть много встроенных проверок под разные ситуации:

  • assertEqual(a, b) - проверяет, что a == b.
  • assertNotEqual(a, b) - проверяет, что a != b.
  • assertTrue(x) - проверяет, что x истинно.
  • assertFalse(x) - проверяет, что x ложно.
  • assertIn(item, list) - проверяет, что item есть в коллекции.
  • assertIsNone(x) - проверяет, что x равен None.
  • assertRaises(Ошибка, функция) - проверяет, что функция выбрасывает нужное исключение.

Проверка исключений

Иногда нам нужно протестировать не успешный сценарий, а ошибку. Например, функция деления должна выбрасывать ZeroDivisionError при делении на ноль. Для этого используется assertRaises.

def divide(a, b):    if b == 0:        raise ValueError("На ноль делить нельзя")    return a / bclass TestDivide(unittest.TestCase):    def test_divide_by_zero(self):        with self.assertRaises(ValueError):            divide(10, 0)

Конструкция with self.assertRaises(...) работает как контекстный менеджер. Если код внутри блока выбросит указанную ошибку - тест пройдёт. Если ошибки не будет (или будет другая) - тест упадёт.

Шпаргалка

Самое важное в одном месте:

  • import unittest подключить модуль
  • unittest.TestCase базовый класс для тестов
  • def test_...() метод-тест
  • assertEqual(a, b) проверка на равенство
  • assertTrue(x) проверка на истину
  • assertRaises(Err) проверка исключения
  • unittest.main() запуск тестов

Если что-то не работает

Разберём типичные проблемы при написании тестов.

  • «Тесты не находит». Модуль unittest ищет файлы, которые начинаются с test_ (например, test_app.py), и классы, унаследованные от TestCase. Если назвать файл иначе - он может быть проигнорирован.
  • «AssertionError». Это не ошибка в тесте, это его успешное срабатывание. Тест обнаружил, что реальный результат не совпадает с ожидаемым. Смотрите, что именно вы передали в assertEqual.
  • «ImportError при запуске». Убедитесь, что файл с тестами и файл с кодом лежат в одной папке, или настройте пути импорта. Для простых проектов достаточно положить их рядом.
  • «Зачем писать тесты, если я могу просто запустить программу и посмотреть?». Для маленького скрипта - можно. Но когда у вас 50 функций и они вызывают друг друга, ручная проверка каждой займёт часы. Тесты запускаются за секунды и делают это за вас.

Если что-то не получается - напишите нам в Telegram, разберёмся вместе.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Проверка на чётность

Напишите функцию is_even(n), которая возвращает True, если число чётное, и False в противном случае. Затем напишите для неё два юнит-теста: для чётного и для нечётного числа.

Подсказка

Функция: return n % 2 == 0. В тестах используйте self.assertTrue(is_even(4)) и self.assertFalse(is_even(5)).

Решение учителя 
def is_even(n):    return n % 2 == 0import unittestclass TestEven(unittest.TestCase):    def test_even(self):        self.assertTrue(is_even(10))    def test_odd(self):        self.assertFalse(is_even(7))if __name__ == '__main__':    unittest.main()
Задача 2. Тестируем строки

Есть функция greet(name), которая возвращает строку "Привет, [name]!". Напишите тест, который проверяет, что для имени «Алексей» функция возвращает именно «Привет, Алексей!».

Подсказка

Используйте метод assertEqual, чтобы сравнить результат функции с ожидаемой строкой. Убедитесь, что знаки препинания и регистр совпадают.

Решение учителя 
def greet(name):    return f"Привет, {name}!"import unittestclass TestGreet(unittest.TestCase):    def test_greet_alexey(self):        result = greet("Алексей")        self.assertEqual(result, "Привет, Алексей!")if __name__ == '__main__':    unittest.main()
Задача 3. Тестируем исключение

Напишите функцию get_age(age), которая выбрасывает ValueError, если возраст меньше 0. Напишите тест, который проверяет, что при передаче отрицательного числа выбрасывается именно это исключение.

Подсказка

В функции используйте raise ValueError("..."). В тесте используйте контекстный менеджер with self.assertRaises(ValueError): и внутри вызовите функцию с отрицательным аргументом.

Решение учителя 
def get_age(age):    if age < 0:        raise ValueError("Возраст не может быть отрицательным")    return ageimport unittestclass TestAge(unittest.TestCase):    def test_negative_age(self):        with self.assertRaises(ValueError):            get_age(-5)if __name__ == '__main__':    unittest.main()
Задача 4. Тестируем скидку

Напишите функцию apply_discount(price, discount). Она должна возвращать цену со скидкой. Скидка передаётся в процентах (например, 10 означает 10%). Напишите тесты: обычная скидка, нулевая скидка и скидка 100% (цена должна стать 0).

Подсказка

Формула: price - (price * discount / 100). Для тестов используйте assertEqual. Например, цена 1000 со скидкой 10% должна дать 900.

Решение учителя 
def apply_discount(price, discount):    return price - (price * discount / 100)import unittestclass TestDiscount(unittest.TestCase):    def test_regular_discount(self):        self.assertEqual(apply_discount(1000, 10), 900)    def test_no_discount(self):        self.assertEqual(apply_discount(500, 0), 500)    def test_full_discount(self):        self.assertEqual(apply_discount(200, 100), 0)if __name__ == '__main__':    unittest.main()

Тесты покрывают граничные случаи (0% и 100%), что делает функцию гораздо надёжнее.

Что мы узнали и что дальше

Тестирование - это то, что отличает код новичка от кода профессионала. Теперь ваши программы имеют страховку от случайных поломок. Вы узнали:

  • Что такое юнит-тесты и зачем они нужны.
  • Как использовать встроенный модуль unittest.
  • Как проверять значения через assertEqual, assertTrue и другие.
  • Как проверять исключения с помощью assertRaises.
