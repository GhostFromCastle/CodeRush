Магические методы

~55 минут Продвинутый уровень Теория и Практика

Добро пожаловать на продвинутый уровень! До этого мы использовали классы в основном для хранения данных и вызова методов вроде dog.bark(). Но что если мы хотим, чтобы наши объекты вели себя как встроенные типы?

Например, чтобы два объекта можно было сложить через +, сравнить через ==, вывести на экран через print() в красивом виде, или узнать их длину через len(). Для этого в Python существуют магические методы (их ещё называют dunder-методами от double underscore).

Вы уже встречались с ними! Метод __init__ - это магический метод, который вызывается автоматически при создании объекта.

Что это такое и зачем они нужны

Магические методы - это методы, которые начинаются и заканчиваются двумя подчёркиваниями: __имя__. Они не вызываются напрямую (как obj.__str__()), а срабатывают автоматически при использовании определённого синтаксиса Python.

Аналогия: встроенные типы вроде списков и строк имеют свои магические методы. Когда вы пишете len("Привет"), Python на самом деле вызывает метод "Привет".__len__(). Когда вы пишете a + b для чисел, Python вызывает a.__add__(b).

Реализуя эти методы в своих классах, вы как бы «включаете» для них поддержку стандартных операторов языка.

__str__ и __repr__: как объект выглядит в виде строки

Когда вы делаете print(obj) или str(obj), Python ищет метод __str__. Если его нет, используется __repr__, а если нет и его - выводится что-то невнятное вроде <__main__.Dog object at 0x7f...>.

Давайте сделаем так, чтобы объект класса Book выводился красиво:

class Book:    def __init__(self, title, author):        self.title = title        self.author = author    def __str__(self):        return f"Книга '{self.title}' автора {self.author}"b = Book("Война и мир", "Толстой")print(b)   # Книга 'Война и мир' автора Толстой

__str__ - это «дружелюбное» представление для пользователя. А __repr__ - это техническое представление для разработчика (обычно возвращает строку, по которой можно воссоздать объект). Если вывести список объектов, Python использует именно __repr__.

__len__: длина объекта

Если вы хотите, чтобы к вашему объекту можно было применить функцию len(), реализуйте метод __len__. Он должен возвращать целое число.

class ShoppingCart:    def __init__(self):        self.items = []    def add(self, item):        self.items.append(item)    def __len__(self):        return len(self.items)cart = ShoppingCart()cart.add("Хлеб")cart.add("Молоко")print(len(cart))   # 2

__eq__: сравнение объектов

По умолчанию оператор == сравнивает объекты по их адресам в памяти (то есть obj1 is obj2). Но мы можем научить Python сравнивать объекты по их содержимому:

class Point:    def __init__(self, x, y):        self.x = x        self.y = y    def __eq__(self, other):        if not isinstance(other, Point):            return False        return self.x == other.x and self.y == other.yp1 = Point(3, 5)p2 = Point(3, 5)p3 = Point(1, 2)print(p1 == p2)   # Trueprint(p1 == p3)   # False
Сравнение и хеширование

Если вы определяете __eq__, Python автоматически делает объекты нехешируемыми (их нельзя добавлять в множества или использовать как ключи словаря). Если вам это нужно, придётся также определить метод __hash__.

Перегрузка операторов

Вы можете научить свои объекты поддерживать математические операции. Например, сложение (__add__) или умножение (__mul__):

class Vector:    def __init__(self, x, y):        self.x = x        self.y = y    def __add__(self, other):        return Vector(self.x + other.x, self.y + other.y)    def __str__(self):        return f"({self.x}, {self.y})"v1 = Vector(1, 2)v2 = Vector(3, 4)v3 = v1 + v2   # сработает __add__print(v3)      # (4, 6)

Контекстные менеджеры: за пределами with open()

Вы уже не раз использовали with open(...) для работы с файлами (урок 15). Это удобный синтаксис, который автоматически закрывает файл даже при ошибках. Но задумывались ли вы, как это работает?

Всё дело в двух магических методах: __enter__ и __exit__. Любой класс, который их определяет, можно использовать в конструкции with. Такие классы называются контекстными менеджерами.

Аналогия: контекстный менеджер - это как турникет в метро. Когда вы проходите через with, срабатывает __enter__ (турникет открывается, и вы попадаете на платформу). Когда блок кода заканчивается - срабатывает __exit__ (турникет закрывается, вы выходите). И неважно, дошли вы до конца блока или упали с ошибкой посреди - турникет всё равно закроется.

Как это работает

  • __enter__(self) - вызывается при входе в блок with. То, что он вернёт, можно присвоить переменной после as.
  • __exit__(self, exc_type, exc_value, traceback) - вызывается при выходе из блока, всегда, даже если внутри произошло исключение. Если вернуть True, исключение будет подавлено (не всплывёт наружу). Если False или None - исключение продолжит распространяться.

Пример - свой контекстный менеджер для измерения времени:

import timeclass Timer:    def __enter__(self):        self.start = time.time()        return self    def __exit__(self, exc_type, exc_value, traceback):        self.end = time.time()        print(f"Затрачено времени: {self.end - self.start:.3f} сек")with Timer():    total = sum(range(1_000_000))    print(f"Сумма: {total}")

Что происходит:

  1. При входе в with вызывается __enter__. Он запоминает время старта.
  2. Выполняется код внутри блока (суммирование).
  3. При выходе из with вызывается __exit__. Он запоминает время конца и печатает разницу.

Пример: менеджер для подключения к базе данных

Классический сценарий использования контекстного менеджера - управление соединениями. Соединение нужно открыть, использовать и обязательно закрыть, даже если что-то пошло не так.

import sqlite3class Database:    def __init__(self, filename):        self.filename = filename    def __enter__(self):        self.connection = sqlite3.connect(self.filename)        print("Подключение установлено")        return self.connection    def __exit__(self, exc_type, exc_value, traceback):        self.connection.close()        print("Подключение закрыто")with Database("my_data.db") as conn:    cursor = conn.cursor()    cursor.execute("SELECT 1")    print("Запрос выполнен")

Даже если внутри блока with произойдёт ошибка, __exit__ всё равно закроет соединение. Это и есть главное преимущество контекстных менеджеров: гарантированное освобождение ресурсов.

Функция contextlib.contextmanager

Писать целый класс ради контекстного менеджера не всегда удобно. В Python есть декоратор @contextlib.contextmanager, который позволяет создать контекстный менеджер из обычной функции-генератора:

from contextlib import contextmanagerimport time@contextmanagerdef timer():    start = time.time()    yield    end = time.time()    print(f"Затрачено: {end - start:.3f} сек")with timer():    sum(range(1_000_000))

Как это работает:

  • Всё, что до yield, выполняется при входе в with (аналог __enter__).
  • Код внутри with выполняется как обычно.
  • Всё, что после yield, выполняется при выходе из with (аналог __exit__).

Этот приём работает на генераторах, которые мы разбирали в уроке 20. @contextmanager - стандартный и очень удобный способ писать компактные контекстные менеджеры. Достаточно помнить одно правило: между созданием ресурса (до yield) и его освобождением (после yield) обязательно должен быть try/finally, если ресурс критичный:

from contextlib import contextmanager@contextmanagerdef open_file(path):    f = open(path, "r", encoding="utf-8")    try:        yield f    finally:        f.close()

Без try/finally при ошибке внутри блока with файл остался бы открытым. Именно так и работает встроенный open внутри себя.

Шпаргалка

Самые полезные магические методы:

  • __init__ конструктор объекта
  • __str__ красивый вывод (print)
  • __repr__ технический вывод
  • __len__ работа с len()
  • __eq__ сравнение через ==
  • __add__ сложение через +
  • __getitem__ доступ по индексу []
  • __enter__ вход в with
  • __exit__ выход из with
  • @contextmanager менеджер из функции

Если что-то не работает

Разберём типичные ошибки при работе с магическими методами и контекстными менеджерами.

  • «TypeError: 'Vector' object is not callable». Вы случайно вызвали магический метод напрямую со скобками: v3 = v1.__add__(v2)(). Скобки в конце не нужны, он вызывается оператором +.
  • print() выводит страшную строку <__main__.Dog object at...>. Вы забыли определить метод __str__.
  • «TypeError: object of type 'Book' has no len()». Вы пытаетесь применить len() к объекту, у которого нет метода __len__.
  • Бесконечная рекурсия в __repr__. Внутри __str__ вы написали return str(self). Это вызовет __str__ заново. Нужно возвращать строку напрямую через f-строки.
  • Ошибка в __eq__. Если вы определили __eq__, но пытаетесь добавить объекты в set(), вы получите TypeError: unhashable type. Для исправления нужно определить метод __hash__ (можно просто return hash((self.x, self.y))).
  • «AttributeError: __enter__» при использовании with. Класс, который вы пытаетесь использовать в with, не является контекстным менеджером - у него нет методов __enter__ и __exit__.
  • «Исключение внутри with всё равно всплывает». Так и должно быть по умолчанию. __exit__ получает информацию об исключении, но не подавляет его. Чтобы подавить - верните из __exit__ значение True.
  • «Ресурс не освободился после ошибки в with». Скорее всего, в __exit__ или после yield нет try/finally. Если ошибка происходит в коде до yield, __exit__ не вызовется. Используйте try/finally в контекстном менеджере.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Красивая дробь

Создайте класс Fraction (дробь) с числителем и знаменателем. Реализуйте метод __str__, чтобы объект выводился в формате «числитель/знаменатель». Создайте дробь 3/4 и выведите её через print.

Подсказка

В методе __str__ верните строку: return f"{self.numerator}/{self.denominator}".

Решение учителя 
class Fraction:    def __init__(self, numerator, denominator):        self.numerator = numerator        self.denominator = denominator    def __str__(self):        return f"{self.numerator}/{self.denominator}"f = Fraction(3, 4)print(f)   # 3/4
Задача 2. Сложение денег

Создайте класс Money с атрибутом amount. Реализуйте метод __add__, чтобы две суммы можно было сложить через +. Верните новый объект Money с общей суммой.

Подсказка

В методе __add__(self, other) напишите return Money(self.amount + other.amount). Убедитесь, что класс Money определён до того, как вы его используете в методе.

Решение учителя 
class Money:    def __init__(self, amount):        self.amount = amount    def __add__(self, other):        return Money(self.amount + other.amount)    def __str__(self):        return f"{self.amount} руб."m1 = Money(500)m2 = Money(300)m3 = m1 + m2print(m3)   # 800 руб.
Задача 3. Свой контекстный менеджер

Создайте класс-контекстный менеджер Session, который имитирует открытие и закрытие пользовательской сессии. При входе в with он должен печатать «Сессия открыта», а при выходе - «Сессия закрыта». Внутри блока with выведите «Работаем...» и проверьте, что обе служебные строки появились в консоли.

Подсказка

Реализуйте методы __enter__ и __exit__. В __enter__ напечатайте «Сессия открыта» и верните self. В __exit__ - напечатайте «Сессия закрыта». Параметры __exit__ можно назвать exc_type, exc_value, traceback, но использовать не обязательно.

Решение учителя 
class Session:    def __enter__(self):        print("Сессия открыта")        return self    def __exit__(self, exc_type, exc_value, traceback):        print("Сессия закрыта")with Session():    print("Работаем...")

Вывод:

Сессия открытаРаботаем...Сессия закрыта

Если запустить этот код несколько раз - вывод всегда будет одинаковым. Методы срабатывают автоматически и строго по порядку.

Задача 4. Гарантированное закрытие

Докажите, что __exit__ вызывается даже при исключении. Используйте Session из предыдущей задачи, но внутри with намеренно разделите 10 на ноль. Оберните весь блок в try/except ZeroDivisionError. Убедитесь, что строка «Сессия закрыта» появилась в консоли до того, как вы поймали исключение.

Подсказка

Оберните конструкцию with в try, а в except ZeroDivisionError напишите print("Ошибка перехвачена"). Порядок вывода покажет, что __exit__ сработал раньше except.

Решение учителя 
class Session:    def __enter__(self):        print("Сессия открыта")        return self    def __exit__(self, exc_type, exc_value, traceback):        print("Сессия закрыта")try:    with Session():        print("Работаем...")        10 / 0except ZeroDivisionError:    print("Ошибка перехвачена")

Вывод:

Сессия открытаРаботаем...Сессия закрытаОшибка перехвачена

Это доказывает главное свойство контекстных менеджеров: код очистки в __exit__ выполняется всегда, даже если внутри блока было исключение. Именно поэтому with считается золотым стандартом управления ресурсами.

Что мы узнали и что дальше

Сегодня мы прикоснулись к самой «магии» Python. Магические методы позволяют вашим классам интегрироваться в язык так, что они становятся неотличимы от встроенных типов. Теперь вы знаете:

  • Что такое dunder-методы и зачем они нужны.
  • Как сделать красивый вывод объекта через __str__.
  • Как реализовать длину через __len__ и доступ по индексу через __getitem__.
  • Как перегрузить операторы сложения и вычитания.
  • Как сравнивать объекты по содержимому через __eq__.
  • Как создавать контекстные менеджеры через __enter__/__exit__.
  • Как использовать @contextlib.contextmanager для компактных менеджеров на генераторах.

Контекстные менеджеры - это одна из тех концепций, которые вы будете использовать ежедневно, даже не задумываясь. Как только в вашем коде появляется ресурс (файл, соединение с базой, блокировка), который нужно гарантированно освободить - это повод написать контекстный менеджер.
