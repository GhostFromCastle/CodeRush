Методология БЭМ: порядок в CSS

~40 минут Продвинутый уровень Теория и Практика

Представьте, что вы работаете в команде из 5 разработчиков над крупным интернет-магазином. У вас есть 100 разных страниц. Один разработчик пишет стили для карточки товара и называет кнопку внутри неё классом .button. Другой разработчик пишет стили для формы обратной связи и тоже называет кнопку .button, но с другими отступами и цветом. В итоге на сайте всё ломается, потому что их стили конфликтуют.

Чтобы такого не происходило, придумали БЭМ. Это аббревиатура, которая расшифровывается как Блок, Элемент, Модификатор. Это методология именования классов, которая делает CSS предсказуемым и независимым.

Три кита БЭМ

1. Блок (Block)

Это независимый, самостоятельный компонент страницы. Его можно переставить в любое место, и он не сломается. Примеры блоков: .header, .logo, .card, .search-form.

Блок всегда имеет осмысленное имя и отвечает только за свой внешний вид.

2. Элемент (Element)

Это составная часть блока. Элемент не может существовать отдельно от своего блока. Он привязан к нему. В HTML это выражается вложенностью, а в CSS - специальным синтаксисом через два подчёркивания (__).

Пример: если у нас есть блок .card, то заголовок внутри него будет .card__title, картинка - .card__image, а кнопка - .card__button.

3. Модификатор (Modifier)

Это свойство блока или элемента, которое меняет его внешний вид или поведение. Например, кнопка может быть большой, красной или заблокированной. В CSS модификатор пишется через два дефиса (--).

Пример: .button--primary (основная кнопка), .button--disabled (неактивная), .card--dark (тёмная карточка).

Аналогия

Блок - это автомобиль. Элементы - это руль, колёса и двигатель (без машины они не поедут). А модификатор - это цвет кузова (красный, чёрный) или тип топлива. Машина остаётся машиной, просто с другими свойствами.

Как это выглядит в коде

Вот пример карточки товара, свёрстанной по БЭМ:

<div class="card card--dark">    <img class="card__image" src="product.jpg" alt="Товар">    <div class="card__content">        <h2 class="card__title">Наушники</h2>        <p class="card__price">5000 ₽</p>        <button class="card__button card__button--disabled">Купить</button>    </div></div>

Обратите внимание на классы. Они выглядят длинными, но зато невероятно понятными. Глядя на card__title, вы сразу понимаете, что это заголовок внутри карточки.

Главное правило БЭМ: никакой вложенности селекторов

Самая частая ошибка новичков, которые начинают использовать БЭМ, — это писать вложенные селекторы в CSS.

Плохо:

.card .card__title {    color: red;}

Хорошо:

.card__title {    color: red;}

Почему так? В БЭМ имена классов уже уникальны. Нам не нужно уточнять в CSS, что этот заголовок лежит именно в карточке, потому что в самом названии класса уже есть приставка card__.

Это даёт потрясающий эффект: специфичность всех селекторов становится одинаковой (один класс). Из-за этого CSS становится плоским и предсказуемым. Вам больше не придётся использовать !important, чтобы перебить какой-то сложный вложенный селектор.

Правила использования

  • Блок не зависит от окружения. Карточку товара можно положить в сайдбар, в каталог или в корзину. Она везде будет выглядеть одинаково.
  • Элементы не используются отдельно от блока. В HTML не должно быть тега с классом card__title, если у него нет родителя с классом card.
  • Вложенность элементов не допускается. Нельзя писать card__content__title. Если внутри контента карточки есть заголовок, это всё равно card__title, а не card__content__title. БЭМ допускает вложенность только на один уровень.
  • Модификатор не используется отдельно. Класс card--dark всегда пишется в HTML в паре с классом card. В CSS мы просто задаём ему дополнительные стили: .card--dark { background: #000; }.

Шпаргалка

Самое важное в одном месте:

  • block независимый компонент (card)
  • block__element часть блока (card__title)
  • block--modifier состояние блока (card--dark)
  • block__element--modifier состояние элемента (button__icon--large)
  • Плоский CSS никакой вложенности селекторов
  • Один класс одинаковая специфичность везде

Если что-то не работает

Разберём типичные проблемы при освоении БЭМ.

  • «Классы получаются слишком длинными». Это правда. card__image-wrapper--rounded выглядит громоздко. Но зато через год вы скажете себе спасибо, потому что сразу поймёте, к какому блоку относится этот класс и где его искать. В БЭМ длина имени не порок, порок - нечитаемость.
  • «Я использую &:hover в нативном CSS, это нормально?» Да, это современный аналог БЭМ в эпоху CSS Nesting. Запись .card__title { &:hover { color: red; } } компилируется в .card__title:hover. Специфичность остаётся низкой, так что это отличный подход.
  • «Можно ли делать глобальные элементы, например, кнопку?» Если кнопка используется по всему сайту, это отдельный Блок (.button), а не элемент карточки. В карточке она тогда будет просто вызываться: <button class="button">. А если она имеет особый вид только в карточке, можно добавить модификатор: class="button button--card".
  • «Я использую id для стилизации». В БЭМ стилизация через #id запрещена. Это убивает переиспользуемость и повышает специфичность до небес. Только классы!

Если что-то не получается или есть вопрос - напишите в Telegram, разберёмся вместе.

Практика

Четыре задачи. Первые две - на понимание структуры БЭМ, вторые две - на переписывание кода.

Задача 1. Определите роль

Что из перечисленного является блоком, что элементом, а что модификатором?

  1. .nav
  2. .nav__link
  3. .nav--sticky
  4. .form__input--error
Подсказка

Смотрите на символы: два подчёркивания - элемент, два дефиса - модификатор.

Разбор
  1. Блок (навигация).
  2. Элемент (ссылка внутри навигации).
  3. Модификатор (навигация с прилипанием).
  4. Модификатор элемента (поле ввода с состоянием ошибки).
Задача 2. Найдите ошибку в БЭМ

Разработчик свёрстал карточку. Какие ошибки по методологии БЭМ он допустил?

<div class="card">    <div class="card__content">        <h2 class="card__content__title">Заголовок</h2>        <div class="button">Кнопка</div>    </div></div>
Подсказка

Посмотрите на длину класса заголовка и на класс кнопки.

Разбор

Ошибки:

  1. Вложенность элементов. Класс card__content__title написан неверно. В БЭМ вложенности элементов нет. Заголовок должен быть просто card__title.
  2. Кнопка без привязки. Кнопка внутри карточки - это элемент карточки. Она должна иметь класс card__button, а не просто button (иначе она может получить стили от глобальной кнопки сайта и сломаться).
Задача 3. Перепишите HTML

У вас есть HTML-код формы. Перепишите названия классов по методологии БЭМ. Блок назовите auth-form.

<form class="form">    <h2 class="title">Вход</h2>    <input class="input" type="text">    <input class="input error" type="password">    <button class="btn primary">Войти</button></form>
Подсказка

Все элементы внутри формы должны иметь префикс auth-form__, а модификаторы - дефисы.

Разбор 
<form class="auth-form">    <h2 class="auth-form__title">Вход</h2>    <input class="auth-form__input" type="text">    <input class="auth-form__input auth-form__input--error" type="password">    <button class="auth-form__button auth-form__button--primary">Войти</button></form>
Задача 4. Перепишите CSS

Теперь перепишите CSS-код для этой формы, избавившись от вложенности (сделайте его плоским).

.auth-form .title {    font-size: 24px;}.auth-form .input {    border: 1px solid #ccc;}.auth-form .input.error {    border-color: red;}
Подсказка

Просто используйте классы, которые мы придумали в предыдущей задаче, без родительских селекторов.

Разбор 
.auth-form__title {    font-size: 24px;}.auth-form__input {    border: 1px solid #ccc;}.auth-form__input--error {    border-color: red;}

Теперь селекторы плоские, специфичность одинаковая (один класс), и стили никогда не пересекутся с другими формами на сайте.

Что мы узнали и что дальше

БЭМ - это не про то, как сделать красиво. Это про то, как сделать поддерживаемо. Теперь ваш CSS не превратится в кашу через месяц работы. Вы умеете разбивать интерфейс на блоки, выделять в них элементы и добавлять модификаторы.

Вы узнали:

  • Что такое Блок, Элемент и Модификатор.
  • Как работает синтаксис __ и --.
  • Почему в БЭМ нельзя использовать вложенные селекторы.
  • Как писать плоский CSS.

В следующем уроке мы поговорим о Доступности (a11y). Вы узнаете, как сделать так, чтобы вашим сайтом могли пользоваться люди с ограниченными возможностями (например, незрячие пользователи со скринридерами), и почему это важно не только с точки зрения этики, но и для SEO.
