Планировщик Cron и финальный проект

~35 минут Linux Только практика

Мы дошли до финала. Вы умеете писать скрипты, работать с файлами, текстом и процессами. Но чтобы скрипт приносил настоящую пользу, он должен работать без вашего участия.

В Linux для автоматического запуска задач по расписанию есть встроенный демон - cron. Сегодня мы научимся настраивать его и напишем финальный проект - скрипт резервного копирования базы данных.

Что такое crontab

Расписание задач для cron хранится в специальном файле, который называется crontab (cron table). У каждого пользователя есть свой собственный crontab.

Чтобы открыть его для редактирования, используется команда:

crontab -e

Обычно при первом запуске система попросит выбрать редактор (например, nano - самый простой).

Синтаксис cron

Каждая строка в crontab описывает одно задание и выглядит так:

* * * * * команда_или_путь_к_скрипту

Пять звёздочек означают время запуска. Расшифровка слева направо:

  1. Минуты (от 0 до 59)
  2. Часы (от 0 до 23)
  3. Дни месяца (от 1 до 31)
  4. Месяцы (от 1 до 12)
  5. Дни недели (от 0 до 6, где 0 - воскресенье)

Звёздочка означает «любое значение». Примеры:

  • 0 3 * * * - каждый день в 03:00 ночи.
  • */5 * * * * - каждые 5 минут.
  • 0 0 1 * * - первого числа каждого месяца в полночь.
  • 0 9 * * 1-5 - в 9 утра с понедельника по пятницу.

Финальный проект: скрипт бэкапа БД

Напишем скрипт db_backup.sh, который делает резервную копию базы данных MySQL, логирует процесс и удаляет старые бэкапы.

#!/bin/bashDB_NAME="my_database"DB_USER="root"BACKUP_DIR="/var/backups/mysql"LOG_FILE="/var/log/db_backup.log"mkdir -p "$BACKUP_DIR"echo "[$(date +'%Y-%m-%d %H:%M:%S')] Начинаю бэкап базы $DB_NAME" >> "$LOG_FILE"TODAY=$(date +%Y-%m-%d)DUMP_FILE="$BACKUP_DIR/${DB_NAME}_$TODAY.sql"mysqldump -u "$DB_USER" "$DB_NAME" > "$DUMP_FILE"if [ $? -eq 0 ]; then    echo "[$(date +'%Y-%m-%d %H:%M:%S')] Успех: $DUMP_FILE" >> "$LOG_FILE"else    echo "[$(date +'%Y-%m-%d %H:%M:%S')] ОШИБКА при создании дампа!" >> "$LOG_FILE"    exit 1fiecho "[$(date +'%Y-%m-%d %H:%M:%S')] Удаляю старые бэкапы..." >> "$LOG_FILE"find "$BACKUP_DIR" -name "*.sql" -mtime +7 -deleteecho "[$(date +'%Y-%m-%d %H:%M:%S')] Работа завершена." >> "$LOG_FILE"

Теперь, чтобы запускать этот скрипт каждый день в 4 утра, откроем crontab:

crontab -e

И добавим в конец файла строку:

0 4 * * * /home/user/scripts/db_backup.sh

Не забудьте сделать скрипт исполняемым (chmod +x db_backup.sh) и указать абсолютный путь к нему.

Шпаргалка

Самое важное в одном месте:

  • crontab -e редактировать расписание
  • crontab -l посмотреть задачи
  • * * * * * мин час день мес нед
  • */5 * * * * каждые 5 минут
  • 0 3 * * * каждый день в 3 ночи

Если что-то не работает

Разберём типичные ошибки при настройке cron.

  • «Скрипт работает вручную, но не в cron». Самая частая причина - cron не знает о переменных окружения вашей оболочки. Всегда используйте абсолютные пути (/usr/bin/python3) и задавайте переменные (например, PATH) прямо внутри скрипта.
  • «Ошибка в логах crontab». Проверьте, что в конце каждой строки расписания нет лишних пробелов. А также убедитесь, что после последней строки осталась пустая строка.
  • «Забыл поставить chmod +x». Cron не сможет запустить скрипт без прав на исполнение.
  • «Вывод ошибок не видно». Cron не отправляет почту по умолчанию. Перенаправьте вывод в лог-файл внутри самого скрипта (как в нашем примере), чтобы потом понять, что пошло не так.

Практика

Четыре задачи по возрастающей сложности. У каждой есть подсказка и решение учителя.

Задача 1. Каждую минуту

Настройте cron так, чтобы ваш скрипт (любой) запускался каждую минуту и записывал текущее время в файл.

Подсказка

Создайте скрипт с командой date >> ~/time.log. В crontab добавьте * * * * * /path/to/script.sh.

Решение учителя 
crontab -e# * * * * * /home/user/time_logger.sh
Задача 2. Перезагрузка сервера

Напишите cron-задание, которое перезагружает сервер (команда reboot) каждое воскресенье в 4 утра.

Подсказка

Поле дня недели для воскресенья - это 0 или 7. Время: 4 часа, 0 минут.

Решение учителя 
0 4 * * 0 reboot
Задача 3. Логирование в скрипте

Доработайте скрипт из Задачи 1. Сделайте так, чтобы перед записью времени в лог, скрипт проверял, не превысил ли файл размер в 1 мегабайт. Если превысил - очищал его.

Подсказка

Используйте stat -c %s файл, чтобы получить размер в байтах. 1 мегабайт = 1048576 байт. Если размер больше, используйте > для очистки файла.

Решение учителя 
#!/bin/bashLOG_FILE="$HOME/time.log"SIZE=$(stat -c %s "$LOG_FILE" 2>/dev/null || echo 0)if [ "$SIZE" -gt 1048576 ]; then    echo "Лог превысил 1МБ, очищаю..." > "$LOG_FILE"fidate >> "$LOG_FILE"
Задача 4. Полный цикл бэкапа

Создайте скрипт, который архивирует папку ~/Documents в ~/Backups с текущей датой. Настройте cron на запуск каждый день в полночь.

Подсказка

Используйте tar для архивации и date +%Y-%m-%d для имени файла. В crontab укажите 0 0 * * * /path/to/backup.sh.

Решение учителя 
#!/bin/bashDATE=$(date +%Y-%m-%d)mkdir -p "$HOME/Backups"tar -czf "$HOME/Backups/docs_$DATE.tar.gz" -C "$HOME" Documents
